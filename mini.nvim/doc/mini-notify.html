mini.notify 문서

이 문서는 ’mini.nvim’의 main 브랜치에서 생성되었습니다.

mini.notify 알림 표시

MIT 라이선스 Copyright (c) 2024 Evgeni Chasnovski

모듈

기능:

  • 단일 플로팅 창에 하나 이상의 하이라이트된 알림을 표시합니다.

  • 알림 관리 (추가, 업데이트, 제거, 지우기).

  • 커스텀 vim.notify() 구현. 조정하려면 MiniNotify.make_notify()를 사용하거나 MiniNotify.setup() 호출 후 수동으로 vim.notify를 저장-복구하세요.

  • LSP 진행 보고서 자동 표시.

  • MiniNotify.get_all()로 액세스하고 MiniNotify.show_history()로 표시할 수 있는 히스토리 추적.

설정

이 모듈은 require('mini.notify').setup({})으로 설정이 필요합니다 ({}를 config 테이블로 교체하세요). 이는 스크립팅이나 수동으로 사용할 수 있는 전역 Lua 테이블 MiniNotify를 생성합니다 (예: :lua MiniNotify.*).

config 구조와 기본값은 MiniNotify.config를 참조하세요.

MiniNotify.config와 동일한 구조를 가져야 하는 vim.b.mininotify_config를 통해 버퍼 로컬에서 런타임 설정 설정을 재정의할 수 있습니다. 자세한 내용은 mini.nvim-buffer-local-config를 참조하세요.

비교

  • j-hui/fidget.nvim:

    • 알림 인터페이스 제공이라는 기본 목표는 유사합니다.

    • 더 많은 설정 옵션과 시각적 효과가 있는 반면, 이 모듈은 그렇지 않습니다 (의도적 설계).

  • rcarriga/nvim-notify:

    • ’j-hui/fidget.nvim’과 유사합니다.

하이라이트 그룹

  • MiniNotifyBorder - 창 테두리.

  • MiniNotifyLspProgress - 내장 LSP 진행 보고서의 알림.

  • MiniNotifyNormal - 기본 전경/배경 하이라이트.

  • MiniNotifyTitle - 창 제목.

하이라이트 그룹을 변경하려면 nvim_set_hl()로 직접 설정하세요.

참고: MiniNotify.make_notify() 이후의 vim.notify() 재정의는 알림 수준마다 고유한 하이라이트 그룹을 사용합니다.

비활성화

알림 표시를 비활성화하려면 vim.g.mininotify_disable (전역) 또는 vim.b.mininotify_disable (버퍼용)을 true로 설정하세요. 다양한 시나리오와 사용자 정의 의도를 고려하여 모듈 기능 비활성화를 위한 정확한 규칙 작성은 사용자의 몫으로 남겨둡니다. 일반적인 레시피는 mini.nvim-disabling-recipes를 참조하세요.

사양

알림 사양

알림은 다음 키를 가진 테이블입니다:

  • <msg> (string) - 알림 메시지가 포함된 단일 문자열. 여러 줄을 구분하려면 \n을 사용하세요.

  • <level> (string) - vim.log.levels의 키로 된 알림 수준. “ERROR”, “WARN”, “INFO” 등.

  • <hl_group> (string) - 알림이 표시되는 하이라이트 그룹.

  • <data> (table) - 알림에 저장할 추가 데이터 (source 등).

  • <ts_add> (number) - 알림이 추가된 시점의 타임스탬프.

  • <ts_update> (number) - 최신 알림 업데이트 시점의 타임스탬프.

  • <ts_remove> (number|nil) - 알림이 제거된 시점의 타임스탬프. 알림이 제거되지 않아 “활성” 상태인 경우 nil입니다.

참고:

  • 타임스탬프는 strftime()과 호환되며 소수점 부분을 가집니다.

setup()

MiniNotify.setup({config})

모듈 설정

다음 작업도 수행합니다:

  • vim.notify() 커스텀 구현 설정 (MiniNotify.make_notify() 참조).

  • 히스토리 정리. 설정을 유지하면서 히스토리를 강제로 정리하려면 MiniNotify.setup(MiniNotify.config)를 사용하세요.

매개변수

{config} (table|nil) 모듈 설정 테이블. MiniNotify.config를 참조하세요.

사용법

require('mini.notify').setup() -- 기본 설정 사용
-- 또는
require('mini.notify').setup({}) -- {}를 설정 테이블로 교체

config

MiniNotify.config

기본값

MiniNotify.config = {
  -- 콘텐츠 관리
  content = {
    -- 알림 메시지 형식을 지정하는 함수
    -- 기본적으로 메시지 앞에 알림 시간을 추가합니다
    format = nil,

    -- 알림 배열을 중요도 순으로 정렬하는 함수
    -- 기본적으로 레벨 순으로 정렬한 다음 업데이트 타임스탬프 순으로 정렬합니다
    sort = nil,
  },

  -- LSP 진행 상황에 대한 알림
  lsp_progress = {
    -- 표시 활성화 여부
    enable = true,

    -- 알림 수준
    level = 'INFO',

    -- 마지막 메시지가 표시되어야 하는 기간 (ms)
    duration_last = 1000,
  },

  -- 창 옵션
  window = {
    -- 플로팅 창 설정
    config = {},

    -- 사용 가능한 열의 점유율(0에서 1 사이)로서의 최대 창 너비
    max_width_share = 0.382,

    -- 'winblend' 옵션 값
    winblend = 25,
  },
}

콘텐츠

config.content는 알림이 표시되는 방식을 정의합니다.

content.format은 단일 알림 객체(MiniNotify-specification 참조)를 받아 알림을 표시할 때 직접 사용할 문자열을 반환하는 함수입니다. 기본값: MiniNotify.default_format()의 경우 nil.

content.sort는 알림 객체 배열(MiniNotify-specification 참조)을 받아 해당 객체 배열을 반환하는 함수입니다. 동시에 표시되는 알림에 대한 커스텀 순서 및/또는 필터를 정의하는 데 사용할 수 있습니다. 참고: 입력에는 content.format을 적용하기 전의 알림이 포함됩니다. 기본값: MiniNotify.default_sort()의 경우 nil.

예시:

require('mini.notify').setup({
  content = {
    -- LSP 진행 상황에 대해 알림 메시지를 그대로 사용
    format = function(notif)
      if notif.data.source == 'lsp_progress' then return notif.msg end
      return MiniNotify.default_format(notif)
    end,

    -- 최신 알림을 먼저 표시
    sort = function(notif_arr)
      table.sort(
        notif_arr,
        function(a, b) return a.ts_update > b.ts_update end
      )
      return notif_arr
    end,
  },
})

LSP 진행 상황

config.lsp_progress는 LSP 진행 상황에 대한 자동 알림을 정의합니다. 진행 상황당 모든 정보가 포함된 단일 업데이트 알림으로 구현됩니다. 설정은 MiniNotify.setup() 내부에서 “$/progress” 메서드에 대한 lsp-handler의 vim.schedule() 예약 설정을 통해 수행됩니다.

lsp_progress.enable은 알림에 LSP 진행 상황을 표시할지 여부를 나타내는 불리언 값입니다. 현재 세션에서 비활성화할 수 있습니다. 기본값: true. 참고: 현재 세션에서 활성화하려면 MiniNotify.setup() 호출 중에 true여야 합니다.

lsp_progress.level은 MiniNotify.add()에서 사용할 레벨입니다. 기본값: 'INFO'.

lsp_progress.duration_last는 마지막 진행 보고서를 제거하기 전 화면에 표시할 시간(밀리초)입니다. 기본값: 1000.

참고:

  • 이는 이전에 설정된 핸들러를 저장하고 호출하여 존중합니다.

  • vim.lsp.handlers의 “$/progress” 메서드를 재정의하면 알림이 비활성화됩니다.

  • 모든 LSP 진행 알림은 data에서 다음 필드를 설정합니다:

    • <source>는 "lsp_progress"입니다.

    • <client_name>은 클라이언트 이름으로 설정됩니다 (클라이언트가 제공하거나 유추됨).

    • <context>는 최신 LSP 요청 컨텍스트입니다 (lsp-handler의 ctx 인수).

    • <response>는 최신 LSP 응답입니다 (lsp-handler의 result 인수).

창

config.window는 알림 창의 동작을 정의합니다.

window.config는 플로팅 창 특성을 정의하는 테이블 또는 이러한 테이블을 반환하는 호출 가능 객체입니다 (이미 알림을 표시하고 있는 창 버퍼의 식별자와 함께 호출됨). nvim_open_win()과 동일한 구조를 가져야 합니다. 너비에 대한 상한선과 함께 오른쪽 상단 모서리에 알림을 표시하는 다음과 같은 기본값이 있습니다:

  • width는 버퍼 콘텐츠에 맞게 선택되지만 ’columns’의 최대 window.max_width_share 점유율입니다. 더 높은 최대 너비를 가지려면 버퍼 콘텐츠에 따라 내부에서 치수를 계산하는 config.window의 함수를 사용하세요.

  • height는 ’wrap’이 활성화된 버퍼 콘텐츠에 맞게 선택됩니다 (width의 기본값을 가정).

  • anchor, col, row는 각각 “NE”, ‘columns’, 0 또는 1 (탭라인에 따라 다름)입니다.

  • border는 “single”입니다.

  • zindex는 합리적으로 가능한 한 위에 있도록 999입니다.

window.max_width_share는 ’columns’의 점유율로 최대 창 너비를 정의합니다. 0(포함 안 함)과 1 사이의 숫자여야 합니다. 기본값: 0.382.

오른쪽 하단 모서리에 알림을 표시하는 예시:

local win_config = function()
  local has_statusline = vim.o.laststatus > 0
  local pad = vim.o.cmdheight + (has_statusline and 1 or 0)
  return { anchor = 'SE', col = vim.o.columns, row = vim.o.lines - pad }
end
require('mini.notify').setup({ window = { config = win_config } })

window.winblend는 알림 창의 ‘winblend’ 값을 정의합니다. 기본값: 25.

make_notify()

MiniNotify.make_notify({opts})

vim.notify 래퍼 만들기

이 함수를 호출하면 이 모듈을 기반으로 하는 vim.notify() 구현이 생성됩니다. 일반적인 아이디어는 안전하게 가능한 한 빨리 알림을 표시하고 (vim.schedule_wrap() 참조) 설정 가능한 시간이 지나면 제거하는 것입니다.

모든 알림은 data 필드에 source = "vim.notify"를 설정합니다.

이는 MiniNotify.setup() 내부에서 기본 옵션과 함께 사용됩니다. 조정하려면 setup() 후에 수동으로 호출하세요. 예를 들어 오류를 더 오래 표시하려면 다음과 같이 하세요:

require('mini.notify').setup()
vim.notify = MiniNotify.make_notify({ ERROR = { duration = 10000 } })

원본 vim.notify를 유지하려면 다음과 같이 하세요:

local notify_orig = vim.notify
require('mini.notify').setup()
vim.notify = notify_orig

매개변수

{opts} (table|nil) 알림 level의 동작을 구성하는 옵션 (MiniNotify.add()와 동일). 필드는 vim.log.levels의 이름과 동일하며 값은 가능한 필드가 있는 테이블입니다:

  • <duration> (number) - 알림이 표시되어야 하는 기간 (ms). 0 이하인 경우 알림이 표시되지 않습니다.

  • <hl_group> (string) - 알림의 하이라이트 그룹. 기본값과 다른 데이터만 제공할 수 있습니다.

기본값:

{
  ERROR = { duration = 5000, hl_group = 'DiagnosticError'  },
  WARN  = { duration = 5000, hl_group = 'DiagnosticWarn'   },
  INFO  = { duration = 5000, hl_group = 'DiagnosticInfo'   },
  DEBUG = { duration = 0,    hl_group = 'DiagnosticHint'   },
  TRACE = { duration = 0,    hl_group = 'DiagnosticOk'     },
  OFF   = { duration = 0,    hl_group = 'MiniNotifyNormal' },
}

add()

MiniNotify.add({msg}, {level}, {hl_group}, {data})

알림 추가

히스토리에 알림을 추가합니다. 이는 “활성” 상태로 간주되어 표시됩니다. 숨기려면 이 함수가 반환하는 식별자와 함께 MiniNotify.remove()를 호출하세요.

예시:

local id = MiniNotify.add('Hello', 'WARN', 'Comment')
vim.defer_fn(function() MiniNotify.remove(id) end, 1000)

매개변수

{msg} (string) 알림 메시지.

{level} (string|nil) vim.log.levels의 키로 된 알림 수준. 기본값: 'INFO'.

{hl_group} (string|nil) 알림 하이라이트 그룹. 기본값: 'MiniNotifyNormal'.

{data} (table|nil) 알림에 저장할 추가 데이터. 기본값: {}.

반환

(number) 알림 식별자.

update()

MiniNotify.update({id}, {new})

활성 알림 업데이트

활성 알림의 내용을 수정합니다.

매개변수

{id} (number) MiniNotify.add()가 반환한 현재 활성 알림의 식별자.

{new} (table) 업데이트할 내용이 있는 테이블. 키는 MiniNotify-specification의 타임스탬프가 아닌 필드여야 하며 값은 새로운 내용 값이어야 합니다. 있는 경우, data 필드는 그대로 업데이트됩니다. 일부만 변경하려면 MiniNotify.get()과 vim.tbl_deep_extend()를 함께 사용하세요.

remove()

MiniNotify.remove({id})

알림 제거

알림이 활성 상태인 경우 활성 상태가 아니게 만듭니다 (ts_remove 필드 설정). 활성 상태가 아닌 경우 아무 작업도 하지 않습니다.

매개변수

{id} (number|nil) 이전에 추가된 알림의 식별자. 그렇지 않은 경우 아무 작업도 수행되지 않습니다 (조용히).

clear()

MiniNotify.clear()

모든 활성 알림 제거

모든 활성 알림을 숨기고 창 표시를 중단합니다 (표시 중인 경우).

refresh()

MiniNotify.refresh()

알림 창 새로 고침

알림 창에 관련 정보를 표시합니다:

  • 활성 알림 배열을 만듭니다 (MiniNotify-specification 참조).

  • 배열에 config.content.sort를 적용합니다. 출력이 알림이 0개인 경우 알림 창이 표시되지 않도록 합니다.

  • 알림 배열의 각 요소에 config.content.format을 적용하고 해당 메시지를 업데이트합니다.

  • 알림으로 콘텐츠를 구성하고 창에 표시합니다.

참고: 빠른 이벤트 (vim.in_fast_event() 내부에 있는 경우 효과가 지연됩니다.

get()

MiniNotify.get({id})

ID로 이전에 추가된 알림 가져오기

매개변수

{id} (number) 알림 식별자.

반환

(table) 알림 객체 (MiniNotify-specification 참조).

get_all()

MiniNotify.get_all()

이전에 추가된 모든 알림 가져오기

알림 식별자를 키로 하는 사용된 알림 맵을 가져옵니다.

활성 알림 객체만 가져오는 데 사용할 수 있습니다. 예시:

-- 활성 알림 가져오기
vim.tbl_filter(
  function(notif) return notif.ts_remove == nil end,
  MiniNotify.get_all()
)

반환

(table) 알림 객체 값을 가진 맵 (MiniNotify-specification 참조). 참고: 메시지는 마지막 유효한 업데이트에서 가져옵니다.

show_history()

MiniNotify.show_history()

히스토리 표시

이전에 표시된 모든 알림이 있는 스크래치 버퍼를 열거나 재사용합니다.

참고:

  • 콘텐츠는 최신 업데이트 시간을 기준으로 가장 오래된 것부터 최신 것 순으로 정렬됩니다.

  • 메시지는 config.content.format으로 형식이 지정됩니다.

default_format()

MiniNotify.default_format({notif})

기본 콘텐츠 형식

config.content.format으로 기본 사용됩니다. 알림 메시지 앞에 사람이 읽을 수 있는 업데이트 시간과 구분 기호를 추가합니다.

매개변수

{notif} (table) 알림 객체 (MiniNotify-specification 참조).

반환

(string) 형식화된 알림 메시지.

default_sort()

MiniNotify.default_sort({notif_arr})

기본 콘텐츠 정렬

config.content.sort로 기본 사용됩니다. 먼저 알림의 level로 정렬합니다 (“ERROR” > “WARN” > “INFO” > “DEBUG” > “TRACE” > “OFF”; 클수록 더 중요함). 동일한 경우 최신 업데이트 시간으로 정렬합니다 (나중일수록 더 중요함).

매개변수

{notif_arr} (table) 알림 배열 (MiniNotify-specification 참조).

반환

(table) 정렬된 알림 배열.
