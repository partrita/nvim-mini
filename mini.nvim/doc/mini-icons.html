mini.icons 문서

’mini.nvim’의 main 브랜치에서 생성됨

mini.icons 아이콘 제공자

MIT License Copyright (c) 2024 Evgeni Chasnovski

모듈

기능:

  • 단일 MiniIcons.get() 호출을 통해 다양한 카테고리(파일 유형, 파일/디렉터리 경로, 확장자, 운영 체제, LSP 종류 값)에 대한 아이콘과 하이라이팅을 제공합니다. 아이콘 및 카테고리 기본값은 재정의할 수 있습니다.

  • 스타일 구성 가능: “glyph” (아이콘 글리프) 또는 “ascii” (글리프가 아닌 대체 텍스트).

  • 색상 체계와 더 잘 어우러지도록 고정된 하이라이트 그룹 세트(기본적으로 내장 그룹에 연결됨)를 사용합니다.

  • 최대 성능을 위한 캐싱.

  • vim.filetype.add() 및 vim.filetype.match()와 통합됩니다.

  • ‘mini.nvim’ 외부의 플러그인과 더 나은 통합을 위해 ’nvim-tree/nvim-web-devicons’의 메서드를 모방(mocking)합니다. MiniIcons.mock_nvim_web_devicons()를 참조하세요.

  • 아이콘을 포함하도록 “LSP 종류(kind)”에 대한 내장 맵을 조정합니다. 특히 이를 통해 mini.completion이 LSP 단계에서 아이콘을 사용할 수 있게 됩니다. MiniIcons.tweak_lsp_kind()를 참조하세요.

참고:

  • 가능한 많은 사용 사례를 위한 아이콘 모음집이 되는 것이 목표는 아닙니다. 각 카테고리에 내장 아이콘 데이터로 포함되기 위한 특정 기준이 있습니다(MiniIcons.get() 참조). 주요 지원 카테고리는 “filetype”입니다.

’mini.icons’를 의존성으로 사용하는 플러그인 저자를 위한 권장 사항:

  • _G.MiniIcons 테이블이 존재하는지 확인하고(사용자가 명시적으로 ’mini.icons’를 활성화했음을 의미), 존재하는 경우에만 아이콘을 제공하세요.

  • 아이콘 문자열과 추가 데이터를 얻으려면 MiniIcons.get() 함수를 사용하세요.

  • 파일 아이콘의 경우 상대 경로 또는 파일 이름만 사용하는 것보다 전체 경로를 사용하는 것을 권장합니다. 경로가 상위 디렉터리를 사용하는 패턴과 일치하는 경우 차이가 발생합니다. MiniIcons.config에 이에 대한 예시가 있습니다.

의존성

권장 의존성:

  • 특수 utf8 글리프 표시를 지원하는 터미널 에뮬레이터(가급적 “overflow” 뷰 지원, 즉 하나가 아닌 두 개의 가로 셀에 표시). WezTerm, Kitty, Alacritty, iTerm2, Ghostty와 같은 대부분의 현대적인 기능이 풍부한 터미널 에뮬레이터는 이를 즉시 지원합니다. “overflow” 기능이 없으면 아이콘이 더 작게 표시될 뿐입니다. 특수 utf8 글리프 지원이 없으면 아이콘 글리프 대신 임의의 기호(또는 물음표 사각형)가 표시됩니다.

  • 3.0.0 버전 이상의 Nerd Fonts(https://www.nerdfonts.com) 아이콘을 지원하는 글꼴(특히 nf-md-* 클래스). 이는 Nerd Fonts 아이콘으로 패치된 글꼴을 사용하거나, 기본 글꼴에서 지원하지 않는 글리프에 대해 NerdFontsSymbolsOnly 글꼴을 대체(fallback) 글꼴로 사용하도록 터미널 에뮬레이터 수준에서 설정되어야 합니다.

터미널 에뮬레이터 및/또는 아이콘 지원 글꼴을 사용하는 것이 불가능한 경우 config.style = 'ascii'를 사용하세요. 그러면 글리프가 아닌 아이콘 세트(시각적으로는 덜 매력적임)가 사용됩니다.

설정

이 모듈은 require('mini.icons').setup({})으로 설정이 필요합니다({}를 config 테이블로 교체하세요). 그러면 스크립팅이나 수동으로(:lua MiniIcons.*를 통해) 사용할 수 있는 전역 Lua 테이블 MiniIcons가 생성됩니다.

config 구조와 기본값에 대해서는 MiniIcons.config를 참조하세요.

비교

  • nvim-tree/nvim-web-devicons (사용자 입장):

    • 각 아이콘에 대해 별도의 하이라이트 그룹을 사용하여 개별 색상을 설정하는 반면, 이 모듈은 고정된 하이라이트 그룹 세트를 사용합니다. 이로 인해 일괄적으로 사용자 정의하기가 더 쉬워지고 실제로 어떤 색상 체계와도 잘 어우러집니다.

    • 이 모듈은 “Material design” 세트인 nf-md-* Nerd Fonts 아이콘을 선호하는 반면, ’nvim-web-devicons’는 주로 “devicons” 세트인 nf-dev-*를 선호합니다.

    • 지원되는 카테고리가 약간 다릅니다(많은 부분이 겹침).

    • 둘 다 모든 아이콘의 사용자 정의를 지원합니다. 오직 이 모듈만이 지원되는 카테고리별 기본 아이콘의 사용자 정의를 지원합니다.

    • 이 모듈을 사용할 때 일반적이지 않은 파일의 아이콘을 얻기 위해 동기적으로 여러 번 호출하는 경우(예: mini.files) 가끔 약간의 지연이 발생할 수 있습니다. 이는 vim.filetype.match() 폴백을 사용하기 때문이며, 나중의 사용을 위해 값이 캐싱되므로 첫 번째 호출 시에만 발생합니다.

    • 이 모듈은 글리프를 사용할 수 없는 경우를 위한 “ascii”와 같은 다양한 아이콘 스타일을 지원하는 반면, ’nvim-web-devicons’는 지원하지 않습니다.

    • 이 모듈은 MiniIcons.mock_nvim_web_devicons() 함수를 제공하여, 호출 시 설치된 ‘nvim-web-devicons’ 플러그인을 흉내 내어 아직 ’mini.icons’를 지원하지 않는 다른 플러그인을 지원할 수 있도록 합니다.

  • nvim-tree/nvim-web-devicons (플러그인 개발자 입장):

    • 둘 다 주요 “아이콘 가져오기” 유형의 함수를 가지고 있습니다:

      • 둘 다 아이콘과 하이라이트 그룹 문자열의 튜플을 반환합니다.

      • 이 모듈은 항상 아이콘 데이터를 반환하며 필요한 경우 사용자가 설정한 기본값으로 폴백하는 반면, ’nvim-web-devicons’는 nil을 반환할 수 있습니다. 이 모듈의 방식은 데이터 대신 또는 옆에 항상 아이콘을 표시하는 가장 일반적인 사용 사례에 더 부합합니다. 출력이 폴백 결과인지 여부를 나타내는 세 번째 반환값이 있습니다(MiniIcons.get() 참조).

      • 이 모듈은 “file” 및 “extension” 카테고리에 대한 폴백으로 vim.filetype.match()를 사용하는 반면, ’nvim-web-devicons’는 수동으로 유지 관리되는 지원 파일 이름 및 확장자 테이블에 전적으로 의존합니다. 폴백을 사용하면 가끔 첫 번째 호출이 느려지는 대신 더 넓은 지원과 Neovim의 파일 유형 감지와의 깊은 통합을 얻을 수 있습니다. 이 차이는 파일 유형 일치보다 더 빠른 파일 확장자 확인을 선호함으로써 합리적인 수준으로 줄어듭니다.

      • 이 모듈은 모든 반환 값을 캐싱하므로 동일한 인수로 다음 호출 시 매우 빠르지만, ’nvim-web-devicons’는 그렇게 하지 않습니다.

      • 이 모듈은 전체 파일/디렉터리 경로를 입력으로 받습니다.

    • 지원되는 카테고리 세트가 다릅니다(MiniIcons.config 참조):

      • 둘 다 “file”, “extension”, “filetype”, “operating system”을 지원합니다. 비록 그 양은 다르지만: ’nvim-web-devicons’는 “operating system”에 대해 더 많은 사례를 다루는 반면, 이 모듈은 다른 사례들에 대해 결국 더 나은 범위를 가집니다.

      • 이 모듈은 “directory” 및 “lsp” 카테고리를 지원합니다.

      • ’nvim-web-devicons’는 “desktop environment” 및 “window management” 카테고리를 다룹니다. 이 모듈은 상대적으로 수요가 낮아 이를 포함하지 않습니다.

  • onsails/lspkind.nvim:

    • CompletionItemKind에 대해서만 아이콘을 제공하는 반면, 이 모듈은 SymbolKind 및 기타 비 LSP 카테고리에 대한 아이콘도 제공합니다.

    • ’hrsh7th/nvim-cmp’를 위한 전용 포맷팅 함수를 제공하는 반면, 이 모듈은 의도적으로 제공하지 않습니다(아이콘을 추가하는 것은 수동으로 구현하기 간단해야 하며, 그 외의 것은 범위 밖입니다).

하이라이트 그룹

아이콘 하이라이트로 다음 하이라이트 그룹 세트만 사용됩니다. 이들은 모두 색상 있는 전경색(foreground)만 정의하는 것이 좋습니다:

  • MiniIconsAzure - 아주르(Azure).

  • MiniIconsBlue - 파란색(Blue).

  • MiniIconsCyan - 청록색(Cyan).

  • MiniIconsGreen - 녹색(Green).

  • MiniIconsGrey - 회색(Grey).

  • MiniIconsOrange - 주황색(Orange).

  • MiniIconsPurple - 보라색(Purple).

  • MiniIconsRed - 빨간색(Red).

  • MiniIconsYellow - 노란색(Yellow).

하이라이트 그룹을 변경하려면 nvim_set_hl()로 직접 설정하세요.

setup()

MiniIcons.setup({config})

모듈 설정

매개변수

{config} (table|nil) 모듈 설정 테이블. MiniIcons.config를 참조하세요.

사용법

require('mini.icons').setup() -- 기본 설정 사용
-- 또는
require('mini.icons').setup({}) -- {}를 사용자 설정 테이블로 교체

config

MiniIcons.config

기본값

MiniIcons.config = {
  -- 아이콘 스타일: 'glyph' 또는 'ascii'
  style = 'glyph',

  -- 카테고리별 사용자 정의. 자세한 내용은 `:h MiniIcons.config`를 참조하세요.
  default   = {},
  directory = {},
  extension = {},
  file      = {},
  filetype  = {},
  lsp       = {},
  os        = {},

  -- "file" 판별 중에 고려할 확장자를 제어
  use_file_extension = function(ext, file) return true end,
}

스타일

config.style은 사용할 아이콘 스타일을 정의하는 문자열입니다. 다음이 될 수 있습니다:

  • 'glyph' (기본값) - 글리프 아이콘 사용(예: 󰈔 및 󰉋 ).

  • 'ascii' - 폴백 ASCII 호환 아이콘 사용. 이는 해당 카테고리 내에서 확인된 아이콘 이름의 첫 글자를 대문자로 표시합니다. 예시:

    MiniIcons.get('file', 'Makefile') -- 아이콘으로 `'M'`을 가짐
MiniIcons.get('extension', 'lua') -- 아이콘으로 `'L'`을 가짐
MiniIcons.get('file', 'file.lua') -- 아이콘으로 `'L'`을 가짐; 'lua' 'extension'
                                  -- 카테고리에서 오는 것으로 확인됨
MiniIcons.get('file', 'myfile')   -- 아이콘으로 `'F'`을 가짐; 'file' 'default'
                                  -- 카테고리에서 오는 것으로 확인됨

카테고리별 사용자 정의

지원되는 카테고리의 아이콘을 사용자 정의하는 데 다음 항목을 사용할 수 있습니다:

  • config.default

  • config.directory

  • config.extension

  • config.file

  • config.filetype

  • config.lsp

  • config.os

사용자 정의는 아이콘 이름 항목의 값으로 <glyph> (아이콘 글리프) 및/또는 <hl> (하이라이트 그룹 이름) 문자열 필드를 가진 테이블을 제공하여 수행해야 합니다. 예시:

require('mini.icons').setup({
  default = {
    -- "file" 카테고리의 기본 글리프 재정의 (하이라이트 그룹 재사용)
    file = { glyph = '󰈤' },
  },
  extension = {
    -- 하이라이트 그룹 재정의 ('mini.icons'의 것일 필요는 없음)
    lua = { hl = 'Special' },

    -- 사용자 정의 확장자에 대한 아이콘 추가. 이는 'file.my.ext'와 같은 입력에 대해
    -- 'file' 카테고리에서도 사용됩니다.
    ['my.ext'] = { glyph = '󰻲', hl = 'MiniIconsRed' },
  },
})

참고:

  • 이러한 사용자 정의는 MiniIcons.setup() 호출 내에서만 적용됩니다. | 성능상의 이유로 :lua MiniIcons.config.xxx = { | }를 통해 대화형으로 변경하는 것은 | 작동하지 않습니다.

  • 대소문자를 무시하고 일치하는 카테고리에는 소문자 이름을 사용하세요. 자세한 내용은 MiniIcons.get()을 참조하세요.

파일 판별 중 확장자 사용

config.use_file_extension은 “file” 카테고리 판별 중에 어떤 확장자를 아이콘 데이터의 소스로 고려할지 제어하는 데 사용할 수 있는 함수입니다(자세한 내용은 MiniIcons.get() 참조). 기본값: 항상 true를 반환하는 함수(즉, 모든 확장자를 고려함).

파일 이름에서 발견된 점(.) 뒤의 가장 긴 접미사에 대해 한 번 호출됩니다. 인수는 ext(발견된 확장자, 소문자)와 file(아이콘이 계산되는 입력, 그대로)입니다. ext를 고려하려면 명시적으로 true를 반환해야 합니다(즉, MiniIcons.get('extension', ext)를 호출하고 출력이 기본값이 아닌 경우 사용함). 그렇지 않으면 확장자는 아예 고려되지 않습니다.

이 설정의 주요 사용 사례는 판별이 vim.filetype.match() 단계에 도달하도록 일부 확장자를 무시하는 것입니다. 이는 인식 가능한 확장자를 가진 파일에 대해 파일 유형 감지가 설정되어 있고 충돌하는 아이콘(당신이 사용하고자 하는)이 있는 경우에 필요합니다. 참고: 문제가 되는 파일 유형 감지가 사전에 알려진 파일 이름만 포함하는 경우 config.file 사용자 정의를 사용하는 것을 권장합니다.

예시:

-- 내장 파일 유형 감지는 "queries/.*%.scm"과 같은 파일을 "query" 파일 유형으로
-- 인식합니다. 그러나 특별한 설정이 없으면 'mini.icons'는 "scm" 확장자를 사용하여
-- Scheme 파일로 판별합니다. 다음은 "scm" 확장자를 무시하고 `vim.filetype.match()`
-- 폴백에 완전히 의존하도록 하는 설정입니다.
require('mini.icons').setup({
  -- 파일 이름의 점을 고려하여 마지막 문자를 명시적으로 확인
  use_file_extension = function(ext) return ext:sub(-3) ~= 'scm' end
})

-- 무시할 확장자의 다른 일반적인 선택지: "yml", "json", "txt".

get()

MiniIcons.get({category}, {name})

아이콘 데이터 가져오기

사용 예시:

-- 결과: `icon='󰢱'`, `hl='MiniIconsAzure'`, `is_default=false`
local icon, hl, is_default = MiniIcons.get('file', 'file.lua')

참고:

  • 아이콘 이름이 대상 카테고리 내에서 명시적으로 지원되지 않더라도 항상 어떤 데이터를 반환합니다. “default” 카테고리가 폴백으로 사용됩니다. 이 특정 사례가 폴백의 결과인지 확인하려면 세 번째 출력 값을 사용하세요.

  • 글리프는 Nerd Fonts 아이콘의 더 풍부한 nf-md-* 클래스(“Material design” 세트)에서 가급적 명시적으로 선호됩니다.

  • 동일한 인수를 사용한 다음 호출의 성능을 높이기 위해 첫 번째 호출 후 출력이 캐싱됩니다. 캐시를 재설정하려면 MiniIcons.setup()을 호출하세요.

  • “extension” 및 “file” 카테고리에 대한 첫 번째 호출 성능을 높이려면 MiniIcons.config에 자주 사용되는 값을 추가하세요. 이들은 vim.filetype.match()를 실행하는 것보다 선호됩니다.

  • “file” 및 “directory” 카테고리에 대한 아이콘 이름 일치는 대소문자를 구분하여 정확하게 수행됩니다. 나머지는 대소문자를 무시하고 수행됩니다.

매개변수

{category} (string) 카테고리 이름. 지원되는 카테고리:

  • 'default' - 모든 카테고리에 대한 폴백으로 사용되는 아이콘 데이터. 아이콘 이름:

    • <Input>: 지원되는 모든 카테고리 이름.

    • <Built-in>: 지원되는 카테고리 이름만.

    예시:

    MiniIcons.get('default', 'file')

  • 'directory' - 디렉터리 경로에 대한 아이콘 데이터. 아이콘 이름:

    • <Input>: 모든 문자열이지만 베이스네임(basename)만 사용됩니다. 존재하지 않는 경로에서도 작동합니다(확인은 수행되지 않음).

    • <Built-in>: 언어/소프트웨어와 관련되지 않은 인기 있는 디렉터리 이름 (Neovim, Git 등과 같은 몇 가지 주목할 만한 예외 제외).

    예시:

    -- 이 모든 것들은 동일한 결과를 냅니다.
MiniIcons.get('directory', '.config')
MiniIcons.get('directory', '~/.config')
MiniIcons.get('directory', '/home/user/.config')

-- 다른 결과를 냅니다.
MiniIcons.get('directory', '.Config')

  • 'extension' - 확장자에 대한 아이콘 데이터. 아이콘 이름:

    • <Input>: 모든 문자열 (추가적인 점 접두사 제외).

    • <Built-in>: 연결된 파일 유형이 없는 인기 있는 확장자와 파일 유형 감지 결과가 충분히 좋지 않은 세트.

    아이콘 데이터는 다음 순서로 확인을 시도합니다:

    • 사용자 설정 및 내장 확장자 목록 (더 나은 결과를 위해). 목록을 보려면 :=MiniIcons.list('extension')를 실행하세요. 점 뒤의 접미사로 존재하는 경우에도 사용됩니다 (가장 긴 것이 선호됨).

    • 자리 표시자 파일 이름을 사용한 vim.filetype.match() 결과로서의 파일 유형. “filetype” 카테고리의 아이콘 데이터를 사용합니다.

    예시:

    -- 이 모든 것들은 동일한 결과를 냅니다.
MiniIcons.get('extension', 'lua')
MiniIcons.get('extension', 'LUA')
MiniIcons.get('extension', 'my.lua')

  • 'file' - 파일 경로에 대한 아이콘 데이터. 아이콘 이름:

    • <Input>: 모든 문자열. 존재하지 않는 경로에서도 작동합니다(확인은 수행되지 않음).

    • <Built-in>: 언어/소프트웨어와 관련되지 않은 인기 있는 파일 이름 (Neovim, Git 등과 같은 몇 가지 주목할 만한 예외 제외) 및 인식 가능한 확장자를 가지고 있지만 특별한 감지 가능 파일 유형을 가진 세트.

    아이콘 데이터는 다음 순서로 확인을 시도합니다:

    • 사용자 설정 및 내장 파일 이름 목록 (입력의 베이스네임과 정확히 일치). 목록을 보려면 :=MiniIcons.list('file')를 실행하세요.

    • 베이스네임 확장자:

      • get('extension', ext)로 직접 일치시키며, 여기서 ext는 점 뒤의 가장 긴 접미사입니다.

      • config.use_file_extension이 true를 반환한 경우에만 고려됩니다.

      • 인식 가능한 확장자(즉, 기본 폴백이 아닌 것)만 사용됩니다.

    • 전체 입력(베이스네임이 아님)을 filename으로 사용한 vim.filetype.match() 결과로서의 파일 유형. “filetype” 카테고리의 아이콘 데이터를 사용합니다.

    예시:

    -- 이 모든 것들은 동일한 결과를 냅니다.
MiniIcons.get('file', 'init.lua')
MiniIcons.get('file', '~/.config/nvim/init.lua')
MiniIcons.get('file', '/home/user/.config/nvim/init.lua')

-- 다른 결과를 냅니다.
MiniIcons.get('file', 'Init.lua')
MiniIcons.get('file', 'init.LUA')

-- `vim.filetype.match()`에서 전체 경로 입력을 존중합니다.
MiniIcons.get('file', '.git/info/attributes')

  • 'filetype' - ‘filetype’ 값에 대한 아이콘 데이터. 아이콘 이름:

    • <Input>: 모든 문자열.

    • <Built-in>: Neovim 생태계에서 합리적으로 사용되는 모든 파일 유형. 이 카테고리는 사용 사례를 지원하기 위한 가장 넓은 망으로 의도되었습니다. 사용자는 특정 파일 유형 감지 설정을 가지는 것이 권장됩니다.

    예시:

    MiniIcons.get('filetype', 'lua')
MiniIcons.get('filetype', 'help')
MiniIcons.get('filetype', 'minifiles')

  • 'lsp' - 다양한 “LSP 종류(kind)” 값에 대한 아이콘 데이터. 아이콘 이름:

    • <Input>: 모든 문자열.

    • <Built-in>: 사용자에게 표시될 수 있는 LSP 사양의 네임스페이스 항목만 해당. CompletionItemKind, SymbolKind 등.

    예시:

    MiniIcons.get('lsp', 'array')
MiniIcons.get('lsp', 'keyword')

  • 'os' - 인기 있는 운영 체제에 대한 아이콘 데이터. 아이콘 이름:

    • <Input>: 모든 문자열.

    • <Built-in>: nf-md-* 클래스 아이콘을 가진 운영 체제만 해당.

    예시:

    MiniIcons.get('os', 'linux')
MiniIcons.get('os', 'arch')
MiniIcons.get('os', 'macos')

{name} (string) 카테고리 내의 아이콘 이름. 특정 카테고리에 대해 명시적으로 지원되는 아이콘 이름을 얻으려면 MiniIcons.list()를 사용하세요.

반환값

(...) 아이콘 문자열, 하이라이트하도록 제안된 하이라이트 그룹 이름, 그리고 이 아이콘이 기본값으로의 폴백 결과로 반환되었는지 여부를 나타내는 불리언의 튜플. 예시:

-- 결과: `icon='󰢱'`, `hl='MiniIconsAzure'`, `is_default=false`
local icon, hl, is_default = MiniIcons.get('file', 'file.lua')

-- 결과: `icon='󰈔'`, `hl='MiniIconsGrey'`, `is_default=true`
local icon, hl, is_default = MiniIcons.get('file', 'not-supported')

list()

MiniIcons.list({category})

명시적으로 지원되는 아이콘 이름 목록

매개변수

{category} (string) MiniIcons.get()에서 지원하는 카테고리 이름.

반환값

(table) 카테고리에 대해 명시적으로 지원되는 아이콘 이름 배열. 참고로, 'file' 및 'extension' 카테고리는 'filetype' 카테고리와 함께 vim.filetype.match()를 사용하는 폴백을 통해 훨씬 더 많은 아이콘 이름을 지원합니다.

mock_nvim_web_devicons()

MiniIcons.mock_nvim_web_devicons()

‘nvim-web-devicons’ 모듈 모방

‘nvim-tree/nvim-web-devicons’ 플러그인의 내보낸 함수들을 모방하려면 이 함수를 호출하세요. MiniIcons.get()과 동등한 기능을 사용하여 아이콘 데이터를 반환하는 모든 함수를 모방합니다.

이 함수는 당신과 관련된 플러그인이 ’nvim-web-devicons’에만 의존하고 아직 ’mini.icons’와의 통합을 추가하지 않은 경우에 유용합니다.

전체 사용 예시:

require('mini.icons').setup()
MiniIcons.mock_nvim_web_devicons()

’nvim-web-devicons’가 설치되어 있지 않아도 작동하며, 설치되어 있어도 작동합니다(’nvim-web-devicons’가 설정된 후에 호출되어야 함).

tweak_lsp_kind()

MiniIcons.tweak_lsp_kind({mode})

내장된 LSP 종류(kind) 이름 조정

“lsp” 카테고리의 아이콘 문자열을 사용하여 vim.lsp.protocol의 해당 맵(CompletionItemKind 및 SymbolKind)을 직접 업데이트합니다. “숫자 ID에서 종류 이름으로” 부분만 업데이트됩니다(원본 맵의 데이터를 보존하기 위해).

업데이트는 다음 모드 중 하나로 수행됩니다:

  • Append: 텍스트 뒤에 아이콘 추가.

  • Prepend: 텍스트 앞에 아이콘 추가 (기본값).

  • Replace: 텍스트 대신 아이콘 사용.

참고:

  • 내장 프로토콜 맵을 사용하므로 mini.completion이 아이콘을 표시하도록 합니다.

  • 전체 vim.lsp 모듈을 로드하게 되므로 시작 시 상당한 시간이 추가될 수 있습니다. 지연 호출(lazy call)을 권장합니다. 예를 들어 MiniDeps.later()와 함께 사용하세요:

    require('mini.icons').setup()
MiniIcons.later(MiniIcons.tweak_lsp_kind)
-- 오타 수정: 원문에는 MiniDeps.later(MiniIcons.tweak_lsp_kind) 라고 되어 있음.
-- mini.deps가 로드되어 있어야 함.

매개변수

{mode} (string|nil) “prepend” (기본값), “append”, “replace” 중 하나.
