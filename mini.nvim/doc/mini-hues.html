mini.hues 문서

mini.nvim의 ‘main’ 브랜치에서 생성됨

mini.hues 설정 가능한 색상 테마 생성

MIT 라이선스 Copyright (c) 2023 Evgeni Chasnovski

모듈

주요 기능:

  • 배경색(background)과 전경색(foreground) 두 가지 기본 색상을 설정해야 합니다. 이들의 음영과 다른 비기본 색상들은 시각적으로 최대한 구별되도록 계산됩니다. 설정 영감은 MiniHues.config를 참조하세요.

  • 설정 가능:

    • 비기본 색상에 사용되는 색조(hue)의 수 (0에서 8까지).

    • 채도 레벨 (“low”, “lowmedium”, “medium”, “mediumhigh”, “high”).

    • 선택된 일부 UI 요소에 사용되는 강조(accent) 색상.

    • 플러그인 통합 (빠른 시작을 위해 선택적으로 활성화 가능).

  • 기본 색상을 위한 무작위 생성기. MiniHues.gen_random_base_colors()를 참조하세요. randomhue 색상 테마를 구동합니다.

  • 색상 테마에 사용되는 팔레트를 계산하는 Lua 함수. MiniHues.make_palette()를 참조하세요.

  • 번들 색상 테마. MiniHues-color-schemes를 참조하세요.

설정

이 모듈은 require('mini.hues').setup({})과 필수 background 및 foreground 필드로 설정이 필요합니다 (취향에 맞게 필드를 추가하세요). 스크립팅이나 수동으로 사용할 수 있는 전역 Lua 테이블 MiniHues를 생성합니다 (:lua MiniHues.* 사용).

config 구조와 기본값은 MiniHues.config를 참조하세요.

이 모듈은 런타임 옵션이 없으므로 vim.b.minihues_config를 사용해도 효과가 없습니다.

예시:

require('mini.hues').setup({
  background = '#11262d',
  foreground = '#c0c8cc',
  plugins = {
    default = false,
    ['nvim-mini/mini.nvim'] = true,
  },
})

참고

  • 이것은 플러그인의 일부 색상 테마를 생성하는 데 사용됩니다 (MiniHues-color-schemes 참조).

  • setup()을 사용하는 것이 실제로 색상 테마를 생성하는 것은 아닙니다. 기본적으로 조정된 highlight-groups 세트를 생성합니다. 자신만의 테마를 만들려면:

    • ’runtimepath’에서 접근 가능한 모든 “colors” 디렉토리(보통 Neovim 설정 디렉토리 내부의 “colors”면 충분함) 안에 “myscheme.lua” 파일(선택한 테마 이름으로 명명)을 넣으세요.

    • “myscheme.lua” 내부에서 팔레트와 함께 require('mini.hues').setup()을 호출하고, 그 후에만 g:colors_name을 “myscheme”으로 설정하세요.

  • 이 모듈은 구현의 단순성을 위해 cterm-colors를 정의하지 않습니다. mini.colors 모듈, 특히 MiniColors-colorscheme:add_cterm_attributes()를 사용하세요.

색상 테마

번들 색상 테마

  • miniwinter : 청색(azure) 배경의 “차가운 겨울” 팔레트.

  • minispring : 녹색 배경의 “꽃피는 봄” 팔레트.

  • minisummer : 갈색/노란색 배경의 “더운 여름” 팔레트.

  • miniautumn : 보라색 배경의 “선선한 가을” 팔레트.

  • randomhue : 무작위로 생성된 동일한 색조의 배경과 전경을 사용합니다. 모든 :colorscheme randomhue 호출은 서로 다른 (무작위지만 신중하게 선택된) 색상을 생성합니다.

    이는 본질적으로 ‘background’ 값을 약간 조정한 MiniHues.setup()과 MiniHues.gen_random_base_colors() 호출의 조합입니다.

    일반적인 :colorscheme처럼 활성화하세요. :lua print(vim.inspect(MiniHues.config))로 현재 활성 설정을 가져올 수 있습니다.

setup()

MiniHues.setup({config})

모듈 설정

주요 부작용(side effect)은 팔레트를 생성하고 적용하는 것입니다. 본질적으로 MiniHues.make_palette()와 MiniHues.apply_palette()의 조합입니다.

사용법

require('mini.hues').setup({
  -- 취향에 따라 구성 테이블을 사용하세요
  -- 'background'와 'foreground' 필드가 모두 있어야 합니다
  background = '#11262d',
  foreground = '#c0c8cc',
})

config

MiniHues.config

기본값

MiniHues.config = {
  -- **필수** '#rrggbb' 16진수 문자열 형식의 기본 색상
  background = nil,
  foreground = nil,

  -- 비기본 색상에 사용되는 색조의 수
  n_hues = 8,

  -- 채도. 'low', 'lowmedium', 'medium', 'mediumhigh', 'high' 중 하나.
  saturation = 'medium',

  -- 강조 색상. 'bg', 'fg', 'red', 'orange', 'yellow', 'green',
  -- 'cyan', 'azure', 'blue', 'purple' 중 하나.
  accent = 'bg',

  -- 플러그인 통합. 모든 통합을 비활성화하려면 'default = false'를 사용하세요.
  -- 플러그인별로 설정할 수도 있습니다 (|MiniHues.config| 참조).
  plugins = { default = true },

  -- 특정 이벤트를 기반으로 하이라이트 그룹을 자동으로 조정할지 여부
  autoadjust = true,
}

특정 설정이 출력 색상 테마에 어떻게 영향을 미치는지에 대한 자세한 내용은 MiniHues.make_palette()를 참조하세요.

플러그인 통합

config.plugins는 어떤 지원되는 플러그인에 대해 하이라이트 그룹을 생성할지 정의합니다. 통합 수를 제한하면 시작 시간이 약간 단축됩니다. 이는 다음과 같이 적용되는 불리언(true/false) 값을 가진 테이블입니다:

  • mini.hues에 나열된 플러그인 이름에 항목이 있으면 해당 항목이 사용됩니다.

  • 그렇지 않으면 config.plugins.default가 사용됩니다.

"mini.nvim" 통합만 로드하는 예시:

require('mini.hues').setup({
  background = '#11262d',
  foreground = '#c0c8cc',
  plugins = {
    default = false,
    ['nvim-mini/mini.nvim'] = true,
  },
})

자동 조정

config.autoadjust는 관련 이벤트에 따라 일부 하이라이트 그룹을 조정할지 정의합니다. 현재 조정되는 그룹:

  • hl-MsgSeparator는 ‘fillchars’의 msgsep 플래그에 따라 조정됩니다. 공백이면 배경을, 그렇지 않으면 전경을 강조합니다.

  • hl-Pmenu는 ‘pumborder’ 값에 따라 조정됩니다 (Neovim>=0.12). 테두리가 생기면 플로팅 창과 동일하게(단, 테두리에 강조 전경색 없음), 그렇지 않으면 hl-CursorLine과 동일하게 설정됩니다. 이 설계는 ins-completion-menu를 일반 플로팅 창과 구별되게 만듭니다.

make_palette()

MiniHues.make_palette({config})

팔레트 생성

팔레트 생성의 일반적인 아이디어는 주로 기본 색상(배경 및 전경)에서 추출된 색상 채널 정보를 기반으로 한다는 것입니다.

모든 작업은 Oklch 색상 공간 내에서 수행되며, 이는 각 색상이 세 가지 숫자로 정의됨을 의미합니다:

  • 밝기 (l) - 색상이 얼마나 밝은지 설명하는 0(검정)에서 100(흰색) 사이의 숫자.

  • 채도 (c) - 색상이 얼마나 다채로운지 설명하는 양수 (값이 클수록 더 화려하고, 0은 회색입니다).

  • 색조 (h) - 색상환/휠에서 “진정한 색상”의 값을 설명하는 [0, 360) 범위의 주기적인 숫자.

Oklch에 대한 자세한 내용은 MiniColors-color-spaces 또는 https://bottosson.github.io/posts/oklab/을 참조하세요.

알고리즘 개요

  • 기본 색상의 밝기, 채도, 색조를 추출합니다.

  • 참조 밝기 값을 생성합니다:

    • 배경 가장자리: 0 또는 100 중 배경 밝기에 더 가까운 것.

    • 전경 가장자리: 0 또는 100 중 배경 가장자리와 다른 것.

    • 중간: 배경과 전경 밝기 값의 산술 평균.

  • 배경색의 밝기를 변경하여 배경 및 전경의 틴트(tint)와 쉐이드(shade)를 계산합니다: 배경 밝기 가장자리에 가까운 색상 두 개와 중간에 가까운 색상 두 개.

  • config.saturation을 기반으로 비기본 색상의 채도 값을 선택합니다.

  • 비기본 색상의 색조를 생성합니다:

    • 배경 및 전경 색조 모두에서 가장 멀리 떨어지도록 config.n_hues개의 점을 가진 등간격 원형 그리드를 맞춥니다. 이는 비기본 색상이 기본 색상과 최대한 다르게 보이도록 보장합니다 (더 나은 시각적 인식을 위해). 예시: 배경 색조 0, 전경 색조 180, config.n_hues 2인 경우 출력 그리드는 { 90, 270 }이 됩니다.

    • 참조 색상의 각 색조(그 자체로 8개 색조의 등간격 그리드임)에 대해 그리드에서 가장 가까운 값을 계산합니다. 이를 통해 실제로는 더 적은 수의 색조를 가졌더라도 동일한 용어("빨강", "초록" 등)로 작업할 수 있습니다.

  • 각 색조에 대해 배경 및 전경 밝기 값을 가진 두 가지 변형의 비기본 색상을 계산합니다.

  • config.accent를 기반으로 두 가지 변형의 강조 색상(배경 및 전경 밝기)을 계산합니다.

참고:

  • 일부 출력 색상은 생성된 Oklch 채널의 정확한 값을 갖지 못할 수 있습니다. 이는 실제로 계산된 색상을 ‘#rrggbb’ 16진수 문자열로 표현할 수 없기 때문입니다. 이 경우 가멋 클리핑(gamut clipping)이라는 프로세스를 수행하여 동일한 색조를 유지하면서 최적의 방식으로 밝기와 채도를 줄입니다. 자세한 내용은 MiniColors-gamut-clip을 참조하세요.

  • 모든 색상이 실제로 하이라이트 그룹에 사용되는 것은 아니며, 완전성을 위해 존재합니다.

매개변수

{config} (table) 팔레트 구성. MiniHues.config와 동일한 구조입니다. <background> 및 <foreground> 필드가 필요합니다.

반환

(table) 다음 필드를 포함하는 팔레트:

  • 제공된 background 및 foreground 색상을 포함하는 <bg> 및 <fg>.

  • <bg_xxx> 및 <fg_xxx> 같은 필드들은 본질적으로 <bg> 및 <fg>와 같지만 밝기 값이 다릅니다: _edge/_edge2 - 가장자리 밝기에 더 가깝고, _mid/_mid2 - 중간 밝기에 더 가깝습니다.

  • 비기본 색상 필드(<red>, <orange>, <yellow>, <green>, <cyan>, <azure>, <blue>, <purple>)는 전경과 동일한 밝기를 가집니다.

  • <_bg> 접미사가 붙은 비기본 색상 필드들은 배경과 동일한 밝기를 가집니다.

  • <accent> 및 <accent_bg>는 전경 및 배경 밝기 값을 가진 강조 색상을 나타냅니다.

참고 항목

MiniHues.get_palette()

apply_palette()

MiniHues.apply_palette({palette}, {plugins}, {opts})

팔레트 적용

제공된 팔레트를 기반으로 색상 테마 하이라이트 그룹과 터미널 색상을 생성합니다. 이는 팔레트 색상을 미세 조정하고 싶을 때 유용합니다. 일반적인 용도로는 MiniHues.setup()을 권장합니다.

매개변수

{palette} (table) MiniHues.make_palette() 출력과 동일한 구조의 테이블.

{plugins} (table|nil) 특정 플러그인에 대한 하이라이트 그룹 생성 여부를 나타내는 불리언 값을 가진 테이블입니다. 자세한 내용은 MiniHues.config를 참조하세요. 기본값: MiniHues.config의 값.

{opts} (table|nil) 옵션. 가능한 필드:

  • <autoadjust> - 필요할 때 일부 하이라이트 그룹을 자동으로 조정할지 여부. 기본값: MiniHues.config의 autoadjust 값.

사용법

local palette = require('mini.hues').make_palette({
  background = '#11262d',
  foreground = '#c0c8cc',
})

gen_random_base_colors()

MiniHues.gen_random_base_colors({opts})

무작위 기본 색상 생성

무작위로 생성된 색조와 휴리스틱하게 선택된 밝기-채도 값을 기반으로 배경 및 전경 색상을 계산합니다.

mini.colors를 사용하여 취향에 맞게 조정된 유사한 기능을 재현할 수 있습니다: > local convert = require(‘mini.colors’).convert local hue = math.random(0, 359) return { background = convert({ l = 15, c = 3, h = hue }, ‘hex’), foreground = convert({ l = 80, c = 1, h = hue }, ‘hex’), }

참고:

  • ‘background’ 설정을 존중합니다 (“dark” 및 “light” 배경에 대해 서로 다른 밝기와 채도 값을 사용).

  • 시작 중에 사용되는 경우, 적절한 무작위 생성을 위해 math.randomseed() 사용이 필요할 수 있습니다. 예시: >

    local hues = require(‘mini.hues’) math.randomseed(vim.loop.hrtime()) hues.setup(hues.gen_random_base_colors())

매개변수

{opts} (table|nil) 옵션. 가능한 값:

  • <gen_hue> (function) - 출력 색조를 위한 단일 숫자를 반환하는 호출 가능한 객체(function). 생성될 색조를 제한하는 데 사용할 수 있습니다. 기본값: 0에서 359 사이의 무작위 정수.

반환

(table) 색상 16진수 문자열을 포함하는 <background> 및 <foreground> 필드를 가진 테이블.
