mini.clue 문서

_ ’mini.nvim’의 main 브랜치에서 생성됨 _

mini.clue 다음 키 힌트 표시

MIT 라이선스 Copyright (c) 2023 Evgeni Chasnovski

모듈

주요 기능:

  • 타겟 키 조합에 도달하기 위한 커스텀 키 쿼리 프로세스를 구현합니다:

    • 사용자 정의 가능한 옵트인 트리거(모드 + 키) 이후에 시작됩니다.

    • 각 키를 누를 때마다 가능한 타겟 세트가 좁혀집니다. <BS>를 누르면 이전 사용자 입력이 제거됩니다. <Esc> 또는 <C-c>를 누르면 프로세스가 조기에 중단됩니다. ’timeoutlen’에 의존하지 않으며 ’langmap’에 대한 기본 지원이 있습니다.

    • 타겟이 하나만 남거나 사용자가 <CR>을 누르면 종료됩니다. 모든 쿼리 키와 가능한 postkeys를 누르는 것을 에뮬레이트하는 결과로 이어집니다.

  • 힌트와 함께 창을 표시합니다 (설정 가능한 지연 시간 이후). 사용 가능한 다음 키와 해당 설명(키맵에 있는 설명과 사용자 제공 클루에서 자동 생성되며 전자를 선호함)을 나열합니다.

  • 키 조합에 대한 구성 가능한 “postkeys”를 제공합니다 - 키 쿼리 프로세스 중에 조합에 도달한 후 에뮬레이트될 키입니다.

  • 일반적인 내장 키/개념에 대한 사용자 정의 가능한 클루 세트를 제공합니다:

    • g 키.

    • z 키.

    • 창(window) 명령.

    • 내장 완성(completion).

    • 마크(marks).

    • 레지스터(registers).

  • 전역 또는 버퍼별로 트리거를 활성화/비활성화하는 Lua 함수를 제공합니다.

자세한 내용은 다음을 참조하세요:

  • MiniClue-key-query-process.

  • MiniClue-examples.

  • MiniClue.config.

  • MiniClue.gen_clues.

참고:

  • 클루를 정의하는 동안 매핑을 생성하는 기능은 없습니다. 이는 이 두 가지 서로 다른 작업을 명확하게 분리하기 위함입니다. 가장 권장되는 방법은 설명(desc 필드)이 포함된 매핑을 수동으로 만드는 것이며, 이 설명은 클루 창 내부에서 자동으로 사용됩니다.

  • 트리거는 특수한 버퍼 로컬 매핑으로 구현됩니다. 이로 인해 몇 가지 주의 사항이 있습니다:

    • 동일한 일반 버퍼 로컬 매핑을 재정의하며 전역 매핑보다 우선순위를 갖습니다.

      예: <C-w>를 Normal 모드 트리거로 설정하면 다른 <C-w> 매핑이 없어야 합니다.

    • 트리거는 가장 최근에 생성된 버퍼 로컬 매핑이어야 하며, 그렇지 않으면 제대로 작동하지 않습니다. 이의 가장 흔한 징후는 클루 창이 표시된 후에만 일부 매핑이 작동하기 시작하는 것입니다.

      예: g가 Normal 모드 트리거로 설정되어 있지만 mini.comment의 gcc가 즉시 작동하지 않습니다. 이는 g 트리거에 대한 매핑 이후에 생성된 g로 시작하는 다른 버퍼 로컬 매핑이 있기 때문일 수 있습니다. 가장 흔한 경우는 LSP 서버의 on_attach 또는 버퍼에서 tree-sitter가 시작되는 동안입니다.

      트리거가 가장 최근의 버퍼 로컬 매핑인지 확인하려면 :<mode-char>map <trigger-keys>를 실행하세요 (예: nmap g). 트리거에 대한 매핑이 가장 먼저 나열되어야 합니다.

      이 모듈은 기본적으로 잘 작동하고 대부분의 일반적인 경우를 다루기 위해 최선을 다하지만, 모든 상황에서 완벽하지는 않습니다. 여기서 해결책은 모든 버퍼 로컬 매핑을 만든 후에 트리거가 생성되도록 하는 것입니다. MiniClue.setup() 또는 MiniClue.ensure_buf_triggers()를 실행하세요.

  • 기존 매핑의 설명이 사용자 제공 클루보다 우선합니다. 이는 클루 창에 표시되는 정보가 가능한 한 관련성이 높도록 하기 위함입니다. 이미 존재하는 매핑의 설명을 추가하거나 사용자 정의하려면 MiniClue.set_mapping_desc()를 사용하세요.

  • 기술적인 어려움으로 인해 Operator-pending 모드 트리거(예: mini.ai의 a/i)에 대한 완벽한 지원은 없습니다:

    • 구현상의 어려움으로 인해 “임시 Normal 모드”(예: i_CTRL-O 이후)에서 명령의 일부로 작동하지 않습니다.

    • 커스텀 연산자(operators)와 함께 사용할 때 예기치 않은 동작이 발생할 수 있습니다.

  • 매크로와 관련된 (대부분 해결된) 문제가 있습니다:

    • 기술적인 이유로 매크로 기록 중에는 모든 트리거가 비활성화됩니다.

    • @ 및 Q 키는 트리거를 일시적으로 비활성화하기 위해 MiniClue.setup() 내부에서 특수하게 매핑됩니다 (키가 아직 매핑되지 않은 경우).

설정

이 모듈은 require('mini.clue').setup({})으로 설정이 필요합니다 ({}를 config 테이블로 교체하세요). 스크립팅이나 수동으로 사용할 수 있는 글로벌 Lua 테이블 MiniClue를 생성합니다 (:lua MiniClue.* 사용).

구성 테이블에는 트리거가 구성되어 있어야 하며, 기본적으로는 아무것도 설정되어 있지 않습니다.

사용 가능한 구성 설정은 MiniClue.config를 참조하세요.

런타임 구성 설정(예: 클루 또는 창 옵션)을 vim.b.miniclue_config 내부의 버퍼에 로컬로 재정의할 수 있으며, 이는 MiniClue.config와 동일한 구조여야 합니다. 자세한 내용은 mini.nvim-buffer-local-config를 참조하세요.

비교

  • folke/which-key.nvim:

    • 둘 다 사용 가능한 다음 키와 사용자 정의 가능한 설명을 표시한다는 동일한 주요 목표를 가지고 있습니다.

    • UI 및 콘텐츠 레이아웃이 다릅니다.

    • 구성 내에서 매핑을 생성할 수 있게 허용하지만, 이 모듈은 두 가지 서로 다른 작업을 명확하게 분리하기 위해 설계상 이를 지원하지 않습니다.

    • 서브모드(submodes) 생성을 허용하지 않지만, 이 모듈은 (postkeys를 통해) 허용합니다.

  • anuvyklack/hydra.nvim:

    • 둘 다 서브모드 생성을 허용합니다. 서브모드는 특정 키 조합에서 시작하고, 일부 키를 다르게 처리하며, <Esc> 이후에 종료되는 상태입니다.

    • 사용 가능한 다음 키에 대한 정보를 서브모드 외부에서 표시하지 않지만, 그것이 이 모듈의 주요 목표입니다.

하이라이트 그룹

  • MiniClueBorder - 창 테두리.

  • MiniClueDescGroup - 클루 창의 그룹 설명.

  • MiniClueDescSingle - 클루 창의 단일 타겟 설명.

  • MiniClueNextKey - 클루 창의 다음 키 레이블.

  • MiniClueNextKeyWithPostkeys - 클루 창의 postkeys가 있는 다음 키 레이블.

  • MiniClueSeparator - 클루 창의 구분선.

  • MiniClueTitle - 창 제목.

하이라이트 그룹을 변경하려면 nvim_set_hl()을 사용하여 직접 설정하세요.

비활성화

트리거 생성을 비활성화하려면 vim.g.miniclue_disable(전역) 또는 vim.b.miniclue_disable(버퍼용)을 true로 설정하세요. 다양한 시나리오와 사용자 정의 의도를 고려하여 모듈 기능 비활성화를 위한 정확한 규칙 작성은 사용자의 몫으로 남겨둡니다. 일반적인 레시피는 mini.nvim-disabling-recipes를 참조하세요.

키 쿼리 프로세스

일반 정보

이 모듈은 매핑을 실행하기 위해 사용자가 키를 순서대로 누르는 일반적인 내장 메커니즘을 모방한 커스텀 키 쿼리 프로세스를 구현합니다. 기본 아이디어는 동일합니다: 타겟에 도달할 때까지 키 조합을 좁혀나갑니다.

이 프로세스가 존재하는 주요 목표는 다음과 같습니다:

  • 특정 매핑에 도달하는 것이 ’timeoutlen’에 독립적이 되도록 합니다. 즉, 현재 입력된 키가 실행되는 고정된 타임아웃이 없습니다.

  • 사용자 제공 지연 시간 이후에 다음 키 클루를 자동으로 표시할 수 있게 합니다 (이 또한 ’timeoutlen’에 독립적임).

  • 특정 키 조합에 도달한 후 구성 가능한 키 입력을 에뮬레이트할 수 있게 합니다. 이 세밀한 제어를 통해 소위 “서브모드(submodes)”를 생성할 수 있습니다. 자세한 내용은 MiniClue-examples-submodes를 참조하세요.

이 프로세스는 주로 Normal 모드의 중첩된 <Leader> 매핑을 위해 설계되었지만, 다른 모든 주요 모드에서도 작동합니다: Visual, Insert, Operator-pending (주의 사항 있음, 완벽한 보장 없음), Command-line, Terminal.

라이프사이클

  • 키 쿼리 프로세스는 사용자가 트리거(특정 모드의 특정 키)를 입력할 때 시작됩니다. 해당 키는 단일 사용자 입력으로 키 쿼리에 추가됩니다. 모든 가능한 모드 키 조합은 트리거 키로 시작하는 것으로 필터링됩니다.

    참고: 트리거는 일반 매핑으로 구현되므로 두 개 이상의 키가 있는 경우 ‘timeoutlen’ 밀리초 이내에 눌러야 합니다.

  • 사용자가 키를 누를 때까지 (무기한으로) 기다립니다. 키에 따라 진행됩니다:

    • 특수 키:

      • <Esc> 또는 <C-c>인 경우, 아무 작업 없이 프로세스를 중단합니다.

      • <CR>인 경우, 프로세스를 중단하고 현재 키 쿼리를 실행합니다. 즉, 사용자가 해당 키를 누르는 것을 에뮬레이트합니다 (nvim_feedkeys() 사용).

      • <BS>인 경우, 쿼리에서 이전 사용자 입력을 제거합니다. 쿼리가 비어 있게 되면 아무 작업 없이 프로세스를 중단합니다.

      • 클루 창을 스크롤하기 위한 키(config.window의 scroll_down / scroll_up, 기본값은 <C-d> / <C-u>)인 경우, 클루 창을 스크롤하고 다음 사용자 키를 기다립니다. 참고: 클루 창이 표시되지 않은 경우 특수 키가 아닌 키로 취급됩니다.

    • 특수 키가 아닌 키. 현재 키 쿼리로 시작하도록 모든 사용 가능한 키 조합을 필터링하면서 쿼리에 키를 추가합니다. 진행:

      • 현재 키 쿼리와 일치하는 사용 가능한 키 조합이 하나만 있는 경우 이를 실행합니다.

      • 현재 쿼리로 시작하는 키 조합이 없는 경우 이를 실행합니다. 예를 들어, 이는 더 긴 키 조합이 있는 상황에서도 연산자(operators)를 원활하게 실행할 수 있게 합니다. 예:

        Normal 모드에서 g가 트리거이고 사용 가능한 매핑이 gc / gcc인 경우

        (예: mini.comment에서), 이는 gci로 시작하는 키 조합이 없더라도 현재 단락에 주석을 달기 위해 gcip를 입력할 수 있게 해줍니다.

      • 그렇지 않으면 새로운 사용자 키 입력을 기다립니다.

클루 창

키 쿼리 프로세스를 시작한 후와 각 키를 누른 후에 타이머가 시작되어 클루 창(사용 가능한 다음 키와 해당 설명에 대한 정보가 포함된 플로팅 창)을 표시합니다. 참고: 창이 이미 표시되어 있는 경우 콘텐츠가 즉시 업데이트됩니다.

클루는 다음과 같은 유형을 가질 수 있습니다:

  • “Terminal next key”: 누르면 쿼리 실행으로 이어집니다.

  • “Terminal next key with postkeys”: 누르면 쿼리 실행과 함께 일부 구성된 postkeys로 이어집니다.

  • “Group next key”: 누르면 사용 가능한 키 조합을 좁히고 다른 키 입력을 기다립니다. 참고: 구성된 설명(config.clues 내부)을 가질 수 있으며, 그렇지 않으면 사용 가능한 키 조합의 수에 따라 자동으로 생성됩니다.

예제

전체 시작 예제

어디서 시작해야 할지 모르겠다면, 이 모듈에서 제공하는 모든 클루와 Normal 및 Visual 모드의 모든 <Leader> 매핑을 포함하는 이 예제를 시도해 보세요:

local miniclue = require('mini.clue')
miniclue.setup({
  triggers = {
    -- Leader 트리거
    { mode = { 'n', 'x' }, keys = '<Leader>' },

    -- `[` 및 `]` 키
    { mode = 'n', keys = '[' },
    { mode = 'n', keys = ']' },

    -- 내장 완성
    { mode = 'i', keys = '<C-x>' },

    -- `g` 키
    { mode = { 'n', 'x' }, keys = 'g' },

    -- 마크
    { mode = { 'n', 'x' }, keys = "'" },
    { mode = { 'n', 'x' }, keys = '`' },

    -- 레지스터
    { mode = { 'n', 'x' }, keys = '"' },
    { mode = { 'i', 'c' }, keys = '<C-r>' },

    -- 창 명령
    { mode = 'n', keys = '<C-w>' },

    -- `z` 키
    { mode = { 'n', 'x' }, keys = 'z' },
  },

  clues = {
    -- <Leader> 매핑 그룹에 대한 설명을 추가하여 이를 보완하세요
    miniclue.gen_clues.square_brackets(),
    miniclue.gen_clues.builtin_completion(),
    miniclue.gen_clues.g(),
    miniclue.gen_clues.marks(),
    miniclue.gen_clues.registers(),
    miniclue.gen_clues.windows(),
    miniclue.gen_clues.z(),
  },
})

Leader 클루

다음과 같은 <Leader> 매핑이 설정되어 있다고 가정합니다:

-- 매핑을 만들고 'mini.clue'를 구성하기 전에 `<Leader>`를 설정하세요
vim.g.mapleader = ' '

local nmap_leader = function(suffix, rhs, desc)
  vim.keymap.set('n', '<Leader>' .. suffix, rhs, { desc = desc })
end
local xmap_leader = function(suffix, rhs, desc)
  vim.keymap.set('x', '<Leader>' .. suffix, rhs, { desc = desc })
end

nmap_leader('bd', '<Cmd>lua MiniBufremove.delete()<CR>',  '삭제(Delete)')
nmap_leader('bw', '<Cmd>lua MiniBufremove.wipeout()<CR>', '완전삭제(Wipeout)')

nmap_leader('lf', '<Cmd>lua vim.lsp.buf.format()<CR>',     '포맷(Format)')
xmap_leader('lf', '<Cmd>lua vim.lsp.buf.format()<CR>',     '포맷(Format)')
nmap_leader('lr', '<Cmd>lua vim.lsp.buf.rename()<CR>',     '이름변경(Rename)')
nmap_leader('lR', '<Cmd>lua vim.lsp.buf.references()<CR>', '참조(References)')

다음 설정은 Normal 및 Visual 모드에서 <Leader>를 트리거로 활성화하고 매핑 그룹에 설명을 추가합니다:

require('mini.clue').setup({
  -- `<Leader>`를 트리거로 등록
  triggers = {
    { mode = { 'n', 'x' }, keys = '<Leader>' },
  },

  -- 매핑 그룹에 대한 설명 추가
  clues = {
    { mode = 'n', keys = '<Leader>b', desc = '+버퍼(Buffers)' },
    { mode = 'n', keys = '<Leader>l', desc = '+LSP' },
  },
})

매핑이 없는 클루

실제로 존재하는 매핑에 대해서만 클루를 표시할 수 있는 것은 아닙니다. 이는 내장 키 조합에 대한 클루를 표시하는 데 유용합니다. 다음은 내장 완성의 하위 집합에 대한 클루 예제입니다 (모든 사용 가능한 완성 소스에 대한 클루를 생성하려면 MiniClue.gen_clues.builtin_completion()을 참조하세요):

require('mini.clue').setup({
  -- `<C-x>`를 트리거로 만듭니다. 그렇지 않으면 키 쿼리 프로세스가 시작되지 않습니다.
  triggers = {
    { mode = 'i', keys = '<C-x>' },
  },

  -- 커스텀 클루 등록
  clues = {
    { mode = 'i', keys = '<C-x><C-f>', desc = '파일명(File names)' },
    { mode = 'i', keys = '<C-x><C-l>', desc = '전체 행(Whole lines)' },
    { mode = 'i', keys = '<C-x><C-o>', desc = 'Omni 완성' },
    { mode = 'i', keys = '<C-x><C-s>', desc = '맞춤법 제안(Spelling suggestions)' },
    { mode = 'i', keys = '<C-x><C-u>', desc = "'completefunc' 사용" },
  }
})

특수 버퍼에서의 트리거

기본적으로 트리거는 나열된(‘buflisted’) 버퍼와 일부 특수한 나열되지 않은 버퍼에서 자동으로 생성됩니다. 필요할 때 수동으로 활성화하려면 MiniClue.ensure_buf_triggers()를 사용하세요. 예를 들어:

au FileType special_ft lua MiniClue.ensure_buf_triggers()

서브모드

MiniClue-examples-submodes

서브모드는 키 쿼리 프로세스 중에 특정 키 조합(“접두사”)을 누른 후에 시작되는 상태로, 일부 키가 다르게 해석됩니다.

이 모듈에서 서브모드는 다음 단계에 따라 구현될 수 있습니다:

  • 서브모드 내부의 각 키에 대한 매핑을 생성합니다. 매핑의 왼쪽(LHS)은 접두사 뒤에 해당 키가 오는 형태여야 합니다.

  • 서브모드 내부의 각 키에 대해 postkeys 값이 접두사와 동일한 클루를 생성합니다. 이는 이 서브모드에서 특정 키 조합을 실행한 후 해당 접두사를 누르는 것이 자동으로 에뮬레이트됨을 의미합니다 (다시 서브모드 내부로 돌아감).

  • 서브모드 접두사(또는 시작 부분의 일부)를 트리거로 등록합니다. <Leader> 및 <Leader>m과 같이 “겹치는” 트리거를 등록하지 마세요.

서브모드 예제

  • mini.move로 이동하기 위한 서브모드:

    • <Leader>m을 눌러 서브모드를 시작합니다.

    • h/j/k/l 중 하나를 눌러 선택 영역/행을 이동합니다.

    • <Esc>를 눌러 서브모드를 중지합니다.

    코드:

    require('mini.move').setup({
  mappings = {
    left       = '<Leader>mh',
    right      = '<Leader>ml',
    down       = '<Leader>mj',
    up         = '<Leader>mk',
    line_left  = '<Leader>mh',
    line_right = '<Leader>ml',
    line_down  = '<Leader>mj',
    line_up    = '<Leader>mk',
  },
})

require('mini.clue').setup({
  triggers = {
    -- `<Leader>m`을 직접 트리거로 설정할 수도 있지만,
    -- `<Leader>`도 사용하지 않도록 주의하세요. 서로 "겹칠" 수 있습니다.
    { mode = { 'n', 'x' }, keys = '<Leader>' },
  },
  clues = {
    { mode = 'n', keys = '<Leader>m', desc = '+이동(Move)' },

    { mode = { 'n', 'x' }, keys = '<Leader>mh', postkeys = '<Leader>m' },
    { mode = { 'n', 'x' }, keys = '<Leader>mj', postkeys = '<Leader>m' },
    { mode = { 'n', 'x' }, keys = '<Leader>mk', postkeys = '<Leader>m' },
    { mode = { 'n', 'x' }, keys = '<Leader>ml', postkeys = '<Leader>m' },
  },
})

  • mini.bracketed를 사용하여 버퍼와 창을 반복하기 위한 서브모드:

    • 특정 방향에 대한 키 쿼리 프로세스를 시작하려면 [ 또는 ]를 누릅니다.

    • 타겟에 도달할 때까지 b / w를 눌러 버퍼/창을 반복합니다.

    • <Esc>를 눌러 서브모드를 중지합니다.

    코드:

    require('mini.bracketed').setup()

require('mini.clue').setup({
  triggers = {
    { mode = 'n', keys = ']' },
    { mode = 'n', keys = '[' },
  },
  clues = {
    { mode = 'n', keys = ']b', postkeys = ']' },
    { mode = 'n', keys = ']w', postkeys = ']' },

    { mode = 'n', keys = '[b', postkeys = '[' },
    { mode = 'n', keys = '[w', postkeys = '[' },
  },
})

  • MiniClue.gen_clues.windows()를 사용한 창 명령 서브모드:

    • 키 쿼리 프로세스를 시작하려면 <C-w>를 누릅니다.

    • 창을 이동 / 포커스 변경 / 크기 조절하는 키를 누릅니다.

    • <Esc>를 눌러 서브모드를 중지합니다.

    코드:

    local miniclue = require('mini.clue')
miniclue.setup({
  triggers = {
    { mode = 'n', keys = '<C-w>' },
  },
  clues = {
    miniclue.gen_clues.windows({
      submode_move = true,
      submode_navigate = true,
      submode_resize = true,
    })
  },
})

클루

config.clues는 키 조합에 대한 추가 정보가 포함된 배열입니다. 각 요소는 다음 중 하나일 수 있습니다:

  • 클루 테이블.

  • 클루 테이블의 배열 (중첩 가능).

  • 이전 두 가지 중 하나를 반환하는 콜러블(함수).

클루 테이블은 다음과 같은 필드를 갖는 테이블입니다:

  • <mode> (string|table) - nvim_set_keymap()에서와 같이 키 조합의 모드 단축 이름(‘n’, ‘x’, ‘i’, ‘o’, ‘c’ 등)을 나타내는 단일 문자 또는 그 배열.

  • <keys> (string) - 클루가 표시될 키 조합. key-notation에서와 같은 “사람이 읽을 수 있는” 키 이름(예: “<Leader>”, “<Space>”, “<Tab>” 등)이 허용됩니다.

  • <desc> (string|function|nil) - 클루 창에 표시되는 선택적인 키 조합 설명. 함수인 경우 문자열 설명을 반환해야 합니다.

  • <postkeys> (string|nil) - keys 이후에 자동으로 실행될 선택적인 postkeys. 서브모드 생성을 허용합니다 (MiniClue-examples-submodes 참조).

참고:

  • Postkeys는 nvim_feedkeys()를 사용한 키 입력의 리터럴 시뮬레이션입니다.

  • 클루 구성을 위한 권장 방법은 desc 필드를 사용하여 매핑을 생성하고, config.clues에는 그룹, postkeys 및 내장 매핑을 설명하는 요소만 제공하는 것입니다.

트리거

config.triggers는 MiniClue-key-query-process가 언제 시작되어야 하는지에 대한 정보가 포함된 배열입니다. 각 요소는 클루 테이블에서와 동일하게 처리되는 <mode> 및 <keys> 필드를 갖는 트리거 테이블입니다.

창

config.window는 클루 창의 동작을 정의합니다.

config.window.delay는 클루 창이 나타날 때까지의 시간(밀리초)입니다. 즉시 표시하려면 0으로 설정할 수 있습니다.

config.window.config는 플로팅 창의 특성을 정의하는 테이블 또는 이러한 테이블을 반환하는 콜러블입니다 (모든 클루를 이미 표시하고 있는 창 버퍼의 식별자와 함께 호출됩니다). 이는 nvim_open_win()과 동일한 구조여야 하며 다음과 같은 향상된 기능이 있습니다:

  • <width> 필드는 "auto"와 같을 수 있으며, 이 경우 창 너비는 콘텐츠에 따라 자동으로 계산됩니다. 기본값은 30의 고정 너비입니다.

  • <row> 및 <col>은 "auto"와 같을 수 있으며, 이 경우 설정된 앵커(기본값은 “SE”, nvim_open_win() 참조)에 “달라붙도록” 계산됩니다. 이를 통해 창이 표시되는 모서리를 변경할 수 있습니다:

    -- 하나의 앵커 선택
local anchor = 'NW' -- 왼쪽 상단
local anchor = 'NE' -- 오른쪽 상단
local anchor = 'SW' -- 왼쪽 하단
local anchor = 'SE' -- 오른쪽 하단

require('mini.clue').setup({
  window = {
    config = { anchor = anchor, row = 'auto', col = 'auto' },
  },
})

config.window.scroll_down / config.window.scroll_up은 클루가 현재 창 높이에 다 맞지 않는 경우 클루 창을 아래로 / 위로 스크롤하는 키를 정의하는 문자열입니다. 비활성화하려면 빈 문자열 ''로 설정하세요.

  • <submode_resize> (boolean) - postkeys 필드를 사용하여 크기 조절 (크기 변경) 명령을 서브모드로 만들지 여부. 기본값: false.
