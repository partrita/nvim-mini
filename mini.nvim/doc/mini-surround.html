mini.surround 문서

mini.nvim의 main 브랜치에서 생성됨

mini.surround 서라운딩(Surround) 동작

MIT 라이선스 Copyright (c) 2021 Evgeni Chasnovski

모듈

빠르고 기능이 풍부한 서라운딩 도구입니다. tpope/vim-surround와 유사한 경험을 하도록 설정할 수 있습니다(MiniSurround-vim-surround-config 참조).

기능:

  • 동작(텍스트 편집 동작은 기본적으로 점 반복(dot-repeat)이 가능하며 [count]를 준수합니다) 및 설정 가능한 매핑:

    • sa로 서라운딩 추가 (비주얼 모드 또는 모션에서).

    • sd로 서라운딩 삭제.

    • sr로 서라운딩 교체.

    • sf 또는 sF로 서라운딩 찾기 (커서를 오른쪽 또는 왼쪽으로 이동).

    • sh로 서라운딩 강조 표시(Highlight).

  • 서라운딩은 “입력”(삭제 및 교체 시작, 찾기, 강조 표시)과 “출력”(추가 및 교체 종료) 모두에서 단일 문자로 식별됩니다:

    • ‘f’ - 함수 호출 (영문자, 숫자, ’_’ 또는 ‘.’으로 구성된 문자열 뒤에 균형 잡힌’()’가 오는 형태). “입력”에서는 함수 호출을 찾고, “출력”에서는 사용자에게 함수 이름을 입력하도록 요청합니다.

    • ‘t’ - 태그. “입력”에서는 동일한 식별자를 가진 태그를 찾고, “출력”에서는 사용자에게 속성을 포함할 수 있는 태그 이름을 입력하도록 요청합니다.

    • ‘()’, ‘[]’, ‘{}’, ’<>’와 같은 모든 괄호 기호. “입력”에서는 균형 잡힌 괄호를 나타내며(여는 괄호 - 공백 포함, 닫는 괄호 - 공백 미포함), “출력”에서는 괄호의 왼쪽과 오른쪽 부분을 나타냅니다.

    • ‘?’ - 대화형. 사용자에게 왼쪽과 오른쪽 부분을 직접 입력하도록 요청합니다.

    • 다른 모든 단일 문자 식별자(getcharstr()가 지원하는)는 왼쪽과 오른쪽 부분이 동일한 서라운딩을 나타냅니다.

  • 현재 위치를 감싸는 것뿐만 아니라 다음, 이전 또는 가장 가까운 서라운딩을 찾기 위한 설정 가능한 검색 방법. 자세한 내용은 MiniSurround.config를 참조하세요.

  • 서라운딩 찾기와 관련된 모든 동작(삭제, 교체, 찾기, 강조 표시)은 검색 방법을 이전/마지막으로 변경하는 접미사와 함께 사용할 수 있습니다. 자세한 내용은 MiniSurround.config를 참조하세요.

해결되지 않을 알려진 문제:

  • 서라운딩 검색은 Lua 패턴(정규식과 유사한 방식)을 사용하여 수행됩니다. 따라서 어느 정도의 오탐이 발생할 수 있습니다.

  • “입력” 서라운딩을 검색할 때, 문자열 내부인지 주석 내부인지 구분하지 않습니다. 따라서 이 경우 함수 호출 ’f(a = “)”, b = 1)’에 대해 올바른 일치를 찾지 못할 수 있습니다.

  • 태그는 정규식과 유사한 방법을 사용하여 검색되므로 문제가 발생할 수 있습니다. 전반적으로는 꽤 훌륭하지만, 자체 중첩된 태그(‘<a><a></a></a>’)의 양쪽 끝을 정확히 일치시키지 못하는 등의 특정 사례는 작동하지 않습니다.

설정

이 모듈은 require('mini.surround').setup({})을 통한 설정이 필요합니다({}를 config 테이블로 교체하세요). 이는 스크립팅이나 수동으로(:lua MiniSurround.*를 통해) 사용할 수 있는 전역 Lua 테이블 MiniSurround를 생성합니다.

config 구조와 기본값은 MiniSurround.config를 참조하세요.

런타임 설정은 vim.b.minisurround_config를 통해 버퍼 로컬로 재정의할 수 있으며, 이는 MiniSurround.config와 동일한 구조를 가져야 합니다. 자세한 내용은 mini.nvim-buffer-local-config를 참조하세요.

모듈이 에러가 아닌 피드백을 표시하지 않게 하려면 config.silent = true로 설정하세요.

사용 예시

일반 매핑:

  • saiw) - 내부 단어(iw)에 대해 괄호())를 추가(sa)합니다.

  • saiw?[[<CR>]]<CR> - 내부 단어(iw)에 대해 대화형 서라운딩(?)을 추가(sa)합니다: 왼쪽은 [[, 오른쪽은 ]].

  • 2sdf - 두 번째(2) 서라운딩 함수 호출(f)을 삭제(sd)합니다.

  • sr)tdiv<CR> - 서라운딩 괄호())를 식별자가 ’div’인 태그(t)로 교체(sr)합니다(명령줄 프롬프트에 div<CR> 입력).

  • sff - 서라운딩 함수 호출(f)의 오른쪽 부분을 찾습니다(sf).

  • sh} - 중괄호(}) 서라운딩을 잠시 동안 강조 표시(sh)합니다.

확장 매핑 (임시로 “이전(prev)”/“다음(next)” 검색 방법 강제):

  • sdnf - 다음(n) 함수 호출(f)을 삭제(sd)합니다.

  • srlf( - 마지막(l) 함수 호출(f)을 공백이 포함된 괄호(()로 교체(sr)합니다.

  • 2sfnt - 두 번째(2) 다음(n) 태그(t)를 찾습니다(sf).

  • 2shl} - 마지막(l) 두 번째(2) 중괄호(})를 강조 표시(sh)합니다.

비교

  • tpope/vim-surround:

    • ’vim-surround’는 완전히 다른 기본 매핑 세트를 가지고 있는 반면, ’mini.surround’는 더 일관된 세트를 가지고 있습니다.

    • ’mini.surround’는 점 반복(dot-repeat), 맞춤형 검색 경로(MiniSurround.config 참조), tree-sitter 쿼리 사용을 허용하는 맞춤형 사양(MiniSurround-surrounding-specification 및 MiniSurround.gen_spec.input.treesitter() 참조), 서라운딩 강조 및 찾기, “마지막/다음” 확장 매핑 등을 지원합니다. ’vim-surround’는 지원하지 않습니다.

  • machakann/vim-sandwich:

    • 두 플러그인 모두 일반적인 동작(추가, 삭제, 교체)에 대해 동일한 키바인딩을 가지고 있습니다.

    • 그 외에는 ’tpope/vim-surround’와의 차이점과 동일합니다 (다만 ’vim-sandwich’는 점 반복을 지원합니다).

  • kylechui/nvim-surround:

    • ’nvim-surround’는 ’tpope/vim-surround’의 기본 매핑 및 로직을 따라 설계된 반면, ’mini.surround’는 ’machakann/vim-sandwich’와 유사한 매핑을 가집니다.

    • ’mini.surround’는 입력 서라운딩에 대해 더 유연한 커스터마이징(복합 패턴, 영역 페어, 검색 방법 등)이 가능합니다.

    • ’mini.surround’는 입력 및 출력 서라운딩 모두에서 [count]를 지원하지만(MiniSurround-count-with-actions 참조), ’nvim-surround’는 지원하지 않습니다.

    • ’mini.surround’는 “마지막/다음” 확장 매핑을 지원합니다.

  • mini.ai:

    • 둘 다 대상을 찾기 위해 비슷한 로직을 사용합니다: ’mini.ai’는 텍스트 오브젝트, ’mini.surround’는 서라운딩 페어. ’mini.ai’가 별도의 a 및 i 텍스트 오브젝트를 위해 추출 패턴을 사용하는 반면, ’mini.surround’는 왼쪽과 오른쪽 서라운딩을 선택하기 위해 이를 사용합니다(기본적으로 a와 i 텍스트 오브젝트 간의 차이).

    • 일부 내장 사양이 약간 다릅니다:

      • ’mini.ai’의 따옴표는 균형을 잡지만, ’mini.surround’는 그렇지 않습니다.

      • ’mini.surround’에는 인자(argument) 서라운딩이 없습니다.

      • ’mini.ai’의 기본 동작은 가장자리 중 하나를 a 텍스트 오브젝트로 선택하는 반면, ’mini.surround’는 양쪽 모두를 선택합니다.

하이라이트 그룹

  • MiniSurround - 요청된 서라운딩의 강조 표시.

하이라이트 그룹을 변경하려면 nvim_set_hl()을 사용하여 직접 설정하세요.

비활성화

비활성화하려면 vim.g.minisurround_disable(전역) 또는 vim.b.minisurround_disable(버퍼용)을 true로 설정하세요. 다양한 시나리오와 커스터마이징 의도를 고려하여 모듈 기능을 비활성화하기 위한 정확한 규칙 작성은 사용자에게 맡겨집니다. 자세한 레시피는 mini.nvim-disabling-recipes를 참조하세요.

내장 서라운딩

이 표는 모든 내장 서라운딩과 그것들이 나타내는 바를 설명합니다. 설명:

  • Key는 서라운딩 식별자를 나타냅니다: 동작 매핑 뒤에 입력해야 하는 단일 문자(MiniSurround.config의 “Mappings” 참조).

  • Name은 서라운딩의 설명입니다.

  • Example line은 예시가 구성되는 문자열입니다. *는 a 문자 위의 커서 위치를 나타냅니다.

  • Delete는 sd 뒤에 서라운딩 식별자를 입력한 결과를 보여줍니다. 이는 sr을 통한 교체(서라운딩 ID가 먼저 입력됨), sh를 통한 강조 표시, sf 및 sF를 통한 찾기에서도 사용되는 “입력” 서라운딩을 보여주기 위함입니다.

  • Replace는 sr! 뒤에 서라운딩 식별자를 입력한 결과를 보여줍니다(사용자의 추가 입력이 있을 수 있음). 이는 sa를 통한 추가(텍스트 오브젝트/모션이 뒤따르거나 비주얼 모드에서 사용됨)에서도 사용되는 “출력” 서라운딩을 보여주기 위함입니다.

예시: * 위치( a 문자를 포함)에서 sd)를 입력하면 !( *a (bb) )! 라인이 ! aa (bb) !로 바뀝니다. 동일한 초기 라인에서 sr!)를 입력하면 (( aa (bb) ))로 바뀝니다.

  • 모든 예시는 기본 config.search_method를 가정합니다.

  • 여는 괄호와 닫는 괄호의 차이점은 내부 가장자리 공백을 처리하는 방식입니다: 여는 괄호는 왼쪽과 오른쪽 부분에 공백을 포함하고, 닫는 괄호는 포함하지 않습니다.

  • b 별칭의 출력값은 )와 동일합니다. q 별칭은 "와 동일합니다.

  • 기본 서라운딩은 구성된 서라운딩 식별자가 아닌 모든 문자에 대해 활성화됩니다. 참고:

    • 기반이 되는 x.-x Lua 패턴의 특수 처리 때문에(MiniSurround-search-algorithm 참조), “감싸기(cover)” 검색 방법에 대해 사소하지 않은 [count]를 실제로 지원하지 않습니다.

    • 커서가 정확히 식별자 문자 위에 있고 좌우 양쪽에 두 개의 일치하는 후보가 있는 경우, 너비가 더 좁은 영역을 생성하는 후보가 우선됩니다.

용어집

참고: 이는 MiniAi-glossary와 유사합니다.

영역 (REGION)

버퍼의 영역을 나타내는 테이블입니다. 필드: 시작 및 끝 위치를 나타내는 <from>과 <to>(포함 관계, <to>는 빈 영역을 설명하기 위해 nil일 수 있음). 각 위치는 라인 <line>과 컬럼 <col>(둘 다 1부터 시작)을 가진 테이블입니다. 예시:

{ from = { line = 1, col = 1 }, to = { line = 2, col = 1 } }

-- 빈 영역
{ from = { line = 10, col = 10 } }

영역 페어 (REGION PAIR)

왼쪽과 오른쪽 서라운딩 영역을 나타내는 테이블입니다. 필드: 영역을 포함하는 <left>와 <right>. 예시:

{
  left  = { from = { line = 1, col = 1 }, to = { line = 1, col = 1 } },
  right = { from = { line = 1, col = 3 } },
}

패턴 (PATTERN)

Lua 패턴을 설명하는 문자열입니다.

스팬 (SPAN)

문자열 내부의 구간(끝 제외)입니다. 예: [1, 5). from과 to 가장자리가 같으면 해당 지점의 빈 스팬을 설명합니다.

스팬 A = [a1, a2)가 B = [b1, b2)를 포함(cover)한다는 것은 B의 모든 요소가 A 내에 있음(a1 <= b < a2)을 의미합니다. 이는 “B가 A 내부에 중첩되어 있다”고도 설명됩니다.

중첩 패턴 (NESTED PATTERN)

중첩된 스팬을 설명하기 위한 패턴 배열입니다.

중첩 패턴과 일치하는 스팬

이전 스팬의 부분 문자열(또는 첫 번째 스팬의 경우 입력 문자열) 내에서 각각 대응하는 패턴과 일치하는 연속적으로 중첩된 스팬 시퀀스가 있는 경우입니다. 예시:

-- 내부 공백이 있는 균형 잡힌 `()`에 대한 중첩 패턴
{ '%b()', '^. .* .$' }

-- 입력 문자열 예시 (읽기 쉽게 아래에 컬럼 표시):
   "( ( () ( ) ) )"
--  12345678901234

여기서 일치하는 스팬은 [1, 15)와 [3, 13)입니다. [5, 7)과 [8, 10)은 모두 첫 번째 패턴과는 일치하지만 두 번째 패턴과는 일치하지 않습니다. (와 )의 다른 모든 조합은 첫 번째 패턴과 일치하지 않습니다(균형이 맞지 않음).

복합 패턴 (COMPOSED PATTERN)

각 요소가 해당 위치에서 가능한 패턴(또는 패턴 배열)을 설명하는 배열입니다. 복합 패턴은 기본적으로 중첩 패턴의 가능한 모든 조합(데카르트 곱)을 정의합니다. 예시:

  1. 균형 잡힌 () 또는 균형 잡힌 [] 중 하나이되, 둘 다 내부 가장자리에 공백이 있는 경우:

    -- 복합 패턴
{ { '%b()', '%b[]' }, '^. .* .$' }

-- 동일한 중첩 패턴 배열로 확장된 복합 패턴
{ '%b()', '^. .* .$' } -- 그리고
{ '%b[]', '^. .* .$' }

  2. “내부 가장자리에 공백이 있는 균형 잡힌 ()” 또는 “내부 가장자리에 공백이 없는 균형 잡힌 []” 중 하나이되, 둘 다 5자 이상인 경우:

    -- 복합 패턴
{ { { '%b()', '^. .* .$' }, { '%b[]', '^.[^ ].*[^ ].$' } }, '.....' }

-- 동일한 중첩 패턴 배열로 확장된 복합 패턴
{ '%b()', '^. .* .$', '.....' } -- 그리고
{ '%b[]', '^.[^ ].*[^ ].$', '.....' }

복합 패턴과 일치하는 스팬

확장된 복합 패턴에서 적어도 하나의 중첩 패턴과 일치하는 경우입니다.

서라운딩 사양 (Surrounding specification)

서라운딩 사양은 다음 키를 가진 테이블입니다:

  • <input> - 삭제와 같은 “입력” 동작을 위해 서라운딩을 찾고 추출하는 방법을 정의합니다. 자세한 내용은 “입력 서라운딩” 섹션을 참조하세요.

  • <output> - 추가와 같은 “출력” 동작을 위해 왼쪽과 오른쪽에 무엇을 추가할지 정의합니다. 자세한 내용은 “출력 서라운딩” 섹션을 참조하세요.

내장 식별자 )에 대한 서라운딩 정보 예시:

{
  input = { '%b()', '^.().*().$' },
  output = { left = '(', right = ')' }
}

입력 서라운딩

입력 서라운딩 사양은 복합 패턴(MiniSurround-glossary 참조)의 구조를 가지며 두 가지 차이점이 있습니다:

  • 마지막 패턴은 서라운딩 부분을 추출하기 위해 마지막 문자열을 어떻게 처리해야 하는지 나타내는 2개 또는 4개의 빈 캡처 그룹을 가져야 합니다:

    • 2개의 캡처는 문자열 시작부터 첫 번째 캡처까지를 왼쪽 부분으로, 두 번째 캡처부터 문자열 끝까지를 오른쪽 부분으로 나타냅니다. 예: a()b()c는 왼쪽 서라운딩을 ‘a’, 오른쪽을 ’c’로 정의합니다.

    • 4개의 캡처는 캡처 1과 2 사이를 왼쪽 부분으로, 캡처 3과 4 사이를 오른쪽 부분으로 정의합니다. 예: a()()b()c()는 왼쪽 부분은 빈 문자열로, 오른쪽 부분은 ’c’로 정의합니다.

  • 특정 위치에서 호출 가능한 객체(vim.is_callable() 참조)를 허용합니다(구성의 복잡성과 계산량이 늘어나는 대신 더 복잡한 서라운딩을 가능하게 합니다):

    • 사양 자체가 호출 가능한 경우, 인자 없이 호출되며 다음 중 하나를 반환해야 합니다:

      • 복합 패턴. 사용자 입력을 구현하는 데 유용합니다. 사용자 프롬프트에서 이름을 가져오는 함수 호출에 대한 입력 서라운딩의 간략한 예시:

        function()
  local left_edge = vim.pesc(vim.fn.input('Function name: '))
  return { left_edge .. '%b()', '^.-%(().*()%)$' }
end

      • 단일 영역 페어(MiniSurround-glossary 참조). 서라운딩에 대해 완전한 제어를 허용할 때 유용합니다. 있는 그대로 사용됩니다. 버퍼의 첫 번째 라인과 마지막 라인을 반환하는 예시:

        function()
  local n_lines = vim.fn.line('$')
  return {
    left = {
      from = { line = 1, col = 1 },
      to = { line = 1, col = vim.fn.getline(1):len() }
    },
    right = {
      from = { line = n_lines, col = 1 },
      to = { line = n_lines, col = vim.fn.getline(n_lines):len() }
    },
  }
end

      • 영역 페어 배열. treesitter(MiniSurround.gen_spec.input.treesitter() 참조)와 같은 다른 도구를 통합할 때 유용합니다. 복합 패턴과 동일한 방식(n_lines, search_method 옵션 등을 준수)으로 출력 영역(왼쪽 영역의 시작부터 오른쪽 영역의 끝까지)을 사용하여 최적의 영역 페어가 선택됩니다. 표시 너비가 80보다 큰 “최적” 라인의 양쪽 끝을 사용하는 예시:

        function()
  local make_line_region_pair = function(n)
    local left = { line = n, col = 1 }
    local right = { line = n, col = vim.fn.getline(n):len() }
    return {
      left = { from = left, to = left },
      right = { from = right, to = right },
    }
  end

  local res = {}
  for i = 1, vim.fn.line('$') do
    if vim.fn.getline(i):len() > 80 then
      table.insert(res, make_line_region_pair(i))
    end
  end
  return res
end

    • 가정된 문자열 패턴 대신 호출 가능한 객체가 있는 경우, (line, init) 시그니처를 가지고 pattern:find()처럼 동작할 것으로 기대됩니다. line에서 init 다음 또는 init 위치의 스팬을 나타내는 두 개의 숫자를 반환해야 합니다(해당하는 스팬이 없으면 nil). !중요 주의 사항!: 이는 출력의 from이 init보다 엄격하게 왼쪽이어서는 안 됨을 의미합니다(무한 루프가 발생할 수 있음). 캡처가 있는 패턴이어야 하므로 마지막 항목으로는 허용되지 않습니다. 너비가 충분히 큰 균형 잡힌 괄호만 일치시키는 예시:

      {
  '%b()',
  function(s, init)
    if init > 1 or s:len() < 5 then return end
    return 1, s:len()
  end,
  '^.().*().$'
}

추가 예시:

-- 세트에서 균형 잡힌 괄호 쌍 (내장 `b` 식별자에 사용됨)
{ { '%b()', '%b[]', '%b{}' }, '^.().*().$' }

-- Lua 블록 문자열
{ '%[%[().-()%]%]' }

일반적으로 사용되는 서라운딩 사양을 생성하는 함수 래퍼는 MiniSurround.gen_spec을 참조하세요.

출력 서라운딩

출력 사양은 <left> 및 <right> 필드를 가진 테이블이거나, 그러한 테이블을 반환하는 호출 가능한 객체(인자 없이 호출됨)일 수 있습니다. 문자열은 여러 줄 부분을 추가하기 위해 줄바꿈 문자 “”을 포함할 수 있습니다.

예시:

-- Lua 블록 문자열
{ left = '[[', right = ']]' }

-- 별도의 라인에 있는 괄호 (들여쓰기는 유지되지 않음)
{ left = '(\n', right = '\n)' }

-- 함수 호출
function()
  local function_name = MiniSurround.user_input('Function name')
  return { left = function_name .. '(', right = ')' }
end

동작과 숫자 인자(count)

[count]는 모든 동작에서 다음과 같은 방식으로 지원됩니다:

  • 추가(add)의 경우, 일반 모드에서 두 가지 유형의 [count]가 지원됩니다: [count1]sa[count2][textobject]. [count1]은 출력 서라운딩의 왼쪽과 오른쪽 부분이 반복되는 횟수를 정의하고, [count2]는 텍스트 오브젝트에 사용됩니다. 비주얼 모드에서 [count]는 [count1]으로 취급됩니다. 예시: 2sa3aw) 및 v3aw2sa)는 3aw 텍스트 오브젝트가 ((와 ))로 감싸지게 됩니다.

  • 삭제/교체/찾기/강조 표시에서 [count]는 “n 번째 서라운딩을 찾아 연산자를 실행함”을 의미합니다. 예시: (a(b(c)b)a) 라인에서 커서가 c 위에 있을 때 2sd)를 입력하면 (ab(c)ba)가 됩니다(“두 번 삭제함”을 의미하여 (abcba)가 되는 것이 아닙니다).

검색 알고리즘

입력 서라운딩 검색은 다음 원칙을 따릅니다:

  • 입력 서라운딩 사양은 서라운딩 식별자를 기반으로 구성됩니다(MiniSurround-surrounding-specification 참조).

  • 일반적인 검색은 일부 2D 버퍼 영역(기준 영역의 주변)을 1D 문자열로 변환하여(각 라인 뒤에 \n 추가) 수행됩니다. 그런 다음 문자열 내에서 사양과 일치하는 최적의 스팬을 검색합니다(MiniSurround-glossary 참조). 그 후 스팬은 다시 2D 영역으로 변환됩니다. 참고: 첫 번째 검색은 기준 영역 라인 내에서 수행되고, 그 이후에만 config.n_lines 내의 주변 영역에서 수행됩니다(MiniSurround.config 참조).

  • 최적의 일치 스팬은 서라운딩 사양과 일치하는 모든 스팬을 순회하며 “현재 최적”과 비교하여 선택됩니다. 비교는 기준 영역(더 좁게 감싸는 것이 더 좋고, 그렇지 않으면 더 가까운 것이 좋음)과 검색 방법(스팬이 고려 대상인지 여부)에 따라 달라집니다.

  • 추출 패턴(중첩 패턴의 마지막 항목)을 기반으로 스팬 페어(영역 페어의 왼쪽 및 오른쪽 영역용)를 추출합니다.

  • 1보다 큰 [count]의 경우, 현재 최적의 일치가 기준 영역이 되어 단계가 반복됩니다. 최종 영역이 기준 영역과 동일한 경우에도 이러한 추가 단계가 한 번 수행됩니다.

참고:

  • 일치하는 모든 스팬에 대한 순회는 중첩 패턴에 대해 깊이 우선 방식으로 수행됩니다.

  • 스팬은 단 한 번만 비교됨이 보장됩니다.

  • 기능 확장을 위해, 일치하는 모든 스팬을 순회하는 동안 복합 패턴의 일부 Lua 패턴은 특수하게 처리됩니다.

    • %bxx (xx는 두 개의 동일한 문자). 동일한 문자의 균형 잡힌 쌍을 나타내며 “짝을 이루는” 일치를 가져옵니다. 예를 들어, "aa" "bb"에 대한 %b""는 "aa"와 "bb"는 일치시키지만 중간의 " "는 일치시키지 않습니다.

    • x.-y (x와 y는 서로 다른 문자열). 너비가 가장 작은 일치만 가져옵니다. 예를 들어, e e o o에 대한 e.-o는 중간의 e o만 가져옵니다. 참고: 이는 부분에 수량자(+ 등)가 있을 때 영향을 미치는데, 이는 보통 프런티어 패턴 %f[]로 해결할 수 있습니다.

setup()

MiniSurround.setup({config})

모듈 설정

매개변수

{config} (table|nil) 모듈 설정 테이블. MiniSurround.config를 참조하세요.

사용법

require('mini.surround').setup() -- 기본 설정 사용
-- 또는
require('mini.surround').setup({}) -- {}를 사용자 설정 테이블로 교체

config

MiniSurround.config

기본값

MiniSurround.config = {
  -- 내장 서라운딩 위에 추가로 사용할 커스텀 서라운딩을 추가합니다.
  -- 예시가 포함된 자세한 정보는 `:h MiniSurround.config`를 참조하세요.
  custom_surroundings = nil,

  -- `MiniSurround.highlight()` 호출 시 강조 표시 지속 시간(ms)
  highlight_duration = 500,

  -- 모듈 매핑. 비활성화하려면 `''`(빈 문자열)을 사용하세요.
  mappings = {
    add = 'sa', -- 일반 및 비주얼 모드에서 서라운딩 추가
    delete = 'sd', -- 서라운딩 삭제
    find = 'sf', -- 서라운딩 찾기 (오른쪽으로)
    find_left = 'sF', -- 서라운딩 찾기 (왼쪽으로)
    highlight = 'sh', -- 서라운딩 강조 표시
    replace = 'sr', -- 서라운딩 교체

    suffix_last = 'l', -- "이전(prev)" 방법으로 검색할 접미사
    suffix_next = 'n', -- "다음(next)" 방법으로 검색할 접미사
  },

  -- 서라운딩을 검색할 라인 수
  n_lines = 20,

  -- 선택 유형(selection type) 존중 여부:
  -- - 라인 단위 모드에서 서라운딩을 별도의 라인에 배치합니다.
  -- - 블록 단위 모드에서 서라운딩을 각 라인에 배치합니다.
  respect_selection_type = false,

  -- 서라운딩 검색 방법 (먼저 현재 라인 내부, 그 다음 주변).
  -- 'cover', 'cover_or_next', 'cover_or_prev', 'cover_or_nearest',
  -- 'next', 'prev', 'nearest' 중 하나. 자세한 내용은
  -- `:h MiniSurround.config`를 참조하세요.
  search_method = 'cover',

  -- 에러가 아닌 피드백 표시를 비활성화할지 여부.
  -- 이는 사용자 입력이 필요한 경우 유휴 시간 후에 표시되는
  -- (순수 정보용) 헬퍼 메시지에도 영향을 미칩니다.
  silent = false,
}

매핑 (Mappings)

config.mappings는 특정 동작에 대해 어떤 매핑이 설정되는지 정의합니다. 기본적으로 “s”(“surround”의 약자)로 시작하는 “접두사 스타일”의 왼쪽 키를 사용합니다: sa - “surround add”, sd - “surround delete” 등.

참고: 매핑 중 어느 것이라도 “s”로 시작하는 경우(기본값), 내장 s가 실수로 트리거되는 것을 방지하기 위해 “s”는 <Nop>에 매핑됩니다(“s”를 누르고 다음 키를 누를 때까지 지연이 충분히 긴 경우 발생할 수 있음). 대신 cl을 사용하세요.

커스텀 서라운딩 (Custom surroundings)

사용자는 config.custom_surroundings를 제공하여 자신만의 서라운딩을 정의할 수 있습니다. 키는 단일 문자 서라운딩 식별자(getcharstr() 지원)이고 값은 서라운딩 사양(MiniSurround-surrounding-specification 참조)인 테이블이어야 합니다.

일반 권장 사항:

  • config.custom_surroundings에는 일부 데이터(예: output만)만 정의할 수 있습니다. 다른 필드는 내장 서라운딩에서 가져옵니다.

  • 사양의 <input> 또는 <output> 필드에서 서라운딩 정보를 반환하는 함수는 사용자 입력이 필요한 경우(예: 함수 이름 요청) 유용합니다. input() 또는 MiniSurround.user_input()을 사용하세요. 현재 서라운딩 작업을 중단하려면 nil을 반환하세요.

  • 키는 getcharstr() 출력일 수 있는 문자 표현을 사용해야 합니다. 예를 들어, '<CR>'이 아니라 '\r'입니다.

config.custom_surroundings 사용 예시(MiniSurround.gen_spec에서 더 많은 예시를 참조하세요):

local surround = require('mini.surround')
surround.setup({
  custom_surroundings = {
    -- `)`가 공백이 포함된 부분을 삽입하도록 만듭니다. `input` 패턴은 동일하게 유지됩니다.
    [')'] = { output = { left = '( ', right = ' )' } },

    -- 함수를 사용하여 서라운딩 정보 계산
    ['*'] = {
      input = function()
        local n_star = MiniSurround.user_input('Number of * to find')
        local many_star = string.rep('%*', tonumber(n_star) or 1)
        return { many_star .. '().-()' .. many_star }
      end,
      output = function()
        local n_star = MiniSurround.user_input('Number of * to output')
        local many_star = string.rep('*', tonumber(n_star) or 1)
        return { left = many_star, right = many_star }
      end,
    },
  },
})

-- Lua 블록 문자열 `[[...]]`에 대한 커스텀 서라운딩 생성
-- 자동 명령 또는 'after/ftplugin/lua.lua' 파일 내부에서 사용하세요
vim.b.minisurround_config = {
  custom_surroundings = {
    s = {
      input = { '%[%[().-()%]%]' },
      output = { left = '[[', right = ']]' },
    },
  },
}

선택 유형 존중 (Respect selection type)

불리언 옵션 config.respect_selection_type은 서라운딩을 추가하고 삭제할 때 선택 유형을 존중할지 여부를 제어합니다. 활성화된 경우:

  • 라인 단위(linewise) 추가는 서라운딩을 별도의 라인에 배치하면서 서라운드된 라인을 들여쓰기합니다.

  • 라인 단위 추가의 결과처럼 보이는 서라운딩을 삭제하면 이를 되돌리는 동작을 합니다: 서라운딩이 있는 라인을 삭제하고 서라운드된 라인을 내어쓰기합니다.

  • 블록 단위(blockwise) 추가는 선택 영역의 시작과 끝뿐만 아니라 전체 가장자리에 서라운딩을 배치합니다. 참고: 구현의 어려움으로 인해 텍스트 외부 및 멀티바이트 문자가 있는 경우에는 제대로 작동하지 않으며, 앞으로도 지원하지 않을 것입니다.

검색 방법 (Search method)

config.search_method 값은 최적의 일치 검색이 수행되는 방식을 정의합니다. 값에 따라 다음 일치 중 하나가 선택됩니다:

  • 감싸는(Covering) 일치. 왼쪽/오른쪽 가장자리가 기준 영역의 왼쪽/오른쪽 가장자리 앞/뒤에 있는 경우.

  • 이전(Previous) 일치. 왼쪽/오른쪽 가장자리가 기준 영역의 왼쪽/오른쪽 가장자리 앞에 있는 경우.

  • 다음(Next) 일치. 왼쪽/오른쪽 가장자리가 기준 영역의 왼쪽/오른쪽 가장자리 뒤에 있는 경우.

  • 가장 가까운(Nearest) 일치. 이전 일치와 다음 일치 중 가장 가까운 것.

가능한 값은 다음과 같습니다:

  • 'cover' (기본값) - 감싸는 일치만 사용합니다. 이전 또는 다음 일치를 사용하지 않고, 서라운딩을 찾지 못했다고 보고합니다.

  • 'cover_or_next' - 감싸는 일치를 사용합니다. 찾지 못하면 다음 일치를 사용합니다.

  • 'cover_or_prev' - 감싸는 일치를 사용합니다. 찾지 못하면 이전 일치를 사용합니다.

  • 'cover_or_nearest' - 감싸는 일치를 사용합니다. 찾지 못하면 가장 가까운 일치를 사용합니다.

  • 'next' - 다음 일치를 사용합니다.

  • 'previous' - 이전 일치를 사용합니다.

  • 'nearest' - 가장 가까운 일치를 사용합니다.

참고: 검색은 먼저 기준 영역 라인에서 수행되고 실패한 경우에만 config.n_lines로 정의된 전체 주변 영역에서 수행됩니다. 이는 config.search_method가 'cover'가 아닌 경우, 더 큰 전체 주변 영역에서 감싸는 일치를 찾을 수 있더라도 첫 번째 단계에서 발견된 “이전” 또는 “다음” 서라운딩이 검색 결과로 나오게 됨을 의미합니다. 이러한 설계는 대부분의 작업이 기준 영역 라인(보통 커서 라인) 내에서 수행된다는 관찰에 근거한 것입니다.

다음은 커서가 bbb 단어 내부에 있을 때 )를 ] 서라운딩으로 교체하는 작업이 'config.search_method' 값에 따라 어떻게 수행되는지 보여주는 예시입니다:

  • 'cover': (a) bbb (c) -> (a) bbb (c) (메시지와 함께)

  • 'cover_or_next': (a) bbb (c) -> (a) bbb [c]

  • 'cover_or_prev': (a) bbb (c) -> [a] bbb (c)

  • 'cover_or_nearest': 커서 위치에 따라 다름. 첫 번째와 두 번째 b에서는 cover_or_prev와 동일(이전 일치가 더 가까우므로), 세 번째에서는 cover_or_next와 동일(다음 일치가 더 가까우므로).

  • 'next': (a) bbb (c) -> (a) bbb [c]. (bbb)의 경우에도 동일한 결과.

  • 'prev': (a) bbb (c) -> [a] bbb (c). (bbb)의 경우에도 동일한 결과.

  • 'nearest': 커서 위치에 따라 다름('cover_or_nearest'와 동일).

검색 접미사 (Search suffixes)

더 많은 검색 가능성을 제공하기 위해 ’mini.surround’는 특정 검색에 대해 “이전” 및 “다음” 방법을 강제하는 확장 매핑을 생성합니다. 이는 매핑 뒤에 특정 접미사를 붙여서 수행됩니다: “이전” 검색 방법을 사용할 매핑에는 config.mappings.suffix_last, “다음” 검색 방법을 사용할 매핑에는 config.mappings.suffix_next.

참고:

  • 서라운딩 검색과 관련된 동작(삭제, 교체, 찾기(오른쪽 및 왼쪽), 강조 표시)에 대해서만 새로운 매핑을 생성합니다.

  • 모든 새로운 매핑은 config.search_method가 특정 검색 방법으로 설정된 것처럼 동작합니다. 점 반복 지원을 유지하고 [count]를 준수합니다.

  • 대응하는 매핑 세트 생성을 비활성화하려면 빈 문자열을 입력하세요.

기본값(suffix_next는 n, suffix_last는 l)과 초기 라인 (aa) (bb) (cc)를 사용한 예시입니다.

  • 커서가 (aa) 내부에 있을 때 sdn)를 입력하면 (aa) bb (cc)가 됩니다.

  • 커서가 (cc) 내부에 있을 때 sdl)를 입력하면 (aa) bb (cc)가 됩니다.

  • 커서가 (aa) 내부에 있을 때 2srn)]를 입력하면 (aa) (bb) [cc]가 됩니다.

MiniAi.gen_spec

gen_spec.input.treesitter()

MiniSurround.gen_spec.input.treesitter({captures}, {opts})

입력 서라운딩을 위한 Treesitter 사양

함수 형태의 사양입니다. 한 쌍의 treesitter 캡처와 함께 호출되면, <outer>와 <inner> 캡처에서 파생된 영역 페어 배열을 출력하는 사양 함수를 반환합니다. 먼저 외부(outer) 캡처와 일치하는 모든 노드를 검색한 다음, 해당 노드 내에서 내부(inner) 캡처와 가장 크게 일치하는 노드(있는 경우)를 찾아 각각을 완성합니다. 결과 영역 페어는 외부 캡처 영역과 내부 캡처 영역의 차이입니다.

이 기능이 작동하려면 원하는 언어에 대한 treesitter 파서 외에도, 사용자가 접근 가능한 언어별 ‘textobjects’ 쿼리를 가지고 있어야 합니다(vim.treesitter.query.get() 참조). 가장 간단한 방법은 treesitter 캡처가 포함된 ‘textobjects.scm’ 쿼리 파일을 인식되는 경로에 저장하는 것입니다. 이는 기본적으로 ‘nvim-treesitter/nvim-treesitter-textobjects’ 플러그인과 호환되도록 설계되었지만, 해당 플러그인 없이도 사용할 수 있습니다.

쿼리 파일을 갖는 두 가지 일반적인 방법:

  • ’nvim-treesitter/nvim-treesitter-textobjects’를 설치합니다. 이 플러그인은 call.outer, call.inner 등과 같이 표준화된 캡처 이름을 사용하여 여러 언어에 대해 잘 관리된 내장 쿼리 파일을 가지고 있습니다.

  • $XDG_CONFIG_HOME 디렉토리에 ‘after/queries/<언어 이름>/textobjects.scm’ 파일을 수동으로 생성합니다. 이 파일은 (나중에 서라운딩 부분을 정의하는 데 사용될) 캡처를 포함하는 쿼리를 담고 있어야 합니다. lua-treesitter-query를 참조하세요. 쿼리 파일에 접근 가능한지 확인하려면 다음 명령을 실행하세요 (예시는 “lua” 언어에 대한 것이며, 출력에 의도한 파일이 적어도 하나는 있어야 합니다):

    :lua print(vim.inspect(vim.treesitter.query.get_files('lua','textobjects')))

‘nvim-treesitter/nvim-treesitter-textobjects’ 캡처를 사용한 함수 정의 텍스트 오브젝트에 대한 예시 설정:

local ts_input = require('mini.surround').gen_spec.input.treesitter
require('mini.surround').setup({
  custom_surroundings = {
    -- 함수 호출을 검색하기 위해 tree-sitter 사용
    f = {
      input = ts_input({ outer = '@call.outer', inner = '@call.inner' })
    },
  }
})

참고:

  • 쿼리 파일에 알 수 없는 treesitter-directives(예: #make-range! 등)가 포함되어 있지 않은지 확인하세요. 포함되어 있으면 lua-treesitter-core가 이를 캡처로 취급하지 않으므로 해당 캡처가 있는 서라운딩을 찾지 못할 수 있습니다. :=vim.treesitter.query.get('lang', 'textobjects')로 확인하여 대상 캡처가 인식되는지 확인하세요.

  • 쿼리 언어를 결정하기 위해 버퍼의 filetype을 사용합니다.

  • 대용량 파일의 경우 패턴 기반 텍스트 오브젝트보다 느립니다. 그래도 여전히 매우 빠릅니다 (매우 큰 파일에서도 한 번의 검색에 수 밀리초 또는 수십 밀리초 정도 소요됨).

매개변수

{captures} (table) 영역 페어의 외부 및 내부 부분에 대한 캡처: 외부([left.form; right.to]) 및 내부((left.to; right.from), 두 가장자리 모두 제외, 즉 서라운딩의 일부가 아님) 영역에 대한 캡처를 포함하는 <outer> 및 <inner> 필드를 가진 테이블입니다. 각 값은 '@'로 시작하는 문자열 캡처여야 합니다.

{opts} (table|nil) 옵션. 가능한 값:

  • <use_nvim_treesitter> - 쿼리를 수행하기 위해 (있는 경우) ‘nvim-treesitter’ 플러그인 사용을 시도할지 여부. ‘nvim-treesitter-textobjects’ 쿼리가 사용되는 경우 더 발전된 동작과 일관된 경험을 구현하는 데 사용되었습니다. 하지만 현재 lua-treesitter-core 메서드가 더 강력해졌으므로, 이 옵션은 곧 제거될 예정입니다. 하위 호환성을 위해서만 존재합니다. 기본값: false.

반환

(function) 외부 캡처와 내부 캡처 간의 차이를 나타내는 현재 버퍼 영역 페어 배열을 반환하는 함수입니다.
