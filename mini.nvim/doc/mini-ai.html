_ ’mini.nvim’의 main 브랜치에서 생성됨 _

mini.ai a/i 텍스트 오브젝트 확장 및 생성

MIT 라이선스 Copyright (c) 2022 Evgeni Chasnovski

모듈

일부 내장 텍스트 오브젝트 (예: a(, a)), a’ 등)를 강화하고, 새로운 오브젝트(예: a*, a<Space>, af, a? 등)를 생성하며, 사용자가 직접 정의할 수 있도록 합니다.

주요 기능:

  • Lua 패턴과 함수를 사용하여 a/i 텍스트 오브젝트를 커스터마이징하여 생성할 수 있습니다. 다음 기능을 지원합니다:

    • 점 반복(Dot-repeat).

    • v:count.

    • 다양한 검색 방법 ( MiniAi.config 참조).

    • 연속 적용 (비주얼 모드를 벗어나지 않고 선택 영역 업데이트).

    • 여러 텍스트 오브젝트에 대한 별칭(Alias).

  • 포괄적인 내장 텍스트 오브젝트 ( MiniAi-builtin-textobjects에서 자세히 확인):

    • 균형 잡힌 괄호 (공백 포함 여부 선택 가능) 및 별칭.

    • 균형 잡힌 따옴표 및 별칭.

    • 함수 호출.

    • 인자(Argument).

    • 태그.

    • 사용자 프롬프트 기반 생성.

    • 라틴 문자가 아닌 모든 문자에 대한 기본값 ( text-objects로 폴백).

    더 많은 텍스트 오브젝트는 MiniExtra.gen_ai_spec을 확인하세요.

  • 텍스트 오브젝트의 왼쪽/오른쪽 가장자리로 점프하기 위한 이동 기능.

  • 일부 내장 텍스트 오브젝트를 미세 조정하기 위한 사양 생성기 세트 ( MiniAi.gen_spec 참조).

  • Treesitter 텍스트 오브젝트 ( MiniAi.gen_spec.treesitter() 헬퍼를 통해 지원).

이 모듈은 비주얼 모드와 연산자 대기(Operator-pending) 모드 모두에서 a와 i에 대한 매핑을 정의하여 작동합니다. 입력 후, 텍스트 오브젝트 식별자로 간주되는 단일 문자 입력을 기다린 다음 해결된 텍스트 오브젝트 사양을 적용합니다 (적절한 식별자를 찾을 수 없는 경우 다른 매핑으로 폴백). 자세한 내용은 MiniAi-textobject-specification 및 MiniAi-algorithm을 참조하세요.

해결되지 않을 것으로 알려진 문제:

  • 내장 텍스트 오브젝트 검색은 주로 Lua 패턴(정규식과 유사한 방식)을 사용하여 수행됩니다. 어느 정도의 오탐(false positive)은 예상해야 합니다.

  • 내장 텍스트 오브젝트 검색 시 문자열이나 주석 내부인지 여부를 구분하지 않습니다. 예를 들어, f(a = ")", b = 1)과 같은 경우 함수 호출에 대해 잘못된 매치가 발생할 수 있습니다.

일반적인 원칙: 트리시터(Treesitter)와 같이 문서 구조에 사용 가능한 파서를 사용하는 도구가 일반적으로 더 정확한 결과를 제공합니다. 이 모듈은 대부분의 경우에 유용한 일반 텍스트용 내장 텍스트 오브젝트(예: “괄호 내부”, “따옴표/언더스코어 주변” 등)를 주로 제공합니다. 고급 사용 사례의 경우 커스텀 텍스트 오브젝트에 대해 함수 사양을 정의하세요.

지원하지 않는(그리고 아마 앞으로도 지원하지 않을) 기능:

  • 공백을 특별하게 처리하기 위한 특수 연산자 제공 (예: ’targets.vim’의 I 및 A). 공백 처리는 텍스트 오브젝트 사양 내부에서 수행되는 것으로 가정합니다 (예: i(와 i)는 공백을 다르게 처리함).

설정

이 모듈은 require('mini.ai').setup({})을 통한 설정이 필요합니다 ({}를 원하는 config 테이블로 교체하세요). 이를 통해 스크립팅이나 수동으로 사용할 수 있는 전역 Lua 테이블 MiniAi가 생성됩니다 ( :lua MiniAi.* 사용).

사용 가능한 설정값은 MiniAi.config를 참조하세요.

vim.b.miniai_config를 사용하여 버퍼별로 런타임 설정(예: config.custom_textobjects)을 재정의할 수 있으며, 이는 MiniAi.config와 동일한 구조를 가져야 합니다. 자세한 내용은 mini.nvim-buffer-local-config를 참조하세요.

에러가 아닌 피드백 표시를 중단하려면 config.silent = true로 설정하세요.

비교

  • wellle/targets.vim:

    • 커스텀 텍스트 오브젝트 생성에 대한 지원이 제한적입니다: 미리 정의된 감지 규칙으로 제약됩니다. ’mini.ai’는 Lua 패턴과 함수를 통해 독자적인 규칙을 생성할 수 있습니다 ( MiniAi-textobject-specification 참조).

    • 텍스트 오브젝트 정보를 얻기 위한 프로그래밍 방식의 API를 제공하지 않습니다. ’mini.ai’는 MiniAi.find_textobject()를 통해 이를 지원합니다.

    • “텍스트 오브젝트의 가장자리로 이동” 기능이 구현되어 있지 않습니다. ’mini.ai’는 MiniAi.move_cursor()와 g[ 및 g] 기본 매핑을 통해 이를 지원합니다.

    • 둘 다 수동 “다음(next)”/“이전(last)” 검색 방향 개념을 구현합니다.

    • A, I 연산자를 구현합니다. ’mini.ai’는 의도적으로 이를 구현하지 않습니다: 이는 연산자가 아닌 텍스트 오브젝트의 속성으로 간주됩니다.

    • “함수 호출” 및 “사용자 프롬프트” 텍스트 오브젝트를 구현하지 않습니다. ’mini.ai’는 각각 f와 ? 식별자로 이를 지원합니다.

    • “인자(argument)” 텍스트 오브젝트 지원이 제한적입니다. 대부분의 상황에서 작동하지만, 따옴표나 {} 내부와 같은 경우 쉼표를 인자 구분 기호로 잘못 감지하는 경우가 많습니다. ’mini.ai’는 이러한 경우를 처리합니다.

  • nvim-treesitter/nvim-treesitter-textobjects:

    • 텍스트 오브젝트 기능과 더불어 여러 언어에 대해 엄선되고 유지 관리되는 인기 있는 텍스트 오브젝트 쿼리 세트를 제공합니다 (이는 MiniAi.gen_spec.treesitter() 기능의 기반이 될 수 있음).

    • 둘 다 treesitter-directives를 지원하여 더 미세하게 조정된 텍스트 오브젝트를 사용할 수 있게 합니다.

    • 트리시터 기반의 텍스트 오브젝트만 구현합니다.

    • v:count를 지원하지 않습니다.

    • 여러 검색 방법을 지원하지 않습니다 (기본적으로 ’cover’만 지원).

    • 대상 텍스트 오브젝트의 연속 적용을 지원하지 않습니다.

비활성화

비활성화하려면 vim.g.miniai_disable(전역) 또는 vim.b.miniai_disable(버퍼용)을 true로 설정하세요. 다양한 시나리오와 커스터마이징 의도를 고려할 때, 모듈 기능을 비활성화하기 위한 정확한 규칙을 작성하는 것은 사용자의 몫입니다. 일반적인 방법은 mini.nvim-disabling-recipes를 참조하세요.

내장 텍스트 오브젝트

이 표는 모든 내장 텍스트 오브젝트와 그것이 나타내는 내용을 설명합니다. 용어 설명:

  • Key는 텍스트 오브젝트 식별자입니다: a/i 다음에 입력해야 하는 단일 문자입니다.

  • Name은 텍스트 오브젝트에 대한 설명입니다.

  • Example line은 예제가 구성되는 문자열입니다. *는 커서 위치를 나타냅니다.

  • a/i는 a 및 i 텍스트 오브젝트를 나타내는 포함 범위를 설명합니다. 탐색을 돕기 위해 구분 기호에 숫자를 사용합니다.

  • 2a/2i는 2a/2i ( v:count 지원) 텍스트 오브젝트 또는 a/i 텍스트 오브젝트 다음에 오는 또 다른 a/i 텍스트 오브젝트를 설명합니다 (연속 적용 시 증분 선택이 됨).

예: * 위치에 커서를 두고 va)를 입력하면 2열부터 12열까지 선택됩니다. 다시 a)를 입력하면 선택 영역이 [1; 13]으로 변경됩니다. 또한 비주얼 선택 외에도 모든 연산자(operator)를 사용하거나 g[/g] 이동을 사용하여 a 텍스트 오브젝트의 왼쪽/오른쪽 가장자리로 이동할 수 있습니다.

참고:

  • 모든 예제는 기본 config.search_method를 가정합니다.

  • 여는 괄호는 i 텍스트 오브젝트에 대해 내부 가장자리 공백을 처리하는 방식이 닫는 괄호와 다릅니다: 여는 괄호는 공백을 무시하고, 닫는 괄호는 포함합니다.

  • 라틴 문자가 아닌 식별자에 대해 기본 텍스트 오브젝트가 활성화됩니다. 이들은 구분 기호로 간주되도록 설계되었으므로, a 텍스트 오브젝트에는 오른쪽 가장자리만 포함됩니다. 양쪽 가장자리를 모두 포함하려면 커스텀 텍스트 오브젝트를 사용하세요 ( MiniAi-textobject-specification 및 MiniAi.config 참조). 참고 사항:

    • 커서가 식별자 문자 바로 위에 있고 왼쪽과 오른쪽에 두 개의 일치하는 후보가 있는 경우, 너비가 더 좁은 지역이 우선적으로 선택됩니다.

용어집

참고: 이는 MiniSurround-glossary와 유사합니다.

REGION (지역)

버퍼의 지역을 나타내는 테이블입니다. 필드:

  • <from> 및 <to>: 시작 및 종료 위치(포함)를 나타냅니다 ( <to>는 빈 지역을 나타내기 위해 nil일 수 있음). 각 위치는 행 <line>과 열 <col>을 가진 테이블입니다 (둘 다 1부터 시작).

  • <vis_mode>: 텍스트 오브젝트를 선택하는 데 사용될 비주얼 모드입니다. MiniAi.select_textobject()의 opts 인자를 참조하세요. 'v', 'V', '\22' (이스케이프된 '<C-v>') 중 하나입니다.

예시:

{ from = { line = 1, col = 1 }, to = { line = 2, col = 1 } }

-- 강제 줄 단위(linewise) 모드
{
  from = { line = 1, col = 1 }, to = { line = 2, col = 1 },
  vis_mode = 'V',
}

-- 빈 지역
{ from = { line = 10, col = 10 } }

PATTERN (패턴)

Lua 패턴을 기술하는 문자열입니다.

SPAN (스팬)

문자열 내부의 구간(마지막 제외)입니다. 예: [1, 5). from과 to 가장자리가 같으면 해당 지점의 빈 스팬을 나타냅니다.

스팬 A = [a1, a2)가 B = [b1, b2)의 모든 요소를 포함하면(a1 <= b < a2), A는 B를 덮고(cover) 있는 것입니다. 이를 “B가 A 내부에 중첩(nested)되어 있다”고도 표현합니다.

NESTED PATTERN (중첩 패턴)

중첩된 스팬을 기술하기 위한 패턴 배열입니다.

SPAN MATCHES NESTED PATTERN (중첩 패턴과 일치하는 스팬)

연속적으로 중첩된 스팬의 시퀀스가 있고, 각 스팬이 이전 스팬의 부분 문자열(첫 번째 스팬의 경우 입력 문자열) 내에서 해당 패턴과 일치하는 경우입니다. 예시:

-- 내부 공백이 있는 균형 잡힌 `()`를 위한 중첩 패턴
{ '%b()', '^. .* .$' }

-- 예시 입력 문자열 (가독성을 위해 아래에 열 번호 표시):
   "( ( () ( ) ) )"
--  12345678901234

여기서 일치하는 스팬은 [1, 15)와 [3, 13)입니다. [5, 7)과 [8, 10)은 첫 번째 패턴에는 일치하지만 두 번째 패턴에는 일치하지 않습니다. (와 )의 다른 모든 조합은 첫 번째 패턴에 일치하지 않습니다 (균형이 맞지 않음).

COMPOSED PATTERN (조합 패턴)

각 요소가 해당 위치에서 가능한 패턴(또는 패턴 배열)을 기술하는 배열입니다. 조합 패턴은 기본적으로 중첩 패턴의 가능한 모든 조합(데카르트 곱)을 정의합니다. 예시:

  1. 내부 공백이 있는 균형 잡힌 () 또는 균형 잡힌 []:

    -- 조합 패턴
{ { '%b()', '%b[]' }, '^. .* .$' }

-- 동일한 중첩 패턴 배열로 확장된 조합 패턴
{ '%b()', '^. .* .$' } -- 그리고
{ '%b[]', '^. .* .$' }

  2. “내부 공백이 있는 균형 잡힌 ()” 또는 “내부 공백이 없는 균형 잡힌 []” 중에서 길이가 5자 이상인 것:

    -- 조합 패턴
{ { { '%b()', '^. .* .$' }, { '%b[]', '^.[^ ].*[^ ].$' } }, '.....' }

-- 동일한 중첩 패턴 배열로 확장된 조합 패턴
{ '%b()', '^. .* .$', '.....' } -- 그리고
{ '%b[]', '^.[^ ].*[^ ].$', '.....' }

SPAN MATCHES COMPOSED PATTERN (조합 패턴과 일치하는 스팬)

확장된 조합 패턴에서 적어도 하나의 중첩 패턴과 일치하는 경우입니다.

텍스트 오브젝트 사양

텍스트 오브젝트 사양은 조합 패턴( MiniAi-glossary 참조)의 구조를 가지며 두 가지 차이점이 있습니다:

  • 마지막 패턴은 a 또는 i 텍스트 오브젝트를 추출하기 위해 마지막 문자열이 처리되는 방식을 나타내는 짝수 개의 빈 캡처 그룹을 가져야 합니다:

    • 캡처가 0개면 전체 문자열이 a와 i를 모두 나타냅니다. 예: xxx는 문자열 xxx와 리터럴로 일치하는 텍스트 오브젝트를 정의합니다.

    • 캡처가 2개면 그 안의 내용이 i 텍스트 오브젝트를 나타냅니다. a는 전체 문자열입니다. 예: x()x()x는 a 텍스트 오브젝트를 xxx로, i를 중간의 x로 정의합니다.

    • 캡처가 4개면 캡처 1과 4 안의 내용이 a 텍스트 오브젝트를, 캡처 2와 3 안의 내용이 i를 정의합니다. 예: x()()x()x()는 a 텍스트 오브젝트를 마지막 xx로, i를 중간의 x로 정의합니다.

  • 특정 위치에서 호출 가능한 객체(callable object, vim.is_callable() 참조)를 허용합니다 (설정의 복잡성과 계산량이 늘어나는 대신 더 복잡한 텍스트 오브젝트를 가능하게 함):

    • 사양 자체가 호출 가능한 경우, MiniAi.find_textobject()와 동일한 인자로 호출되며 다음 중 하나를 반환해야 합니다:

      • 조합 패턴. 사용자 입력을 구현하는 데 유용합니다. 사용자 프롬프트에서 받은 이름으로 함수 호출을 위한 텍스트 오브젝트를 구현하는 간략한 예시:

        function()
  local left_edge = vim.pesc(vim.fn.input('Function name: '))
  return { left_edge .. '%b()', '^.-%(().*()%)$' }
end

      • 단일 출력 지역. 텍스트 오브젝트를 완전히 제어하고 싶을 때 유용합니다. 있는 그대로 사용됩니다. 전체 버퍼를 반환하는 예시:

        function()
  local from = { line = 1, col = 1 }
  local to = {
    line = vim.fn.line('$'),
    col = math.max(vim.fn.getline('$'):len(), 1)
  }
  return { from = from, to = to, vis_mode = 'V' }
end

      • 출력 지역 배열. 트리시터와 같은 다른 도구를 통합하는 데 유용합니다 ( MiniAi.gen_spec.treesitter() 참조). 조합 패턴과 마찬가지로 가장 적합한 지역이 선택됩니다 ( n_lines, search_method 등 옵션 존중). 표시 너비가 80자를 넘는 “최적의” 줄을 선택하는 예시:

        function(_, _, _)
  local res = {}
  for i = 1, vim.api.nvim_buf_line_count(0) do
    local cur_line = vim.fn.getline(i)
    if vim.fn.strdisplaywidth(cur_line) > 80 then
      local region = {
        from = { line = i, col = 1 },
        to = { line = i, col = cur_line:len() },
      }
      table.insert(res, region)
    end
  end
  return res
end

    • 문자열 패턴 대신 호출 가능한 객체가 있는 경우, (line, init) 시그니처를 가지고 pattern:find()처럼 동작할 것으로 기대됩니다. line에서 init 이후 또는 init 지점의 스팬을 나타내는 두 숫자를 반환해야 합니다 (그런 스팬이 없으면 nil). !중요 주의 사항!: 이는 출력의 from이 init보다 엄격하게 왼쪽이어서는 안 됨을 의미합니다 (무한 루프 발생 가능). 마지막 항목으로는 허용되지 않습니다 (캡처가 있는 패턴이어야 함). 충분히 넓은 너비를 가진 균형 잡힌 괄호만 일치시키는 예시:

      {
  '%b()',
  function(s, init)
    if init > 1 or s:len() < 5 then return end
    return 1, s:len()
  end,
  '^.().*().$'
}

더 많은 예시:

-- 세트에서 균형 잡힌 괄호 쌍 (내장 `b` 식별자에 사용됨):
{ { '%b()', '%b[]', '%b{}' }, '^.().*().$' }

-- 숫자와 구두점을 무시하는 단어 모방 (라틴 알파벳 전용):
{ '()()%f[%w]%w+()[ \t]*()' }

-- 카멜 케이스(camel case)를 지원하는 단어 (라틴 알파벳 전용):
{
  {
    '%u[%l%d]+%f[^%l%d]',
    '%f[%S][%l%d]+%f[^%l%d]',
    '%f[%P][%l%d]+%f[^%l%d]',
    '^[%l%d]+%f[^%l%d]',
  },
  '^().*()$'
}

-- 숫자:
{ '%f[%d]%d+' }

-- 'YYYY-MM-DD' 형식의 날짜:
{ '()%d%d%d%d%-%d%d%-%d%d()' }

-- Lua 블록 문자열:
{ '%[%[().-()%]%]' }

자주 사용되는 텍스트 오브젝트 사양을 생성하기 위한 함수 래퍼는 MiniAi.gen_spec을 참조하세요.

알고리즘

텍스트 오브젝트 검색은 다음 원칙에 의존합니다:

  • MiniAi.find_textobject()에서 설명한 것과 동일한 입력 데이터(즉, a 또는 i 여부, 식별자, 참조 지역 등)를 사용합니다.

  • 텍스트 오브젝트 식별자를 기반으로 텍스트 오브젝트 사양이 구성됩니다 ( MiniAi-textobject-specification 참조).

  • 일반적인 검색은 2D 버퍼 지역(참조 지역의 인접 구역)을 1D 문자열로 변환(각 줄 뒤에 \n 추가)하여 수행됩니다. 그런 다음 문자열 내부에서 텍스트 오브젝트 사양과 가장 잘 일치하는 스팬을 검색합니다 ( MiniAi-glossary 참조). 그 후 스팬을 다시 2D 지역으로 변환합니다. 참고: 먼저 참조 지역의 줄 내부에서 검색을 수행하고, 실패한 경우에만 config.n_lines 내의 인접 구역에서 검색합니다 ( MiniAi.config 참조).

  • 텍스트 오브젝트 사양과 일치하는 모든 스팬을 순회하며 “현재 최적”과 비교하여 최적의 일치 스팬을 선택합니다. 비교는 참조 지역(더 좁게 덮는 것이 좋고, 그렇지 않으면 더 가까운 것이 좋음)과 검색 방법(스팬의 고려 여부)에 따라 달라집니다.

  • 추출 패턴(중첩 패턴의 마지막 항목)을 기반으로 스팬을 추출합니다.

  • 연속 검색( opts.n_times가 1보다 큰 경우)을 수행해야 하는 경우, 현재의 최적 매치를 참조 지역으로 하여 단계를 반복합니다. 최종 지역이 참조 지역과 동일한 경우에도 이러한 추가 단계가 한 번 더 수행됩니다 (이를 통해 연속 적용이 가능해짐).

참고:

  • 일치하는 모든 스팬에 대한 순회는 중첩 패턴에 대해 깊이 우선(depth-first) 방식으로 수행됩니다.

  • 스팬은 단 한 번만 비교되도록 보장됩니다.

  • 기능 확장을 위해 모든 일치 스팬을 순회하는 동안 조합 패턴의 일부 Lua 패턴은 특별하게 처리됩니다.

    • %bxx ( xx는 동일한 두 문자). 동일한 문자로 이루어진 균형 잡힌 쌍을 의미하며 “쌍을 이룬” 매치 결과를 냅니다. 예를 들어, "aa" "bb"에 대해 %b""를 사용하면 "aa"와 "bb"에는 일치하지만 중간의 " "에는 일치하지 않습니다.

    • x.-y ( x와 y는 서로 다른 문자열). 너비가 가장 작은 매치 결과만 냅니다. 예를 들어, e e o o에 대해 e.-o를 사용하면 중간의 e o만 결과로 나옵니다. 참고: 부품에 수량자(예: + 등)가 있는 경우 결과에 영향을 미칠 수 있으며, 이는 일반적으로 프런티어 패턴 %f[]로 해결할 수 있습니다 ( MiniAi-textobject-specification의 예제 참조).

require('mini.ai').setup() -- 기본 설정 사용

require('mini.ai').setup({}) -- {}를 원하는 설정 테이블로 교체

기본값

MiniAi.config = {
  -- 필드는 텍스트 오브젝트 ID, 값은 텍스트 오브젝트 사양인 테이블입니다.
  -- 내장 텍스트 오브젝트를 비활성화하는 데에도 사용됩니다. |MiniAi.config|를 참조하세요.
  custom_textobjects = nil,

  mappings = {
    -- 주요 텍스트 오브젝트 접두사
    around = 'a',
    inside = 'i',

    -- 다음/이전 텍스트 오브젝트

    around_next = 'an',
    inside_next = 'in',
    around_last = 'al',
    inside_last = 'il',

    -- 커서를 `a` 텍스트 오브젝트의 해당 가장자리로 이동
    goto_left = 'g[',
    goto_right = 'g]',
  },

  -- 텍스트 오브젝트를 검색할 줄 수
  n_lines = 50,

  -- 오브젝트 검색 방법 (먼저 현재 줄 내부에서 검색하고, 그다음 인접 구역에서 검색).
  -- 'cover', 'cover_or_next', 'cover_or_prev', 'cover_or_nearest',

  search_method = 'cover_or_next',

  -- 에러가 아닌 피드백 표시 여부
  -- 사용자 입력이 필요한 경우 유휴 시간 후에 표시되는 (순수 정보용) 헬퍼 메시지에도 영향을 미칩니다.
  silent = false,
}

커스텀 텍스트 오브젝트

사용자는 config.custom_textobjects를 제공하여 자신만의 텍스트 오브젝트를 정의할 수 있습니다. 키는 getcharstr()이 지원하는 단일 문자 텍스트 오브젝트 식별자여야 하며, 값은 텍스트 오브젝트 사양( MiniAi-textobject-specification 참조)이어야 합니다.

일반 권장 사항:

  • 내장 텍스트 오브젝트를 재정의하는 데 사용할 수 있습니다 ( MiniAi-builtin-textobjects). 외부 또는 Neovim 내장 매핑을 사용하기 위해 모듈의 내장 텍스트 오브젝트를 비활성화하려면 유효하지 않은 입력(사양 형식이 아닌 것)을 제공하세요.

  • 키는 getcharstr() 출력인 문자 표현을 사용해야 합니다. 예를 들어 '<CR>'이 아니라 '\r'을 사용하세요.

예시:

require('mini.ai').setup({
  custom_textobjects = {
    -- 인자(argument) 텍스트 오브젝트 미세 조정
    a = require('mini.ai').gen_spec.argument({ brackets = { '%b()' } }),

    -- 내장 블록 텍스트 오브젝트를 사용하기 위해 괄호 별칭 비활성화
    b = false,

    -- 이제 `vax`는 `xxx`를 선택하고 `vix`는 중간의 `x`를 선택합니다.
    x = { 'x()x()x' },

    -- 전체 버퍼
    g = function()
      local from = { line = 1, col = 1 }
      local to = {
        line = vim.fn.line('$'),
        col = math.max(vim.fn.getline('$'):len(), 1)
      }
      return { from = from, to = to }
    end
  }
})

-- `vim.b.miniai_config`를 사용하여 버퍼별로 커스터마이징
-- 마크다운 파일에 유용한 사양 예시:
local spec_pair = require('mini.ai').gen_spec.pair
vim.b.miniai_config = {
  custom_textobjects = {
    ['*'] = spec_pair('*', '*', { type = 'greedy' }),
    ['_'] = spec_pair('_', '_', { type = 'greedy' }),
  },
}

더 많은 사양 예시는 MiniAi-textobject-specification을 참조하세요.

검색 방법

config.search_method 값은 최적 매치 검색 방식을 정의합니다. 값에 따라 다음 중 하나가 선택됩니다:

  • Covering match (덮는 매치). 왼쪽/오른쪽 가장자리가 참조 지역의 왼쪽/오른쪽 가장자리 이전/이후에 위치합니다.

  • Previous match (이전 매치). 왼쪽/오른쪽 가장자리가 참조 지역의 왼쪽/오른쪽 가장자리 이전에 위치합니다.

  • Next match (다음 매치). 왼쪽/오른쪽 가장자리가 참조 지역의 왼쪽/오른쪽 가장자리 이후에 위치합니다.

  • Nearest match (가장 가까운 매치). 이전 및 다음 매치 중 더 가까운 쪽을 선택합니다.

사용 가능한 값은 다음과 같습니다:

  • 'cover' - 덮는 매치만 사용합니다. 이전이나 다음 매치는 사용하지 않으며, 발견된 텍스트 오브젝트가 없다고 보고합니다.

  • 'cover_or_next' (기본값) - 덮는 매치를 사용합니다. 없으면 다음 매치를 사용합니다.

  • 'cover_or_prev' - 덮는 매치를 사용합니다. 없으면 이전 매치를 사용합니다.

  • 'cover_or_nearest' - 덮는 매치를 사용합니다. 없으면 가장 가까운 매치를 사용합니다.

  • 'next' - 다음 매치를 사용합니다.

  • 'prev' - 이전 매치를 사용합니다.

  • 'nearest' - 가장 가까운 매치를 사용합니다.

참고: 검색은 먼저 참조 지역의 줄에서 수행되고, 실패 시에만 config.n_lines로 정의된 전체 인접 구역에서 수행됩니다. 즉, config.search_method가 'cover'가 아닌 경우, 더 큰 전체 인접 구역에 덮는 매치가 있더라도 첫 번째 단계에서 발견된 “이전” 또는 “다음” 텍스트 오브젝트가 검색 결과가 됩니다. 이 설계는 대부분의 작업이 참조 지역 줄(보통 커서 줄) 내에서 이루어진다는 관찰에 기반합니다.

커서가 bbb 단어 내부에 있을 때 a) 텍스트 오브젝트가 'config.search_method' 값에 따라 어떻게 결정되는지 보여주는 예시입니다:

  • 'cover': (a) bbb (c) -> 없음

  • 'cover_or_next': (a) bbb (c) -> (c)

  • 'cover_or_prev': (a) bbb (c) -> (a)

  • 'cover_or_nearest': 커서 위치에 따라 다릅니다. 첫 번째와 두 번째 b에서는 cover_or_prev처럼 (이전 매치가 더 가까우므로), 세 번째에서는 cover_or_next처럼 (다음 매치가 더 가까우므로) 작동합니다.

  • 'next': (a) bbb (c) -> (c). (bbb)의 경우에도 결과는 동일합니다.

  • 'prev': (a) bbb (c) -> (a). (bbb)의 경우에도 결과는 동일합니다.

  • 'nearest': 커서 위치에 따라 다릅니다 ( 'cover_or_nearest'와 동일).

매핑

around_next / inside_next 및 around_last / inside_last 매핑은 본질적으로 around / inside와 동일하지만 검색 방법으로 'next'와 'prev'를 사용합니다.

참고: 기본 설정 시 Neovim>=0.12의 내장 LSP 매핑인 v_an 및 v_in을 덮어씁니다. 다른 키를 사용하거나 vim.lsp.buf.selection_range()를 사용하여 수동으로 매핑하세요. 예시:

local map_lsp_selection = function(lhs, desc)
  local s = vim.startswith(desc, 'Increase') and 1 or -1
  local rhs = function() vim.lsp.buf.selection_range(s * vim.v.count1) end
  vim.keymap.set('x', lhs, rhs, { desc = desc })
end
map_lsp_selection('<Leader>ls', '선택 영역 확대')
map_lsp_selection('<Leader>lS', '선택 영역 축소')

find_textobject()

MiniAi.find_textobject({ai_type}, {id}, {opts})

텍스트 오브젝트 지역 찾기

매개변수

{ai_type} (string) 'a' 또는 'i' 중 하나입니다.

{id} (string) 텍스트 오브젝트 ID를 나타내는 단일 문자 문자열입니다. 텍스트 오브젝트 지역을 계산하기 위한 사양을 얻는 데 사용됩니다. 참고: 사양이 함수인 경우 모든 현재 인자와 함께 호출됩니다 ( opts는 기본 인자로 채워짐).

{opts} (table|nil) 옵션입니다. 사용 가능한 필드:

  • <n_lines> - 텍스트 오브젝트를 검색할 줄 수입니다. 기본값: config.n_lines ( MiniAi.config 참조).

  • <n_times> - 연속 검색을 수행할 횟수입니다. 각 검색은 이전에 발견된 텍스트 오브젝트 지역을 참조 지역으로 하여 수행됩니다. 기본값: 1.

  • <reference_region> - 덮으려고 시도할 지역입니다 ( MiniAi-glossary 참조). 출력 지역이 이 지역 내부이거나 이 지역과 동일하지 않음을 보장합니다. 기본값: 커서 위치의 빈 지역.

  • <search_method> - 검색 방법입니다. 기본값: config.search_method.

반환

(table|nil) 텍스트 오브젝트의 지역을 반환하거나, opts.reference_region과 다른 텍스트 오브젝트를 opts.n_times회 연속으로 찾지 못한 경우 nil을 반환합니다.

매개변수

{side} (string) 'left' 또는 'right' 중 하나입니다.

{ai_type} (string) 'a' 또는 'i' 중 하나입니다.

{id} (string) 텍스트 오브젝트 ID를 나타내는 단일 문자 문자열입니다.

{opts} (table|nil) MiniAi.find_textobject()와 동일합니다. opts.n_times는 실제 점프 횟수를 의미합니다 (커서가 이미 잠재적 점프 지점에 있는 경우 중요).

gen_spec

MiniAi.gen_spec

일반적인 텍스트 오브젝트 사양 생성

함수 요소가 포함된 테이블입니다. 사양을 얻으려면 호출하세요.

예시:

local gen_spec = require('mini.ai').gen_spec
require('mini.ai').setup({
  custom_textobjects = {
    -- `()` 내부에서 `;` 사이의 인자만 인식하도록 미세 조정
    a = gen_spec.argument({ brackets = { '%b()' }, separator = ';' }),

    -- 함수 이름에서 마침표(.)를 감지하지 않도록 함수 호출 미세 조정
    f = gen_spec.function_call({ name_pattern = '[%w_]' }),

    -- 함수 정의 (이 캡처가 포함된 트리시터 쿼리가 필요함)
    F = gen_spec.treesitter({ a = '@function.outer', i = '@function.inner' }),

    -- `|`가 균형 잡히지 않은 방식으로 양쪽 가장자리를 선택하도록 설정
    ['|'] = gen_spec.pair('|', '|', { type = 'non-balanced' }),
  }
})

gen_spec.argument()

MiniAi.gen_spec.argument({opts})

인자(argument) 사양

인자 텍스트 오브젝트(기본 식별자 a)는 균형 잡힌 괄호 내부에서 제외되지 않은 허용된 구분 기호 사이의 지역입니다. 이 함수를 사용하여 작동 방식을 미세 조정하세요.

예시:

  • argument({ brackets = { '%b()' } })는 균형 잡힌 () 내부에서만 인자를 검색합니다.

  • argument({ separator = '[,;]' })는 ,와 ;를 모두 구분 기호로 처리합니다.

  • argument({ exclude_regions = { '%b()' } })는 균형 잡힌 ()(외부 괄호 내부) 내부에 있는 구분 기호를 무시합니다.

매개변수

{opts} (table|nil) 옵션입니다. 허용되는 필드:

  • <brackets> - 외부 균형 괄호를 위한 패턴 배열입니다. 기본값: { '%b()', '%b[]', '%b{}' } (모든 (), [], {}가 인자를 감쌀 수 있음).

  • <separator> - 구분 기호 패턴입니다. 기본값: ','. 이 옵션의 실제 용도 중 하나는 문자 주변의 공백을 구분 기호의 일부로 포함하는 것입니다. 예를 들어, '%s*,%s*'는 ’,’뿐만 아니라 주변 공백도 구분 기호로 처리합니다. 이는 긍정적인 효과와 부정적인 효과가 모두 있습니다. 한편으로는 첫 번째 인자에서 daa를 실행하면 첫 번째 쉼표 뒤의 공백이 삭제되어 예상되는 결과가 나옵니다. 다른 한편으로는 커서가 문자 구분 기호 근처의 공백 위에 있을 때 어떤 인자가 선택될지 모호해집니다.

  • <exclude_regions> - 구분 기호가 무시될 지역을 위한 패턴 배열입니다. 기본값: { '%b""', "%b''", '%b()', '%b[]', '%b{}' } (균형 잡힌 따옴표나 괄호 내부의 구분 기호는 무시됨).

gen_spec.function_call()

MiniAi.gen_spec.function_call({opts})

함수 호출 사양

함수 호출 텍스트 오브젝트(기본 식별자 f)는 일부 문자 뒤에 균형 잡힌 ()가 오는 지역입니다. 이 함수를 사용하여 작동 방식을 미세 조정하세요.

예시:

  • function_call({ name_pattern = '[%w_]' })는 영숫자나 언더스코어(마침표 제외)만 포함된 함수 이름을 인식합니다.

매개변수

{opts} (table|nil) 옵션입니다. 허용되는 필드:

  • <name_pattern> - 함수 이름에 허용되는 문자 세트의 문자열 패턴입니다. 기본값: '[%w_%.]' (영숫자, 언더스코어 또는 마침표). 참고: []로 감싸야 합니다.

gen_spec.pair()

MiniAi.gen_spec.pair({left}, {right}, {opts})

쌍(pair) 사양

왼쪽이 left, 오른쪽이 right로 둘러싸인 지역에 대한 텍스트 오브젝트를 정의할 때 사용합니다. a 텍스트 오브젝트는 양쪽 가장자리를 포함하고, i는 제외합니다.

지역은 여러 유형( opts.type으로 제어) 중 하나일 수 있습니다. 모든 예시는 기본 검색 방법, a 텍스트 오브젝트를 가정하며, left와 right 모두에 '_'를 사용합니다:

  • Non-balanced (균형 잡히지 않음, { type = 'non-balanced' }), 기본값. 첫 번째 패턴으로 x.-y를 사용하는 것과 동일합니다. 예시: ‘a_b_c’ 줄에서 연속적으로 ‘a’, ‘b’, ’c’에 일치합니다.

  • Balanced (균형 잡힘, { type = 'balanced' }). 첫 번째 패턴으로 %bxy를 사용하는 것과 동일합니다. 예시: ‘a_b_c’ 줄에서 연속적으로 ‘a’, ’c’에 일치합니다. 참고: left와 right 모두 단일 문자여야 합니다.

  • Greedy (탐욕적, { type = 'greedy' }). Non-balanced와 비슷하지만 최대 연속 left 및 right 가장자리를 선택합니다. 예시: ’__a_b’ 줄에서 연속적으로 ‘a’와’__b_’를 선택합니다. 참고: left와 right 모두 단일 문자여야 합니다.

매개변수

{left} (string) 왼쪽 가장자리입니다.

{right} (string) 오른쪽 가장자리입니다.

{opts} (table|nil) 옵션입니다. 사용 가능한 필드:

  • <type> - 쌍의 유형입니다. 'non-balanced' (기본값), 'balanced', 'greedy' 중 하나입니다.

gen_spec.treesitter()

MiniAi.gen_spec.treesitter({ai_captures}, {opts})

트리시터(Treesitter) 사양

함수 형태의 사양입니다. 트리시터 캡처 쌍과 함께 호출되면 해당( a 또는 i) 캡처와 일치하는 지역 배열을 출력하는 사양 함수를 반환합니다.

이 기능이 작동하려면 대상 언어에 대한 트리시터 파서 외에도 사용자가 접근 가능한 언어별 ‘textobjects’ 쿼리를 가지고 있어야 합니다 ( vim.treesitter.query.get() 참조). 가장 간단한 방법은 인식된 경로에 트리시터 캡처가 저장된 ‘textobjects.scm’ 쿼리 파일을 두는 것입니다. 이는 주로 ‘nvim-treesitter/nvim-treesitter-textobjects’ 플러그인과 호환되도록 설계되었지만, 해당 플러그인 없이도 사용할 수 있습니다.

쿼리 파일을 갖는 두 가지 일반적인 방법:

  • ’nvim-treesitter/nvim-treesitter-textobjects’를 설치합니다. 이 플러그인은 많은 언어에 대해 function.outer, function.inner 등 표준화된 캡처 이름을 가진 잘 관리된 내장 쿼리 파일을 제공합니다.

  • $XDG_CONFIG_HOME 디렉토리에 ‘after/queries/<언어 이름>/textobjects.scm’ 파일을 수동으로 생성합니다. 여기에는 (나중에 텍스트 오브젝트를 정의하는 데 사용되는) 캡처가 포함된 쿼리가 들어 있어야 합니다. lua-treesitter-query를 참조하세요. 쿼리 파일에 접근 가능한지 확인하려면 다음을 실행하세요 (lua 언어의 예시이며, 출력에 의도한 파일이 적어도 하나 포함되어야 함):

    :lua print(vim.inspect(vim.treesitter.query.get_files('lua','textobjects')))

‘nvim-treesitter/nvim-treesitter-textobjects’ 캡처를 사용한 함수 정의 텍스트 오브젝트의 설정 예시:

local spec_treesitter = require('mini.ai').gen_spec.treesitter
require('mini.ai').setup({
  custom_textobjects = {
    F = spec_treesitter({ a = '@function.outer', i = '@function.inner' }),
    o = spec_treesitter({
      a = { '@conditional.outer', '@loop.outer' },
      i = { '@conditional.inner', '@loop.inner' },
    })
  }
})

참고:

  • 쿼리 파일에 알 수 없는 treesitter-directives (예: #make-range! 등)가 포함되지 않도록 주의하세요. 그렇지 않으면 lua-treesitter-core가 이를 캡처로 간주하지 않아 해당 캡처에 대한 텍스트 오브젝트를 찾지 못할 수 있습니다. :=vim.treesitter.query.get('lang', 'textobjects')로 대상 캡처가 제대로 인식되는지 확인하세요.

  • 버퍼의 filetype을 사용하여 쿼리 언어를 결정합니다.

  • 대용량 파일의 경우 패턴 기반 텍스트 오브젝트보다 느립니다. 하지만 여전히 매우 빠릅니다 (매우 큰 파일에서도 한 번의 검색에 수 밀리초에서 수십 밀리초 정도 소요됨).

매개변수

{ai_captures} (table) a 및 i 텍스트 오브젝트를 위한 캡처입니다. a 및 i 필드가 있는 테이블로, 각각 a 및 i 텍스트 오브젝트를 위한 캡처를 가집니다. 각 값은 문자열 캡처( '@'로 시작해야 함)이거나 그러한 캡처의 배열(모든 일치 항목 중 최적이 선택됨)일 수 있습니다.

{opts} (table|nil) 옵션입니다. 사용 가능한 값:

  • <use_nvim_treesitter> - 쿼리를 수행할 때 (있는 경우) ‘nvim-treesitter’ 플러그인을 사용하려고 시도할지 여부입니다. 이전에는 ‘nvim-treesitter-textobjects’ 쿼리가 사용될 경우 더 고급 동작과 일관된 경험을 구현하기 위해 사용되었습니다. 하지만 lua-treesitter-core 메서드가 현재 더 강력해졌으므로 이 옵션은 곧 제거될 예정입니다. 하위 호환성을 위해서만 존재합니다. 기본값: false.

반환

(function) 해당( a 또는 i) 트리시터 캡처와 일치하는 현재 버퍼 지역 배열을 반환하는 MiniAi.find_textobject() 시그니처의 함수입니다.

gen_spec.user_prompt()

MiniAi.gen_spec.user_prompt()

사용자 프롬프트로부터의 사양

  • 사용자에게 왼쪽 및 오른쪽 텍스트 오브젝트 가장자리를 원시 문자열(패턴 아님)로 요청합니다.

  • 왼쪽 가장자리 문자열부터 오른쪽 가장자리 문자열까지 일치하는 텍스트 오브젝트 사양을 구성합니다: a는 두 문자열을 모두 포함하고, i는 내부만 포함합니다.

식별자 ?를 가진 MiniAi-builtin-textobjects에 사용됩니다.

반환

(function) 함수 형태의 텍스트 오브젝트 사양입니다.

select_textobject()

MiniAi.select_textobject({ai_type}, {id}, {opts})

텍스트 오브젝트 지역을 비주얼 모드로 선택

지역을 찾지 못한 경우 아무 작업도 하지 않습니다.

매개변수

{ai_type} (string) 'a' 또는 'i' 중 하나입니다.

{id} (string) 텍스트 오브젝트 ID를 나타내는 단일 문자 문자열입니다.

{opts} (table|nil) MiniAi.find_textobject()와 동일합니다. 추가 필드:

  • <vis_mode> - 'v', 'V', '\22' ( '<C-v>'의 이스케이프 버전) 중 하나입니다. 기본값: 최신 비주얼 모드.

  • <operator_pending> - 선택이 연산자 대기 모드를 위한 것인지 여부입니다. 해당 모드의 매핑에 사용되며 직접 사용해서는 안 됩니다. 기본값: false.
