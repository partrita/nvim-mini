’mini.nvim’의 main 브랜치에서 생성됨

mini.snippets 스니펫 관리 및 확장

MIT 라이선스 Copyright (c) 2024 Evgeni Chasnovski

모듈

스니펫은 자주 사용되는 텍스트의 템플릿입니다. 일반적인 워크플로우는 스니펫의 (설정 가능한) 접두사를 입력하고 이를 스니펫 세션으로 확장하는 것입니다.

템플릿은 대개 미리 정의된 텍스트와 사용자가 스니펫 세션 동안 대화식으로 텍스트를 변경/추가할 수 있는 위치(“탭스톱”이라고 함)를 포함합니다.

이 모듈은 LSP 사양에 정의된 스니펫 구문만 지원합니다(약간의 편차 있음). MiniSnippets-syntax-specification을 참조하세요.

기능:

  • 명시적으로 추가하거나 유연하고 성능이 뛰어난 내장 로더 세트를 사용하여 스니펫 컬렉션을 관리합니다. MiniSnippets.gen_loader를 참조하세요.

  • 구성된 스니펫은 현재 로컬 컨텍스트를 기반으로 모든 확장 전에 효율적으로 해석됩니다. 예를 들어, 서로 다른 로컬 tree-sitter 언어(예: 마크다운 코드 블록)에서 서로 다른 스니펫을 사용할 수 있게 해줍니다. MiniSnippets.default_prepare()를 참조하세요.

  • 현재 입력된 텍스트를 기반으로 삽입할 스니펫을 매칭합니다. 정확한 매칭과 퍼지 매칭을 모두 지원합니다. MiniSnippets.default_match()를 참조하세요.

  • vim.ui.select()를 통해 매칭된 여러 스니펫 중에서 선택합니다. MiniSnippets.default_select()를 참조하세요.

  • 특수화된 프로세스 내 LSP 서버를 시작하여 (자동)완성 엔진(예: mini.completion) 내부에서 로드된 스니펫을 표시합니다. MiniSnippets.start_lsp_server()를 참조하세요.

  • 설정 가능한 방식으로 스니펫 세션 동안 삽입, 점프 및 편집을 수행합니다:

    • 점프 및 중지를 위한 설정 가능한 매핑.

    • 쉬운 탐색을 위해 점프 시 탭스톱을 순환합니다.

    • 세션이 자동으로 중지되는 시점에 대한 이해하기 쉬운 규칙.

    • 상대적인 들여쓰기를 유지하면서 연결된 탭스톱의 텍스트 동기화.

    • 동적 탭스톱 상태 시각화(현재/방문함/방문하지 않음 등).

    • 빈 탭스톱의 인라인 시각화(Neovim>=0.10 필요).

    • 새 줄에서 주석 리더를 유지하여 주석 내부에서 작동합니다.

    • 중첩된 세션 지원(활성 세션이 있는 동안 스니펫 확장). MiniSnippets.default_insert()를 참조하세요.

  • 스니펫 본문을 이해하기 쉬운 데이터 구조로 파싱하는 내보내기 함수. MiniSnippets.parse()를 참조하세요.

참고:

  • 기본적으로는 스니펫 컬렉션을 설정하지 않습니다. 매칭할 스니펫을 가지려면 config.snippets를 명시적으로 채워야 합니다.

  • 내장된 스니펫 컬렉션은 제공되지 않습니다. 사용자가 직접 또는 전용 플러그인을 사용하여 자신의 스니펫을 추가해야 합니다.

  • 기본 스니펫 세션에서 변수/탭스톱 변환을 지원하지 않습니다. 이는 간결하게 구현할 수 없는 ECMAScript 정규 표현식 파서가 필요하기 때문입니다.

의존성

이 모듈은 스니펫 컬렉션을 함께 제공하지 않습니다. 수동으로 생성하거나 전용 플러그인을 설치하세요. 예를 들어, rafamadriz/friendly-snippets가 있습니다.

설정

이 모듈은 require('mini.snippets').setup({})({}를 config 테이블로 교체)으로 설정이 필요합니다. 이는 스크립팅 또는 수동으로(:lua MiniSnippets.*) 사용할 수 있는 전역 Lua 테이블 MiniSnippets를 생성합니다.

config 구조 및 기본값은 MiniSnippets.config를 참조하세요.

vim.b.minisnippets_config 내부에 버퍼별로 런타임 설정 설정을 로컬로 재정의할 수 있으며, 이는 MiniSnippets.config와 동일한 구조여야 합니다. 자세한 내용은 mini.nvim-buffer-local-config를 참조하세요.

비교

  • L3MON4D3/LuaSnip:

    • 둘 다 파일 시스템에서 스니펫을 로드하는 기능을 포함합니다. 이 모듈은 여러 공통 로더 생성기를 제공하는 반면, ’LuaSnip’은 더 정교한 로딩 설정을 포함합니다. 또한 둘 다 로드할 스니펫을 명시적으로 선택해야 합니다.

    • 둘 다 LSP 스니펫 형식을 지원합니다. ’LuaSnip’은 또한 이 모듈의 범위를 벗어나는 고유하고 더 정교한 스니펫 형식을 제공합니다.

    • ’LuaSnip’은 스니펫을 자동 확장할 수 있는 반면, 이 모듈은 항상 확장을 위해 사용자의 명시적인 동작이 필요합니다(의도된 설계).

    • 둘 다 스니펫 확장 기능을 포함하지만 몇 가지 측면에서 다릅니다:

      • ’LuaSnip’은 정교한 동적 탭스톱 시각화 설정을 가지고 있습니다. 이 모듈은 몇 가지 전용 하이라이트 그룹을 제공합니다.

      • 이 모듈은 빈 탭스톱의 설정 가능한 시각화를 제공합니다.

      • ’LuaSnip’은 중첩된 세션을 기본적으로 하나로 병합하여 구현합니다. 이 모듈은 각 중첩된 세션을 별개로 처리하여(시각적 과부하를 방지하기 위해) 스택(선입후출)에 저장합니다.

      • ’LuaSnip’은 현재 탭스톱 대체를 위해 Select-mode를 사용하는 반면, 이 모듈은 항상 Insert-mode를 유지합니다. 이를 통해 매핑을 더 쉽게 이해하고 더 타겟팅된 하이라이팅이 가능합니다.

      • 이 모듈은 더 유연한 탐색을 위해 마지막 탭스톱 이후 순환하는 점프를 구현하며(더 유연한 자동 중지 규칙으로 강화됨), ’LuaSnip’은 점프가 마지막 탭스톱에 도달하면 세션을 자동 중지합니다.

  • 내장 vim.snippet (Neovim>=0.10에서):

    • 스니펫을 로드하거나 매칭하는 기능을 포함하지 않는 반면(의도된 설계), 이 모듈은 포함합니다.

    • 둘 다 LSP 스니펫 형식을 기반으로 한 확장 기능을 포함합니다. 스니펫 세션 처리 방식의 차이는 ’LuaSnip’과의 비교와 유사합니다.

  • rafamadriz/friendly-snippets:

    • 스니펫을 관리하거나 확장하는 기능이 없는 스니펫 컬렉션 플러그인입니다. 이 모듈은 ‘friendly-snippets’ 호환성을 염두에 두고 설계되었습니다.

  • abeldekat/cmp-mini-snippets:

    • ’mini.snippets’를 통합하는 hrsh7th/nvim-cmp용 소스입니다.

하이라이트 그룹

  • MiniSnippetsCurrent - 현재 탭스톱.

  • MiniSnippetsCurrentReplace - 현재 탭스톱, 플레이스홀더가 대체될 예정임.

  • MiniSnippetsFinal - 특수 $0 탭스톱.

비활성화

핵심 기능을 비활성화하려면 vim.g.minisnippets_disable(전역) 또는 vim.b.minisnippets_disable(버퍼용)을 true로 설정하세요. 다양한 시나리오와 사용자 정의 의도를 고려하여 모듈의 기능을 비활성화하기 위한 정확한 규칙을 작성하는 것은 사용자의 몫으로 남겨둡니다. 공통 레시피는 mini.nvim-disabling-recipes를 참조하세요.

용어집

POSITION

버퍼 내의 위치를 나타내는 테이블. 필드:

  • <line> (number) - 줄 번호 (1부터 시작).

  • <col> (number) - 열 번호 (1부터 시작).

REGION

버퍼 내의 영역을 나타내는 테이블. 필드: 포함적인 시작/종료 POSITION을 위한 <from> 및 <to>.

SNIPPET

삽입할 템플릿에 대한 데이터. 다음 필드를 포함해야 합니다:

  • <prefix> - 문자열 스니펫 식별자.

  • <body> - 적절한 구문을 가진 문자열 스니펫 내용.

  • <desc> - 사람이 읽을 수 있는 형식의 문자열 스니펫 설명.

구분이 명확한 경우 스니펫 본문을 의미하는 데 사용될 수도 있습니다.

SNIPPET SESSION

사용자가 삽입된 스니펫을 조정할 수 있는 대화식 상태.

MATCHED SNIPPET

매칭된 영역을 가진 <region> 필드를 포함하는 스니펫. 일반적으로 영역을 제거해야 합니다.

SNIPPET NODE

파싱된 스니펫 본문의 단위. MiniSnippets.parse()를 참조하세요.

TABSTOP

사용자가 대화식으로 조정할 수 있도록 스니펫 본문에 지정된 전용 위치. 스니펫 본문에서 $ 다음에 숫자가 오는 형식으로 지정됩니다.

LINKED TABSTOPS

동일한 탭스톱이 할당된 서로 다른 노드들. 동기화되어 업데이트됩니다.

REFERENCE NODE

연결된 탭스톱 중 첫 번째(왼쪽에서 오른쪽으로) 노드. 동기화된 텍스트와 점프 후 커서 위치를 결정하는 데 사용됩니다.

EXPAND

현재 입력된 텍스트를 기반으로 스니펫 세션을 시작하는 동작. 항상 현재 버퍼의 커서 위치에서 수행됩니다. 실행 단계:

  • PREPARE - 컨텍스트에서 원시 설정 스니펫을 해석합니다.

  • MATCH - 커서 위치에서 해석된 스니펫을 매칭합니다.

  • SELECT - 매칭된 스니펫 중에서 선택할 수 있습니다.

  • INSERT - 선택된 스니펫을 삽입하고 스니펫 세션을 시작합니다.

개요

스니펫은 자주 사용되는 텍스트의 템플릿입니다. 일반적인 워크플로우는 스니펫의 (설정 가능한) 접두사를 입력하고 이를 스니펫 세션으로 확장하는 것입니다: 일부 미리 정의된 텍스트를 추가하고 사용자가 특정 위치에서 대화식으로 변경/추가할 수 있도록 허용합니다.

이 개요는 매핑 및 확장에 대한 기본 설정을 가정합니다. 자세한 내용은 MiniSnippets.config 및 MiniSnippets-examples를 참조하세요.

스니펫 구조

스니펫은 세 부분으로 구성됩니다:

  • Prefix - 현재 텍스트와 매칭하는 데 사용되는 식별자.

  • Body - 적절한 구문으로 실제로 삽입되는 내용.

  • Desc - 사람이 읽을 수 있는 형식의 설명.

예시: { prefix = 'tis', body = 'This is snippet', desc = 'Snip' } tis를 입력하고 “확장” 매핑(기본값 <C-j>)을 누르면 “tis”가 제거되고 “This is snippet”이 추가되며 커서가 Insert 모드에서 끝에 위치합니다.

구문

MiniSnippets-syntax-specification

더 작은 접두사를 입력한 후 텍스트만 삽입하는 것도 이미 충분히 강력합니다. 더 큰 유연성을 위해 스니펫 본문은 추가 기능을 제공하도록 특수한 방식으로 형식을 지정할 수 있습니다. 이 모듈은 LSP 사양에 정의된 구문 지원을 구현합니다(약간의 편차 있음). 참조를 위해 이 링크를 확인하세요: https://microsoft.github.io/language-server-protocol/specifications/lsp/3.18/specification/#snippet_syntax

기본 구문 기능의 빠른 개요:

  • 탭스톱은 해당 위치에서 대화식 편집을 위한 스니펫 부분입니다. $1, $2 등으로 표시됩니다. 이들 사이를 탐색하는 것을 “점프”라고 하며, 특수 키를 눌러 탭스톱 식별자의 숫자 순서대로 수행됩니다: <C-l> 및 <C-h>를 눌러 각각 다음 및 이전 탭스톱으로 점프합니다. 특수 탭스톱 $0은 “마지막 탭스톱”이라고 불리며, 스니펫 세션이 자동으로 중지되는 시점을 결정하는 데 사용되고 점프 중에 마지막으로 방문됩니다.

    예시: T1=$1 T2=$2 T0=$0은 세 개의 탭스톱이 있는 T1= T2= T0=으로 확장됩니다.

  • 탭스톱은 플레이스홀더를 가질 수 있습니다: 탭스톱이 아직 편집되지 않은 경우 사용되는 텍스트입니다. 편집이 수행되지 않으면 텍스트가 유지됩니다. 이는 동일한 구문을 따르므로 그 자체로 플레이스홀더가 있는 탭스톱을 포함할 수 있습니다(즉, 중첩될 수 있음). 플레이스홀더가 있는 탭스톱은 ${1:placeholder}로 표시됩니다($1은 ${1:}입니다).

    예시: T1=${1:text} T2=${2:<$1>}은 T1=text T2=<text>로 확장됩니다. 첫 번째 플레이스홀더에서 x를 입력하면 T1=x T2=<x>가 됩니다. 한 번 점프하고 y를 입력하면 T1=x T2=y가 됩니다.

  • 동일한 식별자를 가진 여러 탭스톱이 있을 수 있습니다. 이들은 연결되어 텍스트 편집 중에 동기화되어 업데이트됩니다. 서로 다른 플레이스홀더를 가질 수도 있지만, 첫 번째(왼쪽에서 오른쪽으로) 탭스톱의 플레이스홀더와 동일하도록 강제됩니다.

    예시: T1=${1:text} T1=$1은 T1=text T1=text로 확장됩니다. 첫 번째 플레이스홀더에서 x를 입력하면 T1=x T1=x가 됩니다.

  • 탭스톱은 선택지를 가질 수도 있습니다: 탭스톱 텍스트에 대한 제안입니다. ${1|a,b,c|}로 표시됩니다. 첫 번째 선택지가 플레이스홀더로 사용됩니다.

    예시: T1=${1|left,right|}는 T1=left로 확장됩니다.

  • 변수를 사용하여 사용자 조작 없이 텍스트를 자동으로 삽입할 수 있습니다. 탭스톱과 마찬가지로 각 변수는 변수가 정의되지 않은 경우 사용되는 플레이스홀더를 가질 수 있습니다. 에디터 상태를 설명하는 특별한 변수 세트가 있습니다.

    예시: V1=$TM_FILENAME V2=${NOTDEFINED:placeholder}는 V1=현재-파일-기본이름 V2=placeholder로 확장됩니다.

LSP 사양과 다른 점:

  • 특수 변수 세트가 더 넓으며 VSCode 사양에서 가져왔습니다: https://code.visualstudio.com/docs/editor/userdefinedsnippets#_variables Neovim이 이 정보를 제공하지 않으므로 BLOCK_COMMENT_START 및 BLOCK_COMMENT_END는 예외입니다.

  • 변수 TM_SELECTED_TEXT는 quote_quote 레지스터의 내용으로 해석됩니다. 확장하기 전에 텍스트가 거기에 배치되었다고 가정합니다. 예를 들어 시각적 선택 후 c를 누르고 접두사를 입력한 후 확장합니다. 이를 조정하는 방법은 MiniSnippets-examples를 참조하세요.

  • 환경 변수가 인식되고 지원됩니다: V1=$VIMRUNTIME은 $VIMRUNTIME의 실제 값을 사용합니다.

  • 스니펫 세션 동안 변수 변환은 지원되지 않습니다. Neovim에서 쉽게 구현할 수 없는 ECMAScript 유사 정규 표현식과의 상호 작용이 필요하기 때문입니다. 향후 변경될 수 있습니다. 하지만 파싱 중에 변환이 인식되며 몇 가지 예외가 있습니다:

    • ${1:?if:else}의 if 내부의 }는 (기술적인 이유로) 이스케이프가 필요합니다.

스니펫 본문을 이해하기 쉬운 데이터 구조로 프로그래밍 방식으로 파싱하기 위한 MiniSnippets.parse() 함수가 있습니다.

확장

스니펫을 사용하는 것은 “확장”이라고 불리는 과정을 통해 수행됩니다. 다음과 같이 진행됩니다:

  • 스니펫 접두사 또는 인식 가능한 일부를 입력합니다.

  • <C-j>를 눌러 확장합니다. 다음 단계를 수행합니다:

    • 현재 컨텍스트(버퍼 + 로컬 언어)에서 사용 가능한 스니펫을 준비합니다. 이를 통해 스니펫 설정에서 서로 다른 컨텍스트에서 서로 다른 스니펫을 반환하는 일반 함수 로더를 가질 수 있습니다.

    • 커서 왼쪽의 텍스트를 사용 가능한 접두사와 매칭합니다. 먼저 정확한 매칭을 시도하고 실패하면 퍼지 매칭으로 넘어갑니다.

    • 매칭 결과가 여러 개인 경우 vim.ui.select()를 사용하여 하나를 선택합니다.

    • 단일 매칭 스니펫을 삽입합니다. 스니펫에 탭스톱이 포함되어 있으면 스니펫 세션을 시작합니다.

각 단계에 대한 자세한 내용은 다음을 참조하세요:

  • MiniSnippets.default_prepare()

  • MiniSnippets.default_match()

  • MiniSnippets.default_select()

  • MiniSnippets.default_insert()

스니펫 세션은 탭스톱 위치에서 대화식 편집을 허용합니다:

  • 모든 탭스톱 위치는 탭스톱 “상태”(현재/방문함/방문하지 않음/마지막인지 여부 및 이미 편집되었는지 여부)에 따라 시각화됩니다. 빈 탭스톱은 인라인 가상 텍스트(일반/마지막 탭스톱의 경우 “•”/“∎”)로 시각화됩니다. 이는 세션이 중지된 후 제거됩니다.

  • 첫 번째 탭스톱에서 세션을 시작합니다. 플레이스홀더를 대체할 텍스트를 입력합니다. 현재 탭스톱이 끝나면 <C-l>로 다음 탭스톱으로 점프합니다. 반복합니다. 이전 탭스톱에 대해 마음이 바뀌면 <C-h>로 되돌아갑니다. 점프는 또한 가장자리에서 순환합니다(첫 번째 탭스톱은 마지막 탭스톱 다음입니다).

  • 탭스톱에 선택지가 있는 경우 <C-n> / <C-p>를 사용하여 다음 / 이전 항목을 선택합니다.

  • 활성 세션이 있는 동안 다른 스니펫 세션을 시작하는 것이 허용됩니다. 이는 중첩된 세션을 생성합니다: 현재 세션을 일시 중지하고 새 세션을 시작합니다. 새로 생성된 세션이 중지된 후 일시 중지된 세션을 재개합니다.

  • <C-c>를 눌러 수동으로 세션을 중지하거나 자동으로 중지되게 합니다: 마지막 탭스톱이 현재인 경우 텍스트 편집을 수행하거나 Normal 모드로 나갑니다. 스니펫이 마지막 탭스톱을 명시적으로 정의하지 않으면 스니펫 끝에 추가됩니다.

스니펫 세션에 대한 자세한 내용은 MiniSnippets-session을 참조하세요.

LSP 완성을 지원하는 완성 엔진(예: mini.completion 또는 lsp-autocompletion)을 통해 스니펫을 선택하고 삽입하려면, MiniSnippets.setup() 후에 MiniSnippets.start_lsp_server()를 호출하세요. 이는 ’mini.snippets’로 로드된 스니펫을 매칭하고 제공하는 LSP 서버를 설정합니다. 완성 엔진과 매칭하려면 start_lsp_server({ match = false })를 사용하세요.

관리

기본적으로 ’mini.snippets’는 스니펫을 로드하지 않으며, MiniSnippets.config를 따라 MiniSnippets.setup() 내부에서 명시적으로 수행되어야 합니다.

권장되는 스니펫 관리 방식은 스니펫 데이터가 포함된 전용 파일을 만들고 config.snippets의 함수 로더를 통해 로드하는 것입니다. 기본적이면서도 유능한 스니펫 관리 설정은 MiniSnippets-examples를 참조하세요.

파일 사양

MiniSnippets-file-specification

지원되는 파일의 일반적인 아이디어는 일반적인 스니펫 컬렉션과 최소한 즉시 사용 가능한 경험을 제공하는 것입니다. 즉, “rafamadriz/friendly-snippets”입니다. 다음 파일이 지원됩니다:

  • 확장자:

    • JSON 객체로 읽기/디코딩됨 (vim.json.decode()): *.json, *.code-snippets

    • Lua 파일로 실행됨 (dofile()) 및 반환된 값 사용: *.lua

  • 내용:

    • 딕셔너리형: JSON의 객체, Lua의 반환된 테이블. 순서 보장 없음.

    • 배열형: JSON의 배열, Lua의 반환된 배열 테이블. 순서 유지.

단일 스니펫이 포함된 파일 내용의 예:

  • Lua 딕셔너리형: return { name = { prefix = 't', body = 'Text' } }

  • Lua 배열형: return { { prefix = 't', body = 'Text', desc = 'name' } }

  • JSON 딕셔너리형: { "name": { "prefix": "t", "body": "Text" } }

  • JSON 배열형: [ { "prefix": "t", "body": "Text", "desc": "name" } ]

참고:

  • VSCode 스타일의 “package.json” 파일에 대한 내장 지원은 없습니다. 내장 또는 사용자 정의 로더를 통해 MiniSnippets.setup()에서 구조를 수동으로 정의하세요.

  • 스니펫 데이터의 scope 필드에 대한 내장 지원은 없습니다. 스니펫은 수동으로 더 작은 파일로 분리되어 요청 시 로드되는 것이 예상됩니다.

지원되는 스니펫 구문은 MiniSnippets-syntax-specification을 참조하세요.

일반적인 조언

  • 파일을 ‘runtimepath’의 임의의 경로에 있는 “snippets” 하위 디렉토리에 두세요(예:’$XDG_CONFIG_HOME/nvim/snippets/global.json’). 이는 MiniSnippets.gen_loader.from_runtime() 및 MiniSnippets-examples의 예제와 호환됩니다.

  • 더 크로스 플랫폼 설정을 원한다면 딕셔너리형 내용이 포함된 *.json 파일을 선호하세요. 그렇지 않으면 배열형 내용이 포함된 *.lua 파일을 사용하세요.

  • 컨텍스트에 따라 데이터(일반적으로 <body>)가 변경되는 “동적 스니펫”을 구현하려면 스니펫 데이터를 반환하는 함수가 포함된 *.lua 파일을 사용하세요. 이는 출력 테이블(딕셔너리 또는 배열형)의 요소여야 합니다.

데모

스니펫 관리 및 확장 설계를 파악하는 가장 좋은 방법은 직접 시도해보는 것입니다. 기본 데모를 위한 단계는 다음과 같습니다:

  • 설정 디렉토리에 다음 내용으로 ‘snippets/global.json’ 파일을 생성합니다:

    {
  "Basic":        { "prefix": "ba", "body": "T1=$1 T2=$2 T0=$0"         },
  "Placeholders": { "prefix": "pl", "body": "T1=${1:aa}\nT2=${2:<$1>}"  },
  "Choices":      { "prefix": "ch", "body": "T1=${1|a,b|} T2=${2|c,d|}" },
  "Linked":       { "prefix": "li", "body": "T1=$1\n\tT1=$1"            },
  "Variables":    { "prefix": "va", "body": "Runtime: $VIMRUNTIME\n"    },
  "Complex":      {
    "prefix": "co",
    "body": [ "T1=${1:$RANDOM}", "T3=${3:$1_${2:$1}}", "T2=$2" ]
  }
}

  • MiniSnippets-examples에서 권장하는 대로 ’mini.snippets’를 설정합니다.

  • Neovim을 엽니다. 각 스니펫 접두사를 입력하고 <C-j>를 누릅니다(이미 활성 세션이 있는 경우에도 가능). 거기서부터 탐색해 보세요.

예시

기본 스니펫 관리 설정

대부분의 경우를 다루는 스니펫 관리 설정의 예:

-- 설정
local gen_loader = require('mini.snippets').gen_loader
require('mini.snippets').setup({
  snippets = {
    -- 먼저 전역 스니펫이 포함된 사용자 정의 파일을 로드합니다.
    gen_loader.from_file('~/.config/nvim/snippets/global.json'),

    -- 'runtimepath' 디렉토리의 "snippets/" 하위 디렉토리에서 파일을 읽어
    -- 현재 언어를 기반으로 스니펫을 로드합니다.
    gen_loader.from_lang(),
  },
})

이 설정을 사용하면 사용자 정의 “전역” 스니펫(모든 버퍼에 존재함)이 포함된 단일 파일과 로컬 언어를 기반으로 로드될 스니펫을 가질 수 있습니다(MiniSnippets.gen_loader.from_lang() 참조).

언어 스니펫을 수동으로 생성하거나(‘$XDG_CONFIG_HOME/nvim/snippets/lua.json’ 파일을 생성하고 채움) 전용 스니펫 컬렉션 플러그인(예: ‘rafamadriz/friendly-snippets’)을 설치하여 생성하세요.

참고: 모든 내장 로더와 MiniSnippets.read_file()은 기본적으로 출력을 캐시합니다. 즉, 파일을 처음 읽은 후에는 파일을 변경해도 현재 Neovim 세션 동안에는 효과가 없습니다. 필요한 경우 캐시를 재설정하는 방법은 MiniSnippets.gen_loader를 참조하세요.

현재 컨텍스트에서 사용 가능한 모든 스니펫 중에서 선택

MiniSnippets.default_match()를 사용하면 줄 시작 부분이나 공백 뒤에서 스니펫을 확장(기본값 <C-j>)합니다. 항상 모든 현재 컨텍스트 스니펫 중에서 선택할 수 있도록 하려면 다음과 유사한 매핑을 만드세요:

local rhs = function() MiniSnippets.expand({ match = false }) end
vim.keymap.set('i', '<C-g><C-j>', rhs, { desc = '모두 확장' })

“Supertab” 스타일의 <Tab> / <S-Tab> 매핑

이 모듈은 중첩된 세션을 더 깔끔하게 사용할 수 있도록 기본적으로 확장과 점프에 별도의 키를 사용합니다. 다음은 사용자 정의 <Tab>을 “확장 또는 점프”로, <S-Tab>을 “이전으로 점프”로 설정하는 예입니다:

local snippets = require('mini.snippets')
local match_strict = function(snips)
  -- 커서 왼쪽의 공백과 매칭하지 않음
  return snippets.default_match(snips, { pattern_fuzzy = '%S+' })
end
snippets.setup({
  -- ... 스니펫 설정 ...
  mappings = { expand = '', jump_next = '', jump_prev = '' },
  expand   = { match = match_strict },
})
local expand_or_jump = function()
  local can_expand = #MiniSnippets.expand({ insert = false }) > 0
  if can_expand then vim.schedule(MiniSnippets.expand); return '' end
  local is_active = MiniSnippets.session.get() ~= nil
  if is_active then MiniSnippets.session.jump('next'); return '' end
  return '\t'
end
local jump_prev = function() MiniSnippets.session.jump('prev') end
vim.keymap.set('i', '<Tab>', expand_or_jump, { expr = true })
vim.keymap.set('i', '<S-Tab>', jump_prev)

마지막 탭스톱으로 점프한 후 즉시 세션 중지

전용 MiniSnippets-events를 활용하세요:

local fin_stop = function(args)
  if args.data.tabstop_to == '0' then MiniSnippets.session.stop() end
end
local au_opts = { pattern = 'MiniSnippetsSessionJump', callback = fin_stop }
vim.api.nvim_create_autocmd('User', au_opts)

Normal 모드 종료 시 모든 세션 중지

ModeChanged 및 MiniSnippets-events 이벤트를 사용하세요:

local make_stop = function()
  local au_opts = { pattern = '*:n', once = true }
  au_opts.callback = function()
    while MiniSnippets.session.get() do
      MiniSnippets.session.stop()
    end
  end
  vim.api.nvim_create_autocmd('ModeChanged', au_opts)
end
local opts = { pattern = 'MiniSnippetsSessionStart', callback = make_stop }
vim.api.nvim_create_autocmd('User', opts)

변수 평가 사용자 정의

환경 변수와 config.expand.insert 래퍼를 생성합니다:

local jump_next = function()
  if vim.snippet.active({direction = 1}) then return vim.snippet.jump(1) end

  if vim.snippet.active({direction = -1}) then vim.snippet.jump(-1) end

vim.keymap.set({ 'i', 's' }, '<C-h>', jump_prev)

로드된 스니펫

config.snippets는 스니펫 데이터를 포함하는 배열이며, 스니펫 테이블, 함수 로더 또는 (아무리 깊게 중첩되어도 상관없는) 스니펫 데이터 배열일 수 있습니다.

스니펫은 다음 필드를 가진 테이블입니다:

  • <prefix> (string|table|nil) - 현재 텍스트와 매칭하는 데 사용되는 문자열. 배열인 경우 모든 문자열을 별도의 접두사로 사용해야 합니다.

  • <body> (string|table|nil) - MiniSnippets-syntax-specification을 따라야 하는 스니펫의 내용. 배열은 "\n"으로 연결됩니다.

  • <desc> (string|table|nil) - 스니펫의 설명. 스니펫을 더 사람이 읽기 쉬운 형식으로 표시하는 데 사용될 수 있습니다. 배열은 "\n"으로 연결됩니다.

함수 로더는 단일 context 테이블 인수를 사용하여 호출될 것으로 예상되며(현재 컨텍스트에 대한 모든 데이터를 포함함), config.snippets와 동일한 데이터 구조를 반환합니다.

config.snippets는 모든 확장 시 config.prepare로 해석됩니다. 기본적으로 어떻게 수행되는지는 MiniSnippets.default_prepare()를 참조하세요.

실제 예시는 MiniSnippets-examples를 참조하세요. 다음은 config.snippets 사용자 정의 기능에 대한 예시입니다:

local gen_loader = require('mini.snippets').gen_loader
require('mini.snippets').setup({
  snippets = {
    -- 먼저 전역 스니펫이 포함된 사용자 정의 파일을 로드합니다 (순서가 중요함)
    gen_loader.from_file('~/.config/nvim/snippets/global.json'),

    -- 또는 여기에 명시적으로 추가합니다
    { prefix='cdate', body='$CURRENT_YEAR-$CURRENT_MONTH-$CURRENT_DATE' },

    -- 'runtimepath' 디렉토리의 "snippets/" 하위 디렉토리에서 파일을 읽어
    -- 현재 언어를 기반으로 스니펫을 로드합니다.
    gen_loader.from_lang(),

    -- `gen_loader.from_file()` 및 상대 경로를 사용하여 프로젝트 로컬 스니펫 로드
    -- (파일이 존재하지 않아도 됩니다)
    gen_loader.from_file('.vscode/project.code-snippets'),

    -- 언어별 프로젝트 로컬 스니펫을 위한 사용자 정의 로더
    function(context)
      local rel_path = '.vscode/' .. context.lang .. '.code-snippets'
      if vim.fn.filereadable(rel_path) == 0 then return end
      return MiniSnippets.read_file(rel_path)
    end,

    -- 일부 접두사가 사용되지 않도록 보장합니다 (`body`가 없으므로)
    { prefix = { 'bad', 'prefix' } },
  }
})

매핑

config.mappings는 어떤 매핑이 자동으로 생성되는지 설명합니다.

mappings.expand는 Insert 모드에서 전역적으로 생성되며 커서 위치에서 스니펫을 확장하는 데 사용됩니다. 사용자 정의 매핑에는 MiniSnippets.expand()를 사용하세요.

mappings.jump_next, mappings.jump_prev, 및 mappings.stop은 MiniSnippets.default_insert()의 활성 스니펫 세션 동안 생성됩니다. 각각 다음/이전 탭스톱으로 점프하고 활성 세션을 중지하는 데 사용됩니다. 사용자 정의 Insert 모드 매핑에는 MiniSnippets.session.jump() 및 MiniSnippets.session.stop()을 사용하세요. 참고: "<C-n>" 또는 "<C-p>"를 어떤 동작에도 사용하지 마세요. 내장 완성과 충돌하기 때문입니다: 이들은 완성이 “다음/이전 완성 항목으로 포커스 변경”을 의미하도록 강제합니다. 이는 이 모듈이 점프 중에 내장 완성을 처리하는 방식 때문에 선택지가 있는 탭스톱이 있는 경우보다 더 자주 중요해집니다.

확장

config.expand는 mappings.expand를 누르거나 MiniSnippets.expand()를 통해 수동으로 시작한 후의 확장 단계(MiniSnippets-glossary 참조)를 정의합니다.

expand.prepare는 config.snippets 형식의 raw_snippets를 인수로 받아 단순 스니펫 배열(MiniSnippets-glossary에 설명됨)을 반환해야 하는 함수입니다. 모든 MiniSnippets.expand() 호출 시 호출됩니다. 두 번째 값을 반환하면 경고 메시지의 컨텍스트로 사용됩니다. 기본값: MiniSnippets.default_prepare().

expand.match는 expand.prepare 출력을 받아 매칭된 스니펫 배열(사용자가 최종적으로 삽입하고자 하는 하나 또는 여러 스니펫)을 반환하는 함수입니다. 출력의 매칭 결과를 최선에서 최악 순으로 정렬해야 합니다. 항목은 매칭을 수행하는 데 사용된 현재 버퍼 영역인 region 필드를 포함할 수 있습니다. 일반적으로 (ins-completion 및 abbreviations가 작동하는 방식과 유사하게) 제거해야 합니다. 기본값: MiniSnippets.default_match()

expand.select는 expand.match의 출력과 스니펫을 삽입하는 함수(Insert 모드를 보장하고 스니펫의 매칭 영역을 제거함)를 받는 함수입니다. 사용자가 대화식으로 스니펫을 선택하고 선택한 스니펫을 삽입할 수 있도록 해야 합니다. vim.ui.select()와 호환되도록 설계되었습니다. 비어 있지 않은 모든 expand.match 출력에 대해 호출됩니다(단일 항목인 경우에도 포함). 기본값: MiniSnippets.default_select().

expand.insert는 단일 스니펫 테이블을 입력으로 받아 커서 위치에 스니펫을 삽입하는 함수입니다. 이는 버퍼에 텍스트 템플릿을 추가하고 스니펫 세션을 시작하는 주요 진입점입니다. (일반적인 대화식 사례인) MiniSnippets.expand() 내부에서 호출되는 경우 커서 위치에 스니펫을 삽입하기만 하면 됩니다. Insert 모드 보장 및 매칭된 스니펫 영역 제거는 미리 수행됩니다. 기본값: MiniSnippets.default_insert().

config.expand 사용자 정의 예시:

-- 컨텍스트로 추가 데이터 제공
local my_p = function(raw_snippets)
  local _, cont = MiniSnippets.default_prepare({})
  cont.cursor = vim.api.nvim_win_get_cursor()
  return MiniSnippets.default_prepare(raw_snippets, { context = cont })
end
-- 영숫자만을 기반으로 퍼지 매칭 수행
local my_m = function(snippets)
  return MiniSnippets.default_match(snippets, { pattern_fuzzy = '%w*' })
end
-- 항상 최선의 매칭 스니펫 삽입
local my_s = function(snippets, insert) return insert(snippets[1]) end
-- 빈 탭스톱을 인라인 가상 텍스트로 표시하는 데 다른 문자열 사용
local my_i = function(snippet)
  return MiniSnippets.default_insert(snippet, { empty_tabstop = '$' })
end

require('mini.snippets').setup({
  -- ... 스니펫 설정 ...
  expand = { prepare = my_p, match = my_m, select = my_s, insert = my_i }
})

expand()

MiniSnippets.expand({opts})

커서 위치에서 스니펫 확장

확장 단계(MiniSnippets-glossary 참조)를 수행합니다. 초기 원시 스니펫은 현재 버퍼의 config.snippets에서 가져옵니다. vim.b.minisnippets_config의 스니펫은 전역 스니펫 배열에 추가됩니다.

매개변수

{opts} (table|nil) 옵션. MiniSnippets.config의 expand와 동일한 구조이며 그 값을 기본값으로 사용합니다. 허용되는 값에는 차이가 있습니다:

  • 모든 버퍼 스니펫을 매칭 결과로 가지려면 match = false를 사용하세요.

  • (있는 경우) 항상 최선의 매칭 결과를 확장하려면 select = false를 사용하세요.

  • 삽입하지 않고 모든 매칭 결과를 반환하려면 insert = false를 사용하세요.

참고: opts.insert는 Insert 모드를 보장하고 스니펫의 매칭 영역을 제거하고 커서를 배치한 후에 호출됩니다.

반환

(table|nil) insert가 false인 경우 매칭된 스니펫 배열(expand.match 출력). 그렇지 않으면 nil.

사용법

-- 매칭, 선택할 수 있음, 삽입
MiniSnippets.expand()

-- 최선의 매칭 결과를 매칭하고 확장을 강제함 (있는 경우)
MiniSnippets.expand({ select = false })

-- 모든 현재 컨텍스트 스니펫을 매칭 결과로 사용함
MiniSnippets.expand({ match = false })

-- 모든 매칭된 스니펫 가져오기
local matches = MiniSnippets.expand({ insert = false })

-- 모든 현재 컨텍스트 스니펫 가져오기
local all = MiniSnippets.expand({ match = false, insert = false })

MiniSnippets.gen_loader

스니펫 로더 생성

이것은 함수 요소가 포함된 테이블입니다. 실제로 로더를 가져오려면 호출하세요.

생성된 모든 로더의 공통 기능:

  • MiniSnippets-file-specification과 함께 작동하도록 설계되었습니다.

  • 기본적으로 출력을 캐시합니다. 즉, 동일한 입력 값에 대한 두 번째 이상의 호출은 파일 시스템을 읽지 않습니다. 동일한 생성기에서 생성된 서로 다른 로더는 캐시를 공유합니다. opts.cache를 false로 설정하여 비활성화하세요. 모든 캐시를 지우려면 MiniSnippets.setup()을 호출하세요. 예시:

    MiniSnippets.setup(MiniSnippets.config)

  • vim.notify()를 사용하여 로딩 중 발생한 문제를 표시하는 동시에, 올바르게 정의된 스니펫 데이터를 가능한 많이 로드하려고 시도합니다. opts.silent를 true로 설정하여 비활성화하세요.

gen_loader.from_lang()

MiniSnippets.gen_loader.from_lang({opts})

언어 로더 생성

설정된 언어 패턴과 매칭되는 ’runtimepath’의 “snippets/” 하위 디렉토리에서 파일을 로드합니다. 런타임 로딩에 대한 자세한 내용은 MiniSnippets.gen_loader.from_runtime()을 참조하세요.

언어는 “prepare” 단계 동안 로더 호출에서 사용되는 context 인수의 <lang> 필드(문자열 값이 있는 경우)에서 가져옵니다. 이는 MiniSnippets.default_prepare() 및 대부분의 스니펫 컬렉션 플러그인과 호환됩니다.

매개변수

{opts} (table|nil) 옵션. 가능한 값:

  • <lang_patterns> (table) - MiniSnippets.gen_loader.from_runtime()에서와 같이 스니펫 파일을 찾는 데 사용되는 런타임 패턴 배열에 대한 언어 맵입니다. 패턴은 순서대로 처리됩니다. MiniSnippets.default_prepare()를 사용하면 접두사가 동일한 스니펫이 있는 경우 나중 패턴의 데이터가 사용됨을 의미합니다. 기본 컨텍스트로 현재 언어를 대화식으로 확인하려면 :=MiniSnippets.default_prepare({})를 실행하고 두 번째 테이블의 데이터를 확인하세요.

    (비어 있지 않은 언어의 경우) 기본 패턴 배열은 다음과 같은 *.json 및 *.lua 파일을 읽도록 구성됩니다:

    • 언어 이름의 “snippets/” 하위 디렉토리 내부 (파일은 아무리 깊게 중첩되어도 상관없음).

    • 언어 이름으로 명명되고 “snippets/” 디렉토리(깊이 무관)에 있음. “lua” 언어의 예시:

      { 'lua/**/*.json', 'lua/**/*.lua', '**/lua.json', '**/lua.lua' }

    lang 컨텍스트가 빈 문자열(대개 임시 스크래치 버퍼)인 경우 소싱할 언어로 ""(빈 문자열)에 대한 항목을 추가합니다.

  • <cache> (boolean) - 캐시된 출력을 사용할지 여부. 기본값: true. 참고: 캐싱은 lang 값이 아니라 사용된 런타임 패턴별로 수행되어 서로 다른 from_lang() 로더가 캐시를 공유할 수 있도록 합니다.

  • <silent> (boolean) - 에러가 아닌 메시지를 숨길지 여부. 기본값: false.

반환

(function) 스니펫 로더.

사용법

-- 언어 패턴 조정
local latex_patterns = { 'latex/**/*.json', '**/latex.json' }
local lang_patterns = {
  tex = latex_patterns, plaintex = latex_patterns,

gen_loader.from_runtime()

MiniSnippets.gen_loader.from_runtime({pattern}, {opts})

런타임 로더 생성

’runtimepath’의 “snippets/” 디렉토리 내부에서 pattern과 매칭되는 파일을 로드합니다. 이는 서로 다른 소스에서 유사하게 명명된 여러 파일을 동시에 읽는 데 유용합니다. ’runtimepath’의 순서가 유지됩니다.

일반적인 경우는 서로 다른 “snippets/” 디렉토리에 위치하지만 xxx.{json,lua}와 같이 이름이 같은 언어용 스니펫을 로드하는 것입니다.

  • <config>/snippets/lua.json - 사용자 설정에서 수동으로 큐레이션된 스니펫.

  • <path/to/installed/plugin>/snippets/lua.json - 설치된 플러그인에서 제공.

  • <config>/after/snippets/lua.json - 플러그인의 스니펫을 조정하는 데 사용. 예를 들어, 접두사를 사용하고 본문은 비워 일부 스니펫을 제거합니다.

매개변수

{pattern} (string) 읽을 파일의 패턴. nvim_get_runtime_file()에 설명된 대로 와일드카드를 가질 수 있습니다. “lua” 언어의 예시: 'lua.{json,lua}'.

{opts} (table|nil) 옵션. 가능한 필드:

  • <all> (boolean) - 매칭되는 모든 런타임 파일에서 로드할지 여부. 기본값: true.

  • <cache> (boolean) - 캐시된 출력을 사용할지 여부. 기본값: true. 참고: 캐싱은 pattern 값별로 수행되며, 이는 ‘runtimepath’ 값과 스니펫 파일이 Neovim 세션 동안 변경되지 않는다고 가정합니다. 이러한 방식의 캐싱은 모든 스니펫 확장 시 파일 시스템을 탐색할 필요를 줄여 성능을 크게 향상시킵니다.

  • <silent> (boolean) - 에러가 아닌 메시지를 숨길지 여부. 기본값: false.

반환

(function) 스니펫 로더.

default_prepare()

MiniSnippets.default_prepare({raw_snippets}, {opts})

기본 준비

제공된 컨텍스트를 기반으로 원시 스니펫(MiniSnippets.config의 snippets에서와 같이)을 정규화합니다:

  • 중첩된 배열을 순회하고 평탄화합니다. 함수 로더는 opts.context를 인수로 사용하여 실행되며 출력은 재귀적으로 처리됩니다.

  • 고유하고 비어 있지 않은 접두사를 보장합니다. 나중의 것이 이전의 것을 완전히 재정의합니다(ftplugin 및 유사한 런타임 설계 동작과 유사함). 빈 문자열 접두사는 모두 추가됩니다(매칭 없이 삽입할 수 있도록 함).

  • 필드 변환 및 유추:

    • 배열 prefix를 동일한 본문/설명을 가진 여러 스니펫으로 확장합니다. 없는 prefix를 빈 문자열로 유추합니다.

    • 배열 body를 "\n"으로 연결합니다. 동일한 접두사를 가진 이전에 추가된 스니펫을 제거하도록 하기 위해 없는 body를 유추하지 않습니다.

    • 배열 desc를 "\n"으로 연결합니다. description(호환성용) 또는 body 필드 순서대로 desc 필드를 유추합니다.

  • 출력을 접두사별로 정렬합니다.

MiniSnippets.gen_loader 항목과 달리 출력 캐싱은 없습니다. 이는 gen_loader 캐시의 데이터 복제를 방지하고 메모리 사용량을 줄입니다. 또한 모든 MiniSnippets.expand() 호출이 스니펫을 준비함을 의미하며, 이는 일반적으로 충분히 빠릅니다. 그렇지 않은 경우 수동 캐싱을 고려하세요:

local cache = {}
local prepare_cached = function(raw_snippets)
  local _, cont = MiniSnippets.default_prepare({})
  local id = 'buf=' .. cont.buf_id .. ',lang=' .. cont.lang
  if cache[id] then return unpack(vim.deepcopy(cache[id])) end
  local snippets = MiniSnippets.default_prepare(raw_snippets)
  cache[id] = vim.deepcopy({ snippets, cont })
  return snippets, cont
end

매개변수

{raw_snippets} (table) MiniSnippets.config의 스니펫 데이터 배열.

{opts} (table|nil) 옵션. 가능한 필드:

  • <context> (any) - 호출 가능한 스니펫 데이터의 인수로 사용되는 컨텍스트. 기본값: <buf_id>(현재 버퍼 식별자) 및 <lang>(로컬 언어) 필드가 있는 테이블. 언어는 커서 위치의 tree-sitter 파서에서 계산되며(주입된 언어에서 서로 다른 스니펫 허용), 그렇지 않으면 ’filetype’입니다.

반환

(...) 스니펫 배열 및 제공된 컨텍스트(제공된 것이 없으면 기본값).

default_match()

MiniSnippets.default_match({snippets}, {opts})

기본 매칭

커서 앞의 줄을 기반으로 스니펫을 매칭합니다.

두 가지 매칭 방식을 순차적으로 시도합니다:

  • 커서 왼쪽에서 정확한 스니펫 접두사(있는 경우이며 비어 있지 않음)를 찾습니다. 또한 pattern_exact_boundary와 매칭되는 바이트가 앞에 와야 합니다. 매칭되는 것이 있는 경우 가장 긴 접두사를 가진 것을 반환합니다.

  • opts.pattern_fuzzy를 통해 추출된 베이스(커서 왼쪽 텍스트)에 대해 스니펫 접두사를 퍼지로 매칭합니다. 매칭은 matchfuzzy()를 통해 수행됩니다. 베이스가 비어 있으면 모든 스니펫이 매칭됩니다. 모든 퍼지 매칭 결과를 반환합니다.

매개변수

{snippets} (table) 매칭할 수 있는 스니펫 배열.

{opts} (table|nil) 옵션. 가능한 필드:

  • <pattern_exact_boundary> (string) - 정확한 매칭을 수용하기 위해 그 왼쪽 바이트에 대한 Lua 패턴입니다. 줄 시작은 빈 문자열과 매칭됩니다. 경계로 허용하려면 ? 양정자를 사용하세요. 기본값: [%s%p]? (공백 및 구두점만을 경계로 수용하고 줄 시작에서의 매칭 허용). 예시: 접두사 “l”은 l, _l, x l 줄에서 매칭되지만, 1l, ll에서는 매칭되지 않습니다.

  • <pattern_fuzzy> (string) - 퍼지 매칭을 위해 커서 왼쪽에서 베이스를 추출하는 Lua 패턴입니다. 이 단계를 건너뛰려면 빈 문자열을 제공하세요. 기본값: '%S*' (가능한 많은 공백이 아닌 문자, 빈 문자열 허용).

반환

(table) 최선에서 최악 순으로 정렬된 매칭된 스니펫 배열.

사용법

-- 모든 정확한 매칭 수용
MiniSnippets.default_match(snippets, { pattern_exact_boundary = '.?' })

-- 영숫자만을 기반으로 퍼지 매칭 수행
MiniSnippets.default_match(snippets, { pattern_fuzzy = '%w*' })

default_select()

MiniSnippets.default_select({snippets}, {insert}, {opts})

기본 선택

스니펫을 vim.ui.select() 항목으로 표시하고 선택한 것을 삽입합니다. 최상의 대화식 경험을 위해 vim.ui.select()가 Insert 모드에서 작동해야 합니다(적절하게 호출되고 선택 후 Insert 모드를 복원해야 함). 이는 최소한 MiniPick.ui_select() 및 Neovim 기본값의 경우입니다.

매개변수

{snippets} (table) 스니펫 배열 (config.expand.match의 출력).

{insert} (function|nil) 선택한 스니펫을 삽입하는 함수(유일한 인수로 전달됨). 스니펫의 매칭 영역(필드로 존재하는 경우)을 제거하고 Insert 모드에서 적절한 커서 위치를 보장할 것으로 예상됩니다. 기본값: MiniSnippets.default_insert().

{opts} (table|nil) 옵션. 가능한 필드:

  • <insert_single> (boolean) - 항목이 하나뿐인 snippets에 대해 vim.ui.select()를 건너뛰고 직접 삽입할지 여부. 기본값: true.

default_insert()

MiniSnippets.default_insert({snippet}, {opts})

기본 삽입

스니펫 삽입을 준비하고 수행합니다:

  • Insert 모드를 보장합니다.

  • 스니펫의 매칭 영역(<region> 필드로 존재하는 경우)을 삭제합니다. 커서를 보장합니다.

  • normalize를 활성화하여 MiniSnippets.parse()로 스니펫 본문을 파싱합니다. 특히, 변수를 평가하고, 마지막 노드의 존재를 확인하며, 동일한 탭스톱을 가진 노드들에 대해 동일한 텍스트를 보장합니다. 불가능한 경우 중지합니다.

  • 커서 위치에 스니펫 삽입:

    • 스니펫의 텍스트를 추가합니다. 줄은 “”에서 나뉩니다. 현재 줄의 들여쓰기와 왼쪽 주석 리더(‘commentstring’ 및 ‘comments’에서 유추됨)가 다음 줄에서 반복됩니다. 탭(“)은 ’expandtab’ 및 ’shiftwidth’에 따라 확장됩니다.

    • 실행 가능한 탭스톱(마지막이 아님)이 있는 경우 스니펫 세션을 시작합니다.

세션 생명 주기

MiniSnippets-session

  • 첫 번째 탭스톱에서 커서를 두고 시작합니다. 연결된 탭스톱이 있는 경우 참조 노드(MiniSnippets-glossary 참조)의 시작 부분에 커서가 위치합니다. 모든 탭스톱은 전용 하이라이트 그룹(mini.snippets의 “하이라이트 그룹” 섹션 참조)으로 시각화됩니다. 빈 탭스톱은 인라인 가상 텍스트(일반/마지막 탭스톱의 경우 “•”/“∎”)로 시각화됩니다. 이는 버퍼의 실제 텍스트가 아니며 세션이 중지된 후에 제거됨을 의미합니다.

  • 플레이스홀더를 대체할지 여부를 결정합니다. 그렇지 않은 경우 다음 또는 이전 탭스톱으로 점프합니다. 대체하려는 경우 편집합니다: 새 텍스트를 추가하거나 이미 추가된 텍스트를 삭제합니다. 이 과정에서 연결된 모든 탭스톱(있는 경우)에서 여러 가지 일이 발생합니다:

    • 첫 번째 문자가 입력된 후 플레이스홀더가 제거되고 하이라이팅이 MiniSnippetsCurrentReplace에서 MiniSnippetsCurrent로 변경됩니다.

    • 모든 탭스톱 노드의 텍스트가 참조 노드와 동기화됩니다. 참조 탭스톱 텍스트의 상대적 들여쓰기가 유지됩니다: 연결된 탭스톱의 첫 번째 줄을 제외한 모든 줄이 첫 번째 줄 들여쓰기를 기준으로 다시 들여쓰기됩니다. 참고: 텍스트 동기화는 (성능을 위해) 현재 탭스톱에 대해서만 강제됩니다.

  • MiniSnippets.config mappings에서 조정할 수 있는 <C-l> / <C-h>를 사용하여 다음 / 이전 탭스톱으로 점프합니다. 점프에 대한 자세한 내용은 MiniSnippets.session.jump()를 참조하세요.

  • 탭스톱에 선택지가 있는 경우 매 점프 및 탭스톱 텍스트 삭제 후 모든 선택지가 표시됩니다. 이는 complete()로 수행되므로 <C-n> / <C-p>를 사용하여 다음 / 이전 선택지를 선택하세요. 텍스트를 입력하여 목록을 좁힙니다. ‘completeopt’ 옵션에 menuone 및 noselect 플래그가 포함되어 있을 때 가장 잘 작동합니다. 참고: 문자를 삭제하면 complete()가 작동하는 방식 때문에 목록이 숨겨집니다. 전체 목록이 다시 나타나게 하려면 전체 탭스톱 텍스트를 삭제하세요(예: 하나 이상의 i_CTRL-W 사용).

  • 활성 세션이 있는 동안 스니펫을 확장하여 다른 세션을 중첩하는 것이 허용됩니다(다른 버퍼에서도 가능). 스니펫에 실행 가능한 탭스톱이 없으면 텍스트가 삽입되기만 합니다. 그렇지 않으면 중첩된 세션을 시작합니다:

    • 현재 세션을 일시 중지합니다: 하이라이트를 숨기고 텍스트 변경 추적을 유지합니다.

    • 새 세션을 시작하고 그것이 유일한 세션인 것처럼 동작합니다(편집/점프/중첩).

    • 준비가 되면(더 중첩된 세션 이후일 수도 있음) 세션을 중지합니다. 그러면 이전 세션이 재개됩니다: 현재 탭스톱에 대해 텍스트를 동기화하고 하이라이트를 표시합니다. 세션을 재개한 후에만 텍스트 동기화가 이루어지는 경험은 visual-block 모드에서의 편집 방식과 유사합니다. 더 매끄러운 자동 세션 중지를 위해 다른 것(커서/모드/버퍼 등)은 변경되지 않습니다.

    더 일반적인 “단일 세션으로 병합” 방식보다 “세션 스택” 방식을 선택한 이유에 대한 참고 사항:

    • 하이라이트로 과부하를 주지 않습니다.

    • 서로 다른 버퍼에서 중첩된 세션을 허용합니다.

    • 한 세션을 다른 세션에 주입하는 복잡한 로직이 필요하지 않습니다.

  • 편집/점프/중첩 단계를 원하는 만큼 반복합니다.

  • 중지. 두 가지 방법으로 수행할 수 있습니다:

    • <C-c>를 누르거나 MiniSnippets.session.stop()을 호출하여 수동으로 수행합니다. 정확한 키는 MiniSnippets.config mappings에서 조정할 수 있습니다.

    • 자동으로: 마지막 탭스톱($0)이 현재인 경우 텍스트 편집을 수행하거나 Normal 모드로 전환하면 세션이 중지됩니다. 삽입 후 존재가 보장됩니다. 마지막 모드로 점프한 후 즉시 세션을 중지하지 않는 것은(대부분의 다른 스니펫 플러그인이 하는 방식) 나중에 발견한 오타를 고치기 위해 다른 탭스톱으로 되돌아갈 수 있게 하기 위함입니다. 점프 중에 가장자리를 순환하는 것도 도움이 됩니다. 현재 탭스톱이 마지막이 아닌 경우 스니펫 범위를 벗어난(또는 조심스럽게 내부에서) 빠른 편집을 위해 Normal 모드로 나가는 것은 괜찮습니다. 나중에 다시 Insert 모드로 들어가 다음 탭스톱으로 점프하거나 수동으로 세션을 중지하세요. 사용자 정의 중지 규칙을 설정하는 방법은 MiniSnippets-examples를 참조하세요.

활성/중첩된 세션에 대한 데이터를 가져오려면 MiniSnippets.session.get()을 사용하세요. 매핑에서는 MiniSnippets.session.jump() / MiniSnippets.session.stop()을 사용하세요.

허용되지만 공식적으로 지원/권장되지 않는 사항:

  • 스니펫 범위 내에서 세션 생명 주기 밖에서의 텍스트 편집. 대부분 예상대로 동작하지만 추적 메타데이터(extmarks)를 손상시킬 수 있습니다. 일반적으로 탭스톱 범위를 삭제하는 것 외에는 괜찮을 것입니다. 현재 탭스톱의 텍스트 동기화는 여전히 활성 상태입니다.

매개변수

{all} (boolean|nil) 전체 세션 스택과 함께 배열을 반환할지 여부. 기본값: false.

반환

(table) 세션 데이터가 포함된 단일 테이블(all이 false인 경우) 또는 그 배열. 세션 데이터는 다음 필드를 포함합니다:

  • <buf_id> (number) - 세션 버퍼의 식별자.

  • <cur_tabstop> (string) - 세션의 현재 탭스톱 식별자.

  • <extmark_id> (number) - 세션 범위를 추적하는 extmark 식별자.

  • <insert_args> (table) - 세션을 생성하는 데 사용된 MiniSnippets.default_insert() 인수. <snippet> 및 <opts> 필드가 있는 테이블입니다.

  • <nodes> (table) - 세션 동안 최신 상태로 유지되는 파싱된 스니펫 노드 배열. 정규화된 MiniSnippets.parse() 출력 구조를 가지며, 모든 노드는 현재 노드 상태에 대한 데이터를 가져오는 데 사용할 수 있는 extmark 식별자가 있는 extmark_id 필드를 포함합니다.

  • <ns_id> (number) - 모든 세션의 extmark에 대한 네임스페이스 식별자.

  • <tabstops> (table) - 세션의 탭스톱에 대한 데이터. 필드는 문자열 탭스톱 식별자이며 값은 다음 필드를 가진 테이블입니다:

    • <is_visited> (boolean) - 탭스톱 방문 여부.

    • <next> (string) - 다음 탭스톱 식별자.

    • <prev> (string) - 이전 탭스톱 식별자.

다음/이전 탭스톱으로 점프

다음/이전 탭스톱을 현재로 만듭니다. 다음 단계를 실행합니다:

  • 현재 탭스톱을 방문한 것으로 표시합니다.

  • 탭스톱이 숫자로 정렬되어 있다고 가정하고 다음/이전 탭스톱 ID를 찾습니다. 탭스톱 “0”은 항상 마지막입니다. 검색은 가장자리에서 순환합니다: 첫 번째와 마지막 탭스톱은 서로 다음/이전입니다.

  • 대상 탭스톱에 포커스:

    • 세션 버퍼가 현재인지 확인합니다.

    • 영향을 받는 노드의 하이라이팅을 조정합니다.

    • 탭스톱의 참조 노드(연결된 노드 중 첫 번째 노드)에 커서를 둡니다. 탭스톱이 아직 편집되지 않은 경우 커서는 왼쪽 가장자리에 위치하여(텍스트 입력 시 플레이스홀더 대체), 편집된 경우에는 오른쪽 가장자리에 위치합니다(이미 편집된 텍스트 업데이트).

    • 선택지가 있는 탭스톱에 대해 모든 선택지를 표시합니다. 선택지를 탐색하면 탭스톱의 텍스트가 업데이트됩니다.

매개변수

{direction} (string) “next” 또는 “prev” 중 하나.

parse()

MiniSnippets.parse({snippet_body}, {opts})

스니펫 파싱

매개변수

{snippet_body} (string|table) 문자열 또는 문자열 배열 형식의 스니펫 본문. MiniSnippets-syntax-specification을 따라야 합니다.

{opts} (table|nil) 옵션. 가능한 필드:

  • <normalize> (boolean) - 노드 정규화 여부:

    • 변수 노드를 평가하고 출력을 text 필드로 추가합니다. 변수가 설정되지 않은 경우 text 필드는 nil입니다. opts.lookup의 값이 평가 출력보다 우선됩니다. 변수에 대한 자세한 정보는 MiniSnippets-syntax-specification을 참조하세요.

    • opts.lookup에 존재하는 탭스톱에 대해 text 필드를 추가합니다.

    • 모든 노드가 text 또는 placeholder 필드 중 정확히 하나를 포함하도록 보장합니다. 아무것도 없으면 기본 placeholder(첫 번째 선택지 또는 빈 문자열을 가진 하나의 텍스트 노드)를 추가합니다. 둘 다 있으면 placeholder 필드를 제거합니다.

    • 마지막 탭스톱의 존재를 보장합니다: 없으면 끝에 추가합니다.

    • 동일한 탭스톱을 가진 노드들이 동일한 플레이스홀더를 가지도록 보장합니다. 첫 번째 노드의 것을 사용합니다. 기본값: false.

  • <lookup> (table) - 변수/탭스톱(문자열) 이름에서 해당 값으로의 맵. 기본값: {}.

반환

(table) 노드 배열. 노드는 유형에 따라 다음 필드를 가진 테이블입니다:

  • 텍스트 노드:

    • <text> (string) - 노드의 텍스트.

  • 탭스톱 노드:

    • <tabstop> (string) - 탭스톱 식별자.

    • <text> (string|nil) - 탭스톱 값 (<lookup>에 존재하는 경우).

    • <placeholder> (table|nil) - 플레이스홀더로 사용될 노드 배열.

    • <choices> (table|nil) - 문자열 선택지 배열.

    • <transform> (table|nil) - 변환 문자열 부분의 배열.

  • 변수 노드:

    • <var> (string) - 변수 이름.

    • <text> (string|nil) - 변수 값.

    • <placeholder> (table|nil) - 플레이스홀더로 사용될 노드 배열.

    • <transform> (table|nil) - 변환 문자열 부분의 배열.

start_lsp_server()

MiniSnippets.start_lsp_server({opts})

완성 LSP 서버 시작

이는 (특히 mini.completion 등의) (자동)완성 엔진에서 스니펫을 표시할 목적으로 LSP 서버를 시작(vim.lsp.start())합니다. 서버는 다음을 수행합니다:

  • 커서 위치에서 스니펫을 준비하고 매칭(MiniSnippets.expand()를 통해)하는 textDocument/completion 메서드만 구현합니다.

  • 기본적으로 로드된 모든 버퍼에 자동 첨부됩니다.

매개변수

{opts} (table|nil) 옵션. 가능한 필드:

  • <before_attach> (function) - 버퍼에 첨부하기 전에 실행되는 함수. 버퍼 ID를 인수로 받으며, 버퍼에 첨부하는 것을 취소하려면 false(nil 아님)를 반환할 수 있습니다. 기본값: 로드된 일반 버퍼에 첨부합니다.

  • <match> (false|function) - 완성 후보를 계산할 때 MiniSnippets.expand()로 전달되는 opts.match 값입니다. 커서 위치에서 매칭을 수행하지 않고 커서 컨텍스트에서 사용 가능한 모든 스니펫을 반환하며 완성 엔진이 항목을 매칭하고 정렬하도록 하려면 false를 제공하세요. 기본값: nil (MiniSnippets.default_match()와 동일함).

  • <server_config> (table) - vim.lsp.start()의 첫 번째 인수에 대한 베이스로 사용될 서버 설정입니다(cmd는 재정의됨). 기본값: {}.

  • <triggers> (table) - completionProvider.triggerCharacters 서버 기능으로 사용될 트리거 문자 배열입니다. 기본값: {}.

반환

(integer|nil) 시작된 LSP 서버의 식별자.
