모듈

기능:

  • 모든 배열에서 요소를 선택할 수 있는 단일 윈도우 범용 인터페이스입니다.

  • 필요에 따라 프리뷰 및 정보 뷰를 토글할 수 있습니다.

  • 퍼지 매칭(fuzzy matching)을 수행하고 다른 모드(MiniPick.default_match())를 허용하는, 빠르고 논블로킹(non-blocking)인 대화형 쿼리 매칭(필터+정렬)을 지원합니다.

  • 내장 픽커(MiniPick.builtin 참고):

    • 파일.

    • 패턴 매치(고정 패턴 또는 라이브 피드백; 둘 다 glob 패턴을 통한 파일 필터링 허용).

    • 버퍼.

    • 도움말 태그(Help tags).

    • CLI 출력.

    • 최근 픽커 재개(Resume).

  • 확장 가능한 MiniPick.registry를 사용하는 :Pick 명령을 제공합니다.

  • vim.ui.select() 구현을 제공합니다. 이를 조정하려면 MiniPick.ui_select()를 사용하거나, MiniPick.setup() 호출 후 수동으로 vim.ui.select를 저장/복원하십시오.

  • 픽커 활성화 시 사용할 수 있는 풍부하고 맞춤 설정 가능한 내장 MiniPick-actions:

    • 현재 포커스된 항목 수동 변경.

    • 수직 및 수평 스크롤.

    • 프리뷰 또는 정보 뷰 토글.

    • 나중에 선택할 항목 표시/해제(Mark/unmark).

    • 현재 매치 결과 정제(Refine, 새 픽커의 일부로 만듦).

    • 그 외 다수.

  • 다음을 포함하는 최소한의 유연한 MiniPick-source 사양:

    • 항목(배열, 콜러블, 또는 나중에 수동으로 설정).

    • 소스 이름.

    • 작업 디렉터리(CWD).

    • 매칭 알고리즘.

    • 메인 윈도우에 매치 결과가 표시되는 방식.

    • 항목 프리뷰.

    • 현재 및 표시된 항목에 대한 “선택 시(On choice)” 액션.

  • 사용자 정의 액션/키를 전역, 버퍼별 또는 픽커별로 구성할 수 있습니다.

  • ‘ignorecase’ 및 ’smartcase’를 즉시 지원합니다.

  • 반복되는 프롬프트에서 응답성을 높이기 위한 매치 캐싱을 지원합니다.

참고:

  • 모든 지원 버전에서 작동하지만, Neovim>=0.10에서는 플로팅 윈도우 하단(footer)에 더 많은 시각적 피드백을 제공합니다.

  • 더 많은 픽커는 MiniExtra.pickers를 참고하십시오.

의존성

권장 의존성 (추가 기능을 제공하며, 없어도 작동합니다):

  • 실제 경로 항목 근처에 아이콘을 표시하려면 mini.icons 모듈을 활성화하십시오. 활성화되어 있지 않으면 ‘nvim-tree/nvim-web-devicons’ 플러그인을 사용하거나 아이콘을 표시하지 않습니다.

  • MiniPick-cli-tools MiniPick.builtin.files(), MiniPick.builtin.grep(), MiniPick.builtin.grep_live() 내장 픽커를 지원하는 CLI 도구:

    • rg (github.com/BurntSushi/ripgrep; 세 가지 모두에 충분하며 권장됨).

    • fd (github.com/sharkdp/fd; files에만 해당).

    • git (github.com/git/git; 세 가지 모두에 충분함).

    참고: CLI 도구는 항목을 가져오는 데 필요한 기본 인자만 사용하여 호출됩니다. 출력을 맞춤 설정하려면 각 도구의 구성 방식을 사용하십시오. 시작할 수 있는 몇 가지 예시는 다음과 같습니다:

    • github.com/BurntSushi/ripgrep/blob/master/GUIDE.md#configuration-file

    • github.com/sharkdp/fd#excluding-specific-files-or-directories

    • git-scm.com/docs/gitignore

설정

이 모듈은 require('mini.pick').setup({})을 통한 설정이 필요합니다({}를 사용자 config 테이블로 교체). 이를 통해 스크립팅이나 수동 작업(예: :lua MiniPick.*) 시 사용할 수 있는 전역 Lua 테이블 MiniPick이 생성됩니다.

사용 가능한 구성 설정은 MiniPick.config를 참고하십시오.

MiniPick.config와 동일한 구조를 가진 vim.b.minipick_config를 사용하여 버퍼별로 런타임 구성을 재정의할 수 있습니다. 자세한 내용은 mini.nvim-buffer-local-config를 참고하십시오.

비교

  • nvim-telescope/telescope.nvim:

    • 이 모듈의 주요 영감 원천이므로 상당 부분 중복됩니다.

    • prompt, matches, preview의 3개(또는 2개) 윈도우 UI를 가진 반면, 이 모듈은 모든 것을 하나의 윈도우에 결합합니다. 이를 통해 특이한 시나리오에서도 더 직관적인 맞춤 설정이 가능합니다.

    • 기본 매치 알고리즘이 다소 느린 편인 반면, 이 모듈은 최소 10만 개 이상의 항목에 대해서도 지연 없는 매칭을 제공합니다.

    • 수많은 내장 픽커를 가지고 있는 반면, 이 모듈은 핵심적인 몇 가지만 제공하며 나머지는 다른 ‘mini.nvim’ 모듈에 의존합니다(mini.extra 참고).

  • ibhagwan/fzf-lua:

    • ’nvim-telescope/telescope.nvim’과의 비교와 대부분 유사합니다.

    • 퍼지 매칭을 위해 junegunn/fzf 설치가 필요한 반면, 이 모듈은 내장 Lua 매칭을 제공합니다.

이벤트

사용자 맞춤 설정 및 외부 도구와의 통합을 위해, 일반적인 상황에서 특정 User 자동 명령(autocommand) 이벤트가 트리거됩니다:

  • MiniPickMatch - 쿼리 매치를 업데이트하거나 항목을 설정한 직후.

  • MiniPickStart - 픽커가 시작된 직후.

  • MiniPickStop - 픽커가 중지되기 직전.

개요

일반적인 개념은 객체 배열을 가져와 대화형 필터/정렬/탐색/프리뷰와 함께 표시하고, 하나 이상의 항목을 선택할 수 있게 하는 것입니다.

픽커 시작 방법

  • MiniPick-source를 정의하는 opts.source와 함께 MiniPick.start()를 사용합니다. 예시: MiniPick.start({ source = { items = vim.fn.readdir('.') } })

  • MiniPick.builtin 픽커 중 하나를 직접 사용합니다. 예시: MiniPick.builtin.files({ tool = 'git' })

  • MiniPick.registry의 맞춤형 픽커를 사용하는 :Pick 명령을 사용합니다. 예시: :Pick files tool='git'

사용자 인터페이스

UI는 세 가지 다른 뷰를 표시할 수 있는 단일 윈도우로 구성됩니다:

  • “Main” - 현재 쿼리 매치가 표시되는 곳입니다.

  • “Preview” - 현재 항목의 프리뷰입니다(<Tab>으로 토글).

  • “Info” - 픽커 및 상태에 대한 일반 정보입니다(<S-Tab>으로 토글).

현재 프롬프트는 윈도우 테두리 왼쪽 상단에 표시되며, 캐럿(현재 입력 위치)은 수직선으로 나타납니다.

윈도우 테두리 하단(Neovim>=0.10)에는 추가적인 시각적 피드백이 표시됩니다:

  • 왼쪽은 픽커 이름입니다.

  • 오른쪽은 다음 형식의 정보를 포함합니다:

    <매치 결과 중 현재 인덱스> | <매치 총합> | <표시된 수> / <전체 수>

픽커가 바쁠 때(아직 항목이 설정되지 않았거나 매칭이 진행 중인 경우), config.delay.busy 밀리초의 유휴 시간 후 윈도우 테두리 색상이 MiniPickBorderBusy로 변경됩니다.

수명 주기

  • 문자를 입력하여 매치 결과를 필터링하고 정렬합니다. 눌린 문자 배열인 query와 함께 MiniPick.default_match()를 사용합니다. 매칭 방식 개요:

    • 쿼리가 '로 시작하면 정확히 일치(exact match)하는 항목을 찾습니다.

    • 쿼리가 ^로 시작하면 시작 부분이 정확히 일치하는 항목을 찾습니다.

    • 쿼리가 $로 끝나면 끝 부분이 정확히 일치하는 항목을 찾습니다.

    • 쿼리가 *로 시작하면 퍼지 매칭(fuzzy matching)을 강제합니다.

    • 그 외의 경우 퍼지 매칭을 수행합니다.

    • 정렬은 먼저 매치 너비(width)를 최소화한 다음 매치 시작 위치를 기준으로 수행됩니다. 문자열의 특정 위치를 선호하는 등의 추가 로직은 없습니다.

  • 특수 키를 입력하여 MiniPick-actions를 수행합니다. 기본적인 것들은 다음과 같습니다:

    • <C-n> / <Down>은 아래로, <C-p> / <Up>은 위로 이동합니다.

    • <Left> / <Right>는 프롬프트 캐럿을 왼쪽/오른쪽으로 이동합니다.

    • <S-Tab>은 사용 가능한 모든 매핑이 포함된 정보 창을 토글합니다.

    • <Tab>은 프리뷰를 토글합니다.

    • <C-x> / <C-a>는 현재 / 모든 항목의 표시(mark) 상태를 토글합니다.

    • <C-Space> / <M-Space>는 모든 매치 결과 또는 표시된 항목으로 새 픽커를 만듭니다.

    • <CR> / <M-CR>은 현재/표시된 항목을 선택합니다.

    • <Esc> / <C-c>는 픽커를 중지합니다.

구현 세부 사항

  • 키 입력 처리는 부수 효과 제어를 위해 전용 키 쿼리 프로세스를 통해 수행됩니다. 결과적으로 일반 매핑은 여기서 작동하지 않으며, 픽커 창이 표시되는 동안에는 해당 창이 현재 창이어야 합니다. 창 포커스를 변경하면 짧은 지연 후 픽커가 자동으로 중지됩니다. 픽커와 관련 없는 화면 변경에는 명시적인 :redraw가 필요합니다.

  • 모든 픽커는 논블로킹(non-blocking)이지만 선택된 항목을 반환하기 위해 대기합니다. 예시: file = MiniPick.builtin.files()는 픽커가 표시되는 동안 다른 액션을 실행할 수 있게 하면서도, file에 선택된 항목의 값을 할당합니다.

소스

소스(Source)는 다음 중 하나의 source 필드 내에 정의됩니다(우선순위 오름차순):

  • MiniPick.config - 전역적으로 적용됩니다.

  • vim.b.minipick_config - 버퍼별로 적용됩니다.

  • 픽커 호출 시의 opts.source - 해당 호출에만 적용됩니다.

arglist에서 선택하는 소스 예시:

{ items = vim.fn.argv, name = 'Arglist' }

참고: 이는 주로 픽커를 작성할 때 유용합니다. 제공된 픽커만 사용하려는 경우 건너뛰어도 무방합니다.

항목

MiniPick-source.items

source.items는 선택할 항목을 정의합니다. 다음 중 하나여야 합니다:

  • 다양한 타입을 가질 수 있는 객체 배열. 모든 타입이 허용됩니다.

  • nil. 픽커는 명시적인 MiniPick.set_picker_items() 호출을 기다립니다.

  • 이전 타입 중 하나를 반환하는 콜러블. 시작 시 소스의 cwd가 현재 디렉터리로 설정된 상태에서 한 번 호출됩니다.

MiniPick-source.items-stritems 매칭은 요소의 문자열 표현(여기서는 “stritems”라고 함)을 기반으로 항목 배열에 대해 수행됩니다. 단일 항목에 대해 다음과 같이 계산됩니다:

  • 콜러블이 한 번 호출되고 그 출력이 다음 단계에서 사용됩니다.

  • 문자열 항목은 그대로 사용됩니다.

  • 테이블 항목의 문자열 <text> 필드가 사용됩니다(존재하는 경우).

  • vim.inspect()의 출력을 사용합니다.

예시:

items = { 'aaa.txt', { text = 'bbb' }, function() return 'ccc' end }
-- 해당 stritems는 { 'aaa.txt', 'bbb', 'ccc' }입니다.

기본값은 nil이며, 호출자가 항상 공급하는 것으로 가정합니다.

MiniPick-source.items-common 일반적인 항목 타입이 MiniPick.default_show(), MiniPick.default_preview(), MiniPick.default_choose(), MiniPick.default_choose_marked()와 즉시 연동되도록 하기 위한 몇 가지 권장 사항이 있습니다:

  • 경로 (파일 또는 디렉터리). 문자열 또는 테이블의 path 필드를 사용하십시오. 경로는 절대 경로이거나 source.cwd에 대한 상대 경로일 수 있으며, 일반적인 URI 형식(테이블 필드로 공급되는 경우에만)을 가질 수 있습니다. 예시: 'aaa.txt', { path = 'aaa.txt' }

  • 버퍼. 버퍼 ID를 숫자, 문자열 또는 테이블의 bufnr / buf_id / buf 필드(어떤 이름이든 허용됨)로 사용하십시오. 예시: 1, '1', { bufnr = 1 }, { buf_id = 1 }, { buf = 1 }

  • 파일 또는 버퍼의 줄. 줄 번호를 가진 lnum 필드(1부터 시작)가 포함된 테이블 표현 또는 “<path>\0<line>” 형식의 문자열을 사용하십시오(\0은 실제 null 문자입니다. 슬래시를 이스케이프하지 마십시오. \000이어야 할 수도 있습니다). 예시:

    { path = 'aaa.txt', lnum = 2 }, 'aaa.txt\0002', { bufnr = 1, lnum = 3 }

  • 파일 또는 버퍼의 위치. 줄 및 열 번호를 가진 lnum 및 col 필드(1부터 시작)가 포함된 테이블 표현 또는 “<path>\0<line>\0<col>” 형식의 문자열을 사용하십시오(\0은 실제 null 문자입니다. 슬래시를 이스케이프하지 마십시오. \000이어야 할 수도 있습니다). 예시:

    { path = 'aaa.txt', lnum = 2, col = 3 }, 'aaa.txt\0' .. '2\0003',
{ bufnr = 1, lnum = 3, col = 4 }

  • 파일 또는 버퍼의 영역. 시작 및 끝 줄/열을 위해 lnum, col, end_lnum, end_col 필드가 포함된 테이블 표현을 사용하십시오. 모든 숫자는 1부터 시작하며, 끝 줄은 포함(inclusive)되고 끝 열은 제외(exclusive)됩니다. 이 명명법은 getqflist() 및 diagnostic-structure와 유사합니다. 예시:

    { path = 'aaa.txt', lnum = 2, col = 3, end_lnum = 4, end_col = 5 },
{ bufnr = 1, lnum = 3, col = 4, end_lnum = 5, end_col = 6 }

참고: 모든 테이블 항목은 더 나은 매칭을 위해 text 필드를 가지는 것이 좋습니다.

이름

MiniPick-source.name

source.name은 시각적 피드백에 사용될 픽커의 이름을 정의합니다.

기본값은 “”입니다.

현재 작업 디렉터리

MiniPick-source.cwd

source.cwd는 픽커가 작동하는 현재 작업 디렉터리를 정의하는 문자열입니다. 실제로 존재하는 유효한 디렉터리 경로를 가리켜야 합니다. 이는 상대 경로를 사용하는 일관된 방식을 허용하기 위한 소스의 일부로, 즉 픽커 시작 후 현재 디렉터리가 일정하게 유지되는지에 의존하지 않게 합니다. 또한 MiniPick.builtin.resume() 픽커를 더 견고하게 만듭니다.

픽커의 메인 윈도우의 로컬 현재 디렉터리 (:lcd)로 설정되어 “윈도우 내” 함수(선택/프리뷰/사용자 정의 등)를 위한 코드를 더 간단하게 작성할 수 있게 합니다.

기본값은 현재 디렉터리입니다.

매치

MiniPick-source.match

source.match는 쿼리를 기반으로 stritems(MiniPick-source.items-stritems 참고)가 매칭(필터링 및 정렬)되는 방식을 정의하는 콜러블입니다.

다음 인자와 함께 호출됩니다:

  • stritems - 현재 픽커에서 사용 가능한 모든 stritems입니다.

  • inds - 보통 현재 매치 결과를 가리키는 stritems 인덱스 배열입니다. 쿼리 끝에 문자를 대화형으로 추가하는 경우 현재 매치 결과를 가리킵니다. 더 큰 쿼리에 대한 매치 결과는 이전 매치 결과의 하위 집합이라고 가정합니다(구현 시 이를 무시할 수 있습니다). 이는 더 적은 수의 stritems를 확인하여 성능을 높이는 데 활용될 수 있습니다.

  • query - 문자열 배열입니다. 보통 (사용자가 대화형으로 쿼리를 입력하는 일반적인 경우) 각 문자열은 하나의 문자를 나타냅니다. 그러나 MiniPick.set_picker_query()를 통해 쿼리를 설정할 수 있으므로 모든 문자열이 허용됩니다.

쿼리와 일치하는 stritems 요소의 인덱스 배열을 반환하거나(동기식), MiniPick.set_picker_match_inds()를 사용하여 명시적으로 설정해야 합니다(비동기식 가능).

참고:

  • 결과는 stritems 인덱스의 임의의 배열일 수 있으며, 반드시 입력 inds의 하위 집합일 필요는 없습니다.

  • stritems와 query 모두 ‘ignorecase’ 및 ‘smartcase’ 값에 의존합니다. 쿼리가 “대소문자 무시” 속성을 보여주면(‘ignorecase’만 설정되어 있거나 ’ignorecase’ / ’smartcase’가 모두 설정되어 있고 쿼리에 소문자만 있는 경우), stritems와 query는 소문자만 포함하게 됩니다. 이는 매치 함수 구현을 더 빠르고 단순하게 만들면서 대소문자를 구분하지 않는 매칭을 자동으로 지원하게 합니다.

  • 사용자 정의 source.match를 작성한다는 것은 보통 MiniPick-source.show도 변경해야 함을 의미하는데, 이는 stritems에서 실제로 쿼리와 일치하는 부분을 하이라이트하는 데 사용되기 때문입니다.

초기 순서를 유지하는 단순한 “정확한(exact)” match() 예시:

local match_exact = function(stritems, inds, query)
  local prompt_pattern = vim.pesc(table.concat(query))
  local f = function(i) return stritems[i]:find(prompt_pattern) ~= nil end
  return vim.tbl_filter(f, inds)
end
-- 논블로킹 버전은 `:h MiniPick.poke_is_picker_active()`를 참고하십시오.

기본값은 MiniPick.default_match()입니다.

표시

MiniPick-source.show

source.show는 매치된 항목이 윈도우에 표시되는 방식을 정의하는 콜러블입니다.

다음 인자와 함께 호출됩니다:

  • buf_id - 대상 버퍼의 식별자입니다.

  • items_to_show - 현재 윈도우 뷰에 맞도록 계산된, 현재 매치된 항목의 하위 집합입니다.

  • query - 문자열 배열입니다. source.match와 동일합니다.

items_to_show를 시각적으로 나타내기 위해 버퍼 buf_id를 업데이트해야 하며, 첫 번째 줄부터 한 줄에 한 항목씩 표시해야 합니다(options.content_from_bottom에 의존해서는 안 됩니다). 이는 stritem의 어느 부분이 실제로 쿼리와 일치하는지에 대한 시각화도 포함합니다.

예시 (문자열 항목 가정, 하이라이트 없음):

local show_prepend = function(buf_id, items_arr, query)
  local lines = vim.tbl_map(function(x) return 'Item: ' .. x end, items_arr)
  vim.api.nvim_buf_set_lines(buf_id, 0, -1, false, lines)
end

기본값은 MiniPick.default_show()입니다.

프리뷰

MiniPick-source.preview

source.preview는 항목 프리뷰가 수행되는 방식을 정의하는 콜러블입니다.

다음 인자와 함께 호출됩니다:

  • buf_id - 대상 버퍼의 식별자입니다. 참고: 각 항목 프리뷰 인스턴스에 대해 새로운 스크래치 버퍼가 생성됩니다.

  • item - 프리뷰할 항목입니다.

item을 시각적으로 나타내기 위해 버퍼 buf_id를 업데이트해야 합니다. 픽커의 메인 윈도우에 다른 버퍼를 직접 설정할 수도 있지만, 일반적으로 제공된 buf_id를 직접 업데이트하는 것이 더 견고합니다.

예시:

local preview_inspect = function(buf_id, item)
  local lines = vim.split(vim.inspect(item), '\n')
  vim.api.nvim_buf_set_lines(buf_id, 0, -1, false, lines)
end

기본값은 MiniPick.default_preview()입니다.

항목 선택

MiniPick-source.choose

source.choose는 항목을 선택했을 때 수행할 동작을 정의하는 콜러블입니다.

다음 인자와 함께 호출됩니다:

  • item - 선택된 항목입니다. 항상 nil이 아닙니다.

항목에 대해 의도된 “선택” 액션을 수행하고, 픽커의 계속 여부(즉, 중지하지 않음)를 나타내는 값을 반환해야 합니다: nil 및 false는 픽커를 중지하고, 그 외의 값은 계속합니다.

참고:

  • 픽커 창이 여전히 현재 창일 때 호출됩니다. 대상 창에 무언가를 하려면 MiniPick.get_picker_state() 출력의 windows.target 값을 사용하십시오.

예시:

local choose_file_continue = function(item)
  if vim.fn.filereadable(item) == 0 then return end
  vim.api.nvim_win_call(
    MiniPick.get_picker_state().windows.target,
    function() vim.cmd('edit ' .. item) end
  )
  return true
end

기본값은 MiniPick.default_choose()입니다.

표시된 항목 선택

MiniPick-source.choose_marked

source.choose_marked는 표시(mark)된 항목(MiniPick-actions-mark 참고)을 선택했을 때 수행할 동작을 정의하는 콜러블입니다. 여러 항목을 선택할 수 있는 source.choose의 보조 역할을 합니다.

다음 인자와 함께 호출됩니다:

  • items_marked - 표시된 항목 배열입니다. 비어있을 수 있습니다.

여러 항목에 대해 의도된 “선택” 액션을 수행하고, 픽커의 계속 여부(즉, 중지하지 않음)를 나타내는 값을 반환해야 합니다: nil 및 false는 픽커를 중지하고, 그 외의 값은 계속합니다.

참고:

  • 픽커 창이 여전히 현재 창일 때 호출됩니다. 대상 창에 무언가를 하려면 MiniPick.get_picker_state() 출력의 windows.target 값을 사용하십시오.

예시:

local choose_marked_print = function(items) print(vim.inspect(items)) end

기본값은 MiniPick.default_choose_marked()입니다.

액션

픽커가 활성화된 상태에서 mappings 테이블은 특정 액션을 실행할 특수 키 세트를 정의합니다. 이들은 두 가지 유형이 있습니다:

  • 내장(Built-in): 기본 config.mappings에 존재하는 액션입니다. 다른 키로만 재정의할 수 있습니다.

내장

캐럿

MiniPick-actions-caret

사용자는 쿼리 끝뿐만 아니라 캐럿 위치에서도 문자를 추가할 수 있습니다.

  • mappings.caret_left - 캐럿을 왼쪽으로 이동합니다.

  • mappings.caret_right - 캐럿을 오른쪽으로 이동합니다.

선택

MiniPick-actions-choose

선택(Choose)은 픽커 호출의 의도, 즉 항목을 선택하는 기능을 실제로 구현하는 핵심 액션입니다.

  • mappings.choose - 그대로 선택합니다. 즉, 현재 항목에 source.choose를 적용합니다.

  • mappings.choose_in_split - 대상 창에서 수평 분할을 수행하고, 대상 창을 새 분할 창으로 업데이트한 후 선택합니다.

  • mappings.choose_in_tabpage - choose_in_split과 동일하지만, 탭 페이지를 생성합니다.

  • mappings.choose_in_vsplit - choose_in_split과 동일하지만, 수직으로 분할합니다.

  • mappings.choose_marked - 표시된 항목을 그대로 선택합니다. 즉, 현재 표시된 항목에 source.choose_marked를 적용합니다.

삭제

MiniPick-actions-delete

삭제 액션은 쿼리에서 요소를 삭제하기 위한 것입니다.

  • mappings.delete_char - 왼쪽으로 한 문자를 삭제합니다.

  • mappings.delete_char_right - 오른쪽으로 한 문자를 삭제합니다.

  • mappings.delete_left - 왼쪽의 모든 내용을 삭제합니다(i_CTRL-U와 유사).

  • mappings.delete_word - 왼쪽의 단어를 삭제합니다(i_CTRL-W와 유사).

표시

MiniPick-actions-mark

표시(Marking)는 특정 항목을 별도의 리스트에 추가하는 액션으로, 나중에 mappings.choose_marked를 통해 선택할 수 있습니다(예: 퀵픽스 리스트로 보내기). 이는 오직 하나의 항목만 선택할 수 있는 일반적인 선택 기능의 보조 역할을 합니다.

  • mappings.mark - 현재 항목의 표시/미표시 상태를 토글합니다.

  • mappings.mark_all - 현재 매치된 모든 항목의 표시/미표시 상태를 토글합니다(모두 표시되어 있지 않으면 모두 표시하고, 그렇지 않으면 모두 해제함).

참고:

  • 표시는 쿼리와 매치 결과가 바뀌어도 유지됩니다. 예를 들어, 사용자가 여러 번의 쿼리를 통해 각 매치 결과를 모두 표시하면, 모든 쿼리에서 표시된 항목들이 보존됩니다.
이동

MiniPick-actions-move

이동은 포커스된 항목을 변경하는 핵심 액션입니다.

  • mappings.move_down - 포커스를 아래 항목으로 변경합니다.

  • mappings.move_start - 포커스를 현재 매치된 첫 번째 항목으로 변경합니다.

  • mappings.move_up - 포커스를 위 항목으로 변경합니다.

참고:

  • 위아래 이동은 끝에서 순환합니다: 마지막 항목에서 move_down은 첫 번째 항목으로, 첫 번째 항목에서 move_up은 마지막 항목으로 이동합니다.

  • 프리뷰나 정보 뷰가 표시된 상태에서 이동하면 뷰가 새 항목으로 업데이트됩니다.

  • 다음의 재정의 불가능한 대안 키도 작동합니다:

    • <Down>은 아래로 이동합니다.

    • <Home>은 첫 번째 매치 항목으로 이동합니다.

    • <Up>은 위로 이동합니다.

붙여넣기

MiniPick-actions-paste

붙여넣기는 레지스트리의 내용을 캐럿 위치에 붙여넣는 액션입니다.

  • mappings.paste - 다음 키 입력으로 정의된 레지스터의 내용을 붙여넣습니다.

참고:

  • 표현식 레지스터 =는 지원하지 않습니다.

  • 특수 레지스터 사례를 지원합니다: <C-f> (c_CTRL-R_CTRL-F와 동일), <C-w> (c_CTRL-R_CTRL-W와 동일), <C-a> (c_CTRL-R_CTRL-A와 동일), <C-l> (c_CTRL-R_CTRL-L과 동일).

정제

MiniPick-actions-refine

정제(Refine)는 기본적으로 다음을 실행하는 액션입니다:

  • 특정 항목들을 가져와 (현재 순서대로) 전체 항목으로 만듭니다.

  • 쿼리를 재설정합니다.

  • source.match를 설정의 기본값으로 업데이트합니다.

  • mappings.refine - 현재 매치된 항목들을 정제합니다.

  • mappings.refine_marked - 현재 표시된 항목들을 정제합니다.

이 액션은 적어도 다음 두 가지 경우에 유용합니다:

  • 연속적인 “좁히기” 쿼리를 수행합니다. 예시: 기본 매칭을 사용하여 “hello”와 “world”를 모두 포함하는(순서 상관없음) 항목을 찾으려면, “’hello”(앞에 “’” 주의)를 입력한 후 <C-Space>를 누르고 다시 “’world”를 입력하십시오.

  • match를 기본값으로 재설정합니다. 특히 MiniPick.builtin.grep_live() 및 “workspace_symbol_live” 범위를 가진 MiniExtra.pickers.lsp()에서 유용합니다.

스크롤

MiniPick-actions-scroll

스크롤은 현재 항목 포커스를 인접한 항목보다 더 멀리 이동하거나, 더 많은 정보를 보기 위해 창 뷰를 조정하는 액션입니다.

  • mappings.scroll_down - 매치 결과가 표시된 경우 표시된 매치 수만큼 아래로 이동합니다. 프리뷰 및 정보 뷰에서는 CTRL-F와 같이 아래로 스크롤합니다.

  • mappings.scroll_left - zH와 같이 왼쪽으로 스크롤합니다.

  • mappings.scroll_right - zL과 같이 오른쪽으로 스크롤합니다.

  • mappings.scroll_up - 매치 결과가 표시된 경우 표시된 매치 수만큼 위로 이동합니다. 프리뷰 및 정보 뷰에서는 CTRL-B와 같이 위로 스크롤합니다.

중지

MiniPick-actions-stop

mappings.stop은 픽커를 중지합니다. <C-c>도 항상 픽커를 중지합니다.

토글

MiniPick-actions-toggle

토글 액션은 뷰를 변경하는 방식입니다: 대상이 표시되지 않았으면 표시하고, 그렇지 않으면 메인 뷰로 재설정합니다.

  • mappings.toggle_info - 정보 뷰를 토글합니다.

  • mappings.toggle_preview - 프리뷰를 토글합니다.

참고:

  • 어떠한 방식으로든 쿼리를 업데이트하면 창 뷰가 매치 결과를 보여주도록 재설정됩니다.

  • 현재 항목 포커스를 이동해도 프리뷰 또는 정보 뷰는 업데이트된 항목과 함께 유지됩니다.

사용자 정의

MiniPick-actions-custom

내장 액션과 함께 사용자는 커스텀 액션을 정의할 수 있습니다. 이는 mappings 테이블에 커스텀 요소를 공급함으로써 가능합니다. 필드는 액션 이름(정보 뷰에서 액션 설명을 추론하는 데 사용됨)을 정의합니다. 값은 다음 필드를 가진 테이블입니다:

  • <char> (string) - 액션 트리거 역할을 하는 단일 문자입니다.

  • <func> (function) - 사용자가 <char>을 누른 후 인자 없이 실행될 콜러블입니다. 반환값은 “실행 후 픽커를 중지해야 하는지” 여부로 처리됩니다. 즉, 아무것도 반환하지 않거나 nil 또는 false를 반환하면 픽커를 계속하고, 그 외의 값(가급적 true)을 반환하면 중지합니다.

execute 커스텀 매핑 예시:

execute = {
  char = '<C-e>',
  func = function() vim.cmd(vim.fn.input('Execute: ')) end,
}

지연 시간

config.delay는 플러그인 지연 시간(ms 단위)을 정의합니다. 모두 양수여야 합니다.

delay.async는 비동기 동작을 강제하는 사이의 지연 시간입니다. 이는 보통 프리뷰에서 명시적으로 :redraw를 수행하고 (가시적인 비동기 하이라이트를 보장하기 위해 제한된 횟수만큼), MiniPick.poke_is_picker_active()를 사용하는 것(예를 들어 쿼리가 업데이트된 경우 현재 매칭을 중지하기 위해)을 의미합니다. 값이 작을수록 더 많은 계산 성능을 대가로 더 부드러운 사용자 경험을 제공합니다.

delay.busy는 특정 계산이 시작된 시점과 윈도우 테두리의 하이라이트 그룹을 MiniPickBorderBusy로 바꾸어 시각적 피드백을 제공하는 시점 사이의 지연 시간입니다. 값이 작을수록 피드백은 빨라지지만 깜박임처럼 느껴질 수 있습니다.

옵션

config.options는 몇 가지 범용 옵션을 포함합니다.

options.content_from_bottom은 내용을 아래에서 위로 표시할지를 나타내는 불리언 값입니다. 즉, 가장 잘 매치된 결과가 하단에 표시됩니다. 참고: 더 나은 경험을 위해서는 플로팅 윈도우 하단(footer) 기능이 있는 Neovim>=0.10을 사용하십시오. 기본값: false.

options.use_cache는 프롬프트(즉, 결합된 쿼리)별로 매치 결과를 캐싱할지를 나타내는 불리언 값입니다. 이는 메모리 사용량을 대가로 반복되는 프롬프트(예: 쿼리 항목 삭제 시)에서 더 빠른 응답을 제공합니다. 기본값: false.

config.source는 소스 사양에 대한 폴백(fallback)을 정의합니다. 예를 들어, 기본 match를 다른 구현으로 변경하거나, 일부 MiniPick.builtin 픽커에서 show가 아이콘을 표시하지 않도록 변경하는 데 사용할 수 있습니다(MiniPick-예시 참고). 자세한 정보는 MiniPick-소스를 참고하십시오.

기본 매치

대상 stritems를 필터링하여 쿼리를 포함하는지 확인하고 가장 좋은 매치부터 가장 나쁜 매치 순으로 정렬합니다.

MiniPick-source.match의 기본값을 구현합니다.

기본적으로(특수 모드가 적용되지 않는 경우) 다음과 같은 퍼지 매칭을 수행합니다:

  • stritem이 쿼리의 모든 요소를 동일한 순서로(반드시 연속될 필요는 없으며 사이에 다른 문자가 있을 수 있음) 포함하면 해당 쿼리를 포함하는 것으로 간주합니다. 참고: 빈 쿼리 및 빈 문자열 요소는 모든 문자열에 포함된 것으로 간주됩니다.

  • 정렬은 다음 순서에 따라 수행됩니다(mini.fuzzy와 동일):

    • 매치 너비(끝 열에서 시작 열을 뺀 값)가 작을수록 좋습니다.

    • 매치 너비가 같다면, 시작 열이 작을수록 좋습니다.

    • 매치 너비와 시작 열이 모두 같다면 초기 순서를 유지합니다.

참고:

  • 가장 일반적인 대화형 사용의 경우 query는 입력된 문자당 하나의 요소를 포함합니다.

특수 모드

  • 강제 모드:

    • 쿼리가 “*“로 시작하면 나머지를 퍼지 방식으로 매칭합니다 (다른 모드 없이).

    • 쿼리가 “’”로 시작하면 나머지를 정확히(중간에 다른 문자 없이) 매칭합니다.

  • 위치 모드:

    • 쿼리가 ’^’로 시작하면 시작 부분에서 정확히 일치하는지 확인합니다.

    • 쿼리가 ’$’로 끝나면 끝 부분에서 정확히 일치하는지 확인합니다.

    • 두 모드는 동시에 사용될 수 있습니다.

  • 그룹화됨: 쿼리에 하나 이상의 공백 요소가 포함된 경우입니다. 쿼리를 공백 인덱스에서 나누어 그 사이를 연결한 것과 같이 출력이 계산됩니다.

모드 우선순위: “강제 정확” = “강제 퍼지” > “위치 시작/끝” > “그룹화됨” > “기본값”

예시

stritems가 { '_abc', 'a_bc', 'ab_c', 'abc_' }라고 가정할 때, 프롬프트(결합된 쿼리)를 기반으로 한 매치 결과 예시입니다:

| 프롬프트 | 매치 결과              |
|----------|------------------------|
| abc      | 모두                   |
| *abc     | 모두                   |
|          |                        |
| 'abc     | abc_, _abc             |
| *'abc    | 없음 (항목에 "'" 없음) |
|          |                        |
| ^abc     | abc_                   |
| *^abc    | 없음 (항목에 "^" 없음) |
|          |                        |
| abc$     | _abc                   |
| *abc$    | 없음 (항목에 "$" 없음) |
|          |                        |
| ab c     | abc_, _abc, ab_c       |
| *ab c    | 없음 (항목에 " " 없음) |

쿼리 { 'ab', 'c' }를 가지는 것은 “ab c” 프롬프트와 동일합니다.

이 명령으로 어떻게 작동하는지 느껴볼 수 있습니다:

MiniPick.start({ source = { items = { '_abc', 'a_bc', 'ab_c', 'abc_' } } })

매개변수

{stritems} (table) 모든 stritems 배열입니다.

{inds} (table) 매칭할 stritems 인덱스 배열입니다. 모두 stritems의 문자열 요소를 가리켜야 합니다. 성능상의 이유로 별도의 확인은 하지 않습니다.

{query} (table) 문자열 배열입니다.

{opts} (table|nil) 옵션. 사용 가능한 필드:

  • <sync> (boolean) - 동기적으로 매칭할지 여부입니다. 기본값: false.

픽커 활성 상태 확인(Poke)

소스 메서드의 논블로킹 구현을 위해 설계되었습니다. MiniPick.is_picker_active()의 출력을 반환하지만, 실행 중인 코루틴이 있는지 여부에 따라 다음과 같이 달라집니다:

  • 없다면 즉시 반환합니다.

  • 있다면 coroutine.yield() 이후에 메인 이벤트 루프에 의해 “곧” coroutine.resume()이 호출된 후 반환합니다(vim.schedule() 참고).

논블로킹 정확한(exact) match 예시 (데모용이며 추가 최적화가 가능합니다):

local match_nonblock = function(match_inds, stritems, query)
  local prompt, querytick = table.concat(query), MiniPick.get_querytick()
  local f = function()
    local res = {}
    for _, ind in ipairs(match_inds) do
      local should_stop = not MiniPick.poke_is_picker_active() or
        MiniPick.get_querytick() ~= querytick
      if should_stop then return end

      if stritems[ind]:find(prompt) ~= nil then table.insert(res, ind) end
    end

    MiniPick.set_picker_match_inds(res)
  end

  coroutine.resume(coroutine.create(f))
end

반환값

(boolean) 활성화된 픽커가 있는지 여부입니다.
