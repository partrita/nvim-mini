mini.comment 문서

이 문서는 ’mini.nvim’의 main 브랜치에서 생성되었습니다.

mini.comment 줄 주석 달기

MIT 라이선스 Copyright (c) 2021 Evgeni Chasnovski

모듈

기능:

  • 일반 모드에서의 주석 달기는 count를 존중하며 점 반복(dot-repeatable)이 가능합니다.

  • 기본적으로 주석 구조는 ’commentstring’에서 유추됩니다: 현재 버퍼 또는 로컬로 활성화된 트리시터(tree-sitter) 언어에서 가져옵니다. options.custom_commentstring을 통해 사용자 정의할 수 있습니다 (자세한 내용은 MiniComment.config를 참조하세요).

  • 주석 처리가 성공하기 전후에 커스텀 훅(hook)을 허용합니다.

  • 미묘한 동작에 대해 구성 가능한 옵션을 제공합니다.

하지 않는 것:

  • 블록 및 줄 일부 주석. 줄 단위 주석만 지원합니다.

  • 탭과 공백이 섞인 들여쓰기 처리.

  • 빈 줄의 후행 공백 유지.

참고:

  • 트리시터 인식 주석 처리를 사용하려면 ’commentstring’의 전역 값이 ''(빈 문자열)이어야 합니다. 이는 기본값이므로 수동으로 다른 값으로 설정하지 않도록 주의하세요.

설정

이 모듈은 require('mini.comment').setup({})으로 설정이 필요합니다 ({}를 config 테이블로 교체하세요). 이는 스크립팅이나 수동으로 사용할 수 있는 전역 Lua 테이블 MiniComment를 생성합니다 (예: :lua MiniComment.*).

config 구조와 기본값은 MiniComment.config를 참조하세요.

MiniComment.config와 동일한 구조를 가져야 하는 vim.b.minicomment_config를 통해 버퍼 로컬에서 런타임 설정 설정을 재정의할 수 있습니다. 자세한 내용은 mini.nvim-buffer-local-config를 참조하세요.

비활성화

핵심 기능을 비활성화하려면 vim.g.minicomment_disable (전역) 또는 vim.b.minicomment_disable (버퍼용)을 true로 설정하세요. 다양한 시나리오와 사용자 정의 의도를 고려하여 모듈 기능 비활성화를 위한 정확한 규칙 작성은 사용자의 몫으로 남겨둡니다. 일반적인 레시피는 mini.nvim-disabling-recipes를 참조하세요.

setup()

MiniComment.setup({config})

모듈 설정

매개변수

{config} (table|nil) 모듈 설정 테이블. MiniComment.config를 참조하세요.

사용법

require('mini.comment').setup() -- 기본 설정 사용
-- 또는
require('mini.comment').setup({}) -- {}를 설정 테이블로 교체

config

MiniComment.config

기본값

MiniComment.config = {
  -- 모듈 동작을 제어하는 옵션
  options = {
    -- 커스텀 'commentstring'을 계산하는 함수 (선택 사항)
    custom_commentstring = nil,

    -- 동작 및 텍스트 오브젝트에서 빈 줄을 무시할지 여부
    ignore_blank_line = false,

    -- 들여쓰기가 없는 줄만 주석으로 인식할지 여부
    start_of_line = false,

    -- 주석 부분에 대해 단일 공백 내부 패딩을 강제할지 여부
    pad_comment_parts = true,
  },

  -- 모듈 매핑. 비활성화하려면 `''`(빈 문자열)을 사용하세요.
  mappings = {
    -- 일반 및 비주얼 모드 모두에서 주석 토글 (예: `gcip` - 내부 단락 주석)
    comment = 'gc',

    -- 현재 줄의 주석 토글
    comment_line = 'gcc',

    -- 선택 영역의 주석 토글
    comment_visual = 'gc',

    -- '주석' 텍스트 오브젝트 정의 (예: `dgc` - 전체 주석 블록 삭제)
    -- 매핑이 `comment_visual`과 다른 경우 비주얼 모드에서도 작동합니다.
    textobject = 'gc',
  },

  -- 주석 처리의 특정 단계에서 실행될 훅 함수
  hooks = {
    -- 성공적인 주석 처리 전. 기본적으로 아무 작업도 하지 않습니다.
    pre = function() end,
    -- 성공적인 주석 처리 후. 기본적으로 아무 작업도 하지 않습니다.
    post = function() end,
  },
}

옵션

커스텀 commentstring

options.custom_commentstring은 주석 구조를 유추하는 데 사용되는 ‘commentstring’ 옵션을 사용자 정의하는 함수일 수 있습니다. 모든 주석 동작 전에 다음 인수와 함께 한 번 호출됩니다:

  • ref_position - ’commentstring’을 계산할 위치 (로컬로 다른 주석 규칙이 있는 텍스트의 경우 관련이 있을 수 있음). 구조는 MiniComment.toggle_lines()의 opts.ref_position과 동일합니다.

출력은 유효한 ‘commentstring’(%s를 포함하는 문자열)이어야 합니다.

설정되지 않았거나 출력이 nil인 경우 MiniComment.get_commentstring()이 사용됩니다.

예를 들어, 이 옵션은 활성 트리시터 파서가 있는 경우에도 항상 버퍼의 ’commentstring’을 사용하는 데 사용할 수 있습니다:

require('mini.comment').setup({
  options = {
    custom_commentstring = function() return vim.bo.commentstring end,
  }
})

훅

hooks.pre 및 hooks.post 함수는 성공적인 주석 작업(토글 또는 텍스트 오브젝트 계산) 전후에 실행됩니다. 다음 필드를 가진 단일 테이블 인수와 함께 호출됩니다:

  • <action> (string) - 작업 이름. “toggle” (실제 토글 방향을 아직 모를 때), “comment”, “uncomment”, “textobject” 중 하나.

  • <line_start> (number|nil) - 작업 시작 줄. 아직 모르는 경우 없을 수 있습니다.

  • <line_end> (number|nil) - 작업 종료 줄. 아직 모르는 경우 없을 수 있습니다.

  • <ref_position> (table|nil) - 참조 위치.

참고:

  • hooks.pre에서 ’commentstring’을 변경하는 것이 허용되며 적용됩니다.

  • 훅이 false를 반환하면 추가 작업이 중단됩니다.

operator()

MiniComment.operator({mode})

매핑될 메인 함수

점 반복 및 범위에 대한 주석 처리를 가능하게 하기 위해 표현식 매핑(:map-<expr> 참조)에서 사용하도록 의도되었습니다. 이를 수동으로 할 필요는 없으며, 모든 작업은 MiniComment.setup() 내부에서 수행됩니다.

다소 직관적이지 않은 로직을 가지고 있습니다 (점 반복이 있는 표현식 매핑이 작동하는 방식 때문): 표현식 매핑 내부에서는 인수 없이 호출되어야 하며, 작업을 수행해야 할 때는 인수와 함께 호출되어야 합니다.

매개변수

{mode} (string|nil) ‘operatorfunc’ 모드가 포함된 선택적 문자열 (g@ 참조).

반환

(string|nil) 인수 없이 호출된 경우 ‘g@’, 그렇지 않은 경우 ’’ (단, 작업 수행 후).

toggle_lines()

MiniComment.toggle_lines({line_start}, {line_end}, {opts})

두 줄 번호 사이의 주석 토글

줄이 주석인 경우(모든 줄이 주석이거나 빈 줄임) 주석을 해제하고, 그렇지 않으면 주석을 답니다. 들여쓰기를 존중하며 후행 공백을 삽입하지 않습니다. 비주얼 모드가 아닌 상태에서의 주석 토글은 점 반복이 가능하며 count를 존중합니다.

참고

  • 주석 구조는 버퍼의 ‘commentstring’ 옵션 또는 트리시터 파서의 로컬 언어(활성 상태인 경우)에서 유추됩니다.

  • 이 함수를 호출하면 대상 범위에서 모든 extmarks가 제거됩니다.

매개변수

{line_start} (number) 시작 줄 번호 (1부터 총 줄 수까지 포함).

{line_end} (number) 종료 줄 번호 (1부터 총 줄 수까지 포함).

{opts} (table|nil) 옵션. 가능한 필드:

  • <ref_position> (table) - ‘commentstring’ 값이 계산될 참조 위치의 { row, col } (둘 다 1부터 시작)이 포함된 두 값 배열. 기본값: { line_start, 1 }.

textobject()

MiniComment.textobject()

주석 텍스트 오브젝트 선택

커서 줄에 인접한 모든 주석 처리된 줄을 선택합니다. ignore_blank_line 옵션이 활성화된 경우 (MiniComment.config 참조), 주석 처리된 줄 사이의 빈 줄도 텍스트 오브젝트의 일부로 취급됩니다. 오퍼레이터 모드 매핑(mapmode-o 참조)과 함께 사용하도록 설계되었습니다.

get_commentstring()

MiniComment.get_commentstring({ref_position})

‘commentstring’ 가져오기

이 함수는 현재 버퍼에서 관련 ‘commentstring’ 옵션을 계산하는 기본 방식을 나타냅니다. 주석 구조를 유추하는 데 사용됩니다.

다음과 같은 로직을 가집니다:

  • 활성 트리시터 파서가 있는 경우, ref_position의 로컬 언어에서 ’commentstring’을 가져오려고 시도합니다.

  • 첫 번째 단계가 성공하지 못하면 버퍼의 ’commentstring’을 직접 사용합니다.

매개변수

{ref_position} (table) ’commentstring’을 계산할 현재 버퍼 내부의 참조 위치. MiniComment.toggle_lines()의 opts.ref_position과 동일한 구조입니다.

반환

(string) ’commentstring’의 관련 값.
