mini.keymap 문서

mini.nvim의 main 브랜치에서 생성됨

mini.keymap 특수 키 매핑

MIT 라이선스 Copyright (c) 2025 Evgeni Chasnovski

모듈

기능:

  • 설정 가능한 다단계(multi-step) 동작을 수행하도록 키를 매핑합니다: 1단계 조건이 참이면 1단계 동작을 실행하고, 그렇지 않으면 2단계를 확인하는 방식으로 원래 키를 실행하는 폴백(fallback)까지 계속됩니다. 이는 보통 “스마트” 키(예: “스마트 탭”)라고 불립니다. MiniKeymap.map_multistep()을 참조하세요.

    <Tab>, <S-Tab>, <CR>, <BS>와 같은 특수 키의 입력 모드 매핑을 대상으로 하는 많은 내장 단계가 있습니다:

    • 팝업 메뉴 완성(popupmenu-completion) 탐색 및 수락. mini.completion에 유용합니다.

    • mini.snippets 탐색 및 확장.

    • mini.pairs를 준수하며 <CR> 및 <BS> 실행.

    • 현재 tree-sitter 노드의 앞/뒤로 점프.

    • 여는 문자 앞과 닫는 문자 뒤로 점프 (괄호 및 따옴표).

    • 커서가 들여쓰기 내부에 있을 때 들여쓰기 증가/감소.

    • 왼쪽의 모든 공백 삭제 (“hungry backspace”).

    • vim.snippet 탐색.

    • hrsh7th/nvim-cmp 완성 탐색 및 수락.

    • Saghen/blink.cmp 완성 탐색 및 수락.

    • L3MON4D3/LuaSnip 스니펫 탐색 및 확장.

    • windwp/nvim-autopairs를 준수하며 <CR> 및 <BS> 실행.

  • 키를 “콤보(combo)”로 매핑합니다: 각 키는 즉시 작동하며, 설정된 지연 시간 내에 모든 키가 입력되면 추가 동작을 실행합니다. MiniKeymap.map_combo()를 참조하세요. 일반적인 사용 사례는 다음과 같습니다:

    • 입력(Insert) 및 명령줄(Command-line) 모드에서 입력 가능한 키(예: “jk”, “kj”)를 매핑하여 일반(Normal) 모드로 나갑니다.

    • 동일한 탐색 키를 반복해서 누르는 나쁜 습관을 고치기 위해, 연속으로 너무 많이 눌릴 경우 알림을 표시합니다.

자세한 내용은 다음을 참조하세요:

  • MiniKeymap 예시

설정

이 모듈은 설정이 필수는 아니지만, 사용성 향상을 위해 설정할 수 있습니다. require('mini.keymap').setup({})을 통해 설정하세요({}를 config 테이블로 교체하세요). 이는 스크립팅이나 수동으로(:lua MiniKeymap.*를 통해) 사용할 수 있는 전역 Lua 테이블 MiniKeymap을 생성합니다.

config 구조와 기본값은 MiniKeymap.config를 참조하세요.

이 모듈은 런타임 옵션이 없으므로 vim.b.minikeymap_config를 사용해도 효과가 없습니다.

비교

  • max397574/better-escape.nvim:

    • 매핑 생성 방식은 다르지만 MiniKeymap.map_combo()와 거의 유사합니다.

    • 입력된 키가 자동으로 제거되므로 주로 입력 모드 매핑을 대상으로 합니다. 이 모듈은 키의 명시적 제거(주로 명시적인 <BS><BS>를 통해)를 요구하면서 더 일반적인 경우를 허용합니다.

  • abecodes/tabout.nvim:

    • MiniKeymap.map_multistep()의 'jump_{after,before}_tsnode' 단계와 일반적인 아이디어가 유사합니다.

    • tree-sitter 파서가 활성화된 경우에만 작동합니다. 이 모듈은 tree-sitter 파서 없이도 작동하는 ‘jump_after_close’ 및 ’jump_before_open’을 통해 폴백을 제공합니다.

    • ’tabout.nvim’은 tree-sitter 노드 이동 방식에 대해 더 세밀한 제어가 가능하지만, 이 모듈은 “현재 노드 밖으로 점프”하는 동작을 가집니다.

비활성화

매핑 동작을 비활성화하려면 vim.g.minikeymap_disable(전역) 또는 vim.b.minikeymap_disable(버퍼용)을 true로 설정하세요. 다양한 시나리오와 커스터마이징 의도를 고려하여 모듈 기능을 비활성화하기 위한 정확한 규칙 작성은 사용자에게 맡겨집니다. 일반적인 레시피는 mini.nvim-disabling-recipes를 참조하세요.

예시

다단계 (Multi-step)

다단계 매핑이 어떻게 작동하는지와 어떤 내장 단계가 사용 가능한지에 대한 일반적인 설명은 MiniKeymap.map_multistep()을 참조하세요.

mini.completion 및 mini.pairs와 잘 작동하는 설정:

local map_multistep = require('mini.keymap').map_multistep
map_multistep('i', '<Tab>',   { 'pmenu_next' })
map_multistep('i', '<S-Tab>', { 'pmenu_prev' })
map_multistep('i', '<CR>',    { 'pmenu_accept', 'minipairs_cr' })
map_multistep('i', '<BS>',    { 'minipairs_bs' })

<Tab> / <S-Tab>을 사용하여 mini.snippets를 탐색하고 확장하도록 설정:

local map_multistep = require('mini.keymap').map_multistep

local tab_steps = { 'minisnippets_next','minisnippets_expand','pmenu_next' }
map_multistep('i', '<Tab>', tab_steps)

local shifttab_steps = { 'minisnippets_prev', 'pmenu_prev' }
map_multistep('i', '<S-Tab>', shifttab_steps)

추가적인 스마트 <Tab> 및 <S-Tab> 설정:

local map_multistep = require('mini.keymap').map_multistep

-- 참고: 이는 탭을 입력하지 않습니다. 탭을 입력하려면 <C-v><Tab>을 누르세요.
local tab_steps = {
  'minisnippets_next', 'minisnippets_expand', 'pmenu_next',
  'jump_after_tsnode', 'jump_after_close',
}
map_multistep('i', '<Tab>', tab_steps)

local shifttab_steps = {
  'minisnippets_prev',  'pmenu_prev',
  'jump_before_tsnode', 'jump_before_open',
}
map_multistep('i', '<S-Tab>', shifttab_steps)

활성화된 vim.snippet 세션에서의 탐색은 선택 모드(Select-mode) 매핑도 필요합니다:

local map_multistep = require('mini.keymap').map_multistep
map_multistep({ 'i', 's' }, '<Tab>',   { 'vimsnippet_next', 'pmenu_next' })
map_multistep({ 'i', 's' }, '<S-Tab>', { 'vimsnippet_prev', 'pmenu_prev' })

콤보 (Combos)

콤보가 무엇인지에 대한 일반적인 설명과 사용 시 주의 사항은 MiniKeymap.map_combo()를 참조하세요.

모든 콤보는 왼쪽 키들이 비교적 빠르게 입력되어야 합니다. 키 사이의 지연 시간을 조정하려면 네 번째 인자로 { delay = 500 }(사용자 지정 값)을 추가하세요.

일반 모드로 나가는 “Better escape”

<Esc> 키에 손을 뻗지 않고 일반 모드(Normal-mode)로 나갑니다:

-- 가장 일반적인 모드 지원. 터미널 내부에서 `<Esc>`를 누르는 것과
-- 같은 의미로 't'를 포함할 수도 있습니다.
local mode = { 'i', 'c', 'x', 's' }
require('mini.keymap').map_combo(mode, 'jk', '<BS><BS><Esc>')

-- 키 순서에 신경 쓰지 않으려면 "kj"도 매핑합니다.
require('mini.keymap').map_combo(mode, 'kj', '<BS><BS><Esc>')

-- 터미널 모드에서 일반 모드로 탈출
require('mini.keymap').map_combo('t', 'jk', '<BS><BS><C-\\><C-n>')
require('mini.keymap').map_combo('t', 'kj', '<BS><BS><C-\\><C-n>')
잘못된 탐색 습관 표시

동일한 키를 반복하여 너무 많이 이동할 경우 알림을 표시합니다:

local notify_many_keys = function(key)
  local lhs = string.rep(key, 5)
  local action = function() vim.notify('Too many ' .. key) end
  require('mini.keymap').map_combo({ 'n', 'x' }, lhs, action)
end
notify_many_keys('h')
notify_many_keys('j')
notify_many_keys('k')
notify_many_keys('l')
이전 오타 수정

수동으로 입력 모드를 나가지 않고 이전 오타를 수정합니다([s 및 z= 참조):

local action = '<BS><BS><Esc>[s1z=gi<Right>'
require('mini.keymap').map_combo('i', 'kk', action)
검색 하이라이트 숨기기

<Esc><Esc>를 두 번 눌러 :nohlsearch를 실행합니다. nmap <Esc> <Cmd>nohl<CR>로도 가능하지만, 콤보 방식은 일반 모드에서 <Esc> 매핑을 다른 용도로 사용할 수 있게 해줍니다.

local action = function() vim.cmd('nohlsearch') end
require('mini.keymap').map_combo({ 'n','i','x','c' }, '<Esc><Esc>', action)
버퍼 탐색

일부 이동 명령을 더 입력하기 쉬운 대안으로 교체합니다:

local map_combo = require('mini.keymap').map_combo
map_combo({ 'n', 'x' }, 'll', 'g$')
map_combo({ 'n', 'x' }, 'hh', 'g^')
map_combo({ 'n', 'x' }, 'jj', '}')
map_combo({ 'n', 'x' }, 'kk', '{')

map_multistep()

다단계 동작 매핑

다단계 동작 매핑은 표현식 매핑(:map-expression)입니다. 다단계 동작을 실행하는 과정은 다음과 같습니다:

  • 1단계 조건을 확인합니다. true인 경우 1단계 동작을 실행하고 중단합니다.

  • 2단계 조건을 확인하는 식으로 계속 진행합니다.

  • 더 이상 단계가 없으면 매핑된 키를 반환하는 폴백을 수행합니다.

더 나은 사용자 경험을 위해 <Tab>, <S-Tab>, <CR>, <BS>의 입력 모드 “스마트” 매핑을 위해 설계된 많은 내장 단계가 있습니다. 사용 가능한 내장 단계 (“대상 키”는 제안이며 무엇이든 사용 가능):

참고:

  • 동작 실행은 표현식 매핑(:map-expression)의 제한사항(텍스트나 버퍼 변경 불허 등)을 갖습니다. 복잡한 lua 코드를 실행하려면 동작 내부에서 vim.schedule()을 사용하거나, :map-cmd 형식의 문자열로 코드를 반환하거나, 나중에 실행될 함수를 반환하세요. 사용 예시를 참조하세요.

  • 일부 매핑된 키(예: <Tab>, <CR>)는 플러그인(‘nvim-cmp’, ‘blink-cmp’, ‘nvim-autopairs’ 등)에서 스마트 프리셋을 비활성화해야 할 수도 있습니다.

매개변수

{mode} (string|table) vim.keymap.set()과 동일.

{lhs} (string) vim.keymap.set()과 동일.

{steps} (table) 단계 배열. 각 단계는 내장 단계 이름의 문자열이거나, 두 개의 호출 가능한 메서드(인자 없이 호출됨)를 가진 테이블일 수 있습니다:

  • <condition> - 동작이 실행되어야 하면 true를 반환합니다.

  • <action> - <condition>이 true를 반환할 때 실행될 동작. 유연성을 위해 다음과 같은 값을 반환할 수 있습니다:

    • 문자열 - 표현식 출력으로 반환됩니다. "<Tab>"(<Tab> 키로 처리) 또는 "<Cmd>lua vim.notify('Hello')<CR>"과 같은 것일 수 있습니다. 키코드를 이스케이프하지 않아야 합니다(즉, “가 아닌”<Tab>“을 반환). 이미 이스케이프된 것을 되돌리려면 keytrans()를 사용하세요.

    • 함수 - "<Cmd>lua f()<CR>"인 것처럼 실행되지만 이를 위해 전역 함수를 생성할 필요는 없습니다.

    • false - 단계를 계속 진행합니다.

{opts} (table|nil) vim.keymap.set()과 동일.

사용법

실제 예시는 MiniKeymap 예시를 참조하세요.

예시 설명:

_G.log = {}
local steps = {}
steps[1] = {
  condition = function() table.insert(_G.log, 'C1'); return _G.cond1 end,
  -- 키를 계산하여 반환합니다. 키가 눌린 것처럼 에뮬레이션됩니다.
  action = function() table.insert(_G.log, 'A1'); return 'hello' end,
}

steps[2] = {
  condition = function() table.insert(_G.log, 'C2'); return _G.cond2 end,
  -- 동작을 즉시 수행하고, 다른 단계를 계속 확인하도록 `false` 반환
  action = function() table.insert(_G.log, 'A2'); return false end,
}

steps[3] = {
  condition = function() table.insert(_G.log, 'C3'); return _G.cond3 end,
  -- 표현식 매핑의 제한을 피하기 위해 나중에 동작 수행
  action = function()
    table.insert(_G.log, 'A3_1')
    return function() table.insert(_G.log, 'A3_2') end
  end,
}

-- 입력 모드 <Tab> 매핑 생성
require('mini.keymap').map_multistep('i', '<Tab>', steps)

-- <Tab>을 누르면 폴백 `\t`가 삽입됨; 로그 C1+C2+C3
_G.cond1, _G.cond2, _G.cond3 = false, false, false

-- <Tab>을 누르면 `hello`가 삽입됨; 로그 C1+A1
_G.cond1, _G.cond2, _G.cond3 = true, false, false

-- <Tab>을 누르면 아무것도 삽입되지 않음; 로그 C1+C2+A2+C3+A3_1+A3_2
_G.cond1, _G.cond2, _G.cond3 = false, true, true

gen_step

MiniKeymap.gen_step

다단계 매핑을 위한 단계 생성

함수 요소가 포함된 테이블입니다. 호출하여 실제 단계를 가져옵니다.

gen_step.search_pattern()

MiniKeymap.gen_step.search_pattern({pattern}, {flags}, {opts})

패턴 검색 단계

search()를 사용하여 패턴 일치 항목으로 점프합니다. 최종 위치를 일치 항목 바로 오른쪽으로 조정할 수 있습니다(입력 모드에서 유용함).

매개변수

{pattern} (string) search()과 동일.

{flags} (string|nil) search()과 동일.

{opts} (table|nil) 옵션. 가능한 필드:

  • <side> (string) - "before" (기본값) 또는 "after" 중 하나.

  • <stopline> (number|function) - search()에 전달됨 (숫자 또는 매 검색 전 호출될 함수의 출력값).

  • <timeout> (number) - search()에 전달됨.

  • <skip> (string|function) - search()에 전달됨.

반환

(table) 패턴을 검색하는 단계.

사용법

MiniKeymap.map_multistep()의 내장 단계인 “jump_after_close” 및 “jump_before_open”이 이를 사용하지만 입력 모드에서만 사용됩니다.

여러 모드에서 연속된 모든 괄호의 앞/뒤로 점프하는 단계:

local keymap = require('mini.keymap')
local tab_step_insert = keymap.gen_step.search_pattern(
  -- 견고한 "체이닝"을 위해 'c' 플래그와 'after' 사이드를 사용해야 함
  [=[[)\]}]\+]=], 'ceW', { side = 'after' }
)
keymap.map_multistep('i', '<Tab>', { tab_step_insert })
local tab_step = keymap.gen_step.search_pattern([=[[)\]}]\+]=], 'eW')
keymap.map_multistep({ 'n', 'x' }, '<Tab>', { tab_step })

local stab_step = keymap.gen_step.search_pattern([=[[(\[{]\+]=], 'bW')
keymap.map_multistep({ 'i', 'n', 'x' }, '<S-Tab>', { stab_step })

map_combo()

MiniKeymap.map_combo({mode}, {lhs}, {action}, {opts})

콤보 후속 동작 매핑

콤보 생성: 각 키가 즉시 작동하면서 설정된 지연 시간 내에 모든 키가 순차적으로 입력될 경우 추가 동작을 실행하는 키 시퀀스입니다.

입력 모드 “better escape” jk 콤보와 <BS><BS><Esc> 동작 예시:

  • j를 누릅니다. 부작용 없이 즉시 표시됩니다.

  • 빠르게 (기본값인 200ms 이내에) k를 누릅니다. 그러면 이미 입력된 jk를 삭제하고(<BS><BS>) 일반 모드로 나가는(<Esc>) 것과 동일한 동작이 트리거됩니다.

참고:

  • 중요! 콤보는 일반 매핑이 아니라 vim.on_key()를 통한 별도의 키 추적입니다. 이는 콤보가 보이지 않으며 일반 매핑처럼 관리할 수 없음을 의미하므로 중요합니다. 대신 각 콤보는 전용 네임스페이스(namespace) (가독성을 위해 명명됨)와 연결됩니다. 하지만 생성 후 즉석에서 관리할 일은 거의 없습니다.

  • 문자열 동작은 nvim_input()으로 실행되므로 에뮬레이션된 키들은 사용자 정의 매핑을 준수합니다.

  • 서로 다른 콤보는 독립적으로 추적되고 작동합니다. 예를 들어 jjk와 jk 콤보가 모두 있는 경우, 빠르게 jjk를 입력하면 둘 다 실행됩니다.

  • 매핑이 아닌 실제 입력된 키를 감시할 수 있게 개선된 vim.on_key()가 있는 Neovim>=0.11을 권장합니다. 예를 들어 비주얼 모드에서 xnoremap j gj 스타일의 리맵이 있는 상태에서 jk 콤보를 만들 때 중요합니다. Neovim<0.11에서의 해결책은 gjgk를 콤보의 왼쪽 키로 사용하는 것입니다.

  • 각 콤보는 키 입력마다 매우 적지만 0이 아닌 오버헤드를 추가합니다. 보통 약 1-3 마이크로초(즉, 0.001-0.003ms)로, 대부분의 설정에서 충분히 빠를 것입니다. 총 ~20000번의 키 입력이 발생하는 “일반적인 실제” 코딩 세션에서 하나의 콤보는 약 40ms의 추가 오버헤드를 발생시킵니다. 콤보를 많이 생성할 때는 주의하세요.

매개변수

{mode} (string|table) 모드 ID (“n”, “i” 등)의 문자열 또는 배열. 여러 모드 배열이 여러 개의 단일 모드 콤보보다 성능이 좋습니다.

{lhs} (string|table) 추적할 키 시퀀스 문자열 또는 추적할 키들의 배열 (한 요소가 한 키).

{action} (string|function) 키 시퀀스가 감지된 후 수행할 동작. 문자열인 경우 키로 처리되어 nvim_input()으로 에뮬레이션됩니다. 함수인 경우 vim.schedule()에서 실행됩니다. 에뮬레이션될 문자열 키를 반환할 수 있습니다.

{opts} (table|nil) 옵션. 가능한 필드:

  • <delay> (number) - 키 시퀀스를 감지하기 위해 키들이 눌려야 하는 지연 시간(밀리초). 기본값: 200.

사용법

실제 예시는 MiniKeymap 예시를 참조하세요.

예시 설명:

local map_combo = require('mini.keymap').map_combo

-- 입력 모드에서 `x`를 누른 뒤 1초 내에 `x`를 누르면 'A'를 로그에 남기고
-- `yy`를 추가로 누른 것처럼 에뮬레이션합니다
_G.log = {}
local action = function() table.insert(_G.log, 'A'); return 'yy' end
map_combo('i', 'xx', action, { delay = 1000 })
