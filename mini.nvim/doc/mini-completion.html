mini.completion 문서

mini.nvim의 main 브랜치에서 생성됨

mini.completion 자동 완성 및 시그니처 헬프

MIT 라이선스 Copyright (c) 2021 Evgeni Chasnovski

모듈

주요 디자인 아이디어:

  • 비동기(설정 가능한 “디바운스(debounce)” 지연 시간 포함) “2단계 체인 완성”을 제공합니다: 먼저 LSP 클라이언트(설정된 경우)에서 완성 항목을 가져오려고 시도하고, 결과가 없으면 사용자 정의 동작으로 폴백(fallback)합니다.

  • 완성 관리는 가능한 한 Neovim의 내장 도구를 사용하여 수행됩니다. 완성 제안을 표시하기 위해 팝업 메뉴 완성(popupmenu-completion)이 사용됩니다.

기능:

  • 2단계 체인 완성:

    • 1단계는 MiniCompletion.completefunc_lsp()를 통해 구현된 LSP 완성입니다. 이는 ‘completefunc’ 또는 ‘omnifunc’로 설정되어야 합니다. LSP 클라이언트(‘textDocument/completion’ 요청을 통해)로부터 완성 항목을 가져오려고 시도합니다. 응답 항목의 사용자 정의 전처리(예: 퍼지 매칭 등)가 가능합니다(MiniCompletion.config.lsp_completion.process_items 사용). 기본적으로 완성할 단어로 직접 시작하는 항목들이 유지되며 LSP 사양에 따라 정렬됩니다. 자동 임포트 등과 같은 additionalTextEdits(‘참고’ 섹션 참조)와 스니펫 항목을 지원합니다(스니펫은 mini.snippets 의존성이 있을 때 최상의 결과를 제공합니다).

    • 1단계가 설정되지 않았거나 후보가 없는 경우, 폴백 동작이 실행됩니다. 가장 많이 테스트된 동작은 Neovim의 내장 입력 완성( ins-completion 참조)입니다.

  • 완성 항목 정보(‘completionItem/resolve’ 요청을 통해)와 시그니처 헬프(LSP 서버가 정보를 제공하는 경우 활성 매개변수 하이라이트 포함)를 플로팅 윈도우에 자동으로 표시합니다. 시그니처 헬프는 커서 왼쪽의 문자가 전용 트리거 문자(LSP 서버 기능의 signatureHelpProvider.triggerCharacters에 구성됨)인 경우 표시되며, 현재 열려 있는 경우 지연 없이 업데이트됩니다. 이미 표시된 시그니처 헬프 윈도우는 고정되며, 표시할 내용이 없거나 텍스트가 다르거나 입력 모드를 나갈 때 닫힙니다. 정보/시그니처 윈도우 내에서의 스크롤은 기본적으로 <C-f> / <C-b>로 수행합니다.

  • 자동 동작은 설정된 지연 시간 후에 수행됩니다. 이는 계산 부하를 줄이고 빠른 타이핑(자동 완성 및 시그니처 헬프)과 항목 선택(항목 정보)을 가능하게 합니다.

  • 2단계/폴백 완성을 강제로 실행합니다(기본값은 <C-Space> / <A-Space>).

  • LSP 항목의 하이라이트를 커스터마이징할 수 있습니다. Neovim>=0.11이 필요합니다. 지원되는 필드에 전용 하이라이트 그룹을 설정하려면 config.lsp_completion.process_items를 사용하세요:

    • <abbr_hlgroup> - 항목 레이블(complete-items의 abbr). 기본적으로 항목이 deprecated로 표시되었는지만 확인하고 MiniCompletionDeprecated 하이라이트 그룹을 설정합니다.

    • <kind_hlgroup> - LSP 종류(“Function”, “Keyword” 등). 기본적으로 mini.icons의 “lsp” 카테고리를 사용합니다(활성화된 경우).

수행하지 않는 것:

  • 수많은 설정 가능한 소스 제공.

  • <CR>, <Tab> 등의 자동 매핑. 이러한 키들은 사용자마다 기대하는 바가 매우 다릅니다. 제안 사항은 ’유용한 매핑’을 참조하거나 "pmenu_*" 내장 단계와 함께 MiniKeymap.map_multistep()을 사용하세요.

의존성

권장 의존성(추가 기능을 제공하며, 없어도 작동합니다):

  • LSP 종류(kind)를 강조 표시하기 위한 mini.icons 모듈 활성화(Neovim>=0.11 필요). 없을 경우, MiniCompletion.default_process_items()는 하이라이트를 추가하지 않습니다. MiniIcons.tweak_lsp_kind()도 확인해 보세요.

  • 더 나은 스니펫 처리를 위한 mini.snippets 모듈 활성화(적극 권장). 없고 사용자 정의 스니펫 삽입이 구성되지 않은 경우, Neovim>=0.10에서는 vim.snippet.expand()가 사용됩니다(이전 버전에서는 추가 작업이 수행되지 않습니다). MiniCompletion.default_snippet_insert()를 참조하세요.

설정

이 모듈은 require('mini.completion').setup({})을 통한 설정이 필요합니다({}를 config 테이블로 교체하세요). 이는 스크립팅이나 수동으로(:lua MiniCompletion.*를 통해) 사용할 수 있는 전역 Lua 테이블 MiniCompletion를 생성합니다.

config 구조와 기본값은 MiniCompletion.config를 참조하세요.

런타임 설정은 vim.b.minicompletion_config를 통해 버퍼 로컬로 재정의할 수 있으며, 이는 MiniCompletion.config와 동일한 구조를 가져야 합니다. 자세한 내용은 mini.nvim-buffer-local-config를 참조하세요.

권장 옵션 값

일부 옵션은 자동으로 설정됩니다(MiniCompletion.setup() 전에 설정되지 않은 경우):

  • ’completeopt’는 덜 방해적인 팝업을 위해 “menuone,noselect”로 설정됩니다. 퍼지 매칭을 활성화하려면 수동으로 “menuone,noselect,fuzzy”로 설정하세요. 필터링 시 초기 순서를 유지하려면 “nosort” 플래그를 추가하는 것도 고려해 보세요.

  • ’shortmess’에는 조용한 <C-n> 폴백을 위해 “c” 플래그가 추가됩니다.

  • ’complete’에서 “t” 플래그가 제거됩니다(폴백 동작이 기본값인 경우). 이는 눈에 띄는 지연을 유발하기 때문입니다.

스니펫

LSP 사양에 따라 일부 완성 항목은 스니펫 형태로 제공될 수 있습니다. 스니펫은 미리 정의된 텍스트와 사용자가 스니펫 세션 동안 대화식으로 텍스트를 변경/추가할 수 있는 장소(“탭스탑(tabstops)”이라고 함)가 모두 포함된 템플릿입니다.

’mini.completion’에서 스니펫을 삽입할 항목은 팝업 메뉴에 “S” 기호가 표시됩니다(complete-items의 menu 부분). 실제로 스니펫을 삽입하려면:

  • <C-n> / <C-p>로 항목을 선택합니다. 시각적 깜빡임을 줄이기 위해 항목의 레이블(보통 전체 스니펫은 아님)이 먼저 삽입됩니다. LSP 서버가 항목에 대한 고유 정보를 제공하지 않는 경우 정보 창에 전체 스니펫 텍스트가 표시됩니다.

  • <C-y> (complete_CTRL-Y)를 누르거나 키워드가 아닌 문자(예: <CR>, 새 문자는 제거됨) 삽입을 시도합니다. 이전 단계의 텍스트를 지우고 커서를 설정한 후 스니펫 텍스트와 함께 lsp_completion.snippet_insert를 호출합니다.

  • <C-e> (complete_CTRL-E)를 눌러 스니펫 삽입을 취소하고 완성을 적절히 종료합니다.

삽입된 스니펫을 다루는 방법은 MiniCompletion.default_snippet_insert()를 참조하세요.

참고:

  • LSP 서버가 스니펫을 제안하지 않게 하려면, LSP 서버 시작 시 다음 기능을 비활성화(false로 설정)하세요: textDocument.completion.completionItem.snippetSupport.

  • 스니펫 본문에 탭스탑, 변수, 탭, 개행 문자가 포함되어 있지 않으면 lsp_completion.snippet_insert가 호출되지 않고 텍스트가 그대로 삽입됩니다.

참고

  • 더 적절한(약간 고급인) LSP 완성 설정은 BufEnter 이벤트(기본값)마다 설정하는 것이 아니라, LSP 클라이언트가 연결(attach)될 때마다 설정하는 것입니다. 방법은 다음과 같습니다:

    • MiniCompletion.setup() 설정에서 다음을 사용하세요:

      lsp_completion = { source_func = 'omnifunc', auto_setup = false }

    • LspAttach 이벤트에서 모든 클라이언트 연결에 대해 ‘omnifunc’ 옵션을 정확히 v:lua.MiniCompletion.completefunc_lsp로 설정하세요. 예시:

      local on_attach = function(args)
  vim.bo[args.buf].omnifunc = 'v:lua.MiniCompletion.completefunc_lsp'
end
vim.api.nvim_create_autocmd('LspAttach', { callback = on_attach })

    이 설정은 파일 유형별 ‘omnifunc’(수동 i_CTRL-X_CTRL-O 사용)와 자동 LSP 완성을 동시에 사용할 수 있도록 하기 위해 기본값이 아닙니다.

  • 모듈에서 지원하는 LSP 사양 부분에 대한 정보를 가져오거나 설정하려면 MiniCompletion.get_lsp_capabilities()를 사용하세요. 사용 관련 노트는 해당 도움말을 참조하세요.

  • LSP 단계에서 항목 종류(kind)를 읽을 수 있는 버전으로 표시하기 위해 vim.lsp.protocol.CompletionItemKind 맵을 사용합니다. 표시되는 내용을 변경하려면 이를 직접 수정하세요. mini.icons가 활성화되어 있다면 MiniIcons.tweak_lsp_kind()를 확인해 보세요.

  • 커스텀(재정의된) vim.ui.input() 사용에 문제가 있다면 입력 버퍼(보통 ‘filetype’ 기준)에 대해 ’mini.completion’을 비활성화하세요.

비교

  • hrsh7th/nvim-cmp:

    • 완성 후보를 표시하기 위해 자체 팝업 메뉴를 구현하는 반면, 이 모듈은 내장 입력 완성 메뉴(ins-completion-menu)를 재사용합니다.

    • 각각 별도의 플러그인 형태인 여러 소스를 허용하는 더 복잡한 디자인을 가집니다. 이 모듈은 LSP와 폴백이라는 두 가지 내장 소스만 가집니다.

    • 자동 시그니처 헬프를 위해 별도의 플러그인이 필요합니다.

    • 자체적인 “고스트 텍스트(ghost text)” 기능을 구현하지만, 이 모듈은 구현하지 않습니다.

  • Saghen/blink.cmp:

    • ’nvim-cmp’와의 비교와 거의 비슷합니다: 더 많은 코드와 구성 복잡성을 대가로 더 많은 기능을 제공하는 반면, 이 모듈은 Neovim의 내장 기능에 최대한 의존하면서 “충분한” 소수의 기능만 제공하도록 설계되었습니다.

    • 둘 다 자동 시그니처 헬프를 기본으로 제공합니다.

유용한 매핑

mini.keymap을 사용할 수 있다면 "pmenu_*" 내장 단계와 함께 MiniKeymap.map_multistep()을 사용하는 것을 권장합니다. 예시는 MiniKeymap 예시를 참조하세요.

<Tab> 및 <S-Tab>을 사용하여 완성 목록을 탐색하려면 다음 매핑을 만드세요:

local imap_expr = function(lhs, rhs)
  vim.keymap.set('i', lhs, rhs, { expr = true })
end
imap_expr('<Tab>',   [[pumvisible() ? "\<C-n>" : "\<Tab>"]])
imap_expr('<S-Tab>', [[pumvisible() ? "\<C-p>" : "\<S-Tab>"]])

<CR>의 동작을 더 일관되게 만들려면 init.lua에서 다음 템플릿을 사용하여 사용자 정의 매핑을 만들 수 있습니다:

_G.cr_action = function()
  -- 팝업 메뉴에 선택된 항목이 있으면 <C-y>로 수락합니다
  if vim.fn.complete_info()['selected'] ~= -1 then return '\25' end
  -- 일반 `<CR>`로 폴백합니다. 다른 플러그인에 따라 커스터마이징하고
  -- 싶을 수 있습니다. 예를 들어 'mini.pairs'가 설정되어 있다면,
  -- 다음 줄을 `return MiniPairs.cr()`로 바꾸세요.
  return '\r'
end

vim.keymap.set('i', '<CR>', 'v:lua.cr_action()', { expr = true })

하이라이트 그룹

  • MiniCompletionActiveParameter - 시그니처의 활성 매개변수.

  • MiniCompletionDeprecated - deprecated로 표시된 후보 항목.

  • MiniCompletionInfoBorderOutdated - 후보 항목 사이를 빠르게 이동하는 동안 명시적 지연으로 인해 텍스트가 최신이 아닐 때의 정보 창 테두리.

하이라이트 그룹을 변경하려면 nvim_set_hl()을 사용하여 직접 설정하세요.

비활성화

비활성화하려면 vim.g.minicompletion_disable(전역) 또는 vim.b.minicompletion_disable(버퍼용)을 true로 설정하세요. 다양한 시나리오와 커스터마이징 의도를 고려하여 모듈 기능을 비활성화하기 위한 정확한 규칙 작성은 사용자에게 맡겨집니다. 자세한 레시피는 mini.nvim-disabling-recipes를 참조하세요.

이벤트

사용자 커스터마이징을 위해 특정 상황에서 특정 User 자동 명령 이벤트가 트리거됩니다:

  • 정보 및 시그니처 헬프 윈도우:

    • MiniCompletionWindowOpen - 새 윈도우가 열린 후.

    • MiniCompletionWindowUpdate - 기존 윈도우가 업데이트된 후.

    각 이벤트의 이벤트 데이터(event-data) 테이블에는 kind(“info” 또는 “signature” 중 하나)와 win_id(영향을 받는 윈도우 식별자) 필드가 포함되어 있습니다.

setup()

MiniCompletion.setup({config})

모듈 설정

매개변수

{config} (table|nil) 모듈 설정 테이블. MiniCompletion.config를 참조하세요.

사용법

require('mini.completion').setup() -- 기본 설정 사용
-- 또는
require('mini.completion').setup({}) -- {}를 사용자 설정 테이블로 교체

config

MiniCompletion.config

기본값

MiniCompletion.config = {
  -- 특정 Neovim 이벤트와 동작 사이의 지연 시간 (디바운스 유형, ms 단위).
  -- 아주 큰 지연 시간(예: 10^7)을 설정하여 특정 자동 동작을
  -- (가상으로) 비활성화하는 데 사용할 수 있습니다.
  delay = { completion = 100, info = 100, signature = 50 },

  -- 동작 윈도우 설정:
  -- - `height` 및 `width`는 최대 크기입니다.
  -- - `border`는 테두리를 정의합니다 (`nvim_open_win()`에서와 동일; 기본값 "single").
  window = {
    info = { height = 25, width = 80, border = nil },
    signature = { height = 25, width = 80, border = nil },
  },

  -- 모듈이 LSP 완성을 수행하는 방식
  lsp_completion = {
    -- `source_func`은 'completefunc' 또는 'omnifunc' 중 하나여야 합니다.
    source_func = 'completefunc',

    -- `auto_setup`은 모든 `BufEnter` 이벤트에서 LSP 완성을 설정할지
    -- 여부를 나타내는 불리언 값이어야 합니다.
    auto_setup = true,

    -- LSP 'textDocument/completion' 응답 항목(각 항목에는 서버 식별을 위한
    -- `client_id` 필드가 있음)과 완성할 단어를 인자로 받는 함수입니다.
    -- 출력은 입력과 동일한 형태의 테이블이어야 합니다. 일반적인 사례는
    -- 커스텀 필터/정렬입니다. 기본값: `default_process_items`
    process_items = nil,

    -- 스니펫 문자열을 받아 커서 위치에 삽입하는 함수입니다.
    -- 기본값: `default_snippet_insert`. 'mini.snippets' 사용을 시도하고
    -- Neovim>=0.10에서는 `vim.snippet.expand`로 폴백합니다.
    snippet_insert = nil,
  },

  -- 함수/문자열 형태의 폴백 동작입니다. 입력 모드에서 실행됩니다.
  -- 내장 완성(`:h ins-completion`)을 사용하려면 해당 매핑을 문자열로
  -- 설정하세요. 예: '전체 라인' 완성을 위해 '<C-x><C-l>' 설정.
  fallback_action = '<C-n>',

  -- 모듈 매핑. 비활성화하려면 `''`(빈 문자열)을 사용하세요. 일부 매핑은
  -- 시스템 매핑과 충돌할 수 있습니다.
  mappings = {
    -- 2단계/폴백 완성을 강제로 실행
    force_twostep = '<C-Space>',
    force_fallback = '<A-Space>',

    -- 정보/시그니처 창을 아래/위로 스크롤. 재정의할 때 팝업 메뉴용 내장 키와
    -- 충돌하는지 확인하세요 (예: 'completefunc'/'omnifunc' 소스 함수의
    -- `<C-u>`/`<C-o>`, 또는 `<C-n>`/`<C-p>`).
    scroll_down = '<C-f>',
    scroll_up = '<C-b>',
  },
}

default_process_items()

MiniCompletion.default_process_items({items}, {base}, {opts})

LSP 항목의 기본 처리

단계:

  • 제공된 방법에 따라 항목을 필터링하고 정렬합니다.

  • 항목 종류(kind)의 우선순위에 따라 항목을 추가로 배치합니다.

  • 항목이 deprecated로 표시된 경우 MiniCompletionDeprecated <abbr_hlgroup>를 추가합니다.

  • mini.icons가 활성화되어 있으면 “lsp” 카테고리를 기반으로 <kind_hlgroup>를 추가합니다.

퍼지 매칭을 강제하고, Text 항목을 필터링하고, Snippet 항목을 마지막에 두는 예시:

local kind_priority = { Text = -1, Snippet = 99 }
local opts = { filtersort = 'fuzzy', kind_priority = kind_priority }
local process_items = function(items, base)
  return MiniCompletion.default_process_items(items, base, opts)
end
require('mini.completion').setup({
  lsp_completion = { process_items = process_items },
})

매개변수

{items} (table) LSP 응답의 항목 배열.

{base} (string) 완성이 수행되는 기준 문자열. 완성 함수(complete-functions) 참조.

{opts} (table|nil) 옵션. 가능한 필드:

  • <filtersort> (string|function) - 항목 필터링 및 정렬 방법. 문자열인 경우 다음 중 하나여야 합니다:

    • 'prefix' - base로 시작하지 않는 항목은 필터링하고 LSP 사양에 따라 정렬합니다. 각각 filterText와 sortText를 사용하며 폴백으로 label을 사용합니다.

    • 'fuzzy' - filterText를 사용하여 matchfuzzy()로 필터링 및 정렬합니다.

    • 'none' - 필터링 및 정렬하지 않습니다. 호출 가능한 함수인 경우 items와 base를 인자로 받아 항목 배열을 반환해야 합니다. 기본값: ’completeopt’에 “fuzzy”가 포함되어 있으면 'fuzzy', 그렇지 않으면 'prefix'.

  • <kind_priority> (table) - 완성 항목 종류(Variable, Snippet 등; vim.lsp.protocol.CompletionItemKind의 문자열 키 참조)와 수치적 우선순위의 맵입니다. <filtersort> 적용 후 항목 종류별로 배치하는 데 사용됩니다: 음수 우선순위 종류의 항목은 필터링되고, 나머지는 우선순위 내림차순으로 정렬됩니다(우선순위가 같으면 순서 유지). 우선순위는 어떤 숫자든 가능하며 서로 비교하는 데에만 사용됩니다. 누락된 종류(즉, 모든 서버가 모든 정보를 제공하지는 않음)에는 100이 사용됩니다. 기본값: {} (모두 동일한 우선순위).

반환

(table) LSP 응답에서 처리된 항목 배열.

default_snippet_insert()

MiniCompletion.default_snippet_insert({snippet})

기본 스니펫 삽입

우선순위:

  • 설정된 경우(즉, require('mini.snippets').setup() 이후) mini.snippets을 사용합니다.

  • Neovim>=0.10에서 vim.snippet.expand()를 사용합니다.

  • 커서 위치에 스니펫 텍스트를 그대로 추가합니다.

스니펫이 삽입된 후, 사용자는 필요에 따라 삽입된 텍스트를 수정하기 위해 전용 장소(탭스탑) 사이를 탐색/점프할 것으로 기대됩니다:

  • mini.snippets은 기본적으로 다음/이전 탭스탑으로 점프하기 위해 <C-l> / <C-h>를 사용합니다. MiniSnippets.config의 mappings에서 조정할 수 있습니다.

  • Neovim=0.10의 vim.snippet은 탭스탑 간의 점프를 위해 수동으로 생성된 매핑이 필요합니다(vim.snippet.jump() 참조). Neovim>=0.11은 사용자가 재정의하지 않는 한 자동으로 <Tab> / <S-Tab>으로 설정합니다.

마지막 탭스탑까지 모두 탐색하여 세션을 종료하세요. ’mini.snippets’에서:

  • 텍스트를 수정하거나 입력 모드를 나가도 세션이 종료됩니다. 이는 나중에 발견된 오타 수정을 위해 이전 탭스탑으로의 원활한 탐색을 가능하게 합니다.

  • 세션을 강제로 중단하려면 <C-c>를 누르세요.

매개변수

{snippet} (string) 커서 위치에 삽입할 스니펫 본문.

같이 보기

  • ’mini.snippets’가 설정된 경우 MiniSnippets-session.

  • Neovim 내장 스니펫 엔진인 vim.snippet.

get_lsp_capabilities()

MiniCompletion.get_lsp_capabilities({opts})

클라이언트 LSP 기능(capabilities) 가져오기

가능한 사용 사례:

  • Neovim>=0.11에서 vim.lsp.config()를 통해:

    vim.lsp.config('*', {capabilities = MiniCompletion.get_lsp_capabilities()})

  • 전체 클라이언트 기능을 가져오기 위해 vim.lsp.protocol.make_client_capabilities()와 함께 사용(테이블 병합을 위해 vim.tbl_deep_extend() 사용).

  • 정보를 확인하기 위해 수동으로 :=MiniCompletion.get_lsp_capabilities() 실행.

참고:

  • 'additionalTextEdits'(보통 자동 임포트와 같은 기능에 사용됨)에 대한 완성 해결(resolve) 지원을 선언합니다. 이는 다양한 LSP 서버에 대해 보통 더 견고한 선택이기 때문입니다. 결과적으로, 이는 완성 항목을 선택하고 config.delay.info 밀리초와 서버 응답 시간을 기다려야 함(즉, 정보 창에 관련 텍스트가 표시될 때까지)을 요구합니다. 항목 선택 후 기다리지 않으려면, 그리고 서버가 'additionalTextEdits'가 없을 때도 잘 처리한다면 opts.resolve_additional_text_edits = false로 설정하세요.

매개변수

{opts} (table|nil) 옵션. 가능한 필드:

  • <resolve_additional_text_edits> (boolean) - 'completionitem/resolve'

    요청에서 'additionalTextEdits'를 해결 가능한 것으로 선언할지 여부.

    위의 “참고” 섹션을 참조하세요. 기본값: true.

반환

(table) ’mini.completion’에서 지원하는 LSP 기능에 대한 데이터. vim.lsp.protocol.make_client_capabilities()의 관련 부분과 동일한 구조를 가집니다.
