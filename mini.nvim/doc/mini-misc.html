모듈

다음과 같은 기능들을 제공합니다:

  • MiniMisc.bench_time() - 함수 실행 시간을 벤치마킹합니다. stat_summary()와 함께 사용하면 유용합니다.

  • MiniMisc.log_add(), MiniMisc.log_show() 및 기타 헬퍼 함수 - 특별한 인메모리 로그 배열 작업을 위해 사용합니다. Lua 코드 디버깅 시 유용합니다.

  • MiniMisc.put() 및 MiniMisc.put_text() - 인수를 각각 명령줄과 현재 버퍼에 보기 좋게 출력합니다.

  • MiniMisc.resize_window() - 현재 창을 편집 가능한 너비로 조정합니다.

  • MiniMisc.safely() - 조건에 따라 함수를 실행하고 에러 발생 시 경고를 표시합니다. 간단한 지연 로딩을 사용하여 init.lua를 안전한 섹션으로 구성하는 데 유용합니다.

  • MiniMisc.setup_auto_root() - 현재 디렉토리 자동 변경을 설정합니다.

  • MiniMisc.setup_termbg_sync() - 터미널 배경색 동기화를 설정합니다 (현재 Neovim 인스턴스 주변의 발생 가능한 “프레임”을 제거함).

  • MiniMisc.setup_restore_cursor() - 파일 다시 열기 시 커서 위치 자동 복원을 설정합니다.

  • MiniMisc.stat_summary() - 숫자 배열의 통계 요약을 계산합니다. bench_time()과 함께 사용하면 유용합니다.

  • MiniMisc.tbl_head() 및 MiniMisc.tbl_tail() - 테이블의 “처음” 및 “마지막” 요소를 반환합니다.

  • MiniMisc.zoom() - 버퍼를 확대/축소하여 플로팅 창에서 전체 화면으로 만듭니다.

  • 기타 여러 기능.

설정

이 모듈은 설정이 필수는 아니지만, 사용 편의성을 위해 설정할 수 있습니다. require('mini.misc').setup({})을 통해 설정하세요 ({}를 사용자 config 테이블로 대체). 그러면 스크립팅이나 수동으로 사용할 수 있는 전역 Lua 테이블 MiniMisc가 생성됩니다 (예: :lua MiniMisc.*).

config 구조 및 기본값은 MiniMisc.config를 참조하세요.

이 모듈은 런타임 옵션이 없으므로 vim.b.minimisc_config를 사용해도 아무런 효과가 없습니다.

bench_time()

MiniMisc.bench_time({f}, {n}, {…})

f를 여러 번 실행하고 소요 시간을 측정합니다.

매개변수

{f} (function) 벤치마킹할 실행 함수.

{n} (number|nil) f(...)를 실행할 횟수. 기본값: 1.

{…} (any) f 호출 시의 인수들.

반환값

(...) 소요 시간(초 단위; 나노초까지)과 (마지막) 함수 실행 결과가 담긴 테이블.

log_add()

MiniMisc.log_add({desc}, {state}, {opts})

인메모리 로그 배열에 항목을 추가합니다.

Lua 코드(Neovim 설정 또는 플러그인 등)를 디버깅할 때 유용합니다. 임시 print() 문 대신 이것을 사용하세요.

각 항목은 다음 필드를 가진 테이블입니다:

  • <desc> (any) - 항목 설명. 보통 코드 내의 위치를 설명하는 문자열입니다.

  • <state> (any) - 현재 상태에 대한 데이터. 보통 테이블입니다.

  • <timestamp> (number) - 항목이 추가된 타임스탬프. 인메모리 로그가 시작된(MiniMisc.setup() 또는 MiniMisc.log_clear() 이후) 후의 밀리초 단위 시간입니다. 프로파일링 중에 유용합니다.

매개변수

{desc} (any) 항목 설명.

{state} (any) 현재 상태에 대한 데이터.

{opts} (table|nil) 옵션. 가능한 필드:

  • <deepcopy> - (boolean) {state}에 vim.deepcopy를 적용할지 여부. 보통 코드 실행 중 정확한 상태를 기록하고 테이블이 제자리에서 수정되어 발생하는 부작용을 피하는 데 도움이 됩니다. 기본값 true.

사용법

local t = { a = 1 }
MiniMisc.log_add('before', { t = t }) -- `t = { a = 1 }` 상태를 보여줌
t.a = t.a + 1
MiniMisc.log_add('after', { t = t })  -- `t = { a = 2 }` 상태를 보여줌

-- 로그를 보려면 `:lua MiniMisc.log_show()` 또는 `:=MiniMisc.log_get()`을 사용하세요.

참고

  • MiniMisc.log_get() - 로그 배열 가져오기

  • MiniMisc.log_show() - 전용 버퍼에 로그 배열 표시

  • MiniMisc.log_clear() - 로그 배열 비우기

safely()

MiniMisc.safely({when}, {f})

조건에 따라 함수를 실행하고 에러 발생 시 경고를 표시합니다.

입력 함수는 정확히 한 번 실행됩니다. 발생 가능한 에러는 캡처되어 vim.notify() 경고로 표시됩니다.

간단한 지연 로딩을 사용하여 init.lua를 안전한 섹션으로 구성하는 데 유용합니다.

매개변수

{when} (string) 함수를 실행할 시점. 다음 중 하나:

  • 'now' - 즉시.

  • 'later' - 파일의 다음 코드 실행을 방해하지 않고 곧 실행되도록 큐(queue)에 넣습니다. 대기 중인 함수는 추가된 순서대로 실행됩니다.

  • 'delay:<number>' - vim.defer_fn()을 사용하여 지정된 지연 시간 후에 실행.

  • 'event:<events>' - 지정된 이벤트 중 먼저 트리거되는 이벤트에서 실행.

  • 'event:<events>~<patterns> - 위와 같지만, 이벤트가 지정된 autocmd-pattern과 일치해야 합니다.

  • 'filetype:<filetypes>' - 'event:FileType~<filetypes>'와 같지만, 함수 실행 성공 후 모든 일반 버퍼에 대해 filetype-detect를 수행하고(새로운 ftdetect 스크립트가 추가된 경우) ftplugin을 소싱합니다 (<filetypes>와 일치하는 버퍼에 대해). “언어 플러그인” 로딩에 사용하도록 고안되었습니다.

{f} (function) 실행할 함수 (인수 없음).

사용법

MiniMisc.safely('later', function()
  vim.notify('이 메시지는 다음 "now" 호출 이후에 실행됩니다')
end)
MiniMisc.safely('now', function() error('이 에러는 경고로 표시됩니다') end)

MiniMisc.safely('event:InsertEnter', function()
  require('mini.completion').setup()
end)
MiniMisc.safely('event:CmdlineEnter~/', function()
  vim.notify('처음으로 검색을 시작합니다')
end)

MiniMisc.safely('filetype:tex,plaintex', function()
  -- LaTeX 작성을 개선하는 플러그인 로드
end)

setup_auto_root()

MiniMisc.setup_auto_root({names}, {fallback})

현재 디렉토리 자동 변경 설정

작동 방식:

  • 모든 BufEnter 이벤트에서 MiniMisc.find_root()를 사용하여 현재 버퍼 파일의 루트 디렉토리를 찾고 current-directory를 해당 디렉토리로 설정하는 자동 명령을 생성합니다 (chdir() 사용).

  • ‘autochdir’을 false로 초기화합니다.

매개변수

{names} (table|function|nil) MiniMisc.find_root()로 전달됩니다.

{fallback} (function|nil) MiniMisc.find_root()로 전달됩니다.

사용법

require('mini.misc').setup()
MiniMisc.setup_auto_root()

find_root()

MiniMisc.find_root({buf_id}, {names}, {fallback})

루트 디렉토리 찾기

버퍼 이름(버퍼에 열린 파일의 전체 경로)을 기반으로 루트 디렉토리를 찾습니다. 버퍼가 파일과 연결되어 있지 않으면 nil을 반환합니다.

루트 디렉토리는 미리 정의된 파일 중 적어도 하나를 포함하는 디렉토리입니다. 루트 파일이 처음 나타날 때까지 현재 버퍼 파일의 디렉토리부터 위쪽으로 upward = true 옵션과 함께 vim.fs.find()를 사용하여 검색합니다.

참고:

  • 계산 속도를 높이기 위해 디렉토리 경로 캐싱을 사용합니다. 즉, 이 함수에서 디렉토리 경로가 이미 사용된 후에는 루트 디렉토리의 변경 사항이 감지되지 않습니다. 이를 반영하려면 Neovim을 다시 로드하세요.

매개변수

{buf_id} (number|nil) 사용할 버퍼 식별자 (bufnr() 참조). 기본값: 0 (현재 창).

{names} (table|function|nil) 루트 디렉토리를 식별하는 데 사용되는 파일 이름 배열 또는 호출 가능한 객체. vim.fs.find()로 전달됩니다. 기본값: { '.git', 'Makefile' }.

{fallback} (function|nil) vim.fs.find()로 루트를 찾지 못한 경우 사용할 호출 가능한 폴백(fallback). 버퍼 경로와 함께 호출되며 유효한 디렉토리 경로를 반환해야 합니다.

setup_termbg_sync()

MiniMisc.setup_termbg_sync({opts})

터미널 배경색 동기화 설정

작동 방식:

  • 터미널 에뮬레이터가 적절한 stdout을 통해 OSC 11 제어 시퀀스를 지원하는지 확인합니다. 지원하지 않으면 중단합니다.

  • ColorScheme 및 VimResume 이벤트에 대한 자동 명령을 생성하여 터미널 배경색을 hl-Normal의 guibg와 동일한 색상으로 변경합니다.

  • VimLeavePre 및 VimSuspend 이벤트에 대한 자동 명령을 생성하여 터미널 배경색을 원래 색상으로 되돌립니다.

  • 로딩 순서에 의존하지 않도록 즉시 배경색을 동기화합니다.

주요 사용 사례는 Neovim의 hl-Normal 배경색이 터미널 에뮬레이터 자체에서 사용되는 것과 다를 때 나타나는 Neovim 인스턴스 주변의 “프레임”을 제거하는 것입니다.

Neovim>=0.10에서만 작동합니다.

매개변수

{opts} (table|nil) 옵션. 가능한 필드:

  • <explicit_reset> (boolean) - 터미널 배경색을 이 함수가 호출되었을 때의 색상으로 명시적으로 설정하여 리셋할지 여부. 터미널 에뮬레이터가 OSC 111 제어 시퀀스를 지원하지 않는 경우 true로 설정하세요. 기본값: false.

setup_restore_cursor()

MiniMisc.setup_restore_cursor({opts})

파일 열기 시 커서 위치 복원

파일을 다시 열 때 커서가 이전에 떠났던 위치에 놓이도록 합니다. 이는 restore-cursor를 더 세련된 방식으로 구현합니다. 파일은 인식된 파일 타입(‘filetype’ 참조)을 가져야 하며 일반 버퍼(‘buftype’ 참조)에서 열려야 합니다.

참고: ’shadafile’에 저장된 파일 마크 데이터에 의존합니다 (shada-f 참조). 이 기능을 활성화했는지 확인하세요.

매개변수

{opts} (table|nil) 옵션. 가능한 필드:

  • <center> - (boolean) 커서를 복원한 후 창을 중앙으로 정렬합니다. 기본값: true.

  • <ignore_filetype> - 무시할 파일 타입 배열 (‘filetype’ 참조). 기본값: { "gitcommit", "gitrebase" }.

사용법

require('mini.misc').setup_restore_cursor()

stat_summary()

MiniMisc.stat_summary({t})

숫자 배열의 통계 요약 계산

MiniMisc.bench_time()을 사용한 시간 벤치마킹 요약을 계산하는 데 유용할 수 있습니다.

매개변수

{t} (table) 숫자로 구성된 배열 (ipairs에 적합한 테이블).

반환값

(table) 다음 키 아래에 요약 값이 담긴 테이블 (향후 확장될 수 있음): <maximum>(최대값), <mean>(평균), <median>(중앙값), <minimum>(최소값), <n>(요소 수), <sd>(표본 표준 편차).

tbl_head()

MiniMisc.tbl_head({t}, {n})

pairs에 의해 결정된 테이블의 “처음” 요소들을 반환합니다.

참고: 요소의 순서는 다를 수 있습니다.

매개변수

{t} (table) 입력 테이블.

{n} (number|nil) 처음 요소의 최대 개수. 기본값: 5.

반환값

(table) t에서 최대 n개의 처음 요소(동일한 키 사용)가 담긴 테이블.

tbl_tail()

MiniMisc.tbl_tail({t}, {n})

pairs에 의해 결정된 테이블의 “마지막” 요소들을 반환합니다.

이 함수는 t의 요소들을 두 번 거칩니다:

  • 첫 번째는 요소의 개수를 세기 위해.

  • 두 번째는 결과를 생성하기 위해.

참고: 요소의 순서는 다를 수 있습니다.

매개변수

{t} (table) 입력 테이블.

{n} (number|nil) 마지막 요소의 최대 개수. 기본값: 5.

반환값

(table) t에서 최대 n개의 마지막 요소(동일한 키 사용)가 담긴 테이블.

use_nested_comments()

MiniMisc.use_nested_comments({buf_id})

중첩된 주석 리더 가능성 추가

이 함수는 ‘commentstring’ 버퍼 옵션을 파싱하여 공백이 아닌 주석 리더(주석 처리된 줄의 왼쪽에 있는 기호)를 추출하고, ‘comments’ 옵션을 로컬에서 수정(n:<leader>를 앞에 추가)하여 작동합니다. ’commentstring’이 비어 있거나 앞뒤에 모두 주석 기호가 있는 경우(예: “/%s/”) 아무 작업도 수행하지 않습니다.

이 함수로 추가된 중첩 주석 리더는 중첩된 주석의 포맷팅에 유용합니다. 예를 들어, Lua에서 ‘–’를 사용한 “1단계” 주석과’—-’를 사용한 “2단계” 주석이 있는 경우, 중첩 주석 리더를 사용하면 2단계 주석도 1단계와 동일하게 gq로 포맷팅할 수 있습니다.

권장되는 사용법은 autocmd를 사용하는 것입니다:

local use_nested_comments = function() MiniMisc.use_nested_comments() end
vim.api.nvim_create_autocmd('BufEnter', { callback = use_nested_comments })

참고: 대부분의 파일 타입에서 ‘commentstring’ 옵션은 해당 파일 타입의 버퍼에 들어갈 때만 추가되므로, 현재가 아닌 buf_id를 사용하면 원하는 효과를 얻지 못할 수 있습니다.

매개변수

{buf_id} (number|nil) 함수가 작동할 버퍼 식별자 (bufnr() 참조). 기본값: 0 (현재 창).

zoom()

MiniMisc.zoom({buf_id}, {config})

버퍼를 확대/축소하여 플로팅 창에서 전체 화면으로 만듭니다.

이 함수는 여러 창으로 작업하는 동안 해당 버퍼의 코드를 더 많이 보기 위해 일시적으로 확대가 필요할 때 유용합니다. 확대/축소를 해제하려면 (인수 없이) 다시 호출하세요.

매개변수

{buf_id} (number|nil) 확대할 버퍼 식별자 (bufnr() 참조). 기본값: 0 (현재 창).

{config} (table|nil) 창을 위한 선택적 설정 (nvim_open_win()과 동일).

반환값

(boolean) 현재 버퍼가 확대되었는지 여부.
