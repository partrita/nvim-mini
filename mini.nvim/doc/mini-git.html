mini.git 문서

_ ’mini.nvim’의 main 브랜치에서 생성됨 _

mini.git Git 통합

MIT 라이선스 Copyright (c) 2024 Evgeni Chasnovski

모듈

기능:

  • Git 관련 데이터 자동 추적: 루트 경로, 상태, HEAD 등. 상태줄(statusline)에서 편리하게 사용할 수 있도록 버퍼 로컬 변수를 노출합니다. 자세한 내용은 MiniGit.enable() 및 MiniGit.get_buf_data()를 참조하세요.

  • :Git 명령어: 현재 인스턴스와의 긴밀한 통합을 통해 파일의 저장소 루트 내에서 임의의 git 호출을 실행합니다 (출력을 알림/버퍼로 표시, 커밋 메시지 편집에 사용 등).

  • Git 히스토리를 조사하기 위한 헬퍼 함수:

    • MiniGit.show_range_history(): 특정 줄 범위가 어떻게 변해왔는지 보여줍니다.

    • MiniGit.show_diff_source(): diff 항목 시점의 파일 상태를 보여줍니다.

    • MiniGit.show_at_cursor(): 컨텍스트에 따라 Git 관련 데이터를 보여줍니다.

제공하지 않는 기능:

  • 모든 기능을 갖춘 Git 클라이언트를 대체하지 않습니다. 원칙: 기능이 현재 Neovim의 상태(열려 있는 버퍼 등)에 의존하지 않는다면 범위 밖입니다. 더 많은 기능이 필요한 경우 mini.diff를 사용하거나 모든 기능을 갖춘 Git 클라이언트를 사용하세요.

상세 정보 소스:

  • :Git

  • MiniGit-examples

  • MiniGit.enable()

  • MiniGit.get_buf_data()

설정

이 모듈은 require('mini.git').setup({})을 통한 설정이 필요합니다 ({}를 사용자 config 테이블로 대체). 그러면 스크립팅이나 수동으로 사용할 수 있는 전역 Lua 테이블 MiniGit이 생성됩니다 (예: :lua MiniGit.*).

config 구조와 기본값은 MiniGit.config를 참조하세요.

비교

  • tpope/vim-fugitive:

    • 주로 전용 Git 클라이언트인 반면, 이 모듈은 그렇지 않습니다 (의도된 설계).

    • 고정된 상태줄 구성 요소를 통해서만 버퍼 로컬 Git 데이터를 제공하지만, 이 모듈은 Lua 테이블 형태로 더 풍부한 데이터를 제공합니다.

    • 둘 다 :Git 명령어를 제공하지만, ’vim-fugitive’는 일부 사례(예: :Git blame 등)를 특별하게 처리하는 반면, 이 모듈은 대부분 모든 사례를 동일하게 처리합니다. 수동으로 사용자 정의하는 방법은 MiniGit-examples를 참조하세요. 또한 이 모듈은 약간 다른 (보통 더 풍부한) 자동 완성 제안을 제공합니다.

  • NeogitOrg/neogit:

    • ’tpope/vim-fugitive’와 유사하지만 :Git 명령어가 없습니다.

  • lewis6991/gitsigns.nvim:

    • 세부적인 diff 상태에 중점을 둔 버퍼 로컬 Git 데이터를 제공하지만, 이 모듈은 저장소 및 파일 레벨 데이터(루트, HEAD, 파일 상태 등)에 더 중점을 둡니다. diff 추적에는 mini.diff를 사용하세요.

비활성화

버퍼가 추적되지 않게 하려면 vim.g.minigit_disable(전역) 또는 vim.b.minigit_disable(버퍼별)을 true로 설정하세요. 다양한 시나리오와 사용자 정의 의도를 고려하여 모듈 기능 비활성화에 대한 정확한 규칙을 작성하는 것은 사용자의 몫으로 남겨둡니다. 일반적인 방법은 mini.nvim-disabling-recipes를 참조하세요.

예시

상태줄 구성 요소

추적된 버퍼 데이터는 vim.b.minigit_summary_string 버퍼 로컬 변수를 통해 상태줄에서 사용할 수 있습니다. 이는 있는 그대로 사용될 것으로 예상됩니다. 다른 정보를 표시하려면 MiniGitUpdated User 이벤트 내에서 버퍼 로컬 변수를 직접 수정하세요:

-- HEAD 이름만 요약 문자열로 사용
local format_summary = function(data)
  -- 버퍼 로컬 테이블 요약 활용
  local summary = vim.b[data.buf].minigit_summary
  vim.b[data.buf].minigit_summary_string = summary.head_name or ''
end

local au_opts = { pattern = 'MiniGitUpdated', callback = format_summary }
vim.api.nvim_create_autocmd('User', au_opts)

명령어 출력 조정

:Git 명령어의 버퍼 출력은 MiniGitCommandSplit User 이벤트의 자동 명령 내에서 조정할 수 있습니다 (MiniGit-command-events 참조). 예를 들어, :vertical Git blame -- % 명령어가 blame 출력을 현재 창 상태와 맞추도록 하려면 다음 코드를 사용하세요:

local align_blame = function(au_data)
  if au_data.data.git_subcommand ~= 'blame' then return end

  -- blame 출력을 소스와 맞춤
  local win_src = au_data.data.win_source
  vim.wo.wrap = false
  vim.fn.winrestview({ topline = vim.fn.line('w0', win_src) })
  vim.api.nvim_win_set_cursor(0, { vim.fn.line('.', win_src), 0 })

  -- 두 창을 묶어서 함께 스크롤되도록 함
  vim.wo[win_src].scrollbind, vim.wo.scrollbind = true, true
end

local au_opts = { pattern = 'MiniGitCommandSplit', callback = align_blame }
vim.api.nvim_create_autocmd('User', au_opts)

히스토리 탐색

MiniGit.show_at_cursor() 함수는 Git 히스토리 탐색을 쉽게 하기 위해 특별히 제공됩니다. 다음과 같은 다양한 방식으로 사용할 수 있습니다:

  • 이미 커밋된 파일의 버퍼 내에서 호출하여 현재 줄(또는 비주얼 모드로 선택된 범위)의 히스토리 진화를 보여줍니다. 이는 본질적으로 적절한 -L 플래그가 붙은 :Git log HEAD입니다. 이는 MiniGit.show_diff_source()의 출력 내부에서도 작동합니다.

  • 커밋 해시 위에서 호출하여 해당 커밋을 전체적으로 조사합니다. 이는 보통 :Git log 출력에서 유용합니다.

  • diff 항목 내에서 호출하여 특정 커밋 시점의 파일 상태를 조사합니다. 기본적으로 커밋 후의 상태를 보여주지만, 커서가 “삭제된” 줄(즉, “-”로 시작하는 줄)에 있는 경우 커밋 전의 상태를 보여줍니다.

이 워크플로우는 다음과 같이 매핑을 사용하면 더 대화형으로 만들 수 있습니다:

local rhs = '<Cmd>lua MiniGit.show_at_cursor()<CR>'
vim.keymap.set({ 'n', 'x' }, '<Leader>gs', rhs, { desc = 'Show at cursor' })

:Git

:Git 사용자 명령어는 현재 열려 있는 Neovim 프로세스와의 추가 통합을 통해 git CLI 호출을 실행합니다:

  • 명령어는 현재 활성화된 파일의 저장소 루트 내에서 실행됩니다 (파일이 이 모듈에 의해 추적되지 않는 경우 현재 디렉토리(current-directory) 내에서 실행됨).

  • 명령어 출력은 창 분할 내의 전용 버퍼 또는 vim.notify()를 통한 알림으로 표시됩니다. 어떤 방식이 사용될지는 특정 Git 하위 명령어가 사용자가 조사할 데이터를 보여주기로 되어 있는지(log, status 등) 아니면 그렇지 않은지(commit, push 등)에 따라 결정됩니다. 이는 Git 자체가 제공하는 데이터를 기반으로 자동으로 결정됩니다. 명령어 실행 후 분할 창이 현재 창이 됩니다.

    출력을 특정 유형의 분할로 강제하려면 분할 관련 :command-modifiers (:vertical, :horizontal, 또는 :tab)를 사용하세요. 기본 분할 방향은 MiniGit.config의 command.split에 의해 제어됩니다.

    출력을 전혀 표시하지 않으려면 :silent 명령 수식어를 사용하세요.

    에러와 경고는 항상 알림으로 표시됩니다.

    명령어 출력을 조정하는 예시는 MiniGit-examples를 참조하세요.

  • 대화형 사용자 입력이 필요한 작업(예: :Git commit 또는 :Git rebase --interactive)을 위한 편집기는 현재 세션 내의 별도 분할 창에서 열립니다. 일반 버퍼에서와 같이 수정하고, :write로 변경 사항을 저장한 후 :close / :quit을 실행하면 Git CLI 명령어가 재개됩니다.

사용 예시:

  • :Git log --oneline: 현재 저장소의 요약 로그 표시.

  • :vert Git blame -- %: 수직 분할 창에서 줄별 최신 커밋 표시.

  • :Git help rebase: rebase 하위 명령에 대한 도움말 페이지 표시.

  • :Git -C <cwd> status: 현재 디렉토리(current-directory) 내에서 git status 실행.

<Tab> 키로 호출할 수 있는 컨텍스트 인식 자동 완성도 제공됩니다:

  • 완성할 단어가 “-”로 시작하면 현재 Git 하위 명령에 대한 옵션이 표시됩니다. 예를 들어 :Git log -에서 자동 완성을 하면 -L, --oneline 등이 제안됩니다.

  • 커서 왼쪽에 명시적인 ” – “가 있으면 점진적인 경로 제안이 표시됩니다.

  • 아직 인식된 Git 하위 명령이 없으면 하위 명령 목록을 보여줍니다. 그렇지 않으면 일부 일반적인 하위 명령의 경우 대상 목록이 제안됩니다. 예: :Git branch의 경우 브랜치 목록 등.

참고 사항:

  • 경로는 항상 명령어 실행 디렉토리(파일의 저장소 루트 또는 없는 경우 현재 디렉토리(current-directory))에 대한 상대 경로로 처리됩니다.

  • 공백이 포함된 항목에 따옴표를 사용하지 말고, 직접 \로 이스케이프하세요. 예: :Git commit -m Hello\ world ( :Git commit -m 'Hello world'는 'Hello와 world'를 별개의 인수로 취급하므로 사용하지 마세요).

이벤트

MiniGit-command-events

명령어 실행 중에 트리거되는 여러 User 이벤트가 있습니다:

  • MiniGitCommandDone: 명령어 실행이 완료된 후. Lua 콜백의 경우 다음과 같은 필드를 가진 특수 data 테이블을 제공합니다:

    • <cmd_input> (table): 실행된 명령어에 대한 구조화된 데이터. nvim_create_user_command()의 Lua 함수 입력과 동일한 구조를 가집니다.

    • <cwd> (string): Git 명령어가 실행된 디렉토리 경로.

    • <exit_code> (number): CLI 프로세스의 종료 코드.

    • <git_command> (table): 실행된 전체 명령어의 인수가 포함된 배열.

    • <git_subcommand> (string): 감지된 Git 하위 명령 (예: “log” 등).

    • <stderr> (string): 프로세스의 stderr 출력.

    • <stdout> (string): 프로세스의 stdout 출력.

  • MiniGitCommandSplit: 명령어가 분할 창에 출력을 표시한 후. MiniGitCommandDone 이후에 트리거되며, 추가 필드가 포함된 유사한 data 테이블을 제공합니다:

    • <win_source> (number): “소스” 창(명령 실행 직전의 현재 창)의 식별자.

    • <win_stdout> (number): 명령어 출력 창의 식별자.

setup()

MiniGit.setup({config})

모듈 설정

일반적인 부수 효과( mini.nvim 참조) 외에도 다음을 수행합니다:

  • 디스크에 있는 실제 파일에 대해 모든 일반 버퍼에서 자동 활성화를 설정합니다.

  • :Git 명령어를 생성합니다.

매개변수

{config} (table|nil) 모듈 설정 테이블. MiniGit.config를 참조하세요.

사용법

require('mini.git').setup() -- 기본 설정 사용
-- 또는
require('mini.git').setup({}) -- {}를 사용자 설정 테이블로 대체

config

MiniGit.config

기본값

MiniGit.config = {
  -- 일반 CLI 실행
  job = {
    -- Git 실행 파일 경로
    git_executable = 'git',

    -- 강제 종료 전까지 각 작업의 타임아웃 (ms 단위)
    timeout = 30000,
  },

  -- `:Git` 명령어 옵션
  command = {
    -- 기본 분할 방향
    split = 'auto',
  },
}

작업(Job)

config.job은 CLI 실행을 사용자 정의하기 위한 옵션을 포함합니다.

job.git_executable은 Git 실행 파일의 전체 경로를 정의합니다. 기본값: “git”.

job.timeout은 작업 시작부터 강제로 중단될 때까지의 기간(ms 단위)입니다. 기본값: 30000.

명령어(Command)

config.command는 :Git 명령어를 사용자 정의하기 위한 옵션을 포함합니다.

command.split은 :Git 명령어 출력의 기본 분할 방향을 정의합니다. “horizontal”, “vertical”, “tab”, “auto” 중 하나일 수 있습니다. “auto” 값은 탭페이지에 ‘mini.git’ 버퍼만 표시되는 경우 :vertical을 사용하고, 그렇지 않으면 :tab을 사용합니다. 기본값: “auto”.

show_at_cursor()

MiniGit.show_at_cursor({opts})

커서 위치의 Git 관련 데이터 표시

  • mini.deps 확인 버퍼 내부인 경우, 분할 창에 관련 커밋 데이터를 표시합니다.

  • 커밋 형태의 <cword>가 있으면 분할 창에 표시합니다.

  • 가능하다면 MiniGit.show_diff_source()를 통해 diff 소스를 표시합니다.

  • 가능하다면 MiniGit.show_range_history()를 통해 범위 히스토리를 표시합니다.

  • 그렇지 않으면 에러를 발생시킵니다.

매개변수

{opts} (table|nil) 옵션. 가능한 값:

  • <split> (string): 분할 방향. “horizontal”, “vertical”, “tab”, “auto”(기본값) 중 하나. “auto” 값은 탭페이지에 ‘mini.git’ 버퍼만 표시되는 경우 :vertical을 사용하고, 그렇지 않으면 :tab을 사용합니다.

  • 다른 함수로 전달하기에 적절한 필드들.

show_diff_source()

MiniGit.show_diff_source({opts})

diff 소스 표시

버퍼에 통합 패치(unified patch) 형식의 텍스트가 포함된 경우 (예: :Git log --patch, :Git diff, MiniGit.show_range_history() 이후), 특정 시점의 파일 상태를 보여줍니다. 대상 커밋/상태, 경로 및 줄 번호는 커서 위치에서 추론됩니다.

참고 사항:

  • 상대 경로가 작동하려면 현재 디렉토리(current-directory)가 Git 루트여야 합니다.

  • 커서가 헌크(hunk) 줄 내부 또는 경로가 있는 “—” / “+++” 줄 위에 있어야 합니다.

  • :Git diff 출력의 기본 형식만 지원됩니다: :Git diff, :Git diff --cached, :Git diff <commit>.

매개변수

{opts} (table|nil) 옵션. 가능한 값:

  • <split> (string): 분할 방향. “horizontal”, “vertical”, “tab”, “auto”(기본값) 중 하나. “auto” 값은 탭페이지에 ‘mini.git’ 버퍼만 표시되는 경우 :vertical을 사용하고, 그렇지 않으면 :tab을 사용합니다.

  • <target> (string): 어떤 파일 상태를 보여줄지 설정. “before”, “after”, “both” (수직 분할로 두 상태 모두 표시), “auto”(기본값) 중 하나. “auto” 값은 커서 줄이 “-”로 시작하면 “before” 상태를, 그렇지 않으면 “after” 상태를 보여줍니다.

show_range_history()

MiniGit.show_range_history({opts})

범위 히스토리 표시

현재 버퍼의 특정 줄 범위가 Git 히스토리를 통해 어떻게 변해왔는지에 대한 데이터를 계산하고 분할 창에 표시합니다. 본질적으로 -L 플래그가 붙은 git log입니다.

참고 사항:

  • MiniGit.diff_foldexpr()와 잘 작동합니다.

  • 유효한 줄 범위를 계산하기 쉽지 않으므로, 커밋되지 않은 변경 사항이 있는 경우에는 작동하지 않습니다.

매개변수

{opts} (table|nil) 옵션. 가능한 필드:

  • <line_start> (number): 범위 시작 줄.

  • <line_end> (number): 범위 끝 줄. <line_start>와 <line_end>가 모두 제공되지 않으면 노멀 모드에서는 현재 줄이, 비주얼 모드에서는 비주얼 선택 영역이 기본값이 됩니다.

  • <log_args> (table): git log 호출에 추가할 옵션 배열.

  • <split> (string): 분할 방향. “horizontal”, “vertical”, “tab”, “auto”(기본값) 중 하나. “auto” 값은 탭페이지에 ‘mini.git’ 버퍼만 표시되는 경우 :vertical을 사용하고, 그렇지 않으면 :tab을 사용합니다.

diff_foldexpr()

MiniGit.diff_foldexpr({lnum})

Git 로그를 위한 접기 표현식

통합 diff(unified diff)에서 헌크(hunk), 파일 패치 및 로그 항목의 내용을 접습니다. “diff” (예: :Git diff 이후) 및 “git” (예: :Git log --patch 또는 커밋에 대한 :Git show 이후) 파일 유형에 유용합니다. MiniGit.show_range_history()와 잘 작동합니다.

접기 레벨의 일반적인 개념 ( zr 및 zm을 사용하여 대화형으로 조정 가능):

  • 레벨 0에서는 전체 패치 또는 로그 항목당 한 줄이 표시됩니다.

  • 레벨 1에서는 패치된 파일당 한 줄이 표시됩니다.

  • 레벨 2에서는 헌크(hunk)당 한 줄이 표시됩니다.

  • 레벨 3에서는 접기가 없습니다.

자동 설정을 위해 “git” 및 “diff” 파일 유형에 대해 다음과 같이 설정하세요 ( FileType 자동 명령 또는 ftplugin 내부):

setlocal foldmethod=expr foldexpr=v:lua.MiniGit.diff_foldexpr()

매개변수

{lnum} (number|nil) 접기 레벨이 계산되는 줄 번호. 기본값: v:lnum.

반환값

(number|string) 줄 접기 레벨. fold-expr을 참조하세요.

enable()

MiniGit.enable({buf_id})

파일 버퍼에서 Git 추적 활성화

추적은 파일 내용 또는 파일 저장소의 변경에 반응하여 버퍼 데이터를 최신 상태로 유지함으로써 수행됩니다. 데이터는 다음을 통해 사용할 수 있습니다:

  • MiniGit.get_buf_data(): 실제로 추적되는 데이터 목록은 해당 도움말을 참조하세요.

  • vim.b.minigit_summary (테이블) 및 vim.b.minigit_summary_string (문자열) 버퍼 로컬 변수: 상태줄에 더 적합합니다. vim.b.minigit_summary_string은 HEAD, 파일 상태 및 진행 중인 작업에 대한 정보를 포함합니다 (자세한 내용은 MiniGit.get_buf_data() 참조). 상태줄에서 조정하고 사용하는 방법은 MiniGit-examples를 참조하세요.

참고: 이 함수는 모든 새로운 일반 버퍼에 대해 자동으로 호출됩니다. 버퍼가 비활성화된 경우 명시적으로 호출하세요.

추적 데이터가 업데이트될 때마다 User 이벤트 MiniGitUpdated가 트리거됩니다. 이벤트가 트리거되는 시점에 MiniGit.get_buf_data()에 나열된 모든 데이터가 (아직) 존재하지 않을 수도 있습니다.

매개변수

{buf_id} (number) 대상 버퍼 식별자. 기본값: 현재 버퍼의 경우 0.

get_buf_data()

MiniGit.get_buf_data({buf_id})

버퍼 데이터 가져오기

매개변수

{buf_id} (number) 대상 버퍼 식별자. 기본값: 현재 버퍼의 경우 0.

반환값

(table|nil) 버퍼의 Git 데이터가 포함된 테이블 또는 버퍼가 활성화되지 않은 경우 nil. 파일이 Git 저장소의 일부가 아닌 경우 테이블은 비어 있습니다. 테이블에는 다음 필드가 있습니다:

  • <repo> (string): ‘.git’ 디렉토리의 전체 경로.

  • <root> (string): 워킹 트리 루트의 전체 경로.

  • <head> (string): 현재 HEAD의 전체 커밋.

  • <head_name> (string): 현재 HEAD의 짧은 이름 (예: “master”). 분리된(detached) HEAD인 경우 “HEAD”입니다.

  • <status> (string): git status에 의해 반환된 두 문자 파일 상태.

  • <in_progress> (string): 현재 진행 중인 작업의 이름 (bisect, merge 등). “,”로 구분된 여러 작업의 조합일 수 있습니다.
