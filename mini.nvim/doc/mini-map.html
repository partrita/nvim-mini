mini.map 문서

_ ’mini.nvim’의 main 브랜치에서 생성됨 _

mini.map 버퍼 텍스트 개요 창

MIT 라이선스 Copyright (c) 2022 Evgeni Chasnovski

모듈

주요 기능:

  • 현재 버퍼 텍스트의 자동으로 업데이트되는 개요를 표시하는 특수 플로팅 창(floating window)을 표시하고 관리합니다. 창은 Neovim 인스턴스의 전체 높이를 차지하며 왼쪽 또는 오른쪽 사이드에 고정됩니다. 맵 콘텐츠는 현재 모든 줄을 가져와 이진 화이트스페이스/논-화이트스페이스 마스크로 변환하고, 적절한 차원으로 리스케일링한 후, 특수 인코딩 심볼로 구성된 문자열로 다시 변환하여 계산됩니다. 이 모든 작업은 매우 빠르고 비동기적으로 수행됩니다. MiniMap.open(), MiniMap.refresh(), MiniMap.close(), MiniMap.toggle(), MiniMap.toggle_side()를 참조하세요. 일반적인 개요와 팁은 mini.map-usage를 참조하세요.

  • 맵 콘텐츠 옆에 스크롤바(scrollbar)를 표시합니다. 이는 현재 줄과 뷰(상단 및 하단에 표시되는 줄)를 나타냅니다. 표시되는 유일한 항목이 될 수 있어 맵 창을 “순수 스크롤바”로 만들 수도 있습니다. MiniMap.config의 “Pure scrollbar config” 섹션을 참조하세요.

  • 현재 버퍼의 특정 데이터를 나타내는 맵 라인을 하이라이트합니다. 이는 통합(integrations)이라 불리는 확장 가능한 콜러블(callable) 세트를 통해 수행됩니다 (MiniMap.config의 “Integrations” 섹션 참조). 일반적인 통합을 위해 사전 구축된 생성기가 있습니다:

    • 내장 검색 (/ 및 유사한 결과).

    • 내장 진단 (vim.diagnostic.get()에서 가져옴).

    • mini.diff에서 제공하는 일반 diff 헝크(hunks).

    • ’lewis6991/gitsigns.nvim’에서 제공하는 헝크. 자세한 내용은 MiniMap.gen_integration을 참조하세요.

  • 맵 창에 포커스하여 현재(소스) 버퍼를 빠르게 탐색합니다. 맵 창 내부에서 이동하면 소스 창의 커서 위치가 업데이트되어 빠르고 타겟팅된 버퍼 탐색이 가능합니다. 다시 포커스하려면 현재 탐색된 위치를 수락하기 위해 <CR>을 누르거나 원래 위치로 돌아가기 위해 <Esc>를 누르세요. MiniMap.toggle_focus()를 참조하세요.

  • MiniMap.config 및/또는 MiniMap.open() 또는 MiniMap.refresh()의 opts 인수를 통해 사용자 정의 가능:

    • 서로 다른 해상도의 이진 정보를 표시하는 데 사용되는 인코딩 심볼(기본값은 3x2). 다양한 기본 문자 패밀리 및 해상도에 대한 사전 구축된 생성기가 있습니다. MiniMap.gen_encode_symbols를 참조하세요.

    • 줄과 뷰에 대해 별도의 스크롤바 심볼. 어떤 너비든 가질 수 있습니다(스크롤바를 사실상 비활성화하는 너비 0 포함).

    • 맵 라인 하이라이트를 생성하는 통합.

    • 창 옵션: 사이드(왼쪽/오른쪽), 너비, ‘winblend’ 등.

하지 않는 것:

  • Insert 모드에서 입력할 때 자동으로 새로 고치지 않습니다. 논-블로킹(non-blocking) 방식으로 수행할 수 있지만 여전히 상당한 계산 오버헤드를 유발할 수 있습니다(특히 매우 큰 파일에서).

  • 유연한 창 구성을 제공하지 않습니다. 전체 높이의 플로팅 창이 기본 버퍼의 시야를 가리는 경우, MiniMap.toggle() 또는 MiniMap.toggle_side()를 사용하세요. 글로벌 상태표시줄(global statusline)과 함께 사용할 때 가장 잘 작동합니다.

  • 자동 열기 기능을 제공하지 않습니다. 맵 창이 표시되어야 하는 시점에 대한 사용자 선호도가 매우 다양하므로 자동 열기 설정은 사용자에게 맡깁니다. 일반적인 접근 방식은 VimEnter 이벤트에서 MiniMap.open()을 호출하는 것입니다. mini.starter를 사용하는 경우 <CR> 버퍼 매핑을 수정할 수 있습니다:

    local set_map_keymap = function()
  local rhs = function()
    MiniStarter.eval_current_item()
    MiniMap.open()
  end
  -- Enter 키를 누르면 현재 항목을 실행하고 미니맵을 엽니다
  vim.keymap.set('n', '<CR>', rhs, { buffer = true })
end
local opts = { pattern = 'MiniStarterOpened', callback = set_map_keymap }
-- MiniStarter가 열렸을 때 매핑을 설정합니다
vim.api.nvim_create_autocmd('User', opts)

설정

이 모듈은 require('mini.map').setup({})으로 설정이 필요합니다 ({}를 config 테이블로 교체하세요). 스크립팅이나 수동으로 사용할 수 있는 글로벌 Lua 테이블 MiniMap을 생성합니다 (:lua MiniMap.* 사용).

사용 가능한 구성 설정은 MiniMap.config를 참조하세요.

런타임 구성 설정(예: config.modifiers)을 vim.b.minimap_config 내부의 버퍼에 로컬로 재정의할 수 있으며, 이는 MiniMap.config와 동일한 구조여야 합니다. 자세한 내용은 mini.nvim-buffer-local-config를 참조하세요.

의존성

권장 의존성 (통합을 위한 추가 기능 제공):

  • MiniMap.gen_integration.diff()를 통한 일반 diff 하이라이팅을 위해 활성화된 mini.diff 모듈. 없는 경우 하이라이팅이 추가되지 않습니다.

  • MiniMap.gen_integration.gitsigns()를 통한 Git 상태 하이라이팅을 위한 lewis6991/gitsigns.nvim 플러그인. 없는 경우 하이라이팅이 추가되지 않습니다.

비교

  • wfxr/minimap.vim:

    • ’mini.map’은 Rust 의존성이 있는 ’minimap.vim’만큼 빠르면서도 의존성이 없습니다.

    • ’mini.map’은 플로팅 창을 사용하는 반면 ’minimap.vim’은 일반 창을 사용합니다.

    • ’mini.map’은 스크롤바와 통합 카운트가 있는 약간 다른 시각적 인터페이스를 제공합니다.

    • ’mini.map’은 인코딩 심볼 사용자 정의를 허용하지만 ’minimap.vim’은 허용하지 않습니다.

    • ’mini.map’은 하이라이트 통합 확장을 허용하는 반면, ’minimap.vim’은 내장 검색 및 git 상태만 지원합니다.

    • ’mini.map’은 비동기(논-블로킹) 방식으로 업데이트되지만 ’minimap.vim’은 그렇지 않습니다.

    • ’mini.map’은 순수 스크롤바로 사용할 수 있지만 ’minimap.vim’은 그렇지 않습니다.

  • dstein64/nvim-scrollview:

    • ’mini.map’은 현재 줄과 뷰(가변 높이)를 보여주는 두 부분으로 된 스크롤바를 사용하는 반면, ’nvim-scrollview’는 현재 뷰(고정 높이)만 보여줍니다.

    • ’nvim-scrollview’는 폴드(folds)를 존중하여 표시되는 줄의 뷰를 보여주는 반면, ’mini.map’은 설계상 항상 실제 줄을 기반으로 뷰를 보여줍니다.

    • ’nvim-scrollview’는 마우스로 드래그할 수 있는 스크롤바를 생성하지만 ’mini.nvim’은 설계상 그렇지 않습니다 (MiniMap.toggle_focus() 사용).

    • ’mini.map’은 버퍼 윤곽선(outline)을 보여줄 수 있지만 ’nvim-scrollview’는 그렇지 않습니다.

    • ’mini.map’은 통합 하이라이트를 보여줄 수 있지만 ’nvim-scrollview’는 그렇지 않습니다.

  • petertriho/nvim-scrollbar:

    • ’mini.map’은 현재 줄과 뷰(가변 높이)를 보여주는 두 부분으로 된 스크롤바를 사용하는 반면, ’nvim-scrollbar’는 현재 뷰만 보여줍니다.

    • ’mini.map’은 버퍼 윤곽선을 보여줄 수 있지만 ’nvim-scrollbar’는 그렇지 않습니다.

    • ’mini.map’은 완전히 확장 가능한 통합 하이라이트를 제공하지만, ’nvim-scrollbar’는 진단 및 검색(의존성 필요)만 지원합니다.

  • lewis6991/satellite.nvim:

    • ’dstein64/nvim-scrollview’와 거의 동일한 차이점이 있지만, ’satellite.nvim’은 일부 통합 하이라이트를 표시할 수 있습니다.

하이라이트 그룹

  • MiniMapNormal - 전체 창의 기본 하이라이트.

  • MiniMapSymbolCount - 라인별 통합 항목의 수.

  • MiniMapSymbolLine - 현재 줄을 나타내는 스크롤바 부분.

  • MiniMapSymbolView - 현재 뷰를 나타내는 스크롤바 부분.

하이라이트 그룹을 변경하려면 nvim_set_hl()을 사용하여 직접 설정하세요.

비활성화

비활성화하려면 vim.g.minimap_disable(전역) 또는 vim.b.minimap_disable(버퍼용)을 true로 설정하세요. 다양한 시나리오와 사용자 정의 의도를 고려하여 모듈 기능 비활성화를 위한 정확한 규칙 작성은 사용자의 몫으로 남겨둡니다. 일반적인 레시피는 mini.nvim-disabling-recipes를 참조하세요.

사용법

매핑

이 모듈은 매핑을 생성하지 않으며 사용자가 수동으로 매핑할 수 있는 함수만 제공합니다. 다음은 한 가지 <Leader> 매핑 세트의 예입니다:

vim.keymap.set('n', '<Leader>mc', MiniMap.close)
vim.keymap.set('n', '<Leader>mf', MiniMap.toggle_focus)
vim.keymap.set('n', '<Leader>mo', MiniMap.open)
vim.keymap.set('n', '<Leader>mr', MiniMap.refresh)
vim.keymap.set('n', '<Leader>ms', MiniMap.toggle_side)
vim.keymap.set('n', '<Leader>mt', MiniMap.toggle)

자동 새로고침 작동 방식

자동 새로고침은 적절한 이벤트가 발생할 때 MiniMap.refresh()를 호출하여 수행됩니다. 불필요한 계산을 피하기 위해 특별히 선택된 parts 인수 값으로 수행됩니다. 예를 들어, 커서만 이동한 경우(CursorMoved), 스크롤바만 업데이트되며 통합이나 라인 인코딩의 재계산은 수행되지 않습니다.

시각적 혼란을 피하기 위해 자동 새로고침은 일반 버퍼와 도움말 페이지(즉, ‘buftype’이 비어 있거나 “help”인 경우)에서만 수행됩니다.

콘텐츠가 최신 상태가 아니라고 생각되면 다음 중 하나를 시도해 보세요:

  • MiniMap.refresh()를 수동으로 호출합니다. 더 쉽게 사용할 수 있도록 매핑을 만드세요.

  • 현재 버퍼를 저장합니다(예: :write 사용).

  • Normal 모드를 나갔다 다시 들어갑니다(Neovim 버전이 ModeChanged를 지원하는 경우).

setup()

MiniMap.setup({config})

모듈 설정

매개변수

{config} (table|nil) 모듈 구성 테이블. MiniMap.config를 참조하세요.

사용법

require('mini.map').setup() -- 기본 구성 사용
-- 또는
require('mini.map').setup({}) -- {}를 사용자 구성 테이블로 교체

config

MiniMap.config

기본값

MiniMap.config = {
  -- 하이라이트 통합 (기본적으로 없음)
  integrations = nil,

  -- 데이터 표시에 사용되는 심볼
  symbols = {
    -- 인코딩 심볼. 사양은 `:h MiniMap.config`를,
    -- 사전 구축된 항목은 `:h MiniMap.gen_encode_symbols`를 참조하세요.
    -- 기본값: 3x2 해상도의 속이 찬 블록.
    encode = nil,

    -- 뷰와 줄을 위한 스크롤바 부분. 비활성화하려면 빈 문자열을 사용하세요.
    scroll_line = '█',
    scroll_view = '┃',
  },

  -- 창 옵션
  window = {
    -- 창을 일반적인 방식(`wincmd` 또는 마우스)으로 포커스할 수 있는지 여부
    focusable = false,

    -- 고정할 사이드 ('left' 또는 'right')
    side = 'right',

    -- 다중 통합 하이라이트의 개수를 표시할지 여부
    show_integration_count = true,

    -- 총 너비
    width = 10,

    -- 'winblend' 옵션 값
    winblend = 25,

    -- Z-index
    zindex = 10,
  },
}

심볼

config.symbols의 옵션은 맵 창에 다양한 정보를 표시하는 데 사용되는 문자를 정의합니다.

인코딩 심볼

config.symbols.encode 옵션은 소스 버퍼 라인을 인코딩하는 데 사용되는 문자를 정의합니다. 인코딩 알고리즘에 대한 자세한 내용은 MiniMap.encode_strings()를 참조하세요.

이 옵션은 다음과 같은 구조의 테이블이어야 합니다:

  • <resolution> 필드 - 각 심볼의 행과 열 해상도를 갖는 <row> 및 <col> 요소를 포함하는 테이블. 이는 인코딩 구조와 필요한 인코딩 심볼 수를 정의합니다.

  • 숫자 필드 1, 2, …, 2^(row_resolution * col_resolution). 각 심볼은 (row_resolution, col_resolution) 불리언 마스크(화이트스페이스가 아니면 true, 화이트스페이스면 false)를 나타내며, (역순) 이진 숫자로 생성됩니다: true는 1, false는 0. 왼쪽에서 오른쪽으로, 위에서 아래로 순회합니다(왼쪽 상단이 최하위 비트, 오른쪽 하단이 최상위 비트). 따라서 첫 번째 심볼은 완전한 화이트스페이스를, 마지막 심볼은 완전한 논-화이트스페이스를 인코딩합니다.

nil(기본값)인 경우, '3x2' 식별자가 있는 MiniMap.gen_encode_symbols.block()의 출력이 사용됩니다.

예: { ‘1’, ‘2’, ‘3’, ‘4’, resolution = { row = 1, col = 2 } }. 이는 각 입력 행에서 두 문자를 인코딩합니다. 따라서 문자열 ' a aaa'는 '1234'로 인코딩됩니다.

사전 구축된 인코딩 심볼 생성기가 있습니다:

  • MiniMap.gen_encode_symbols.block()

  • MiniMap.gen_encode_symbols.dot()

  • MiniMap.gen_encode_symbols.shade()

스크롤바 심볼

config.symbols.scroll_line 및 config.symbols.scroll_view 옵션은 맵 창 내부에서 현재 줄과 현재 뷰를 나타내는 데 사용되는 문자열을 정의합니다. 길이에 제한이 없으며 맵 창 콘텐츠가 이에 맞춰 조정됩니다.

제공된 창 너비가 작아서 스크롤바의 (일부)만 표시될 수 있는 경우 이를 “순수 스크롤바(pure scrollbar)”라고 합니다. 동작은 일반 맵 창과 약간 다릅니다. 나중에 나오는 “Pure scrollbar config” 섹션을 참조하세요.

스크롤바 심볼에 대한 몇 가지 제안:

  • 뷰-라인 쌍: ‘▒’ 및 ‘█’.

  • 라인 - ‘🮚’, ‘▶’.

  • 뷰 - ‘╎’, ‘┋’, ‘┋’.

통합

config.integrations 옵션은 통합 배열입니다. 각 통합은 소스 버퍼의 일부 중요한 라인을 나타내는 맵 라인 하이라이트를 정의하는 데 사용됩니다. nil(기본값)인 경우 통합이 사용되지 않습니다.

각 통합은 하이라이트하려는 소스 버퍼 라인에 대한 데이터 배열을 반환하는 콜러블이어야 합니다. 각 배열 요소는 <line> (소스 버퍼 라인 번호) 및 <hl_group> (하이라이트 그룹 이름이 포함된 문자열) 키가 있는 테이블이어야 합니다. 참고: 소스 버퍼 범위를 벗어난 라인 번호는 가장 가까운 적절한 라인 번호로 변환됩니다.

단일 통합의 출력 예:

{
  { line = 1, hl_group = 'Search' },
  { line = 2, hl_group = 'Operator' },
  { line = 9, hl_group = 'Search'}
}

맵 하이라이트로의 변환은 “먼저 발견된” 기준(first seen basis)으로 수행됩니다: 맵 라인에 적용되는 실제 하이라이트 그룹은 해당 맵 라인으로 변환 가능한 첫 번째 통합 출력에서 가져옵니다. 동일한 맵 라인을 갖는 다른 출력(변환 후)은 스크롤바와 인코딩된 라인 사이에 표시되는 통합 카운트에 기여합니다 (config.window.show_integration_count가 true인 경우).

이전 예제 출력은 기본 '3x2' 해상도에서 맵 라인 1과 3에 hl-Search 하이라이트를 추가하고, 첫 번째 라인에 통합 카운트 2를 표시합니다.

통합 배열의 모든 요소는 시작부터 끝까지 하나씩 호출되며 그 출력은 단일 배열의 끝에 추가됩니다. 즉, 다른 통합이 동일한 맵 라인을 하이라이트할 경우 우선순위가 더 높아야 하는 더 중요한 통합을 배열의 처음에 배치해야 합니다.

config.integrations 사용 예:

local map = require('mini.map')
map.setup({
  integrations = {
    map.gen_integration.builtin_search(),
    map.gen_integration.diff(),
    map.gen_integration.diagnostic(),
  },
})

창 구성

config.window 옵션은 맵 창의 일부 속성을 정의합니다.

window.focusable - MiniMap.toggle_focus() 이외의 다른 방법(:wincmd, CTRL-W 또는 마우스)으로 맵 창에 포커스할 수 있는지 여부. 기본값: false.

window.side - 맵 창을 고정할 사이드: 'left' 또는 'right' (기본값).

window.show_integration_count - 스크롤바와 인코딩된 라인 사이에 통합 카운트를 표시할지 여부. 통합 카운트는 동일한 맵 라인으로 변환된 통합 출력의 수입니다. true인 경우 2에서 9까지의 숫자와 9보다 큰 카운트를 나타내는 문자 ’+’가 있는 단일 셀 열을 추가합니다. 카운트 1은 하이라이트된 맵 라인으로 충분하므로 표시되지 않습니다. 기본값: true.

window.width - 스크롤바 및 통합 카운트 열을 포함한 플로팅 창의 너비. 기본값: 10.

window.winblend - 플로팅 창의 ‘winblend’ 값. 0은 완전히 불투명하게, 100은 완전히 투명하게 만듭니다(콘텐츠는 여전히 보이지만 하이라이트가 약간 다름).

window.zindex - 플로팅 창의 z-index. 기본값: 10.

순수 스크롤바 구성

“순수 스크롤바(Pure scrollbar)”는 창 너비가 인코딩된 콘텐츠를 표시하기에 충분하지 않은 구성입니다. 기본 “맵” 접근 방식과 다음과 같은 차이점이 있습니다:

  • MiniMap.encode_strings()로 라인 인코딩을 수행하지 않고 대신 고정된 수의 라인(창 높이와 동일)으로 인코딩을 사용합니다.

  • 통합 하이라이트가 계산되지 않습니다.

구성:

require('mini.map').setup({
  -- `symbols`를 기호에 맞게 사용자 정의하세요

  window = {
    -- 이를 스크롤 심볼의 최대 너비로 설정하세요
    width = 1,

    -- 이를 기호에 맞게 설정하세요. 0, 25, 50, 75, 100 값을 시도해 보세요
    winblend = 100,

    -- 추가 열이 필요하지 않습니다
    show_integration_count = false,
  }
})

current

MiniMap.current

맵의 현재 상태에 대한 정보가 포함된 테이블

최소한 다음 키들이 지원됩니다:

  • <buf_data> - 버퍼 식별자가 포함된 테이블. <map> 필드에는 맵을 표시하는 데 사용되는 버퍼의 식별자가 포함됩니다. <source> 필드에는 맵이 콘텐츠를 표시하고 있는 버퍼(즉, 소스 버퍼)의 식별자가 포함됩니다.

  • <win_data> - 특정 탭페이지에서 맵을 표시하는 데 사용되는 창 식별자 테이블. 키: 탭페이지 식별자, 값: 창 식별자.

  • <opts> - 맵 표시를 제어하는 데 사용되는 현재 옵션. MiniMap.config와 동일한 구조입니다. 글로벌 및 버퍼 로컬 구성보다 우선순위가 높습니다. MiniMap.close()로 마지막 맵 창을 닫을 때 재설정됩니다.

encode_strings()

MiniMap.encode_strings({strings}, {opts})

문자열 인코딩

임의의 문자열 배열을 가져와 논-화이트스페이스 윤곽선을 계산합니다. 출력은 구성 가능한 배열 길이, 문자열 너비 및 인코딩을 나타내는 심볼이 있는 문자열 배열입니다.

각 인코딩 심볼은 이진 정보를 전달할 수 있는 해상도를 가지고 있다고 가정합니다. 예를 들어 해상도 3x2(행 해상도 3, 열 해상도 2)는 각 심볼이 3개 행과 2개 열의 이진 데이터를 인코딩할 수 있음을 의미합니다. 여기서는 논-화이트스페이스 마스크를 인코딩하는 데 사용됩니다. 자세한 내용은 MiniMap.config의 “Encode symbols” 섹션을 참조하세요.

인코딩 단계는 다음과 같습니다:

  • 문자열을 불리언 마스크로 변환: 각 행이 문자열을 나타내는 2D 불리언 배열. 문자열의 각 문자(멀티바이트 가능)가 화이트스페이스가 아니면 각 행 하위 배열의 요소가 true, 그렇지 않으면 false입니다. 참고: 탭은 ‘tabstop’ 공백으로 확장됩니다.

  • 적절한 차원으로 리스케일링:

    • 각 출력 차원은 모든 입력 문자열을 인코딩하기에 충분하지만 제공된 차원(각각 opts.n_rows * resolution.row 및 opts.n_cols * resolution.col)을 넘지 않습니다.

    • 입력 차원이 출력에 맞기에 너무 큰 경우 정보 손실이 있는 그리드 다운스케일링을 수행합니다. 입력 불리언 마스크는 가능한 한 동일한 차원을 갖는 2D 빈(bins)으로 나뉩니다. 각 빈은 단일 불리언 값으로 변환됩니다: 빈에 하나 이상의 true 요소가 포함되면 true, 그렇지 않으면 false입니다. 이는 화이트스페이스 출력이 빈의 모든 항목이 화이트스페이스임을 의미하고, 논-화이트스페이스 출력은 일부 항목이 논-화이트스페이스임을 의미합니다.

  • 불리언 마스크를 심볼 문자열로 변환:

    • 리스케일링된 입력 불리언 마스크는 심볼 해상도 차원의 빈으로 나뉩니다 (false 외부 패딩 가정).

    • 해상도 차원을 갖는 각 빈은 인코딩 심볼로 변환됩니다. 단일 변환 가능한 (resolution.row, resolution.col) 불리언 마스크는 (역순) 이진 숫자로 취급됩니다: true는 1, false는 0. 왼쪽에서 오른쪽으로, 위에서 아래로 순회합니다(왼쪽 상단이 최하위 비트, 오른쪽 하단이 최상위 비트).

예:

출력에 너비가 2인 심볼이 3개 행 있어야 한다고 가정합니다. 인코딩 심볼은 1x2 해상도의 ’ ‘,’▌‘,’▐‘,’█’입니다.

입력 문자열 가정:

aaaaa
 b b

 d d
e e

단계:

  • 불리언 마스크로 변환 (각 행은 불리언 배열, “t”/“f” ~ true/false, 빈 곳은 false와 동일):

    ttttt
ftft

ftft
tft

  • 리스케일링. 출력 차원은 n_rows * resolution.row = 3 * 1 = 3 행과 n_cols * resolution.col = 2 * 2 = 4 열입니다. 가능한 한 동일한 3개 행과 4개 열 그리드를 만들고 빈을 단일 불리언으로 변환합니다. 결과:

    tttt
tftf
ttff

  • 심볼로 변환. 1x2 빈을 만들고 입력을 (역순) 이진 숫자(ff=00=0, tf=10=1, ft=01=2, tt=11=3)로 취급하고 제공된 옵션에서 해당하는 심볼(값에 1을 더한 값)을 가져옵니다. 결과:

    ██
▌▌
█

매개변수

{strings} (table) 임의의 문자열 배열.

{opts} (table|nil) 옵션. 가능한 필드:

  • <n_rows> - 출력 인코딩의 행 수. 너무 크면 모든 입력 문자열을 인코딩하는 데 필요한 최대치로 잘립니다 (심볼 행 해상도 고려). 기본값: math.huge.

  • <n_cols> - 모든 인코딩 문자열의 너비. 너무 크면 모든 입력 문자열을 인코딩하는 데 필요한 최대치로 잘립니다 (심볼 열 해상도 고려). 기본값: math.huge.

  • <symbols> - 추가 resolution 필드가 있는 심볼 배열. 자세한 내용은 MiniMap.config의 “Encode symbols” 섹션을 참조하세요. 기본값: '3x2' 식별자가 있는 MiniMap.gen_encode_symbols.block()의 출력.

반환

(table) 인코딩된 문자열 배열.

open()

MiniMap.open({opts})

맵 창 열기

현재 탭페이지에 맵 창을 만들고 표시합니다. 기본적으로 두 단계로 진행됩니다:

  • 아직 생성되지 않은 경우 맵 버퍼(라인 및 기타 시각적 지표를 설정하는 데 사용됨)와 맵 창을 생성합니다.

  • MiniMap.refresh()를 호출합니다.

매개변수

{opts} (table|nil) 맵 구성을 정의하는 데 사용되는 옵션. MiniMap.config와 동일한 구조입니다. 적어도 한 개의 탭페이지에 맵 창이 열려 있을 때까지 효력이 있습니다. 기본값은 다음 순서대로 가져옵니다:

  • MiniMap.current의 opts 필드에서.

  • vim.b.minimap_config에서.

  • MiniMap.config에서.

refresh()

MiniMap.refresh({opts}, {parts})

맵 창 새로고침

이 함수는 두 가지 목적으로 사용됩니다:

  • opts를 통해 현재 맵 구성을 업데이트합니다.

  • parts를 통해 표시되는 콘텐츠의 일부를 업데이트합니다.

매개변수

{opts} (table|nil) 맵 구성을 정의하는 데 사용되는 옵션. MiniMap.config와 동일한 구조입니다. 적어도 한 개의 탭페이지에 맵 창이 열려 있을 때까지 효력이 있습니다. 기본값은 다음 순서대로 가져옵니다:

  • MiniMap.current의 opts 필드에서.

  • vim.b.minimap_config에서.

  • MiniMap.config에서.

{parts} (table|nil) 업데이트할 부분. 불리언 값을 갖는 인식되는 키 (모두 기본값은 true):

  • <integrations> - 통합 하이라이트를 업데이트할지 여부.

  • <lines> - 맵 라인을 업데이트할지 여부.

  • <scrollbar> - 스크롤바를 업데이트할지 여부.

맵 창으로/에서 포커스 토글

맵 창 내부에 있지 않으면 커서를 맵 창 내부에 둡니다. 그렇지 않으면 소스 버퍼가 있는 이전 창에 커서를 둡니다.

커서가 맵 창 내부에서 이동할 때(포커스 직후가 아닌 경우), 소스 창의 뷰가 현재 맵 라인으로 변환 가능한 첫 번째 라인을 표시하도록 업데이트됩니다. 이를 통해 소스 버퍼를 빠르게 타겟팅하여 탐색할 수 있습니다.

맵 창에서 다시 포커스를 맞추는 데는 적어도 다음과 같은 추가적인 방법이 있습니다:

  • 소스 버퍼에서 현재 탐색된 위치를 수락하려면 <CR>을 누릅니다. false 인수로 이 함수를 호출하는 것과 동일합니다.

  • 맵 창에 포커스를 맞추기 전의 원래 위치로 돌아가려면 <Esc>를 누릅니다. true 인수로 이 함수를 호출하는 것과 동일합니다.

매개변수

{use_previous_cursor} (boolean|nil) 원래 커서 위치(맵 창에 포커스를 맞추기 전의 위치)에서 소스 창에 포커스를 맞출지 여부.

toggle_side()

MiniMap.toggle_side()

맵 창 사이드 토글

맵 창의 사이드를 변경하기 위해 MiniMap.refresh()를 호출하는 간단한 편의용 래퍼입니다.

gen_encode_symbols

MiniMap.gen_encode_symbols

인코딩 심볼 생성

이것은 함수 요소를 가진 테이블입니다. 실제로 인코딩 심볼을 가져오려면 호출하세요.

각 요소는 'rxc' 형식(예: '3x2')의 문자열 해상도 식별자를 사용합니다. 여기서 r은 각 심볼의 행 해상도(인코딩할 수 있는 이진 데이터의 행 수)이고 c는 열 해상도(인코딩할 수 있는 열 수)입니다.

gen_encode_symbols.block()

MiniMap.gen_encode_symbols.block({id})

블록 인코딩 심볼 생성

출력은 이진 데이터를 인코딩하기 위해 속이 찬 블록을 사용합니다. 예: ‘🬗’, ‘▟’, ‘█’.

매개변수

{id} (string) 해상도 식별자. 사용 가능한 값: '1x2', '2x1', '2x2', '3x2' (’mini.map’의 기본값).

통합 생성

이것은 함수 요소를 가진 테이블입니다. 실제로 인코딩 심볼을 가져오려면 호출하세요.

각 요소는 맵 라인을 하이라이트하는 데 사용되는 하이라이트 그룹을 정의하는 테이블을 사용합니다.

gen_integration.builtin_search()

MiniMap.gen_integration.builtin_search({hl_groups})

내장 검색

현재 내장 검색(/, ? 등)과 일치하는 라인을 하이라이트합니다. 통합 카운트는 실제 일치 횟수를 반영합니다.

‘hlsearch’ (OptionSet 참조) 또는 v:hlsearch가 변경될 때마다 통합 하이라이팅 업데이트를 유도합니다. 일부 키의 경우에는 발생하지 않음에 유의하세요:

  • n, N, star 또는 #로 검색을 시작한 후. 이러한 키에서 하이라이트 업데이트를 활성화하려면 커스텀 매핑을 만드세요. 다음과 같이:

    for _, key in ipairs({ 'n', 'N', '*', '#' }) do
  local rhs = key ..
    '<Cmd>lua MiniMap.refresh({}, {lines = false, scrollbar = false})<CR>'
  -- 해당 키를 누르면 검색 후 미니맵을 새로고칩니다
  vim.keymap.set('n', key, rhs)
end

매개변수

{hl_groups} (table|nil) 하이라이트 그룹을 정의하는 테이블. 다음 필드를 가질 수 있습니다:

  • <search> - 검색 일치 항목에 대한 하이라이트 그룹. 기본값: hl-Search.

gen_integration.diagnostic()

MiniMap.gen_integration.diagnostic({hl_groups})

내장 진단

현재 진단 항목과 일치하는 라인을 하이라이트합니다. 항목은 현재(소스) 버퍼에 대해 vim.diagnostic.get()으로 계산됩니다.

DiagnosticChanged 이벤트마다 통합 하이라이팅 업데이트를 유도합니다. 심각도(vim.diagnostic.severity 참조)가 높은 진단 항목이 더 높은 하이라이트 우선순위를 갖습니다 (오류가 다른 모든 항목보다 먼저 표시되는 등).

매개변수

{hl_groups} (table|nil) 하이라이트 그룹을 정의하는 테이블. 제공된 필드는 하이라이트할 진단 심각도도 정의합니다. 다음 필드를 가질 수 있습니다:

  • <error> - 오류 항목에 대한 하이라이트 그룹. 기본값: hl-DiagnosticFloatingError.

  • <warn> - 경고 항목에 대한 하이라이트 그룹. 기본값: nil (표시되지 않음).

  • <info> - 정보 항목에 대한 하이라이트 그룹. 기본값: nil (표시되지 않음).

  • <hint> - 힌트 항목에 대한 하이라이트 그룹. 기본값: nil (표시되지 않음).

사용법

-- 모든 진단 레벨 표시
local map = require('mini.map')
local diagnostic_integration = map.gen_integration.diagnostic({
  error = 'DiagnosticFloatingError',
  warn  = 'DiagnosticFloatingWarn',
  info  = 'DiagnosticFloatingInfo',
  hint  = 'DiagnosticFloatingHint',
})
-- 진단 통합을 사용하여 미니맵 설정
map.setup({ integrations = { diagnostic_integration } })
