mini.colors 문서

’mini.nvim’의 main 브랜치에서 생성됨

mini.colors 모든 색상 스키마를 조정하고 저장합니다

MIT 라이선스 Copyright (c) 2023 Evgeni Chasnovski

모듈

기능:

  • 색상 스키마 객체 생성: 수동(MiniColors.as_colorscheme())으로 생성하거나 현재 등록된 색상 스키마(현재 활성화된 것 포함; MiniColors.get_colorscheme() 참고)를 조회하여 생성할 수 있습니다.

  • 색상 스키마 데이터 추론 및 수정:

    • 배경색을 제거하여 투명도 추가(터미널 에뮬레이터에서 투명도를 지원해야 함).

    • GUI 색상을 기반으로 cterm 속성(cterm-colors)을 추론하여 ’notermguicolors’와 호환되게 만듭니다.

    • 하이라이트 그룹 링크(:highlight-link)를 해결합니다.

    • 중복된 하이라이트 그룹을 제거하여 압축합니다.

    • 사용된 색상의 팔레트를 추출하거나 이를 기반으로 터미널 색상(terminal-config)을 추론합니다.

  • 취향이나 목적에 맞게 색상 수정(MiniColors-colorscheme-methods 참고):

    • 색상 16진수 문자열에 임의의 함수를 적용합니다.

    • 채널(명도, 채도, 색상, 색온도, 빨강, 초록, 파랑 등; MiniColors-channels 참고)을 업데이트합니다. 직접 함수를 사용하거나 다음 메서드 중 하나를 사용하십시오:

      • 채널에 값을 더하거나 계수를 곱합니다. 예를 들어 “모든 색상의 채도에 10 더하기” 또는 “채도에 2 곱하기”를 통해 색상을 더 선명하게(회색기 제거) 만들 수 있습니다.

      • 반전. 예를 들어 “명도 반전”을 통해 다크/라이트 테마를 서로 전환할 수 있습니다.

      • 하나 이상의 값으로 설정(현재 값과 가장 가까운 값을 선택). 예를 들어 “하나 또는 두 개의 색상으로 설정”하여 단색(monochromatic) 또는 이색(dichromatic) 색상 스키마를 만들 수 있습니다.

      • 특정 원본에서 멀어지게 하며, 가까운 값일수록 더 강하게 적용합니다. 예를 들어 “색상 30(빨강)에서 멀어지게” 하여 색상 스키마에서 빨간색을 제거할 수 있습니다. 멀어지는 정도는 구성 가능합니다.

    • 색각 결핍(color vision deficiency)을 시뮬레이션합니다.

  • 색상 스키마가 준비되면 바로 적용하여 효과를 확인하거나, 완전히 작동하는 별도의 색상 스키마로서 Lua 파일로 저장할 수 있습니다.

  • 피드백을 받으며 대화형으로 실험할 수 있습니다(MiniColors.interactive()).

  • MiniColors.animate() 또는 :Colorscheme 사용자 명령을 통해 색상 스키마 간의 전환 애니메이션을 보여줍니다.

  • 지원되는 색 공간 내에서 변환합니다(MiniColors.convert()):

    • 16진수 문자열(Hex).

    • 8비트 숫자(터미널 색상).

    • RGB.

    • Oklab, Oklch, Okhsl (https://bottosson.github.io/posts/oklab/).

참고:

  • 일반적인 작업을 위한 코드 스니펫이 포함된 MiniColors-recipes 컬렉션이 있습니다.

  • 가능한 많은 색 공간을 지원하는 것이 목표가 아니며, 현재 존재하는 색 공간만 지원합니다.

조정 퀵 스타트

  • :lua require('mini.colors').interactive()를 실행합니다.

  • 노출된 색상 스키마 메서드를 호출하는 코드를 작성하고 <M-a>로 적용하며 실험합니다. 자세한 정보는 MiniColors-colorscheme-methods 및 MiniColors-recipes를 참고하십시오.

  • 결과가 마음에 들면 <M-w>로 색상 스키마를 저장합니다. 그렇지 않다면 <M-r>로 초기 색상 스키마로 재설정합니다.

  • 일부 하이라이트 그룹만 더 개선할 수 있다면, 저장된 색상 스키마 파일 내에서 직접 조정하십시오.

설정

이 모듈은 설정을 필수로 요구하지 않지만, 사용 편의성을 위해 설정할 수 있습니다. require('mini.colors').setup({})으로 설정하십시오({}를 config 테이블로 교체). 이를 통해 스크립트나 수동 작업 시 사용할 수 있는 전역 Lua 테이블 MiniColors가 생성됩니다(예: :lua MiniColors.*).

config 구조와 기본값은 MiniColors.config를 참고하십시오.

이 모듈은 런타임 옵션이 없으므로 vim.b.minicolors_config를 사용해도 효과가 없습니다.

레시피

다음의 모든 코드 스니펫은 대화형 버퍼(MiniColors.interactive()) 내부에서 실행되는 것을 가정합니다. 직접 복사하여 붙여넣을 수 있습니다.

현재 색상 스키마에 단일 메서드를 적용하려면 다음을 사용하십시오.

:lua MiniColors.get_colorscheme():<메서드 내용>:apply().

레시피:

  • 명도(lightness) 조정:

    -- 다크/라이트 색상 스키마를 라이트/다크로 반전
chan_invert('lightness', { gamut_clip = 'cusp' })

-- 일정한 대비 비율 보장
chan_set('lightness', 15, { filter = 'bg' })
chan_set('lightness', 85, { filter = 'fg' })

  • 채도(saturation) 조정:

    -- 배경색의 채도는 낮추고 전경색은 높이기
chan_add('saturation', -20, { filter = 'bg' })
chan_add('saturation', 20,  { filter = 'fg' })

-- 회색조(grayscale)로 변환
chan_set('saturation', 0)

  • 색상(hue) 조정:

    -- 단색 변형 생성 (초록색 사용)
chan_set('hue', 135)

-- 이색 변형 생성 (Neovim 테마 색상 사용)
chan_set('hue', { 140, 245 })

  • 색온도(temperature) 조정:

    -- 색온도 반전 (차가운 테마를 따뜻하게 또는 반대로)
chan_invert('temperature')

-- 배경색은 더 차갑게, 전경색은 더 따뜻하게 만들기
chan_add('temperature', -40, { filter = 'bg' })
chan_add('temperature', 40,  { filter = 'fg' })

  • 색각 결핍 대응 (자신에게 가장 잘 맞는 조합을 찾아보십시오):

    • 텍스트 채도 대비 개선 (일반적으로 가장 좋은 시작 방법):

      chan_set('saturation', { 10, 90 }, { filter = 'fg' })

    • 모든 색상에서 특정 색상 제거 (빨강 30, 노랑 90, 초록 135, 파랑 270 사용):

      -- 빨간색 제거
chan_repel('hue', 30, 45)

    • 균일한 간격의 팔레트 강제 (문제가 있는 것으로 알려진 색상 제거):

      -- 적녹 색맹에게 좋은 선택일 수 있음
chan_set('hue', { 90, 180, 270})

-- 청황 색맹에게 좋은 선택일 수 있음
chan_set('hue', { 0, 90, 180 })

    • 온도나 압력(pressure)을 반전시키면 가독성이 좋아질 수 있음:

      chan_invert('temperature')
chan_invert('pressure')

    • 모든 방법이 실패한다면, 운 좋게 색상 무작위 생성이 도움이 될 수 있음:

      chan_modify('hue', function() return math.random(0, 359) end)

  • 색상 스키마 제작자는 MiniColors-colorscheme:simulate_cvd()를 사용하여 다양한 색각 결핍 유형을 시뮬레이션하고, 색맹인 사람의 눈에 색상 스키마가 어떻게 보일지 확인할 수 있습니다.

색 공간

색 공간은 색상을 정량적으로 설명하는 방법입니다. 이 모듈에서 색 공간은 MiniColors-channels의 원본과 MiniColors.convert()의 입력으로 사용됩니다.

지원되는 색 공간 목록(괄호 안은 ID):

  • 8비트 (8-bit) - 16에서 255 사이의 정수. 보통 0-15도 지원되지만, 터미널 에뮬레이터 테마에 따라 달라지므로 신뢰할 수 없습니다. 참고: https://en.wikipedia.org/wiki/ANSI_escape_code#8-bit

  • 16진수 (hex) - “#xxxxxx” 형식의 문자열 (여기서 x는 16진수).

  • RGB (rgb) - r (빨강), g (초록), b (파랑) 숫자 필드를 가진 테이블. 표시 범위는 0에서 255 사이입니다.

  • Oklab (oklab) - l (명도; [0; 100] 범위의 숫자), a, b (둘 다 범위 제한 없는 숫자; 가시 범위는 보통 -30에서 30 사이) 필드를 가진 테이블. 필드 l은 색상이 얼마나 밝은지, a는 “초록-빨강” 정도, b는 “파랑-노랑” 정도를 설명합니다.

  • Oklch (oklch) - l (Oklab과 동일), c (크로마; 양수, 가시 범위는 보통 32 미만), h (회색인 경우 nil, 아니면 [0, 360) 범위의 주기적 숫자) 필드를 가진 테이블. 필드 c는 색상이 얼마나 선명한지, h는 색상 휠 상의 “실제 색상” 값을 설명합니다. 참고: 회색과 같은 무채색은 색상(hue) 정보가 없습니다.

  • Okhsl (okhsl) - Oklch에서 c가 s(채도; [0; 100] 범위의 숫자)로 대체된 형태입니다. 필드 s는 특정 명도 및 색상 조합에 대해 가시적인 최대 크로마에 대한 비율(퍼센트)을 설명합니다. 최대 크로마 계산에 사용되는 수학적 모델은 근사치이므로, 명도가 매우 낮거나 높은 고채도 색상의 경우 오차가 발생할 수 있습니다.

Oklab/Oklch/Okhsl 자료:

  • https://bottosson.github.io/posts/oklab/ - Oklab 및 Oklch의 초기 유도 및 소개.

  • https://bottosson.github.io/misc/colorpicker - 대화형 색상 선택기. 명도, 크로마, 채도, 색상 개념을 직접 익히기에 좋습니다.

Oklab/Oklch/Okhsl은 (위 자료에 따라) 정수에 더 적합하도록 l, a, b, c, s 채널 정규화를 사용합니다. CSS와 같은 일부 구현은 [0; 1] 범위나 퍼센트를 더 지향합니다. 필요한 경우 출력값을 100으로 나누거나 곱하여 조정하십시오. 또한 MiniColors.convert()에서 adjust_lightness = false를 사용하십시오.

가멋 클립

MiniColors-gamut-clip

Neovim의 하이라이트 그룹 색상은 일반적으로 0에서 255 사이의 빨강, 초록, 파랑 값을 HEX 문자열 형태로 지정합니다(gui-colors 참고). 하지만 이것이 가능한 모든 색상을 나타내는 것은 아닙니다.

MiniColors-colorscheme-methods를 사용하여 색상을 조작할 때, HEX 문자열로 직접 변환할 수 없는 “불가능한” 색상이 만들어질 수 있습니다. 예를 들어, Oklch 공간에서 “#fce094” 색상의 명도를 반전시키면 { l = 10, c = 10, h = 90 } 색상이 되는데, 이 “어두운 노란색”은 HEX로 표현할 수 없습니다.

가멋 클리핑(Gamut clipping)은 가시 영역 밖의 색상(HEX 문자열로 표현할 수 없는 색상)을 특정 지각적 특성을 최대한 유지하면서 가시 영역 안으로 변환하는 작업입니다.

이 모듈의 가멋 클리핑은 Oklch 색 공간 내부에서 수행됩니다. 목표는 명도나 크로마를 조작하는 동안 색상(hue)을 최대한 유지하는 것입니다.

지원되는 가멋 클립 방법 목록(괄호 안은 ID):

  • 크로마 클립 ('chroma') - 색상이 가시 영역 안에 들어올 때까지 명도를 유지하면서 크로마를 줄입니다. 기본 방법입니다.

  • 명도 클립 ('lightness') - 색상이 가시 영역 안에 들어올 때까지 크로마를 유지하면서 명도를 줄입니다.

  • 커스프에 따른 클립 ('cusp') - 색상(hue)에 따라 명도와 크로마를 절충하여 줄입니다. 커스프는 동일한 색상(hue)을 가진 가시 영역 단면(색상 잎) 내부에서 가장 높은 크로마를 가진 색상입니다. 단면의 모양이 (0, 0) - (0, 100) - (크로마, 명도 좌표의 “커스프”)를 꼭짓점으로 하는 대략적인 삼각형 모양이기 때문에 그렇게 불립니다. 커스프를 기준으로 하는 가멋 클리핑은 색상이 가시 영역 안에 들어올 때까지 현재 커스프와 동일한 명도를 가진 회색(0, cusp_lightness) 지점을 향해 색상을 변화시킴으로써 수행됩니다.

요약하자면:

  • 보통 'chroma'로 충분합니다.

  • 색상이 너무 탁해지면 'cusp'를 시도해보십시오.

  • 여전히 색감이 부족하다면 'lightness'를 시도해보십시오.

참고:

  • 현재 구현된 공식은 (코드 복잡성을 줄이기 위해) 근사치이므로, 명도가 매우 낮거나 높은 고채도 색상에서는 문제가 발생할 수 있습니다.

채널

색상 채널은 색상의 특정 측면을 설명하는 숫자입니다. 보통 색 공간의 직접적인 또는 수정된 좌표입니다. 색 공간에 대한 정보는 MiniColors-color-spaces를 참고하십시오.

지원되는 채널 목록(괄호 안은 ID):

  • 명도 (lightness) - Oklch의 보정된 l 구성 요소. 색상이 얼마나 밝은지 설명합니다. 0(가장 어두움)에서 100(가장 밝음)까지의 범위를 갖습니다.

  • 크로마 (chroma) - Oklch의 c 구성 요소. 절대 단위로 색상이 얼마나 선명한지 설명합니다. 0(회색)에서 무한대(실제로는 약 30 내외)까지의 범위를 갖습니다.

  • 채도 (saturation) - Okhsl의 s 구성 요소. 상대 단위로 색상이 얼마나 선명한지 설명합니다. 0(회색)에서 100(주어진 명도-색상 쌍에 대한 최대 채도)까지의 범위를 갖습니다.

  • 색상 (hue) - Oklch의 h 구성 요소. 빨강/초록/파랑과 같은 “실제 색상 값”을 숫자로 설명합니다. 0(포함)에서 360(미포함) 사이의 주기적인 값입니다. 색상 휠 상의 각도로 인식하는 것이 가장 좋습니다.

    일반적인 색상 이름에 대한 근사치:

    • 0 - 분홍색.

    • 30 - 빨간색.

    • 60 - 주황색.

    • 90 - 노란색.

    • 135 - 초록색.

    • 180 - 청록색(cyan).

    • 225 - 연한 파란색.

    • 270 - 파란색.

    • 315 - 자홍색(magenta)/보라색.

  • 색온도 (temperature) - 현재 색상(hue)에서 270도(파랑)까지의 원형 거리입니다. 270도(파랑)와 90도(노랑)를 기준으로 0(차가움)에서 180(따뜻함)까지의 범위를 갖습니다. b 채널과 유사하지만 크로마를 유지하려고 시도합니다.

  • 압력 (pressure) - 현재 색상(hue)에서 180도까지의 원형 거리입니다. 180도와 0도를 기준으로 0(낮음; 초록빛)에서 180(높음; 빨간빛)까지의 범위를 갖습니다. a 채널과 유사하지만 크로마를 유지하려고 시도합니다. 널리 사용되지는 않으며, 색온도와 유사한 기능을 위해 추가되었습니다.

  • a (a) - Oklab의 a 구성 요소. 색상이 얼마나 “초록-빨강”인지 설명합니다. 모든 값을 가질 수 있습니다. 음수는 “초록빛”, 양수는 “빨간빛”을 의미합니다.

  • b (b) - Oklab의 b 구성 요소. 색상이 얼마나 “파랑-노랑”인지 설명합니다. 모든 값을 가질 수 있습니다. 음수는 “파란빛”, 양수는 “노란빛”을 의미합니다.

  • 빨강 (red) - RGB의 r 구성 요소. 빨간색의 양을 설명합니다. 0(빨강 없음)에서 255(최대 빨강)까지의 범위를 갖습니다.

  • 초록 (green) - RGB의 g 구성 요소. 초록색의 양을 설명합니다. 0(초록 없음)에서 255(최대 초록)까지의 범위를 갖습니다.

  • 파랑 (blue) - RGB의 b 구성 요소. 파란색의 양을 설명합니다. 0(파랑 없음)에서 255(최대 파랑)까지의 범위를 갖습니다.

색상 스키마

색상 스키마(Colorscheme) 객체는 이 모듈의 핵심 구조입니다. 필드에는 색상과 관련된 모든 데이터를 포함하며, 이를 수정하는 메서드를 제공합니다.

MiniColors.as_colorscheme()를 사용하여 수동으로 색상 스키마 객체를 생성합니다:

MiniColors.as_colorscheme({
  name = 'my_cs',
  groups = {
    Normal   = { fg = '#dddddd', bg = '#222222' },
    SpellBad = { sp = '#dd2222', undercurl = true },
  },
  terminal = { [0] = '#222222', [1] = '#dd2222' },
})

MiniColors.get_colorscheme()를 사용하여 등록된 색상 스키마(현재 활성화된 것 포함)를 객체로 가져옵니다:

-- 현재 색상 스키마 가져오기
MiniColors.get_colorscheme()

-- 이름을 지정하여 등록된 색상 스키마 가져오기
MiniColors.get_colorscheme('minischeme', { new_name = 'maxischeme' })

chan_repel()

MiniColors-colorscheme:chan_repel()

특정 원본에서 멀어지게 합니다.

원본 배열(sources)과 멀어지는 정도(coef)가 주어지면, 현재 채널 값에 다음 속성을 가진 특정 양(“nudge”)을 더합니다:

  • 여러 원본으로부터의 이동량(nudge)이 합산됩니다.

  • 이동량은 coef에 정비례합니다: coef가 클수록 이동량이 커집니다.

  • 이동량은 현재 값과 원본 사이의 거리에 반비례합니다: 양수 coef의 경우 거리가 멀수록 이동량이 작아집니다. 즉, 거리가 멀어질수록 밀어내는 효과가 약해집니다.

  • 양수 coef의 경우, 원본 근처의 이동량은 전체 [source - coef; source + coef] 범위를 제거하도록 계산됩니다.

  • 음수 coef는 원본으로 끌어당기는 결과를 낳습니다. [source - coef; source + coef] 범위의 이동량은 해당 범위를 완전히 source로 붕괴시키도록 계산됩니다.

예시:

-- 빨간색으로부터 색상(hue)을 멀어지게 하여 20에서 40 사이의 색상을 제거
chan_repel('hue', 30, 10)

-- 빨간색으로 색상을 끌어당겨 [20; 40] 범위를 30으로 붕괴
chan_repel('hue', 30, -10)
매개변수

{channel} (string) 지원되는 MiniColors-channels 중 하나.

{sources} (table|number) 멀어질 기준이 되는 하나 이상의 원본.

{coef} (number) 멀어지는 정도(끌어당기려면 음수).

{opts} (table|nil) 옵션. 사용 가능한 필드:

  • <filter> (function|string) - 업데이트할 색상을 필터링합니다. 가능한 값:

    • 대상 속성을 나타내는 문자열. 'fg', 'bg', 'sp', 'term'(터미널 색상만) 중 하나.

    • MiniColors-colorscheme:color_modify()와 동일한 시그니처를 가진 콜러블. 기본값: 모든 색상을 업데이트하려면 nil.

  • <gamut_clip> (string) - 가멋 클리핑 방법. 'chroma', 'lightness', 'cusp' 중 하나. MiniColors-gamut-clip을 참고하십시오. 기본값: 'chroma'.

  • <filter> (function|string) - 업데이트할 색상을 필터링합니다. 가능한 값:

    • 대상 속성을 나타내는 문자열. 'fg', 'bg', 'sp', 'term'(터미널 색상만) 중 하나.

    • MiniColors-colorscheme:color_modify()와 동일한 시그니처를 가진 콜러블. 기본값: 모든 색상을 업데이트하려면 nil.

  • <gamut_clip> (string) - 가멋 클리핑 방법. 'chroma', 'lightness', 'cusp' 중 하나. MiniColors-gamut-clip을 참고하십시오. 기본값: 'chroma'.

color_modify()

MiniColors-colorscheme:color_modify()

콜러블을 사용하여 모든 색상을 수정합니다. 다음 입력을 기반으로 새 색상 값(HEX 문자열 또는 속성을 제거하려면 nil)을 반환해야 합니다:

  • 현재 색상 (HEX 문자열).

  • 색상에 대한 데이터: 다음 필드를 가진 테이블:

    • <attr> - 'fg', 'bg', 'sp', 터미널 색상의 경우 'term' 중 하나.

    • <name> - 색상 원본의 이름. 하이라이트 그룹의 이름이거나 터미널 색상의 경우 terminal_color_x 형식의 문자열(terminal-config 참고).

예시:

-- "N"으로 시작하는 그룹의 모든 전경색을 '#dd2222'로 설정
color_modify(function(hex, data)
  if data.attr == 'fg' and data.name:find('^N') then
    return '#dd2222'
  end
  return hex
end)
매개변수

{f} (function) 새 색상 값을 반환하는 콜러블.

compress()

MiniColors-colorscheme:compress()

중복된 하이라이트 그룹을 제거합니다. 중복은 다음 두 가지 종류 중 하나입니다:

  • :hi-clear 이후의 값과 동일한 값을 가진 그룹 (보통 새로운 정보를 추가하지 않음을 의미).

  • 일반적으로 보관할 가치가 없는 플러그인 하이라이트 그룹 목록에 포함된 그룹. 현재 대상 플러그인 목록:

    • nvim-tree/nvim-web-devicons

    • norcalli/nvim-colorizer.lua

이 메서드는 MiniColors-colorscheme:write()를 통해 파일로 저장하기 전에 색상 스키마의 크기를 줄이는 데 유용합니다.

매개변수

{opts} (table|nil) 옵션. 사용 가능한 필드:

  • <plugins> (boolean) - 선별된 플러그인 목록의 하이라이트 그룹을 제거할지 여부. 기본값: true.
get_palette()

MiniColors-colorscheme:get_palette()

자주 사용되는 색상을 가져옵니다. 기본적으로 모든 색상의 발생 횟수를 세고 드문 색상을 필터링합니다.

이 기능을 적용하기 전에 MiniColors-colorscheme:compress()와 MiniColors-colorscheme:resolve_links()를 모두 적용하는 것이 좋습니다.

매개변수

{opts} (table|nil) 옵션. 사용 가능한 필드:

  • <threshold> (number) - 유지할 그룹의 상대적 임계값. 전체 색상 수에 비해 이 수치보다 적게 발생하는 그룹은 출력에 포함되지 않습니다. 기본값: 0.01.
resolve_links()

MiniColors-colorscheme:resolve_links()

링크(:highlight-link)를 해결합니다. link 속성을 가진 모든 하이라이트 그룹이 연결된 그룹의 데이터를 갖도록 만듭니다.

참고:

  • 중첩된 링크를 해결합니다.

  • 현재 색상 스키마 객체에 없는 그룹에 링크된 경우 해결되지 않습니다.

simulate_cvd()

MiniColors-colorscheme:simulate_cvd()

색각 결핍(CVD, 색맹)을 시뮬레이션합니다. 기본적으로 MiniColors-colorscheme:color_modify() 메서드 호출의 일부로 MiniColors.simulate_cvd()를 사용하는 래퍼입니다.

매개변수

{cvd_type} (string) 'protan', 'deutan', 'tritan', 'mono' 중 하나.

{severity} (number|nil) CVD의 심각도, 0에서 1 사이의 숫자. 기본값: 1.

write()

MiniColors-colorscheme:write()

색상 스키마를 파일로 저장합니다. 일반 색상 스키마로 즉시 사용할 수 있는 Lua 스크립트가 됩니다. 색상 스키마 조정 결과를 저장하거나 다른 색상 스키마의 로컬 스냅샷을 만드는 데 유용합니다.

시작할 때 이 파일을 소싱하는 것은 조건부 :hi-clear 호출과 일련의 nvim_set_hl() 호출로 구성되므로, 초기 색상 스키마를 소싱하는 것보다 일반적으로 성능이 더 좋습니다.

기본 저장 위치는 Neovim 설정 디렉터리의 “colors” 디렉터리입니다(base-directories 참고). 저장 후에는 :colorscheme 또는 :Colorscheme으로 소싱할 수 있습니다.

파일 이름은 기본적으로 name 필드에서 가져옵니다(nil인 경우 'mini_colors' 사용). 해당 이름의 색상 스키마가 이미 존재하면 현재 시간을 기준으로 접두사를 추가하여 고유하게 만듭니다.

참고:

  • 색상을 업데이트한 경우, 저장하기 전에 MiniColors-colorscheme:add_cterm_attributes()로 cterm 속성을 추론하는 것이 좋습니다.
매개변수

{opts} (table|nil) 옵션. 사용 가능한 필드:

  • <compress> (boolean) - 저장하기 전에 MiniColors-colorscheme:compress()를 호출할지 여부. 기본값: true.

  • <name> (string|nil) - 저장될 파일의 기본 이름. 기본값: name 필드에서 추론하려면 nil.

  • <directory> (string) - 파일이 저장될 디렉터리. 기본값: Neovim 홈 설정의 “colors” 하위 디렉터리(stdpath("config")).

interactive()

MiniColors.interactive({opts})

대화형 실험 시작

사용자가 일반 Lua 코드를 작성하여 색상 스키마를 조정하고 시각적 피드백을 즉시 확인할 수 있는 특별한 버퍼를 생성합니다.

일반 원칙

  • 초기 색상 스키마 객체은 대화형 버퍼 생성 시 해당 버퍼에 고정됩니다.

  • 특별한 버퍼 편의 매핑이 제공됩니다:

    • 현재 버퍼 내용을 적용(소싱)합니다.

    • 색상 스키마를 재설정(초기 색상 스키마를 현재 상태로 설정)합니다.

    • 현재 버퍼 내용을 적용한 결과를 파일로 저장합니다. 현재 내용을 소싱하고 MiniColors-colorscheme:write()를 호출합니다.

    • 대화형 버퍼를 닫습니다.

  • 사용자는 대화형 버퍼에 일반 Lua 코드를 작성하고 편의 매핑을 사용하여 적용함으로써 색상 스키마를 반복적으로 조정할 수 있습니다.

  • 대화형 버퍼의 적용은 기본적으로 다음 단계를 거칩니다:

    • 모든 적용 시 self를 초기 색상 스키마 객체로 노출합니다. 모든 적용에 대해 항상 동일합니다.

    • 초기 색상 스키마 메서드를 독립형 함수로 노출합니다. 따라서 사용자는 self = self:add_transparency() 대신 add_transparency()만 작성할 수 있습니다.

    • 버퍼 내용을 일반 Lua 코드로 소싱합니다.

대화형 버퍼 내용 예시:

chan_modify('hue', function() return math.random(0, 359) end)
simulate_cvd('protan')

  • <colorscheme> (table|nil) - 실행될 코드의 초기 색상 스키마로 사용될 MiniColors-colorscheme 객체. 기본적으로 현재 색상 스키마를 사용합니다.
